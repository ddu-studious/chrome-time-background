## 两份技能的差异

| 检查项 | 个人版 | 系统版 | 建议 |
| --- | --- | --- | --- |
| 常规生图 | 优先原生工具，工具不可用时自动转 CLI | 默认内置工具；CLI 需明确选择或确认 | 采用系统版，避免无意切到另一计费路径 |
| CLI 默认模型 | 技能正文和脚本均为 `gpt-image-1.5` | 正文和脚本均为 `gpt-image-2` | 个人版若继续保留，不能只改文案而留下旧脚本默认值 |
| 透明图 | 没有完整区分内置和不同 CLI 模型的能力 | 内置直接请求透明；CLI 对不支持透明的模型明确处理 | 采用系统规则，不为透明图静默切模型 |
| 批量素材 | 泛称 generate-batch，容易导向 CLI | 未明确 API 时逐个调用内置工具 | 区分“很多图”和“选择 API 批处理” |
| 项目文件 | 主要写 CLI 输出目录约定 | 生成后把选定项目资产复制进工作区 | 采用系统版，不能引用只留在 Codex 默认目录里的项目资产 |
| 原生可编辑素材 | 未明确排除简单代码 / SVG 资产 | 已有可编辑向量或代码原生资产优先直接编辑 | 不用生图替换现有可编辑图标或模拟引擎 |

个人版不是完全不能用：它已正确写明原生工具优先、原生不需 API Key。需要更新的是自动回退、CLI 默认值与工作区落盘规则。两份技能同名且本轮被同时指定，存在规则不一致；未验证所有客户端的同名技能解析优先级，不据此断言某个目录必然覆盖另一个。

## 推荐处理

1. 日常直接使用系统版 `imagegen`；无需安装“更强提示词”类第三方技能来换模型。
2. 如果个人版没有独有工作流，先备份后停用这份重复副本；不要手工改系统目录。
3. 如果确有本地 API 批处理需求，将个人工作流另命名并明确“用户选择 API 才运行”。通过系统 CLI 暴露的参数调用，保留其模型校验；不要改写生图脚本，也不在技能里储存密钥。

以上为可执行的迁移建议，本轮没有运行停用、安装、升级或删除动作。
