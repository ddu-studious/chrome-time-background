# 水族馆 Implementation Plan

> **For agentic workers:** 本仓库规则禁止子代理，按 `superpowers:executing-plans` 在当前会话内逐任务执行。步骤用复选框跟踪。

**Goal:** 在首页水母背景里加一层用户自己放入的鱼，鱼可以放入、可以捞出；水母仍是主线，水母与任务的关系不变。

**Architecture:** 纯逻辑 `AquariumCore`（群游、数量上限、命中、抓取状态）+ 控制器 `Aquarium`（存储、托盘、网兜、指针状态机、Canvas 2D 画法）。鱼画在背景体验共享画布上、在水母之前画；宿主 `background-experience.js` 只多两处接线（画鱼、抓鱼路由），水母皮肤只多一个只读 `bells()`。

**Tech Stack:** 原生 JavaScript、Canvas 2D、`chrome.storage.local`、`node --test`。不引入 Three.js、CDN、新权限或网络（理由见设计 §3）。

设计文档：`docs/superpowers/specs/2026-10-17-aquarium-design.md`（含素材审阅 §2A）。

## Global Constraints

- 水母是主线：鱼比水母小一档、更淡、画在水母后面，不画任务名；水母行为、任务完成链路、纸篓完全不变。
- 不新增权限、网络请求、依赖、CDN；不用 `innerHTML`、不自建 RAF/画布（宿主是唯一帧循环）、不写内联事件处理（`test/csp-no-inline-handler.test.js`）。
- 受“启用背景体验”总开关、`reduce-motion`（水母皮肤本就不启动）、`saveData`、页面隐藏、工作台遮挡限制。
- 存储键 `aquariumV1 = {v:1, fish:[{id, species, addedAt}]}`，在 `chrome.storage.local`；不存位置；读取按白名单校验；读不到或损坏时当空水族馆且**不覆盖**原数据；写入串行、先读最新值再改；写入失败回滚并提示。
- 条目（用户放入的单位）上限 12、省流量 6；渲染条数上限 40、省流量 16；大型（蝠鲼、鲸鲨）合计最多 2 个条目；这三个数字最终以真实 Chromium 帧耗时测量为准。
- 8 种鱼：霓虹灯鱼 `neon`、蓝吊 `tang`（群居，一次放入约 5 条算 1 个条目）、小丑鱼 `clown`、河豚 `puffer`、神仙鱼 `angel`、小锤头鲨 `hammer`（单条）、蝠鲼 `manta`、鲸鲨 `whaleshark`（大型）。鲨鱼不捕食。
- 抓取优先级：水母优先，鱼只在没有水母命中时才能抓；不抢任务条、卡片、Dock、时钟文字的点击（只在 `isBackgroundTarget` 上生效，只认主指针主键）。
- 捞出 = 拖过约 6 px 后出现网兜区，松手在网兜内才移除；Esc、失焦、`pointercancel`、页面隐藏、关皮肤/总开关只放开；已提交的捞出不可撤回；居民列表里每条有“捞出”按钮作键盘/触屏等价操作。
- 第一版不做：喂食、拉鱼尾、布景、稀有来访者、捕食、收藏鱼篓。
- 版本钉子：新增 `js/aquarium-core.js?v=1`、`js/aquarium.js?v=1`、`css/aquarium.css?v=1`；`jellyfish.js` 与 `background-experience.js`、`settings-page.js` 的 `?v=` 随改动递增，并同步对应契约测试里的钉子。
- 验证分层报告：静态检查、业务替身测试、HTTP 预览（真实 Chromium）、真实 Chrome 扩展、真实账号，不把一层写成另一层通过。项目约定：未经用户要求不提交 Git，各任务末尾的 git commit 只是建议提交点，由用户决定是否提交；所有改动只在 worktree `~/worktrees/ctb-aquarium`（分支 `feat/aquarium-20261017`）里，不动原工作区。

### Task 1: `AquariumCore`（纯逻辑）

**Files:**
- Create: `js/aquarium-core.js`
- Test: `test/aquarium-core.test.js`

**Interfaces — Produces（后续任务依赖这些名字）:**
- `PARAMS`（冻结）：`MAX_ENTRIES 12`、`MAX_ENTRIES_LOW 6`、`MAX_FISH 40`、`MAX_FISH_LOW 16`、`MAX_LARGE 2`，以及群游、避让、深度参数。
- `SPECIES`（冻结数组）：每项 `{id, name, kind: 'school'|'solo'|'large', group, len, speed, band: [lo, hi], colors: [slot, slot]}`；`speciesById(id)` → 项或 `null`。
- `normalizeEntries(raw, lowPower=false)` → `{ entries: [{id, species, addedAt}], dropped }`（只留白名单种类、合法 id/时间、去重、按上限截断；`raw` 非数组 → `entries: []`）。
- `canAdd(entries, speciesId, lowPower=false)` → `{ok:true}` 或 `{ok:false, reason: 'unknown'|'full'|'large'|'render'}`。
- `renderCount(entries)` → 渲染条数。
- `createWorld({width, height, random, lowPower})`、`resize(world, w, h)`。
- `reconcile(world, entries, {instant, from})`：按条目生成/淡出鱼；`from` 是 `{x, y}`，新鱼从该点游入（缺省从屏幕下方入场）。
- `step(world, dtMs, {pointer, bells})`：`pointer` 为 `{x, y}|null`，`bells` 为 `[{x, y, r}]`。
- `hitTest(world, x, y)` → 鱼或 `null`；`grab(world, fish, x, y)` → boolean；`release(world, fish, velocity)`；`dismiss(world, entryId)`：该条目的鱼快速淡出并从世界移除。
- 鱼对象字段：`{id, entry, species, x, y, vx, vy, ang, z, phase, alpha, state: 'entering'|'alive'|'leaving'|'held', held}`。

- [ ] **Step 1: 写失败测试**——`test/aquarium-core.test.js` 覆盖：
  1. `SPECIES` 恰好 8 种、id 唯一、`neon/tang` 是 school 且 `group ≥ 4`、`manta/whaleshark` 是 large、`colors` 槽位 0..7。
  2. `normalizeEntries`：未知种类、重复 id、非法时间、非数组被丢弃；超过 12（省流量 6）截断；大型超过 2 个后面的被丢弃；合法数据原样保留。
  3. `canAdd`：满 12 返回 `full`；第 3 个大型返回 `large`；渲染条数会超 40 时返回 `render`；未知种类 `unknown`；正常 `ok`。
  4. `reconcile`：空世界按条目生成鱼（群居条目生成 `group` 条，同一 `entry`）；移除条目后其鱼进入 `leaving` 并在淡出时间后从 `world.fish` 消失；`instant` 直接 `alive`；超出省流量渲染上限不生成。
  5. `step`：长时间推进后所有鱼始终在 `[−margin, width+margin]` 内、纵向落在各自 `band` 的松弛范围内；**纵向分布测试**——模拟 120 秒、每 50 ms 一步、12 个条目，统计所有鱼在最上方 20% 高度的时间占比 < 35%，且上、中、下三段各至少 10%。
  6. 群游：同一条目的鱼平均两两距离不会无限发散（最后 30 秒平均距离 < 屏幕宽 0.5）；不同条目不被强制聚拢。
  7. 避让：快速移动（速度 > `FLEE_SPEED`）的指针靠近时鱼获得远离方向的速度分量；慢速指针不惊动；钟罩 `bells` 内的鱼被推出钟罩半径外（最终距离 ≥ `r`）。
  8. 命中与抓取：`hitTest` 命中 `alive` 的鱼、不命中 `leaving`/`held`/`alpha` 过低的鱼；`grab` 后 `held` 的鱼跟随 `pointer`；`release` 后恢复游动；`dismiss` 之后 `hitTest` 不再命中。
  9. 确定性：同一个随机种子产生同一份轨迹；坏输入（NaN 坐标、`dtMs` 为 0 或负、`pointer` 缺省）不抛错、不产生 NaN。

### Task 2: `Aquarium` 控制器（存储、托盘、网兜、指针状态机、画法）

**Files:**
- Create: `js/aquarium.js`、`css/aquarium.css`
- Test: `test/aquarium.test.js`

**Interfaces — Consumes:** Task 1 的全部导出；`JellyfishCore.nightAmount(hour)`（可选，缺失按白天）。

**Interfaces — Produces（宿主在 Task 3 调用）:**
- `Aquarium.create(env)` → 控制器；浏览器里 `window.Aquarium = create()`（只创建不启动，同 `JellyfishSkin`）。`env` 可注入 `document/window/chrome/now/random/warn/bells`。
- `start()`、`stop()`、`isActive()`；`frame({ctx, width, height, dt, pointer, lowPower, night, nightHour, amount, bells})` → boolean（先于水母画；异常只停鱼层并 `warn`）。
- `hoverAt(x, y)` → boolean；`grabAt(x, y)` → boolean（命中并抓住）；`tick(point, frameTime)`（每帧由 `frame` 内部调用）；`drop(x, y)` → boolean（是否“拖过”，宿主据此吞 click）；`cancel()` → boolean；`isGrabbing()`。
- `add(speciesId)` → `Promise<{ok, reason?}>`；`remove(entryId)` → `Promise<{ok}>`；`entries()` → 快照数组；`state()` → 诊断对象。

- [ ] **Step 1: 写失败测试**——`test/aquarium.test.js`（替身 `chrome.storage.local`、假时钟、最小假 DOM、记录型画布）覆盖：
  1. `start()` 读取 `aquariumV1`：合法数据 → 条目；不存在 → 空；损坏/未知种类 → 丢弃坏条目，**读取阶段不写回**；读取失败 → 空水族馆且不写。
  2. `add`：写入先读最新值再改（并发两次 `add` 都生效、顺序串行）；超上限/大型上限/渲染上限返回对应 `reason` 且不写；写入失败 → 内存回滚、返回 `{ok:false, reason:'storage'}`。
  3. `remove`：写入成功后条目消失；写入失败回滚（鱼回来）。
  4. 托盘 DOM：只用 `createElement`，每个种类一个按钮，满额时按钮 `disabled` 且有提示文字；居民列表每条有“捞出”按钮，点它等同于 `remove`；有 `aria-label`；`stop()` 后 DOM 移除、监听移除。
  5. 抓取状态机：`grabAt` 命中才开始；拖动小于 6 px 松手 = 放回、`drop` 返回 `false`；拖过 6 px 才显示网兜；松手在网兜内 → `remove` 恰好一次且 `drop` 返回 `true`；松手在网兜外 → 放回、不写存储；`cancel()`、`stop()`、页面隐藏 → 放开、不写存储；等写入期间再次 `grabAt` 不会二次抓取。
  6. 绘制契约：没有鱼时 `frame` 一笔不画；有鱼时 `save/restore` 配对；省流量模式不抛错；画法抛异常 → `warn` 一次、之后 `frame` 返回 `false`、其他状态不受影响。
  7. 源码扫描（放到 Task 3 的集成测试里统一做）。
