# 真三维动物、相对尺度与自然追逃执行计划

状态：经用户“好的，执行吧”授权，已实施独立 HTTP 原型。首轮可体验闭环已完成，正式迁移和完整生态验收仍未完成。技术依据见[调研与技术方案](../../research/research-aquarium-3d-scale-ecology-20261021.md)。

## 交付边界

在新的隔离实验页逐段实现，现有浅礁 demo 保留作对照。正式首页、背景设置、任务和居民存储均不在此计划的首轮修改范围内。固定造景默认关闭，动物与背景采用透明合成。

先做到“一种真实 3D 鱼 + 多个稳定个体 + 一块能遮挡和阻挡的礁石”，通过后再扩大物种、生态和交互。任何阶段未通过验收时只保留该阶段实验结果，不把后续效果堆上去掩盖问题。

## P0：冻结物种、尺寸与依赖合同

**工作**
- 锁定先行物种为上游已有的 Amphiprion percula；可将其 3D 模型用于体积样板，但不能把未核实的生命周期分布冒称生物统计。
- 明确 TL / SL 等测量口径，记录模型锚点、单位、体宽体高。蓝吊与大动物单独建候选档案，泛称不参与真实比例验收。
- 核对 Deskworlds 固定提交的公开导出与 roster 约束；保留配套 Three r180。BVH 0.9.16、Yuka 0.7.8 分别核验实际分发包、许可证、维护与已知漏洞，生成锁文件。
- 只用公开 API。若需要上游未导出的能力，先找正式入口或向上游扩展；不复制内部材质函数冒充 SDK 集成。
- 建一个尺标 fixture：同深度、同姿态、固定相机和确定性种子。

**交付 / 通过条件**
- 物种资料表、资产来源表、单位转换表、依赖锁。
- 不混用盘宽与体长；所有演示值标明来源事实或拟定参数。
- 当前背景不改变，未加载新造景时没有 GPU 场景或外部网络请求。

## P1：真正三维的最小样板

**工作**
- 一个透明 Three.js Renderer 同时画动物和测试障碍，取消这批鱼的旧 2D 绘制，杜绝双重显示。
- 复用 createFishSchool / makeFishGeometry；项目只做姿态、单位、成员列表和生命周期适配。
- 固定录制 0° / 45° / 90° / 180° / 俯视的模型视图，验证厚度、鱼鳍空间朝向和体表前后关系。
- 把一条鱼从石块前面游到后面再出来，先验证共享深度；鱼身不使用整物体半透明来伪装水下效果。
- 空成员组、增加与捞出导致的实例批次重建必须有明确资源释放和失败表现。

**交付 / 通过条件**
- 可交互的单物种真 3D 样板和固定视角截图。
- 身体在各视角不退化成平面；石后部分确实被挡住。
- 关闭造景时没有色块、深度遮挡或额外壁纸滤镜。
- shader 编译失败不能静默换成“看起来成功”的另一套模型。

## P2：统一比例与同种个体差异

**工作**
- 统一米制世界，单独处理上游分米坐标与光学 / 水流参数。
- 每个个体有稳定的身份、生活阶段（可缺省）、测量值和随机种子。先按确认范围分层抽样，再绑定 3D 尺寸。
- 第一版不启用实时成长；先表现不同阶段共存。缺少阶段依据的先称小 / 中 / 大体型。
- 提供“同深度尺标”和“自然透视”两种研究视图；默认布局中小鱼靠近、巨大动物只进开阔远景。
- 变化的是镜头与距离，不以屏幕可见下限篡改真实身体。可访问性由选择轮廓、较大命中区、居民列表解决。

**交付 / 通过条件**
- 同一物种至少 6 个不同尺寸个体，刷新和画质切换后尺寸不漂移。
- 同深度基准姿态的尺寸比例与档案一致，建议初始几何误差门槛 1%；此为工程目标，需按模型锚点验证。
- 视口 / DPR / LOD 变化不改变米制尺寸；不能把远处的同一条鱼重新分类成幼鱼。
- 蓝吊、海龟、蝠鲼、鲨类的资产和单位未核验前，不扩大为“全部物种真实比例已完成”。

## P3：尺寸感知避障与非穿透

**工作**
- 从同一组可见礁石建立空间查询与碰撞代理；几何版本与场景开关同步。
- 首先复用上游 clearWater / clearSegment / 路径图，按体型净空分组验证；固定 margin 的原图不作为所有鱼的最终路径图。
- 复用 BVH 对静态礁网格做可见性、最近点、交叉查询；大鱼用长度、宽度与姿态一致的代理，不只用中心点。
- 验证普通巡游、快速逃逸、低帧率大步长、窄洞、拱桥、贴壁转身；碰撞失败保留最后有效姿态，不瞬移穿墙。
- 若无 WASM 路线不能可靠覆盖扫掠与旋转，停止“硬碰撞已完成”的交付，开独立 Rapier 探针。利用其正式 shape cast / controller；控制器只处理平移，转身另验，禁止假定 CCD 自动涵盖一切。
- 原型可研究替代后端；正式 CSP 是否启用 WASM 必须另行明确，不修改现有扩展策略。

**交付 / 通过条件**
- 同一个洞：小鱼可过，大鱼不能过；不存在鱼中心已出去但身体仍穿石的情况。
- 开关造景后没有隐形墙或旧路径引用。
- Raycaster 选不到被实体完全挡住的鱼，列表定位仍可用。
- 记录代理精度、最大位移与转动的适用边界。示例成功不能推成全场景物理正确。

## P4：追逐、逃跑、躲藏、捕食

**工作**
- 保留原捕食 FSM、最长追逐、休息、捕食频率、补员与独立随机流，抽出空间 / 感知适配。
- Yuka 提供 Pursuit / Evade 等三维转向结果；唯一 World 进行一次姿态积分和碰撞修正。
- 资格从“物种典型尺寸”改为“具体个体、生活阶段、食谱、身体横截面与口部代理”。
- 猎物能发现威胁、急转、分散、进入可容纳自己的掩体；追逐者会失去目标、受转弯 / 体力约束并放弃。
- 捕食接触使用三维嘴部体积与可见路径；同屏重叠不算接触。
- 同一猎物的捕获按 World 内的唯一事件原子处理，两个捕食者不能重复吞掉同一对象。
- 用户正抓着的鱼、任务水母、临时离场对象都不得成为捕食目标；鲸鲨 / 蝠鲼不加入追咬食谱。
- 沿用只影响内存展示的陪伴规则，禁止捕食自动永久删居民条目或写任务 / 记忆。

**必须通过的情景**
1. 合格捕食者追击可食小鱼，存在捕到和逃脱两种结果。
2. 小鱼进入窄洞后，大鱼不能穿洞或隔墙捕食。
3. 幼年捕食者对较大猎物不合格，同种较大个体可按食谱进入候选。
4. 两条鱼屏幕重叠但深度不同，不发生假捕获。
5. 超时 / 饥饿恢复 / 目标被用户抓走后正确结束追逐。
6. 同一猎物同一时刻最多一次捕获，统计与实际离场数量一致。
7. 任务水母始终不在候选集合；刷新后原居民名单保持。

## P5：保留完整交互与任务边界

**工作**
- 原居民列表、放入、喂食、捞出入口对接三维对象引用，避免把 DOM 下标当个体 ID。
- 拖拽在可见交互层进行，抓取期间从生态候选中撤出；释放回水域找合法落点，取消 / 失焦 / 页面隐藏都回到既有规则。
- 原有网兜 / 任务纸篓仍判定用户操作；业务成功必须等原所有者回执，不由动画推断。
- 任务水母视觉可升级为三维钟罩与触手，任务文字保持可读；任务完成逻辑不迁入物理世界。
- 喂食投放和真正进食分别显示，继续使用既有限额。

**通过条件**
- 放入 / 捞出 / 喂食 / 拉拽 / Esc / 失焦 / 失败回执 / 页面隐藏分别验收。
- 用户抓取与捕食同帧时不会出现已移除对象继续被操作、任务误完成或重复存储写入。
- 既有相关回归测试通过，并补充只覆盖新增跨层风险的测试。

## P6：资源、视觉与迁移决策

**工作**
- 实测 8 / 20 / 40 条鱼的帧时间、首帧、CPU 与 GPU 分别可观测项、内存、隐藏暂停和连续切换释放。
- 模拟采用固定步长、有限追帧，邻居与感知查询限频；渲染 LOD 不改变物理尺寸和捕食规则。
- 画质降级先减细节、粒子与更新频率，不能悄悄把真实 3D 动物改回纸片而仍显示“真 3D”。
- 交付物种尺标对照、完整追逃录像 / 回放、背景开关像素对照、碰撞反例集和测试报告。
- 正式接入单独评审版本迁移：原存储入口持久化个体元数据、未知版本拒写、备份 / 回滚、旧版不得静默抹字段。新旧引擎互斥。

**进入正式功能前的门槛**
- 先通过用户对体积、比例和自然行为的观感验收。
- 再通过真实 Chrome 扩展与实际配置验证；HTTP demo 不替代它。
- 模型授权、依赖锁、CSP、可取消 / 可回滚与资源释放有证据。
- 本计划不预先承诺某个 GPU 帧率或生物学精度；目标与实测分开记录。

## 第一个应执行的完整小闭环

P0 → P1 → P2：**同一种真 3D 小丑鱼，多个稳定大小，绕一块礁石前后游动，有尺标，有背景开关。**

这一步先解决本次最直接的两项反馈——纸片感与尺寸。之后 P3 → P4 做“大鱼追、小鱼钻缝逃跑”的第二个闭环，再把 P5 交互完整接回。每个闭环都留下可重放的证据，不以静态好看的截图代替验收。
