# 桌面水母形象系统 设计稿

日期：2026-10-17　状态：用户已逐节确认方向与结构。**S1a（颜色与花纹，计划 `docs/superpowers/plans/2026-10-17-jelly-appearance-s1a.md`）已实现，当晚的欠账也已补完（§11），见 `docs/technical/jelly-appearance-20261017.md`；S1b（尺寸）与子项目 2–4、材质、节日换装、“换一只”菜单未做。物种接口与首批 4 种动物的设计稿见 `docs/superpowers/specs/2026-10-17-jelly-species-design.md`（待用户确认，未实现）。**

## 0. 背景与拆分

用户希望桌面水母（macOS 原生组件，`desktop-reminder/jelly-*.swift`）有更多可选择、可玩的形态，灵感来自 `ai-research/outputs/x-marine-50-20261017/` 的 50 帖海洋动物创作整理（xlsx 与同目录 `posts.json` 内容一致；帖子多数未确认源码与许可证，**只借创意，不借代码**；逐项映射与阅读范围见 §9）。

范围太大，已拆成四个子项目，各自走一轮“设计 → 计划 → 实现”：

1. **形象系统**（本文）：颜色、花纹、材质、尺寸、节日限定，以及选择入口。后面的子项目依赖它。
2. 互动玩法：戳、摸、喂食、拉触手（触手要改成链式物理）。与 1 基本独立。
3. 新品种与伙伴包：先抽“物种渲染接口”，再加新动物。**首批名单已由用户定为小锤头鲨、蝠鲼、海龟、鲸鲨（同一时刻只有一只，在设置里切换）**（原写“章鱼、蝠鲼、海龟”是读表前排的，漏了表里最多的鲨鱼，见 §9.0 与 §11）。依赖 1 的外观模型；设计稿见 `2026-10-17-jelly-species-design.md`。
4. 收集养成与图鉴：依赖 Chrome 侧事件（番茄钟、任务、喝水）与 3 的来访者。

顺序：1 → 2 → 3 → 4（2 可插在任何位置）。**本文只覆盖 1。**

**顺序调整（2026-10-17 晚，用户选择）**：先补 S1a 自己的欠账（已完成，§11）→ 再做 3 的“物种接口 + 首批 4 种动物”→ 然后才是 1 里的材质（软糖/毛绒/线框/铅笔/像素），让材质直接做在新接口上、对所有动物一份实现。尺寸（S1b）、节日（S4）、互动（2）与收集（4）的先后用户这次没有再选，沿用本文原顺序，开工前再向用户确认。

## 1. 目标与不做

目标：

- 用户可选水母的颜色（8 色）、花纹（纯色/双色/渐变/七彩）、材质（玻璃/软糖/毛绒/线框/铅笔线稿/像素）、尺寸（小/中/大）。
- 可选“随机”“每天换一只”“节日限定自动换装”。
- 不动设置的用户看到的外观与现在**完全一致**。

不做（本轮）：配饰（帽子、眼镜等，用户已明确不选）、多只水母、新物种、互动玩法、养成图鉴。

## 2. 已确认的决定

| 议题 | 决定 |
|---|---|
| 倒计时阶段色与自选色 | **阶段色覆盖**：平静阶段用自选色；临近/紧迫/最后 10 秒/到点整只平滑过渡成阶段色，结束后回到自选色 |
| 本轮维度 | 颜色、花纹、尺寸、节日限定、材质（五种新材质全做，分档交付） |
| 节日触发 | **默认关**，设置里勾“节日限定”后节日当天自动换装，节后恢复自选形象 |
| 选择入口 | 设置页卡片 + 右键“换一只”（随机颜色与花纹，不动材质和尺寸）+ 右键子菜单切换材质与尺寸 + “每天换一只”开关 |
| 数据归属 | **Chrome 是唯一的设置所有者**，原生端无状态，只按下发的具体值绘制 |

## 3. 数据模型与协议

### 3.1 存储（Chrome 侧）

使用**独立存储键** `desktopJellyAppearanceV1`（键名暂定，计划阶段定稿），**不放进 `desktopJellyV1`**：现有 `JellyDesktop.normalize` 只保留 `resident`/`night`，旧版本保存一次就会把多出的字段抹掉；桌面 AI 助手单独用 `desktopAssistantV1` 也是同一个原因。该键缺失按默认：

```text
appearance: {
  color:    0..7                           // “随机”是一个动作（reroll），写回的仍是具体色位
  look:     'solid' | 'duo' | 'blend' | 'rainbow'
  material: 'glass' | 'gummy' | 'plush' | 'wire' | 'pencil' | 'pixel'
  size:     'small' | 'medium' | 'large'
  seasonal: boolean   // 默认 false，只有明确 true 才开
  daily:    boolean   // 默认 false，只有明确 true 才开；为 true 时颜色与花纹由本地日期决定，忽略存储的 color/look
}
```

默认：`glass` + 色位 5（冰蓝，等同现在的平静阶段色）+ `solid` + `medium`。色位编号沿用首页 `JellyfishSkin.PALETTE` 的色相环顺序（红、橙、黄、绿、薄荷、冰蓝、紫、洋红）。

### 3.2 下发（协议版本不变）

`jelly` 命令增加可选字段，**Chrome 把 `daily`/节日全部解析成具体值再发**：

```text
appearance: { color, colors:[色位…≤3], look, material, size, season: null | 'spring-festival' | 'lantern' | 'dragon-boat' | 'mid-autumn' | 'halloween' | 'christmas' }
```

- `daily`：由本地日期决定，同一天结果稳定，不存历史。
- “随机”：用户选择“随机”或点“换一只”时，Chrome 抽一次并把**具体值**写回存储，之后不再变；因此重启、重连后外观稳定。
- **不升协议版本**（仍为 v7）：“水母差事”设计稿已占用 v8，且 `appearance` 只是 `jelly` 命令里的一个可选字段、旧组件本来就会忽略。能力探测改为看回执：新组件在 `jelly` 回执里带 `appearance:{status:'ok'}`，Chrome 据此判断；回执里没有就在设置页提示“需要更新组件才能生效”（与桌面助手的热键状态同一做法）。更新组件后须重载扩展。
- 原生解析走白名单：未知字段或越界值回到该字段默认值，`colors` 超过 3 个或色位不在 0–7 的整体回到 `[color]`。

### 3.3 右键“换一只”

经现有 `jellySetting` 事件回到 Chrome（与“收起水母”同一路径），只请求“重新抽颜色与花纹”，Chrome 写入后再下发。原生不改任何设置。材质、尺寸的子菜单同样发 `jellySetting`（带 `appearance` 的子集），由 Chrome 校验并保存。

### 3.4 节日判定

放在 Chrome 侧、后台可用的纯函数（暂名 `JellySeason`，不依赖 DOM），输入本地日期，输出 `season` 或 `null`。

- 固定日期：万圣节 10-31、圣诞节 12-25（与 `js/holidays.js` 的数据一致）。
- 农历：春节（正月初一）、元宵（正月十五）、端午（五月初五）、中秋（八月十五），需要农历换算。
- **注意**：`js/holidays.js` 是绑定页面 DOM 与 `settingsManager` 的类，**后台不能直接复用**；农历库 `js/lunar-lib.js` 是 UMD，理论上可 `importScripts`，但体积大（约 5.5k 行）且目前不在后台加载。**计划阶段必须先核实**它能否在 Service Worker 里正常加载、冷启动代价多大；只有 `seasonal` 开启时才计算农历。如果不可行，退路是只用固定日期节日加一份小的农历节日对照表（不重写通用农历引擎）。

## 4. 原生端结构

`JellyView.draw` 目前把钟罩、触手、脸硬编码为一套玻璃画法。拆开：

### 4.1 新增源文件（登记 `build.mjs` 清单与 `test/desktop-companion-logic.test.mjs`）

- `jelly-appearance.swift`（纯 Foundation，可单独编译自测）：
  - `JellyAppearance` 解析与白名单；
  - 8 色调色板：**色相顺序与 JS `PALETTE` 一致、色位数相同，测试对照色相顺序，不比 RGB**（桌面是半透明叠在未知壁纸上，数值需单独调；色位 5 必须恰好等于现有平静色 `JellyTint.calm`，默认外观才逐像素不变）；
  - 花纹 → `JellyPaint {a, b, c}`（语义与首页 `paintOf` 一致）；
  - 阶段色覆盖函数（平静用自选色，其余阶段平滑过渡）；
  - 尺寸倍率：小 0.8、中 1.0、大 1.3。
- `jelly-materials.swift`（AppKit）：`JellyPainter` 协议（`bell`、`tentacles`、`face` 三个入口）与六个实现 `Glass`（现有代码原样搬入）、`Gummy`、`Plush`、`Wire`、`Pencil`、`Pixel`。`JellyView.draw` 只负责位置、倾斜、夜晚荧光、睡觉标记与气泡。

### 4.2 各材质与颜色的关系

- **软糖**：不透明度更高、高光更厚，渐变用 `JellyPaint`。
- **毛绒**：哑光无高光，边缘一圈短绒；绒的偏移启动时算一次并缓存，**不得每帧随机**（会闪）。
- **线框**：钟罩与触手只描发光线条，线色取自选色。
- **铅笔线稿**：黑灰线条加手抖，自选色只作淡淡一层水彩底（否则颜色选项对它没有意义）。
- **像素**：整只画到低分辨率再最近邻放大，颜色量化到自选色附近几档。
- 睡觉的 z、脸红、眨眼按材质各画一版。

### 4.2.1 依据素材表后的修订（2026-10-17 补，见 §9）

- **软糖不只是“更不透明”**：素材 #35 原帖正文写明“抓住一条腕、拉伸、松手，整个身体弹跳着回到原形”，#37/#38 也是挤压形变加回弹。所以软糖的特征是**形变幅度更大且带回弹**。现有 `JellyPose.squash` 与 `contraction` 已经存在，软糖 painter 放大它们的作用范围并加一个欠阻尼回弹（弹簧曲线），而不只是换渐变。这属于纯显示，不改业务。
- **毛绒要有重量感**：素材 #2、#39 的卖点是毛绒表面、拟人表情，#39 还强调“提起后腿下垂”。毛绒 painter 在被拖拽（`grabbed`）时触手明显下垂，而不是像玻璃那样飘。
- **线框的发光依赖深色背景**：素材 #31（Cyber Ocean）是深色背景上的青色发光线条加辉光。桌面水母落在**未知壁纸**上，浅色桌面上发光线会消失。线框与铅笔线稿必须像气泡调色板一样，用“深线加浅描边光晕”的双层画法，保证在纯白和纯黑底上都可辨，并加对比度自测（口径同气泡：叠在白/黑上取更差者）。
- **铅笔线稿**：素材 #18（Pencil+4 描边）、#22（手绘渐变与描边）支持“描边加淡水彩底”的方向；同样要过上一条的双底可见性检查。
- **像素**：素材 #19（体素风）支持方块轮廓路线。

### 4.3 尺寸与窗口

窗口尺寸、钟罩基线、触手长度乘以倍率：小约 136×120、中 170×150（与现在一致）、大约 221×195。气泡版式不缩放，只有水母本体缩放。夜晚光晕半径已由窗口几何计算，自动适配（外圈 8 点 alpha ≤ 1 的约束不变）。**抛掷、泳线、气泡位置、点击命中区在大号下须重新验收**，这是风险点。

### 4.4 节日装饰

`season` 非空时，在材质 painter 之上叠一层小装饰，每个节日一个纯绘制函数；装饰由 `season` id 决定，不进协议数据。

### 4.5 通用约束

- “减少动态效果”下所有材质与装饰静止。
- 夜晚荧光对所有材质都叠加；线框与像素的光晕强度单独调。
- 气泡调色板（浅/深两套对比度）**不受材质影响**，继续由现有自测守住。
- 默认外观必须与重构前逐像素一致（见 §6）。

## 5. 设置页

“桌面水母”卡片增加“形象”区：8 色色板 + “随机”“每天换一只”、花纹四选一、材质六选一、尺寸三选一、“节日限定”开关。

**预览说明**：真正的预览就是桌面上那只水母——水母常驻时，选择立即生效，所见即所得；设置页本身只做色板与选项的静态示意（CSS），**不在设置页里再实现一套六种材质的 Canvas 绘制**（那会成为第二份实现，且与原生画法必然不一致）。水母未常驻时没有实时预览，页面须明确这一点。S1a 的实际做法：一份固定的 SVG 加 CSS 变量，取色规则与原生一致并由测试守住；材质做出来以后，示意图仍只表达颜色与花纹，不画材质。

## 7. 复用与不引入

- 复用：首页 `PALETTE` 与 `pickLook` 的语义；现有 `jelly` 命令、`jellySetting` 事件、`jelly-desktop.js` 的串行存储与规范化（外观读写沿用同一条串行队列，键独立）；`user-quiet.mjs`；隔离验收脚本。

## 11. 回头看（2026-10-17，S1a 完成后；当晚补欠账后更新）

**S1a 自己的欠账**（设计稿写了、没做到或没做全；均已核实，处理结果见 `docs/technical/jelly-appearance-20261017.md`）：

1. “每天换一只”过午夜不会主动重新下发——**已补**：开着“每天换”时，每次下发外观预约“下一个本地午夜 + 1 秒”的一次性定时器，到点通知后台重新下发；常驻连接延续这条链。真实 Chrome 过午夜未验收。
2. §6 要求的帧耗时 / CPU 对比没做——**已测**（离屏绘制，不含窗口合成）：纯色/双色/渐变每帧与基线的差别在噪声内（≤ +1.4%），七彩每帧约 +0.056 ms（白天 +25.6%、夜晚 +12.1%），按 30 fps 折算占一个核从 0.66% 到 0.83%。
3. §5 说的“静态示意”只做了色板——**已补**：卡片第一项是当前形象的示意图（“每天换一只”开着时叫“今天这只”），取色规则与原生一致并由测试守住；示意图是静态示意，不是实时预览。
4. 变异检查只对像素闸门做过一次——**已系统做**：Chrome 侧 JS 与工具 806 个（存活 32，96.0%）、渲染检查 377 个（存活 22，94.2%）、Swift 纯逻辑 214 个（存活 4，均等价）、AppKit 手写 23 个（存活 2：口腕颜色是没有任何自动检查观察到的真实盲区，另一个等价）；存活者逐个归类，见技术文档。
5. 8 色辨识度与浅/深桌面上的可见性只是目测——**已补自动测量与防退化线**：白底/黑底两个极端底色上的身体对比度与色位间 Lab 色差，另有“四种花纹是否画对颜色位”的渲染检查。仍没有测真实壁纸；黄色在白底上对比度最低（1.21），是量出来的事实，没有改调色板。
