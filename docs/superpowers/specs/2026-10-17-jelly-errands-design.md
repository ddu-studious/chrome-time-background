# 水母差事设计

## 1. 目标与已确认的决策

桌面水母现在大部分时间在睡觉：只有闹钟倒计时、到点响铃、喝水/起身提醒（默认全关）三件事会叫醒它。目标是让它**主动开口、主动活动**：推荐好听的歌、提醒今天的工作日志、盘点未完成的任务、随机来点小乐子。

| 问题 | 用户决策 |
|---|---|
| 主动到什么程度 | **B 档**：可以自己展示、自己轮播低风险内容；**放歌、改数据永远要用户点一下**。不做“自己放歌、自己顺延任务” |
| 默认活跃度 | **适中**：每小时最多 4 条 |
| 任务名显示 | **默认只显示数量**；显示任务名要单独打开（气泡会盖在任何应用上，含屏幕共享） |
| 不在电脑前 | **使用系统空闲时间判断**，用户离开时不吐泡泡，回来后再说 |

## 2. 现状（已核对代码）

- **为什么睡**：`jelly-controller.swift` 里 `rest` 在 `calm` 阶段恒为真；空闲时 `JellyModel.tickInterval(active:)` 每 30 秒才走一次；`JellyModel.nudgeKinds` 只认 `water`/`stretch`，`nudgeActions` 只认 `done`/`snooze`。
- **内容已有、没接到水母上**：
  - 任务在 `chrome.storage.local.memos`；工作日志在 `worklogEntries`。
  - `js/background.js` 里已有五个系统通知发送器，由 `chrome.alarms` 触发：`sendDailySummary`、`checkOverdueTasks`、`sendWarmTipNotification`、`sendWorklogReminder`、`checkWorklogProgress`。它们完全不经过水母。
  - 温情提示库 `WARM_QUOTES`（名言/方法论/笑话/寓言/健康）在 `background.js` 内，纯离线。
  - 每日推荐歌曲：后台已有 `neteaseApiCall`，音乐页用 `/api/v3/discovery/recommend/songs`；起播走 `offscreen_play`，带真实队列版本校验。
- **可复用的成熟模式**：`js/jelly-nudge.js` 的 `presenter` + 3 秒确认 + 退回系统通知 + `act()`；`AlarmDesktop.showNudge`；响铃气泡的“游到鼠标所在屏幕底部中央”落点逻辑与 `ringClickGuard`；`nudgeAction` 回执与 8 秒无回执提示。

## 3. 架构

**Chrome 仍是唯一调度者与执行者，原生端只显示与转发。** 原生端不读 `memos`、不自己定时、不另存业务状态。

| 单元 | 职责 | 依赖 |
|---|---|---|
| `js/jelly-errands-core.js`（新，纯逻辑） | 差事类别表、紧急度、冷却、打扰预算、收敛规则、内容去重、文案生成；不碰 DOM、`Date`、存储，时钟与随机数可注入 | 无 |
| `js/jelly-errands.js`（新，控制器） | 读取数据源、`chrome.alarms` 评估、调用 presenter、处理按钮动作、存储自己的状态 | `JellyErrandsCore`、`JellyNudge`（合并预算）、`JellyDesktop.presenter` |
| 原生 `errand` 命令（协议 v8） | 通用气泡：类别白名单、≤3 按钮、存活时间、回执 | 复用 nudge 气泡窗口与 `glass-view` |
| 原生“活动”行为 | 开口前游过来、巡游、睡觉条件 | `jelly-swim.swift` 的 `startDash` |
| 原生 `presence` 事件 | 只上报 `active`/`away` 两态变化 | 系统空闲秒数（只读） |

- **后台加载**：新增两个脚本需加入 `js/background.js` 的 `importScripts`，顺序在 `jelly-nudge.js` 之后、`jelly-desktop.js` 之前或之后均可，以实现计划核对依赖为准。
- **喝水/起身并入同一预算**：`JellyNudge` 的逻辑不重写，调度器在放行前向它查询“最近一次提醒时间”，共用最小间隔与每小时上限。
- **五个现有系统通知发送器**：改为先请水母接手（同 `presenter` 模式，3 秒内无确认退回系统通知），同一件事只走一条路，不会水母说一遍、系统通知再说一遍。其触发条件、文案规则与去重标记（如 `worklog_reminded_*`）不变。

## 4. 差事清单

| 差事 | 数据源 | 气泡 | 按钮（点了才动） | 紧急度 |
|---|---|---|---|---|
| 晨间概览（每天首次上线一次，6–11 点内） | `memos` 只读 | “今天 N 个任务，其中 M 个已过期” | 看看 / 稍后 | 中 |
| 过期与未完成任务 | `memos` 只读（排除 `completed`、`failed`） | “M 个任务过期了”；开启“显示任务名”后给最紧的一个 | 去处理 / 明天再说 | 高 |
| 工作日志 | `worklogEntries` 只读 | “下午只记了 1 小时”；复用现有 12/15/17 点工时检查点 | 记一条 / 稍后 | 高 |
| 推荐歌曲 | 后台每日推荐；未登录或失败退回热门歌单搜索；都失败则本次跳过 | “来一首《…》？”（歌名与歌手经 `clean`） | 播放 / 换一首 / 不听 | 低 |
| 小乐子 | `WARM_QUOTES`，偶尔翻出一条未完成的旧任务（只显示标题时按“显示任务名”开关） | 一句话 | 再来一条 / 够了 | 最低 |
| 喝水、起身（已有） | 现有逻辑 | 现有气泡 | 喝了 / 动了 | 按现有 |

边界：

- **放歌**：提议前先问播放状态，已在播放则不提议。点“播放”后走现有 `offscreen_play` 与队列版本校验。回执文案只写“已交给播放器”，不写“已播放”；失败显示原因。点“换一首”只换候选，不播放。
- **任务**：v1 水母**不写 `memos`**。“去处理”只打开任务面板，“明天再说”只写调度器自己的静默标记。后台与页面同时写 `memos` 有竞态，不在本期引入。
- **工作日志**：“记一条”只打开工作日志入口，不代写。
- **推荐歌曲只依据接口返回**，不声称“按你的口味”“适合现在的心情”。

## 5. 调度器规则

- **评估节奏**：`chrome.alarms` 每 5 分钟一次（常驻端口也让 Service Worker 不休眠，但不依赖这一点）。
- **放行条件**（全部满足才弹）：
  1. 设置开启，且水母常驻、已连接、组件版本 ≥ 8。
  2. 在活动时段内（默认与“水母关怀”时段一致，工作日 09:00–18:00，可改）。
  3. 当前 `presence` 为 `active`，且回到 `active` 已满 20 秒。
  4. 当前没有响铃、倒计时紧迫阶段或其他气泡。
  5. 距上一条差事气泡 ≥ 15 分钟，且本小时条数未超过档位上限（安静 2 / 适中 4 / 勤快 8）。
- **选择**：在可用差事中按“紧急度 × 距上次提示的时间”挑一个；同一内容当天不重复。
- **收敛**：同一类差事连续 2 次被“不听 / 够了 / 明天再说”或自行消失，当天不再提这一类。次日重置，不存历史。
- **水母不在或没接手**：小乐子与歌曲直接静默跳过，**不弹系统通知**；过期任务、日志缺口走原系统通知（第 3 节）。
- **预算与失败**：评估失败只记一条警告日志，不重试风暴；每次评估最多读一次 `memos` 与 `worklogEntries`。

## 6. 协议 v8

在 v7 上增量，旧组件忽略新命令与新字段，旧版本设置页提示更新组件（更新后须重载扩展）。

- **命令 `errand`**：`{ id, kind, title, text, buttons[1…3], ttl }`。
  - `kind` 白名单：`brief`、`task`、`worklog`、`song`、`tidbit`。
  - 按钮 `id` 白名单：`open`、`later`、`play`、`another`、`dismiss`、`more`。每条差事允许的按钮组合在 Swift 与 JS 各有一份表，对照测试逐条核对（与热键语法的做法相同）。
  - 文字限制沿用 `JellyModel.clean`：标题 ≤24，正文 ≤120，按钮 ≤12；控制字符与方向控制符一律去掉；`ttl` 夹在 10–180 秒，默认 90。
  - 校验失败回 `ok:false`，Chrome 据此静默跳过（歌曲、小乐子）或退回系统通知（过期任务、日志）。
- **事件 `errandAction { id, action, actionId }` 与命令 `errandActionResult`**：沿用 `nudgeAction` 的模式。**只有匹配的回执才显示成功**；失败或 8 秒无回执恢复按钮并提示，不声称成功，同一 `actionId` 重试在 Chrome 侧幂等。
- **事件 `presence { state }`**：`active` / `away` 两态，只在变化时发送，不发空闲秒数。阈值 5 分钟，取自系统空闲时间的只读查询（实现计划需确认具体 API，已知项目里 `desktop-reminder/user-quiet.mjs` 用 `ioreg` 的 `HIDIdleTime`，原生进程内可用 `CGEventSource.secondsSinceLastEventType`，均无需权限）。不记录、不上传。
- **命令 `jelly` 增量字段 `errands`**：带 `{ enabled:true }` 才启用活动行为（巡游、开口前游过来、睡觉条件）；不带就是关闭，保持现有行为。

## 7. “活动活动”：水母本身要动起来

- **开口前先游过来**：有差事时，先游到鼠标所在屏幕可见区底部中央（复用响铃的落点逻辑与跨屏规则），轻拍一下钟罩，再弹气泡；气泡收起后游回原位。
- **巡游**：常驻且开启时，每隔 3–8 分钟（随机）游一圈，持续 20–40 秒，之后回到泳线歇着。
- **睡觉只在三种情况**：夜间（复用 `CountdownModel.nightAmount` 的曲线）、`presence` 为 `away` 超过 10 分钟、用户关了差事。
- **减少动态效果**：不巡游，不游过来，气泡直接在原位淡入。
- **右键菜单“水母，给我…”**：子项有“今日概览”“来首歌”“来点乐子”“记工时”。这是用户主动叫它的入口，走同一套差事生成与动作回执，不占打扰预算。
- **点一下水母**：沿用现有戳一下的形变，不新增行为。
- **耗电**：只在巡游和气泡存在期间提速到逐秒/逐帧，其余时间保持 30 秒节拍。必须在隔离环境实测 CPU（响铃期间已知约 5–10%）。

## 8. 设置

设置页“桌面水母”卡片下新增“水母差事”区（经 `jelly_desktop_get/set` 消息，沿用后台 `sender.id` 校验）：

- 总开关 `errands`（默认关，只有明确 `true` 才开）。
- 活跃度：安静 / 适中 / 勤快（默认适中，用户首次开启时即为适中）。
- 差事分项：任务、工作日志、推荐歌曲、小乐子（总开关打开后默认全开，可逐项关）。
- “气泡里显示任务名”（默认关）。
- 活动时段与“只在工作日”（默认同水母关怀）。

存储：独立键 `jellyErrandsV1`（`chrome.storage.sync`，设置）与 `jellyErrandsStateV1`（`chrome.storage.local`，只存当天的冷却、条数、静默标记、已展示内容指纹，换日清零，无历史）。不放进 `desktopJellyV1`，回滚旧版本时不会被抹掉。

## 9. 安全、隐私与权限

- **不新增权限，不新增网络目标，不调用模型。** v1 全是确定性逻辑；让 AI 决定“今天该提什么”留到以后，且必须走本机 AI 网关的预算与超时。
- **隐私**：默认只显示数量；任务名、歌名等内容当作不可信输入清洗；气泡文字不进日志（日志只写固定类别 `system/jelly-errands`）。
- **系统空闲时间**是新增读取点，但只读、不需要权限、只上报两态；这与 AGENTS 中“不使用 `chrome.idle`、不读活动状态”的既有原则不同，**交付时必须同步更新 AGENTS.md 与技术文档，写明原因与边界**。
- **副作用**：放歌是唯一有声音/状态副作用的动作，必须用户点击，沿用 unknown 回执边界，不自动重放。

## 10. 错误处理

- 数据读取失败：本次跳过该差事，不影响其他差事，不覆盖原数据。
- 推荐接口失败或未登录：退回热门歌单；仍失败则跳过歌曲，不提示用户。
- 原生端校验失败、无确认或组件过旧：歌曲与小乐子静默跳过；过期任务与日志退回系统通知。
- 连接断开后重连：沿用 `JellyDesktop` 的有界退避；重连成功后不补发过期的差事，只在下一次评估时重新判断。
- 调度器异常：只停掉差事评估，水母、喝水提醒、倒计时不受影响。

## 11. 测试与验收

- **纯逻辑**：预算（每小时上限、最小间隔）、紧急度排序、收敛、内容去重、时段与工作日、晨间概览一天一次、随机数与时钟可注入、种子可复现。
- **控制器**：存储、时钟、`presenter`、数据读取全部注入；覆盖按钮动作幂等、8 秒无回执、presenter 失败降级路径、放歌失败与 unknown。
- **协议**：Swift 与 JS 白名单对照测试（类别、按钮、文字限制）；旧组件忽略新字段。
- **原生**：`companion-selftest.swift` 加入新纯逻辑；隔离构建的 `jelly-smoke.mjs`、`bridge-smoke.mjs` 增加差事场景（合成鼠标、`TIMEKEEPER_TEST_HOOKS=1`）；验收脚本沿用 `user-quiet.mjs` 礼让用户，不做整屏截图，只 `screencapture -l` 自家窗口。
- **接入层**：`test/jelly-desktop-integration.test.js` 风格的源码扫描（无 `innerHTML`、无新增网络、`importScripts` 顺序）；`background.js` 的沙箱截取约束不得被破坏（新接线放在既有片段之外）。
- **变异检查**：对预算、收敛、白名单、降级路径逐个做，只改 `/tmp` 里的副本。
- **不能声称已验收**：真实 Chrome 156、真实账号（网易云登录态）、真实闹钟与通知并存、全屏 Space、多显示器组合、VoiceOver、长时间 CPU 占用。重装组件与重载扩展由用户做。
- 交付时新增 `docs/technical/jelly-errands-20261017.md`，并同步 `AGENTS.md` 与各 `_index.md`。

## 12. 分期

1. **第一期（最能治“懒”）**：`jelly-errands-core/controller`、协议 v8 `errand` 命令、开口前游过来、`presence` 事件，差事含晨间概览、过期任务、工作日志（含五个系统通知发送器改为“先水母后通知”）、小乐子。
2. **第二期**：推荐歌曲（含播放动作与失败边界）、右键菜单“水母，给我…”。
3. **第三期**：巡游与时段性格、睡觉条件的完整规则。

## 13. 不做（YAGNI）

自动放歌、水母直接改或顺延任务、代写工作日志、AI 生成差事内容、摄像头或麦克风、读取其他应用的前台状态、跨天的使用历史、学习用户口味的推荐模型。
