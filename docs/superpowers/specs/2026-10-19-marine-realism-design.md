# 海洋动物写实化与水族馆海水效果设计稿

日期：2026-10-19　状态：**已实现并在隔离环境验证，实现说明见 `docs/technical/marine-realism-20261019.md` 与 `docs/technical/aquarium-water-20261019.md`；美术观感与你自己的 Chrome 配置、重装后的真实桌面组件未验收**（本稿只写“为什么这样做”与“我替你定了哪些默认值”）。

## 0. 问题

你的原话：桌面和浏览器内的海洋动物都已经实现了，但新增加的这几种（小锤头鲨、蝠鲼、海龟、鲸鲨）不太真实，希望参考你提供的 X 链接和我自己找的素材，看看怎么做得更真实；首页水族馆再加海水、海浪的效果；桌面端的真实效果与扩展水族馆最好能对齐。

我的诊断（依据见调研）：旧画法是**刚性的躯干轮廓 + 几个绕轴摆动的鳍 + 卡通脸 + 用户可选的调色板**。真实动物差在四处：整条脊柱在行波而不是刚体平移；背深腹浅的逆荫蔽配色与物种花纹；鳍与翼沿展向的相位滞后；转弯时身体弯成弧。与颜色选择无关。

## 1. 目标与不做

目标：

- 四种动物更像真实动物（体型比例、配色、花纹、游动方式），首页与桌面**用同一份数据与同一条公式**。
- 首页水族馆有海水效果。
- 现有卡通动物、水母、协议、权限、存储格式**不变**；写实可关；任何一端出错都能退回原样。

不做：

- 不引入三维引擎、模型文件、Lottie/Rive 或任何第三方运行时；不引用 X 上任何作品的代码、模型与素材（参考图只在 `/tmp` 里量过比例，不入库、不描摹）。
- 海水效果**不是侧面剖开、看得见浪尖的画法**（见 §4）。
- 不做动物的互动与收集新玩法；不给桌面动物加景深雾与光晕（桌面是半透明叠在壁纸上，那样会糊）。

## 2. 方案比较

| 方案 | 结论 |
|---|---|
| A. 三维模型 + three.js / glTF | 否。X 上不少作品是这条路线，但仓库里没有许可清楚的模型，扩展要求脚本随包本地化（不用 CDN），原生端还要再做一套三维渲染；与“两端同一份数据”相反 |
| B. Lottie / Rive 之类的动画运行时 | 否。需要第三方运行时与美术资源；姿态由外部状态（转弯、被拉尾、被抓）实时驱动，预制动画不贴合 |
| C. 预渲染的位图序列 | 否。资源大，转弯、拉尾、翻面都要另做，两端像素也各自一套 |
| D. 保持旧画法，只调颜色与鳍的摆幅 | 否。这正是你说“不真实”的做法，问题在结构不在参数 |
| **E. 自写的 2.5D 矢量骨架求值器（MarineRig）** | **选定**。数据是路径、颜色与几个运动参数，求值是纯函数；JS 一份、Swift 一份（数据由生成器从 JS 生成、两边对拍），两端各一支很薄的画笔。可由真实姿态（相位、转弯、拉尾、幅度）驱动 |

## 3. 选定做法（概要）

- **求值**：压平 → 部件拍动（转动 + 沿展向相位滞后 + 可选压扁）→ 脊柱行波弯曲（头几乎不动、尾幅最大、转弯弯成弧）→ 可选拉尾。公式、限额与表驱动快路径见技术文档。
- **数据**：每种动物约 26–34 个图层：多层嵌套的明暗带做背深腹浅，斑点/盾片/鳃裂/鳍条用固定种子生成（每次一致），眼睛与口；写实动物用自己的自然体色，不吃颜色与花纹设置。
- **水族馆**：`Real.draw` 按核心的位置、朝向、相位、转弯、深度画；远处更淡更蓝（景深雾）、夜里更暗并有光晕；画法出错整页退回卡通（海龟没有卡通画法则不画）。
- **桌面**：生成器把同一份展开数据变成 Swift 常量；原生 `MarineRigPainter` 经 CoreGraphics 画；放置、姿态、游动、睡着、被抓、倒计时、响铃等全部复用卡通动物的既有管线；倒计时阶段色按 34% 混入。
- **对齐**：数据、压平、变形、放置规格只有一份，静态姿态下两端像素用独立写的检查核对；运动模型、景深雾、光晕、背景有意不对齐（见技术文档）。
- **海水层**：一张半分辨率的 WebGL 加光层（水面波光、光束、焦散、微粒、气泡），失败即关、没有后备画法，另有帧率监护器。

## 4. 我替你定了的默认值（你没回答，所以这里写明，想改告诉我）

1. **默认写实**：首页 `aquariumRealistic` 默认开，桌面 Chrome 侧 `realistic` 默认 `true`（原生侧默认卡通、只认明确的 `true`）。理由：你要的就是更真实；两端都能一键回卡通。
2. **海龟在水族馆里只有写实画法**：水族馆原来没有海龟（本次作为第 9 种动物加入），没有为它再写一套卡通画法；写实数据不可用时它不画，居民列表与存储不受影响。桌面的卡通海龟原本就有（侧视），写实版是**俯视背面**，所以桌面上切换样式时海龟会换视角。
3. **“海浪”做成水下视角的水面光影，而不是侧面剖开的浪尖**：X 上的海水 demo 里最常见、也最适合放在首页背景之后的是这一类（光束、焦散、水面波光、气泡）；侧面剖开的浪需要重做舞台、改变鱼的活动范围与交互，成本与风险是另一个量级。**如果你要的是浪尖，请直接说，那是一个独立功能。**
4. **帧率监护器宁可晚关也不误杀**：启动期不计、页面流畅过才监护、最晚等 30 秒（真实 Chrome 里第一版因为误杀启动期卡顿而改的，见海水层文档）。代价是弱机器上最坏要卡约 30 秒才降级。
5. **对齐范围只含静态几何与颜色**：运动节奏两端各自调（水族馆是相位倍率，桌面是 Hz），景深雾与光晕只在水族馆。
6. **没有协议升级**：回执里多一个 `realistic` 字段，旧组件没有它就按卡通算并如实提示。

## 5. 需要你确认的事

- **美术观感**：四种动物的比例、花纹密度、鳍摆幅、游动节奏、海水层的亮度与密度，都需要你亲眼看。看了不满意请直接说哪一只哪里不像，数据是路径与数字，可以逐项调。
- 在你自己的 Chrome 里**重载扩展**；桌面端要看到写实动物，需要**重装桌面组件**（`node desktop-reminder/build.mjs --extension-id=<id> --install`），旧组件会如实提示“还没有写实版”。
- 海水效果在你的机器上是否流畅（弱 GPU/高分屏）；不流畅时设置页可单独关掉。
