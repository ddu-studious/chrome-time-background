# 水族馆“大鱼吃小鱼”捕食能力设计稿

日期：2026-10-19　状态：**已实现（2026-10-20，全部未提交）。** 你选了“按设计稿默认值现在做”，实际落地、与本稿的三处校准偏差、验证与限制见 `docs/technical/aquarium-predation-20261020.md`；下面正文是 2026-10-19 当时的规划原文，措辞保持不变（所以文中的“只规划”“等你确认”都是当时的说法）。

## 0. 你的要求与我的理解

你的原话：“可以规划一个大于吃小鱼的能力了。但是不能吃水母。”

- “大于”按“**大鱼**”理解（同一条消息里没有别的比较对象）。如果你想的是别的意思，请告诉我。
- **硬约束：水母（首页背景皮肤里的水母，以及桌面水母）永远不会被吃。** 首页的每只水母对应一个待办任务（见 `AGENTS.md` 的触感实验条目），把它“吃掉”会让屏幕上的任务状态与真实数据对不上，所以这条不是“默认不吃”，而是**结构上做不到**（第 4.6 节）。
- 这一轮只规划。你在同一条消息里还提了另外四件事（海水盖住壁纸、鲨鱼按真实比例、拖拽像游泳、潮起潮落），它们已经做完，见 `docs/technical/aquarium-tide-size-drag-20261019.md`。

**这是对一条已记录的决定的推翻，要写明**：最初的水族馆设计稿（`docs/superpowers/specs/2026-10-17-aquarium-design.md` 第 49、100、136 行）明确写过“**不做捕食**（#3 捕食行为，永久不做）”，理由是“放入的鱼被吃掉会和‘只有捞出才是移除’冲突”。这次是你明确提出的新要求，所以按新要求重新设计；原来的理由用第 4.5 节回应——**存储一字不改、被吃的鱼会自动补回、刷新即恢复，‘只有用户捞出才真正移除’依然成立**。实现落地时，需要同步改掉那份旧设计稿、`docs/technical/aquarium-20261017.md`（第 9、13 行“不吃水母”“鲨类性格温和，没有捕食”）、`js/aquarium-core.js:120` 的注释和 `AGENTS.md` 里对应的说法。

## 1. 目标与不做

| 目标 | 不做 |
|---|---|
| 大鱼会**看得见地**追小鱼：转向、逼近、冲刺、吞下，吞食有短动画和气泡 | **不吃水母**（任何形式）；不吃海龟、蝠鲼、鲸鲨、其它大鱼 |
| 规则有**生物学依据**：谁吃谁、多大的吃得下、吃饱了就不吃 | 不改存储格式，不新增权限、网络、依赖；不把被吃的鱼从 `aquariumV1` 里删掉 |
| 不破坏已有功能：拖拽、喂食、避让水母、省流量、真实/卡通两种画法 | 不做繁殖与种群动态（NetLogo 的狼羊模型不加限制就不稳定，见第 3 节来源 5） |
| 可关闭；关闭时与现在**逐位一致**（黄金轨迹不变） | 不做桌面端（桌面只有一只动物，没有猎物） |
| 有测试、有校准、有真实浏览器验证 | 不新增物种（想要更多捕食者，如梭鱼，是另一个功能） |

## 2. 现状盘点（已按代码核对）

1. **鱼是“用户放入的条目”的投影**：`aquariumV1 = {v:1, fish:[{id,species,addedAt}]}`，不存位置；`Core.reconcile` 由条目生成 `world.fish`，群居条目一次生成 `group` 条（霓虹灯鱼、蓝吊各 5 条）；`js/aquarium.js` 头注释写明“唯一写入的是 aquariumV1，且只在用户放入或捞出时”。**所以捕食只能是世界层的瞬态，不能改存储。**
2. **物种表已有真实体长 `meters`**：霓虹灯鱼 0.04 m、蓝吊 0.2、小丑鱼 0.11、河豚 0.3、神仙鱼 0.15、小锤头鲨 2.5、海龟 1.25、蝠鲼 4.6、鲸鲨 9（蓝吊/神仙鱼/河豚的数字是我取的典型值，不是来自这次检索的出处）。`js/aquarium-core.js` 里现有注释“鲨鱼只是性格温和的居民，没有捕食行为”，实现时要一并改掉。
3. **水母只是只读输入**：`Core.step(world, dt, { pointer, bells, attractors, surface })` 里的 `bells` 是水母钟罩的坐标列表，不是 `world.fish` 里的实体；鱼只会避开钟罩（`BELL_AVOID/BELL_KEEP`），不会影响水母。
4. **全体鱼共用一个 `world.random`**，黄金轨迹已钉住（`test/aquarium-core.test.js`）；任何会多抽随机数的新行为，都会改变同一个世界里其它鱼的轨迹。
5. **饲料玩法**（`js/aquarium-play-core.js`）：大个子按“嘴距”吃饲料（`mouthOf` 已含侧视转身的透视缩短 `xs`），吃到时冒气泡；捕食可以直接复用 `mouthOf` 与气泡。
6. **抓取状态机**：被抓着的鱼 `state === 'held'`；松手后沿用自己的速度滑一段（`GLIDE_*`）。
7. **画法有两条**（写实 `Real.draw`、卡通 `drawFish`），都读 `fish.alpha` 与缩放，被吃动画可以复用这两个量，不必改画法。
8. **设置开关的做法有现成模式**：`aquariumFish / aquariumWater / aquariumRealistic` 三个键，默认开、只有明确 `false` 才关，接线在 `settings.html`、`js/settings-page.js`（三处）、`js/background-experience.js`（归一化两处 + 传给 `aq.frame`）。

## 3. 生物学依据（决定规则，而不是随便定）

> 来源是我这轮检索到的论文摘要与科普页面，**没有通读原文**；数字请以原文为准。详细出处与许可在调研文档里。

| 动物 | 在这个水族馆里的角色 | 依据 |
|---|---|---|
| **小锤头鲨** | **唯一的捕食者** | 双髻鲨（*Sphyrna lewini*）胃含物研究：墨西哥马萨特兰 556 条（48–160 cm）以飞枪乌贼和硬骨鱼（鲹科 IRI 26%）为主，是**机会主义的泛食者，吃什么由数量与可得性决定**（来源 1）；哥斯达黎加幼鲨 teleost 占 41.07%、软体 30.36%、甲壳 28.57%（来源 2）；加利福尼亚湾幼鲨 teleost 出现频率 64.3%，**29.3% 的胃是空的**（来源 3）。→ ①吃鱼是真实行为 ②不挑食 ③**不是时时在吃**，对应到模型：有饥饿与餍足，不是持续追击 |
| 蝠鲼、鲸鲨 | **不是捕食者**（滤食） | 都是滤食性：张嘴游过浮游动物云，过滤磷虾、甲壳类、小鱼和鱼卵（来源 4：Smithsonian、BOEM）。它们**会吸入小鱼，但不是追逐个体**。让用户放进去的霓虹灯鱼从鲸鲨嘴边消失，体验上就是“被吃”，所以默认不做，作为可选项交给你定 |
| 海龟 | **不是捕食者** | 成体绿海龟基本是草食（海草、海藻）；幼体杂食，**吃水母**（来源 6）。这与“不能吃水母”冲突，所以海龟一律不参与捕食 |
| 霓虹灯鱼、蓝吊 | 猎物（群居） | 体长远小于捕食者的口裂限制（第 4.1 节） |
| 小丑鱼、神仙鱼 | 猎物（单条） | 同上 |
| 河豚 | **默认不是猎物** | 受威胁会鼓起身体、体内有河豚毒素，很多捕食者会放弃它（**常识性判断，这轮没有检索来源**）。也是为了少丢用户的鱼；你可以改成“是猎物” |
| 水母 | **永远不是猎物** | 你的硬约束 |

**模型来源（行为部分）**：

- Tu & Terzopoulos 1994《Artificial Fishes》（来源 5）：饥饿度 `H(t) = min[1 − n_e(t)·R(Δt_H)/a, 1]`，`R(x) = 1 − p0·x` 是消化率（名义 `p0 = 0.00067`，`0.005` 会变成“饿狼”）；意图生成器先看恐惧，再看饥饿，**饥饿超过阈值 `r`（0 < r < 0.5）才去吃**；捕食者追**成本最小**的猎物 `C_k = d_k (1 + β1·S_k + β2·E_k/π)`，其中 `d_k` 是**捕食者的嘴到猎物身体中心**的距离，`S_k = 1` 表示猎物在鱼群里，`E_k ∈ [0, π)` 是转向代价，`β1 = 0.5`、`β2 = 0.2`；捕食者“选定猎物并吃到餍足”。
- 口裂限制（检索摘要，**来自次级来源，未核对原文**）：礁鲨类的猎物长度多在自身体长的 20%–36%；天使鲨 75.6% 的猎物小于自身体长的 30%、95% 小于 40%；猎物体高小于口裂的约 60%；也有捕食者的猎物超过自身体长的 50%（切割齿的鲨鱼）。→ 取**保守值 0.3**，用 `meters` 而不是像素体长计算（小鱼的像素体长有可见下限，不代表真实比例）。
- NetLogo《Wolf Sheep Predation》（来源 7）：能量驱动；简化版本的捕食者—猎物种群**不加限制是不稳定的**（要么灭绝要么爆炸）。→ **补员由外部决定（第 6 节），不做种群反馈**。

## 4. 行为设计

### 4.1 谁能吃谁（规则表，数据驱动）

在物种表上加三个字段（实现时）：

```
diet: 'predator' | 'prey' | 'none'      // 小锤头鲨 predator；霓虹/蓝吊/小丑/神仙 prey；其余 none
gape: 0.3                               // 仅 predator：猎物真实体长 ≤ gape × 自己的真实体长（meters）
```

**判定函数**（纯函数，可穷举测试）：`canEat(predatorSpec, preySpec)` = `predator.diet === 'predator' && prey.diet === 'prey' && prey.meters ≤ predator.gape × predator.meters`。当前水族馆里小锤头鲨 2.5 m → 最大 0.75 m，4 种猎物都满足（最大的蓝吊 0.2 m = 8%）；规则的价值在于以后加物种时不会写出“小鱼吃大鱼”。水母不在 `SPECIES` 表里，**不可能进入这个函数**。

### 4.2 捕食者状态机

```
cruise ──(饥饿 ≥ 阈值 且 有合格猎物在感知范围内)──▶ hunt ──(口到猎物 ≤ 冲刺距离)──▶ strike
  ▲                                                   │                                 │
  │                                          (丢失/超时/被抓住)                  (命中 | 超时)
  │                                                   ▼                                 ▼
  └────────────── rest（恢复，不捕食）◀──────── 失败 ◀──────────────────────── handle（吞咽 1 秒）
                                                                                      │
                                                                         digest（餍足，饥饿度回落）
```

- **饥饿度 `H`**：每秒增加 `HUNGER_RATE`（初值 1/240，即约 4 分钟由饱到极饿），吞下一条减 `MEAL`（初值 0.6，下限 0）；初始 `H` 在 0.2–0.6 里取，这样放进去后 0–100 秒内会看到第一次捕食。**阈值 `H ≥ 0.5`**（对应论文 `r < 0.5`）。
- **目标选择**：每 0.5 秒在“合格猎物”里取成本 `C_k = d_k (1 + 0.5·S_k + 0.2·E_k/π)` 最小者（沿用论文的两个系数，初值）；已有目标时，只有新成本低于现有的 0.7 倍才换，避免来回切换。合格 = `canEat` 为真 ∧ `state === 'alive'` ∧ `alpha ≥ 0.9` ∧ 不是 `held` ∧ 不在豁免期（第 5 节）∧ 在感知半径内（初值 `min(6 倍体长, 屏宽 × 0.5)`）。`S_k` = 同条目存活的同伴 ≥ 3 条且都在聚合半径（`COH_R` × 体长）内。
- **逼近**：朝猎物的**预测位置**（猎物速度 × 至多 1 秒的提前量）走，速度 `cruise × 1.3`；**仍然服从现有的大个子运动模型**（侧视的 yaw 转身：转半圈用时 π × `YAW_R`(0.35) × 体长 ÷ 速度，巡航速度下小锤头鲨约 2.7 秒，冲刺时速度大、更快；俯仰上限 `FREE_PITCH` 0.6 rad ≈ 34°；边界/水面/钟罩避让）。这是写实的关键：锤头鲨不能原地掉头，也追不上跑到它身后的猎物，所以“追不到、绕一圈再来”是正常的。
- **冲刺 `strike`**：嘴到猎物中心 ≤ `STRIKE_R`（初值 1.2 倍体长）时，最多 1.1 秒内提速（仍受上面的转向约束）。**冲刺速度必须单独定义，不能沿用现有的速度上限**——盘点发现的坑：水族馆里的速度是**像素速度，不是真实速度**，小鱼为了看起来灵动被设得很快：霓虹灯鱼巡航 80 px/s，被惊动时上限 `FLEE_CAP`(2.6) × 80 = **208 px/s**，而小锤头鲨巡航 58 px/s，按同一个 2.6 倍上限只有 **151 px/s**。照搬现有上限，鲨鱼在直线上永远追不上最小的鱼（现实里相反：幼年锤头鲨的爆发速度远高于霓虹灯鱼）。规则：`strikeSpeed = clamp(max(cruise × 2.6, 1.2 × 目标猎物当前速度上限), …, cruise × 4.5)`，这是**只对捕食者、只在 `strike` 状态**的上限；猎物的逃跑上限不动。能不能吃到仍由几何（转向代价、俯仰锥、1.1 秒窗口）和 `p_catch` 决定，而不是速度碾压。这一项要在 S1 里先用模拟量出自然命中率再定系数。
- **命中**：冲刺期间任意一帧，嘴心到猎物心 ≤ `0.18 × len + 4`（与饲料的 `EAT_R_MOUTH` 同一口径，用 `mouthOf`，已含 `xs` 透视缩短）**且** 随机数 < `p_catch`；`p_catch = clamp(0.7 − 0.35·S_k, 0.15, 0.85)`（初值：单独的 0.7，在鱼群里的 0.35）。随机数来自**独立的随机流**（4.7）。
- **失败**：冲刺结束没吃到 → `rest` 3–5 秒；连续 3 次失败 → 放弃 20 秒。**捕食者永远不会“追到底”**（论文是“吃到餍足”，但屏幕上无休止的追逐不是你要的陪伴感）。
- **吞下 `handle`**：猎物进入“被吃”态 0.25 秒（位置收向嘴、体长缩到 0.3、透明度到 0；复用被捞起的 `SCOOP_*` 思路和 `alpha/scale` 画法），嘴边 3–4 个气泡（复用玩法层的 `addBubbles`），捕食者放慢到 0.6 倍 1 秒，`H -= MEAL`。
- **全局限速**：整个水族馆最多每 20 秒一次捕获（`KILL_GAP_S`），防止多个捕食者同时清场；每个捕食者吃完后 `H` 回落，天然限速（取 `MEAL = 0.6`、`HUNGER_RATE = 1/240` 时，同一条捕食者两次进食至少间隔 120 秒）。

### 4.3 猎物的反应

- **恐惧**沿用论文的 `F = min(D0/d, 1)` 形式，但只在捕食者处于 `hunt/strike` 时才有效；不在捕食的捕食者（巡航、餍足、恢复）**不会惊动猎物**，鱼群从它身边平静游过——这与真实的礁区观察一致，也避免整缸鱼一直在逃。
- 逃跑复用现有的避让机制：在 `ALERT_R`（初值 `2.5 × 捕食者体长 + 80 px`，上限 450 px）内，猎物获得远离捕食者的合力 `FLEE_PRED_W` 和速度倍数 `FLEE_BOOST 2.2`（不超过现有的 `FLEE_CAP`）；**同一群里有一条被惊动，其余在 0.3 秒内跟着逃**（鱼群的“恐慌波”），之后用现有的群游规则重新聚拢（`test/aquarium-school-regroup.test.js` 盯着聚拢速度）。
- 逃跑有反应时间 `REACT_S`（0.25 秒）：猎物逃跑的速度上限仍是现有的 `FLEE_CAP`（2.6 倍自己的巡航速度），冲刺的速度上限按 4.2 节另算；追上与否取决于几何（谁在谁的前方锥里、转身要多久）和 `p_catch`，**不靠让鲨鱼瞬移或速度碾压**。

### 4.4 与其它玩法的关系

| 功能 | 规则 |
|---|---|
| 拖拽（被抓着） | `held` 的鱼**不会被捕食**；捕食者被抓住就取消当前狩猎（回 `cruise`） |
| 松手 | 被放开的鱼有 `SAFE_S = 4` 秒豁免期，免得用户把鱼“丢进”鲨鱼嘴里 |
| 刚放入/淡入中的鱼 | `entering` 状态与淡入后 3 秒内不会被捕食 |
| 网兜捞出（`leaving`） | 不会被捕食 |
| 喂饲料 | 正在狩猎的捕食者忽略饲料吸引（不会半路改道）；吃饱的捕食者仍和现在一样吃饲料。饲料不影响 `H` |
| 戳一下 | 戳猎物：现有的冲刺照旧；戳正在 `strike` 的捕食者：冲刺中止，转入 `rest` |
| 水母 | 捕食者与猎物都照旧避开钟罩；`bells` 仍是只读输入 |
| 省流量（`lowPower`） | **关闭捕食**（少一套逐帧计算，也不增加省流量模式下的状态变化） |
| “减少动态效果” | 宿主整体停掉水族馆动画，不需要额外处理 |

### 4.5 存储与补员（关键：不改存储，也不能清空鱼缸）

- **`aquariumV1` 一字不改**；被吃只发生在世界里，**刷新页面一切恢复**。所以“唯一写入点是用户放入/捞出”的原则不变。
- 被吃的鱼进入 `world.vacancies = [{ entry, species, due }]`，到 `due` 时从屏幕边缘游入一条**新的**（与大个子入场同一条路径，淡入 `ENTER_S`），群居种 **25 秒**补一条，单条种 **75 秒**；同时存在的空缺最多 8 个。
- **陷阱（实现时必须处理）**：`Core.reconcile` 用 `world.fish` 里是否还有这个条目来判断“已存在”。单条鱼被吃光后，这个条目在世界里就“消失”了，下一次 `reconcile` 会当作新条目**立刻**重新生成——补员延迟就被绕过了。`reconcile` 必须把“有空缺的条目”也算作存在，条目被捞出时同时丢弃它的空缺和 `world.groups[entry]`。
- 托盘与居民列表的条目数、容量统计只看条目，不受影响；可选：在居民行显示“补员中”（低优先级）。

### 4.6 “不吃水母”如何做成结构性的

1. 猎物只能是 `world.fish` 里的鱼，且 `canEat` 要求 `prey.diet === 'prey'`；水母不在物种表里，没有 `diet`。
2. `bells` 数组在 `Core.step` 里是**只读**的；捕食代码只遍历 `world.fish`。
3. 测试：对随机世界（含水母钟罩列表）跑捕食，断言步进前后 `bells` 深度相等、被移除的鱼的物种恒属于猎物集合；再加源码钉子——捕食模块不得引用 `bells` 做删除或统计。
4. 海龟的“真实食性里有水母”被明确排除（它不是捕食者）。

### 4.7 随机数与黄金轨迹

- `createWorld` 新增 `predation: false`（**默认关**）。关闭时**不抽任何随机数、不改任何字段更新顺序**，现有黄金轨迹（5 种小鱼、8 种鱼两个钉子）与所有现有测试逐位不变。
- 开启时，狩猎判定（命中概率、初始饥饿度、失败后的恢复时长）使用**独立的随机流**：开启时从 `world.random` 取一次种子，之后狩猎判定不再碰 `world.random`，这样捕食不会扰动鱼群、避让和家的选择用的那条流。捕获时的气泡复用玩法层的 `addBubbles`（它用 `world.random`，只在发生捕获时才调用）；开启后的轨迹本来就和关闭时不同，“关闭时逐位一致”只约束关闭状态。
- 控制器每帧把设置里的 `predation` 与 `lowPower` 交给 `Core.step`（和 `surface` 的传法一样）。

## 5. 设置与界面

- 设置页“水族馆”分组新增一个开关 `aquariumPredation`（键名沿用现有三个开关的写法）。默认值见第 9 节。**只有放了小锤头鲨且有猎物时才有任何可见变化。**
- 不新增弹窗；被吃时不弹提示。托盘里可选显示“最近被吃 N 条（会自动补回）”，低优先级。
- 桌面端无改动。

## 6. 测试与校准计划

| 层 | 内容 |
|---|---|
| 规则表 | `canEat` 对 9 种动物逐对穷举：只有小锤头鲨对 4 种猎物为真；河豚、海龟、蝠鲼、鲸鲨、小锤头鲨自己都为假；口裂比例改小到不满足时为假（用 `meters`，不用像素） |
| 状态机 | 脚本化小世界：饥饿到阈值才进入 `hunt`；逼近→冲刺→命中/失败各自的转移；连续失败进入放弃期；被抓/豁免期内不会被选为目标；目标切换的 0.7 迟滞 |
| 成本函数 | 对已知配置，核对 `C_k` 与论文公式（β1 = 0.5、β2 = 0.2）逐位一致；鱼群里的猎物比孤立的贵 |
| 命中 | 固定随机流下，`p_catch` 的上下夹取与群内/单独的差别；嘴心距离用 `mouthOf`（含 `xs`） |
| 补员 | 单条被吃后 75 秒才补、群居 25 秒；`reconcile` 不会提前补；条目被捞出时空缺与家一并丢弃；空缺 ≤ 8 |
| 存储 | 捕食全程 `aquariumV1` 零写入（控制器的写入只在 `mutate()`）；刷新后一切恢复 |
| 水母 | 随机世界里 `bells` 不变；移除的鱼恒为猎物物种；源码钉子 |
| 关闭时一致 | `predation:false` 时黄金轨迹、全部现有测试逐位不变；开启但没有捕食者时同样不变 |
| 统计校准 | 固定种子（≥ 200 个）× 10 分钟：每条捕食者每 10 分钟捕获数的范围（验收：有猎物时 3–6 条）、追逐时长 p95 ≤ 15 秒、鱼缸最低存活比例 ≥ 70%、`hunt` 状态的帧占比；**成功率取决于几何，要先量自然命中率再定 `p_catch`，不凭空设数** |
| 真实 Chrome 156（隔离配置） | 帧耗时开/关对比、真实截图序列（逼近、冲刺、吞下、补员）、拖拽与喂食并存、水母钟罩旁的行为 |
| 变异检查 | 只改 `/tmp` 副本并核对仓库哈希：口裂比较符号、`diet` 判定、豁免期、补员延迟、水母相关的任何一处 |

**黄金轨迹的守法**：状态机与成本函数都是纯逻辑，放进 `aquarium-core.js`（或拆出 `aquarium-predation-core.js`，同样不碰 DOM/存储/`Date`），绘制只读 `fish.alpha`、缩放与已有的气泡。

## 7. 风险

| 风险 | 对策 |
|---|---|
| 用户觉得“自己的鱼被吃了”不舒服 | 不改存储、刷新即恢复、自动补员、可关闭、猎物豁免期；默认值由你定 |
| 种群振荡（捕食者—猎物不稳定，来源 7） | 没有繁殖；补员是外部的；饥饿限速 + 全局 20 秒限速 |
| 大个子转得慢，几乎追不到 | 正是写实的一部分；`p_catch` 与感知半径按**实测的自然命中率**标定，不靠让鲨鱼“瞬移”作弊 |
| 共享随机流改变现有轨迹 | 默认关；开启时用独立随机流 |
| `reconcile` 把被吃的条目立刻重新生成 | 4.5 的陷阱条款与测试 |
| 逐帧成本 | 渲染条数上限 `MAX_FISH` 40（省流量 16，且省流量时关闭捕食）；小锤头鲨在物种表里没有单独的数量限制（`MAX_LARGE` 只管蝠鲼与鲸鲨），最坏 12 个条目都是锤头鲨——成本函数每 0.5 秒才算一次，复杂度 ≤ 捕食者数 × 猎物数（最坏约 12 × 40），仍在真实浏览器里量帧耗时；全局 20 秒一次的捕获限速同时防止多条鲨鱼清场 |
| 画面上出现“鱼凭空消失” | 吞食动画 0.25 秒 + 气泡；被吃的鱼在嘴的位置消失 |

## 9. 需要你决定的默认值（我替你给的建议）

1. **默认开还是关**：建议**开**（你明确要这个能力；同类开关都是默认开；只有放了小锤头鲨才有变化；省流量自动关）。
2. **补员方式**：建议“**自动补回**”（群居 25 秒、单条 75 秒，刷新也恢复）；备选“被吃后到刷新前一直少一条”或“真的从存储里删掉”（后者会改变‘只有用户放入/捞出才写存储’的原则，不建议）。
3. **捕食频率**：建议“**偶尔**”（每条捕食者约每 2 分钟一次，上面的初值）；备选“适中”（约每 1 分钟）、“频繁”（约每 30 秒）。
4. **猎物范围**：建议霓虹灯鱼、蓝吊、小丑鱼、神仙鱼；**河豚默认不吃**；**鲸鲨与蝠鲼默认不吸入小鱼**（可选：让它们在游过鱼群时偶尔吸入一条）。
