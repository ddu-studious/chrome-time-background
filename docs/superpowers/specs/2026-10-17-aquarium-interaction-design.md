# 水族馆互动设计

## 1. 目标与已确认的决策

水族馆（`docs/superpowers/specs/2026-10-17-aquarium-design.md`）第一版只做了放入与捞出。本设计是后续四个子项目中的第 1 个——**互动**：让用户能戳鱼、拉鱼尾、给鱼喂食。其余三个（布景、稀有来访者、记忆）各自单独做设计，顺序是 互动 → 布景 → 来访者 → 记忆。

| 问题 | 用户决策 |
|---|---|
| 后续想做哪些 | 喂食、拉鱼尾/戳、布景、稀有来访者、图鉴、保存位置，**全部都要**，拆成 4 个子项目依次做 |
| 先做哪个 | 按“互动 → 布景 → 来访者 → 记忆”，本文件只管互动 |
| 手势模型 | **无模式**：点鱼 = 戳；按在尾部（后半身）拖 = 拉尾；喂食靠把饲料从托盘拖出去（点一下也能撒）；点在空水里的行为不变；“点击冲击波”并入“戳”，只在点在鱼上时出现 |
| 喂食的后果 | **轻**：吃到的鱼冒几个泡、变亮约 20 秒后恢复；不存储、不绑任务、水母不受影响 |
| 拉尾的手感 | **拉伸 + 回弹**：只改画法（尾巴被拉长弯曲）加阻尼弹簧回弹、向前一冲；不做脊柱链物理 |
| 实现路线 | 路线 A：新增两个模块，现有文件只开最小的口子（见 §4） |
| 行为细节（设计第 1 节） | 用户确认；其中设计时新增的三条取舍一并被接受：成群小鱼不做拉尾、按在后半身才算拉尾、戳不吞掉 click |
| 原设计 §9 的“不做”清单 | 其中“喂食、点击冲击波、拉鱼尾”在本子项目解禁；布景、来访者、收藏、保存位置等仍不做 |

灵感来自用户整理的素材（#43、#44 喂食与冲击波，#37 拉鱼尾），只借创意，不借代码。

## 2. 现状（已核对代码）

- **指针路由**（`js/background-experience.js`）：`onPointerDown` 先 `tryGrab`（先水母、再鱼），只认空白背景 `isBackgroundTarget` 上的主指针主键；一旦抓住，背景玩法（脉冲、织光、引力核心、彗光、旋涡）不会触发。所以**点在鱼上现在什么都不发生**，点在空水里照旧。`endGrab` 调 `Aquarium.drop(x, y)`，返回 true（真的拖过）才让宿主吞掉随后 450 ms 内的那次 click。
- **鱼控制器**（`js/aquarium.js`）：`DRAG_PX = 6`；`grabAt` 建立会话；`drop` 在没拖过时只 `Core.release` 并返回 false；`frame` 里依次 `Core.step`、`tick`，再按 z 从远到近画鱼。托盘由 `buildUi` 建：物种按钮行、容量行、原因行、居民列表、`aria-live` 状态行。
- **鱼的运动**（`js/aquarium-core.js`）：`stepFish` 把速度以 `TURN = 2.0 /s` 拉向期望速度，并把速度夹在 `巡航速度 × FLEE_CAP(2.6)` 以内。所以一次性冲量以约 0.5 秒的时间常数衰减，也不会超过巡航速度的 2.6 倍。命中区是椭圆 `rx = 0.6·len·1.25 + 14`、`ry = 0.35·len·1.25 + 14`。
- **鱼的尺寸**（1440×900，8 个种子里全部个体）：霓虹灯鱼 13.6–17.5 px、蓝吊 18.7–24.1、小丑鱼 25.4–32.3、河豚 27.1–34.4、神仙鱼 28.8–36.6、小锤头鲨 47.5–60.3、蝠鲼 81.4–103.3、鲸鲨 110.2–139.9。成群小鱼（霓虹灯鱼、蓝吊，每个条目 5 条）太小，看不出拉伸。
- **画布限制**：鱼画在宿主共享画布上，合成方式是 `screen`（只会变亮），深色细节必须临时切到 `source-over`（小丑鱼的白带、神仙鱼的竖纹、所有眼睛已这样处理）。
- **基线数字**（HTTP 预览真实 Chromium，无头软件渲染，用于回归比较）：鱼层 JS 耗时平均 0.28 ms、P95 0.40 ms、最大 0.7 ms（36 条鱼，DPR 2）；整缸静置 60 秒打转占比 ≤ 1.47%；抓取试验 31 次按下抓中 26 次。见 `docs/technical/aquarium-20261017.md`。

## 3. 用户看到的行为

下面的数字（6 px、140 px、300 px、24 粒、14 秒、20 秒、0.8 秒等）全部是初值，实现时在真实 Chromium 里看轨迹与逐帧图校准，校准后的值写回技术文档。

### 3.1 戳

- 点一下鱼：按下到松手之间移动不超过 `DRAG_PX`（6 px）。对所有 8 种鱼都有效。
- 被戳的鱼猛地窜开，摆尾加快，嘴边冒 2–3 个小泡。
- 点击处荡开一圈涟漪；约 140 px（再乘视口缩放）内的其他鱼被轻轻推开，越近越强，成群小鱼会散开再聚拢；大型鱼的反应打折。
- 同一条鱼 0.4 秒内不重复响应；涟漪同时最多 3 圈。
- 点在鱼上以前什么都不发生，以后就是戳；点在空水里的行为不变。戳不吞掉这次点击，只有真的捞起鱼时才吞（和现在一样）。
- 水母不受影响。

### 3.2 拉鱼尾

- 适用于单条鱼和大型鱼（小丑鱼、河豚、神仙鱼、小锤头鲨、蝠鲼、鲸鲨）。**成群小鱼不做拉尾**（只有 14–24 px 长，拉伸看不出来），只保留戳和捞。
- 按在**后半身**（按下点在鱼本地坐标 `lx ≤ 0`，即中心线之后）并拖动：尾巴朝指针方向被拉长、弯曲，最多拉长约 35% 体长（另设绝对上限），鱼身加快摆尾像在挣扎。
- 一路拖进网兜仍然是“捞出”，规则、写入与回滚不变。
- 半路松手（含 Esc、失焦、`pointercancel` 等取消）：尾巴带阻尼回弹一次，鱼向前冲一下，冒 2 个泡。
- 按在前半身，手感还是现在的抓取。

### 3.3 喂食

- 托盘里新增“喂食”按钮：
  - 点一下，或键盘 Enter/空格：从屏幕上部落下 6 粒饲料，横向在中间 60% 里随机。
  - 从按钮上按住拖出去、在水里松手：饲料落在松手处，每粒在 ±40 px（再乘视口缩放）内散开。拖的时候指针旁跟着一小撮饲料。松在托盘上、按 Esc、窗口失焦或 `pointercancel` 则取消。
- 饲料是暖色小光点，慢慢下沉并轻轻飘摆；同屏最多 24 粒（省流量模式 8 粒），最长存在约 14 秒。
- 按钮有约 0.8 秒冷却，冷却期内的点击被忽略（不提示）；同屏饲料到上限时，状态行提示“饲料还没吃完”。池子里没有鱼（条目为空）时按钮禁用，并写明原因（沿用物种按钮的 `title` 加 `aria-describedby`）。
- 约 300 px（再乘视口缩放）内的鱼（含大型鱼）游向最近的一粒，碰到就吃掉。吃到的那条冒 2 个泡，变亮约 20 秒后恢复。成群的鱼各吃各的，群游规则照旧。水母不吃也不躲。

### 3.4 都不存储

- 饲料、泡、涟漪、变亮状态、拉尾弹簧只在内存里，刷新即清空；不绑定任务、没有声音、不新增设置开关，跟着现有“水族馆小鱼”（`aquariumFish`）总开关。
- 沿用鱼层现有的“减少动态效果、页面隐藏、被工作台遮挡即停、省流量降级”规则，玩法不另设例外。
- 喂食按钮可以用键盘；戳和拉尾只有指针操作（触屏理论上能用，不验证）。

## 4. 架构

### 4.1 路线选择

| 路线 | 结论 |
|---|---|
| **A 新增两个小模块，现有文件只开最小的口子** | **采用**。和项目里 `*-core.js` 加控制器的惯例一致 |
| B 直接加进 `aquarium-core.js` 与 `aquarium.js` | 不选：两个文件会涨到约 900 和 1200 行（估计），玩法状态与群游状态搅在一起，已验证的“不打转、翻面、网兜”测试和变异检查范围变得难界定 |
| C 另起 DOM 或画布画饲料和泡 | 不选：多一套 RAF 和节点，宿主已有唯一的 RAF |

### 4.2 模块与改动面

| 文件 | 职责 | 依赖 |
|---|---|---|
| `js/aquarium-play-core.js`（新） | 纯逻辑：饲料、泡、涟漪、变亮倒计时、拉尾弹簧、戳与撒饲料的规则、拉尾分区判定。不碰 DOM、存储、`Date`，随机数全走 `world.random`；所有数字集中在它自己的 `PARAMS` | `AquariumCore`（`cruiseSpeed`、`speciesById`、`clamp`、`PARAMS.MIN_DT/MAX_DT`） |
| `js/aquarium-play.js`（新） | 画法与喂食按钮：涟漪、饲料、泡的画法，喂食按钮与跟手饲料（只读玩法状态，不含规则） | `AquariumPlayCore`（只用它的 `PARAMS`） |

现有文件的改动：

- `js/aquarium-core.js`（写计划时按原型修正，见 §11）：三处改动，不带新参数时与现在逐位一致（黄金轨迹与黄金抓取测试钉住）：
  1. `step` 的输入多一个可选的 `attractors`，每项 `{ x, y, reach, weight, boost }`：核心只校验——数字须有限且 `reach > 0`，否则整项丢弃；`weight` 夹在 0–3，`boost` 夹在 0.5–2.5（不超过 `FLEE_CAP`，免得被速度上限悄悄截掉）；`stepFish` 里朝范围内最近的吸引点游，并按 `boost` 加快期望速度。数字由玩法模块给出，核心不新增常量。
  2. 导出已有的 `cruiseSpeed(world, fish)`（玩法冲量以它为单位；`stepFish` 改为调用它，数值不变）。
  3. 拉尾要让鱼“被拖着走”才不穿帮：`Core.grab(world, fish, x, y, { tail: true })` 在 `fish.held` 里多记被抓点（鱼本地坐标）与平滑后的指针速度，`stepHeld` 多一条 tail 分支（被抓的点留在指针下，鱼头朝远离指针运动的方向；指针缺失时重新取基准），新增 `PARAMS.HOLD_PV_RATE`；`held` 对所有抓取多一个 `tail` 字段（普通抓取为 `false`）。
- `js/aquarium.js`：`grabAt` 用 `PlayCore.isTailZone` 判断拉尾分区，以 `{ tail: true }` 抓取并记进会话；`drop` 在没拖过时调用戳（返回 false，不吞 click）；拉尾会话在拖过但没进网兜时触发回弹，`cancel` 取消拉尾会话时同样收尾（没拖过则静默）；非拉尾的抓取行为不变；`frame` 里先由饲料算出吸引点，`Core.step` 之后推进玩法，再按 涟漪 → 鱼 → 饲料与泡 的顺序绘制；`spineOf(fish, shape, len, pull)` 与 `drawFish(ctx, fish, palette, view, extras)` 各多一个可选参数（拉伸位移、变亮），`geometry` 多导出 `spineOf`，缺省时输出与现在逐点相同；`buildUi` 里挂喂食按钮；`stop`/`destroyUi` 里清理；玩法层可注入（`env.playCore`、`env.play`，传 `null` 即关闭），每一次玩法调用都包在 `playGuard` 里，出错只停玩法（`disablePlay`：本次会话内不再试，下次 `start` 重试），`state()` 多一个 `playFailed`。
- `index.html`：按 `aquarium-core.js` → `aquarium-play-core.js` → `aquarium-play.js` → `aquarium.js` 的顺序加两个 `<script>`（在 `aquarium.js` 之前），并升 `aquarium-core.js`、`aquarium.js` 的 `?v=`；`css/aquarium.css` 补喂食按钮与跟手饲料样式并升 `?v=`；`settings.html` 的“水族馆小鱼”开关说明补一句互动说明。
- **本子项目不新增的改动**：宿主 `background-experience.js`（水族馆第一轮已接好，戳走现有的“没拖过就松手”路径，喂食走自己的 DOM 事件）、水母代码、存储 `aquariumV1`、`manifest`、权限、依赖。

### 4.3 状态与一帧的顺序

- 玩法状态 `play = { pellets, ripples, bubbles, fed, pulls, ... }` 在控制器里与 `world` 同生命周期，省流量切换导致 `world` 重建时一起重建；窗口尺寸变化时饲料、涟漪和泡的位置按比例缩放（拉尾弹簧是鱼本地的小位移，不缩放）。鱼对象本身不挂玩法字段（只有核心在抓取时往 `fish.held` 里记拉尾的被抓点与指针速度）。
- 玩法模块（`aquarium-play-core.js`）**唯一写到鱼身上的是速度冲量 `vx/vy`**（戳、冲击波、回弹后的冲刺），冲量落在 `stepFish` 现有的速度上限之内；拉尾时鱼被抓着的位置与朝向由核心的 `stepHeld`（tail 分支）管。变亮、拉伸由控制器通过可选参数交给 `drawFish`，不改鱼对象。
- 一帧：由饲料算出吸引点 → `Core.step(world, dt, { pointer, bells, attractors })` → `Play.step`（饲料下沉、过期、被吃，泡上浮，涟漪扩散，变亮倒计时，拉尾弹簧）→ 绘制：涟漪、鱼（`drawFish` 带可选的变亮和拉伸）、饲料与泡。
- **戳**：`drop()` 发现没拖过 → `Play.poke(...)`：给被戳的鱼一个远离点击处的冲量（点在离鱼中心很近处、方向不可靠时，沿当前朝向向前窜），放出涟漪，按距离推开周围的鱼，在嘴边冒泡。
- **拉尾**：`grabAt()` 判断“不是成群小鱼且按在后半身”，用 `Core.grab(…, { tail: true })` 抓住并 `beginHold`。拖着走时，鱼绕被抓的点转、被抓的点留在指针下（核心的 tail 分支）；弹簧目标是指针运动方向（折算到鱼本地坐标）上 `min(指针速度 × PULL_GAIN, 35% 体长, 绝对上限)` 的位移——没有额外的“基础张力”，指针停住时目标回到 0；`spineOf` 按 `PULL_WEIGHT`（越靠尾越大，头与前身不动）把位移分到 5 个站位，鳍、条纹、白带都跟着脊柱走，不用单独处理。松手或取消：目标归零，欠阻尼弹簧回弹一次，同时鱼朝鱼头方向冲一下并冒泡（`endHold`）；拖进网兜、没拖就松手这类静默收尾（`quiet`）直接清掉弹簧，没有回弹、冲刺和泡，捞起走现有动画。
- **喂食**：按钮点击或键盘触发 `Play.sprinkle`；按钮上按住拖出去时，控制器显示跟手饲料，松手用 `overUi`（托盘的开关按钮或展开的面板的矩形）判断是否落在托盘上，是则取消，否则在松手处 `Play.sprinkle`。喂食拖拽只用自己的指针事件（按下在按钮上，之后在 `document` 上收 `pointermove`、`pointerup`、`pointercancel` 与 Esc，窗口失焦也取消），不与宿主的 `isBackgroundTarget` 路由冲突。

### 4.4 接口（计划里定稿）

- `AquariumPlayCore`：`PARAMS`、`create()`、`resize(play, ratioX, ratioY)`、`counts(play)`、`poke(play, world, fish, at)`、`sprinkle(play, world, opts?)`（`opts` 为空：从上部落下；`{ x, y }`：落在那里；`count`：粒数 1…12）、`attractors(play, world)`、`extrasOf(play, fish) → { pull, fed }`、`isTailZone(fish, x, y)`、`beginHold(play, world, fish)`（要求鱼是用 `Core.grab(…, { tail: true })` 抓住的）、`endHold(play, world, fish, opts?)`（`{ quiet: true }` 静默收尾）、`step(play, world, dtMs)`。拒绝时返回 `{ ok: false, reason }`：`poke` 为 `invalid`、`state`、`cooldown`；`sprinkle` 为 `invalid`、`cooldown`、`busy`；`beginHold`、`endHold` 为 `state`。不抛错。
- `AquariumPlay`：`drawBack(ctx, play, view)`（涟漪，画在鱼后面）、`drawFront(ctx, play, view)`（饲料与泡，画在鱼前面）、`mountFeed(parent, hooks) → { button, setEnabled(enabled, reason, describedBy), destroy() }`，`hooks = { doc, win?, now?, feed(point | null), overUi(x, y) }`，另导出 `DRAG_PX`、`SWALLOW_MS`；`view = { scale, lowPower }`。
- 两个新模块都是 UMD：CommonJS 给 `node --test`，浏览器挂 `window.AquariumPlayCore`、`window.AquariumPlay`。

### 4.5 初始参数（全部是初值，由真实轨迹和逐帧图校准）

| 参数 | 初值 | 说明 |
|---|---|---|
| `POKE_COOLDOWN_S` | 0.4 | 同一条鱼 |
| `POKE_DASH` | 2.4 | 被戳的鱼冲量 = 巡航速度 × 此值，受 `FLEE_CAP` 2.6 倍封顶 |
| `POKE_CENTER` | 0.15 | 点击处离鱼中心近于 此值 × 体长 时方向不可靠，改为沿当前朝向向前窜 |
| `SHOCK_R` | 140 | px × 视口缩放，再加每条鱼自己的体长；推开别的鱼的范围 |
| `SHOCK_DASH` | 1.2 | 邻居冲量 = 巡航速度 × 此值 × (1 − 距离 / 范围) |
| `SHOCK_LARGE` | 0.35 | 大型鱼的冲量折扣 |
| `RIPPLE_S`、`RIPPLE_R` | 0.7、110 | 涟漪扩散时长（秒）与画出来的最终半径（px × 视口缩放） |
| `MAX_RIPPLES` | 3（省流量 1） | |
| `MAX_BUBBLES` | 24（省流量 8） | |
| `POKE_BUBBLES`、`EAT_BUBBLES`、`RELEASE_BUBBLES` | 2（戳时再加 0 或 1）、2、2 | 戳、吃到饲料、回弹各冒几个泡 |
| `TAIL_ZONE` | 0 | 按下点本地 `lx ≤ 此值 × 体长` 算后半身 |
| `PULL_GAIN` | 0.1 | 拉伸量 = 指针速度（px/s）× 此值（px） |
| `PULL_MAX`、`PULL_ABS` | 0.35、40 | 体长的倍数；另设绝对上限 px × 视口缩放，免得蝠鲼、鲸鲨拉得过头 |
| `PULL_OMEGA`、`PULL_ZETA` | 16 rad/s、0.5 | 欠阻尼：回弹约一次，约 0.5 秒收敛 |
| `PULL_WEIGHT`（画法侧） | `[0, 0, 0.12, 0.5, 1]` | 拉伸位移落在 5 个站位上的比例，头与前身不动 |

| `SPRINKLE_COUNT`、`SPRINKLE_MAX` | 6、12 | 点一下落几粒；`count` 的上限 |
| `SPRINKLE_X0`、`SPRINKLE_X1`、`SPRINKLE_Y` | 0.2、0.8、0.12 | 点一下时的落点：屏宽的 20%–80%、屏高的 12% |

| `PELLET_SINK` | 40 | px/s × 视口缩放 |
| `PELLET_LIFE_S` | 14 | |

## 5. 错误处理与降级

- **玩法模块缺席或抛错，只关玩法，不带走鱼层。** 两个新模块加载不到时，`aquarium.js` 的行为与现在完全一致：没有喂食按钮，点鱼也不会戳。玩法的每一次调用（推进、绘制、戳、撒饲料、拉尾收尾）都包一层 try/catch（`playGuard`），出错只停玩法（本次会话内不再试，下次 `start` 重试）并留一条警告；现有 `frame` 里整层停用（`failed`）保持原样，只管画鱼本身的错。
- **输入一律校验**：坐标与 `dt` 不是有限数就忽略。饲料 24/8、泡 24/8、涟漪 3/1 的上限在核心里强制，不只靠按钮禁用。鱼被捞走（离开中）或不在了，它的弹簧记录在下一步被清掉；变亮记录按时间到期（最长 20 秒；鱼 id 在一个世界里不复用，世界重建时玩法状态一起重建，所以不会错用）。
- **取消路径收干净**：喂食拖拽被取消、被 `stop()` 打断或页面隐藏时，跟手饲料和事件监听都撤掉；弹簧遇到被捞走、世界重建、窗口尺寸变化都能正确收尾。
- **不碰存储、网络、权限**：玩法操作不得调用 `chrome.storage.local.set`；新文件里不得出现 `fetch`、`XMLHttpRequest`、`innerHTML`、`eval`、`localStorage`、`chrome.storage`（源码扫描测试守住）；界面只用 `createElement` 与 `textContent`。
- **可访问性**：喂食按钮有 `aria-label`；状态行沿用现有 `aria-live`，文字为“落下了 N 粒饲料 / 饲料还没吃完 / 喂食出错，已停用戳、喂食和拉尾”；没有鱼时按钮禁用，`title` 写“先放入一条鱼，才能喂食”并用 `aria-describedby` 指向列表里的空状态提示。
- 多个标签页各有各的饲料与泡（不存储、不共享），这是预期行为。

## 7. 风险

- 吸引力调不好，可能让鱼挤成一团或围着饲料转；缓解：吃掉的饲料立即消失，`EAT_R_LEN` 与 `EAT_R_PAD` 取得宽松，用轨迹测试和打转指标把关，必要时降权重或缩小范围。
- 吃到饲料后的变亮在夜间或深色背景上可能不明显；缓解：以真实截图判断，必要时加一圈柔光。
- 拉尾对小锤头鲨（48–60 px）效果最小，对 100 px 以上的大型鱼最大；缓解：绝对上限，逐种看序列图。
- 浅色的饲料、涟漪在亮背景上可能被 `screen` 混合吞掉；缓解：见 §6.5 亮背景。原型在合成的亮色背景（亮度约 0.86）上的截图：饲料清楚（亮度差 0.41–0.54），涟漪偏淡但看得见，气泡几乎看不见（只有 `screen` 的浅色圈）；气泡只是点缀，是否也给它垫一圈深色细边，留到真实截图验收时定。
- 真实 GPU 上的耗时未知；缓解：两个上限（饲料、泡）可调，省流量模式减半。
- `stepFish` 里加吸引点分支可能改变现有轨迹的浮点计算顺序；缓解：无吸引点时提前跳过，由黄金轨迹测试逐位比较。

## 11. 写实现计划时对本规格的修正（2026-10-17）

规格经用户确认后，在 `/tmp` 里把全部代码原型跑通（测试、变异检查、真实 Chromium 预览），发现原文有下面这些与事实不符或不够准确之处，已改回上文各节；行为设计（第 1–3 节用户确认的内容）没有变：

1. **依赖**：`aquarium-play-core.js` 依赖 `AquariumCore`（§4.2 原写“无”）；`aquarium-play.js` 只依赖 `AquariumPlayCore`（原写还依赖 `AquariumCore`）。脚本顺序 core → play-core → play → aquarium。
2. **核心改动不止吸引点**：原文“`attractors` 是唯一动到鱼运动逻辑的地方”不成立。另有导出 `cruiseSpeed`、`Core.grab(…, { tail })` 与 `stepHeld` 的 tail 分支、`HOLD_PV_RATE`；校验口径改为 `reach ≤ 0` 整项丢弃、`weight` 0–3、`boost` 0.5–2.5。普通抓取与不带吸引点的轨迹仍与现在逐位一致。
3. **拉尾的实现**：鱼被抓着时的位置与朝向由核心管（被抓点留在指针下、鱼头朝远离指针运动的方向），“只改画法”只对尾巴的拉伸成立；拉伸量只随指针速度（`PULL_GAIN`），没有“基础张力”。
4. **涟漪与推开范围分成两个参数**：`RIPPLE_R` 110（画出的半径）与 `SHOCK_R` 140（推开范围，再加每条鱼的体长）。
5. **窗口尺寸变化**：饲料、涟漪、泡的位置都按比例缩放，不是“涟漪和泡直接清掉”。
6. **变亮记录**不在鱼被移除时清，按时间到期；弹簧记录在鱼离开或不见时下一步清。
7. **接口定稿**（§4.4）：`create()` 无参数，`step(play, world, dtMs)`，`beginHold(play, world, fish)`，`endHold(…, { quiet })`，绘制拆为 `drawBack` 与 `drawFront`，`mountFeed` 的 `setEnabled` 多一个 `describedBy`。
