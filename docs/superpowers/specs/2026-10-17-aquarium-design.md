# 水族馆设计

## 1. 目标与已确认的决策

把首页“水母背景”升级为水族馆：水母仍是主线，用户可以往里**放入**鱼，也可以把鱼**捞出**。

| 问题 | 用户决策 |
|---|---|
| 鱼从哪来 | **自由放入**，不与任务挂钩；**只有水母与任务挂钩，水母是主线** |
| 捞出后 | **直接移除**；想要再从图鉴放一条 |
| 操作入口 | **首页直接操作**：底部图鉴托盘点击放入，拖到网兜区捞出 |
| 外观 | **发光半透明**，与水母同一套视觉语言，夜晚有荧光 |
| 技术选型 | 用户不设限（Three.js 也可），要求选合适的、与项目统一（见 §3） |
| 第一版范围 | 只做放入与捞出；**喂食、拉鱼尾不做**，留作后续 |

素材来源是用户整理的 `X海洋动物创作50帖.xlsx`（28 条鲨鱼、22 条其他海洋动物）。逐条审阅与它如何改变本设计，见第 2A 节。

## 2. 现状（已核对代码）

- 水母皮肤 `js/jellyfish*.js` 画在背景体验共享的 2D 画布 `#background-experience-canvas` 上，不自建 RAF 和画布；宿主 `js/background-experience.js` 的 `drawJellyfish` 每帧调用 `skin.frame(...)`。
- 水母一只对应一个待办，同屏最多 8 只（省流量 4 只）；`js/jellyfish-core.js` 已 1080 行、`js/jellyfish.js` 已 702 行，不再往里塞新功能。
- 宿主已有指针转发：`tryGrab`（只认空白背景 `isBackgroundTarget`、主指针主键）、`endGrab`、`cancelGrab`、拖过后吞掉 click；抓水母拖进纸篓完成任务。
- 受“启用背景体验”总开关、`reduce-motion`、`saveData`、页面隐藏、工作台遮挡限制；减少动态效果下皮肤不启动。

### 从 #48 与 #44 学到的（影响设计）

1. **剪影加深度灰度就够了**：#48 实际运行的画面是 80 条鱼的剪影，只靠大小与灰度的差别表现远近，没有真 3D 光照。这直接支持第 3 节的 2D 伪深度结论。
2. **鱼的数量要比我最初定的 12 条多**：群游要有一定数量才像群。因此上限改成按“条目”和“渲染条数”两层管（见第 5 节），而不是总共 12 条。
3. **光标有两种关系**：#44 是“驱散 + 点击冲击波”，#43 是“鱼群跟随缓慢光标”。第一版采用“快速移动才惊动、慢速无视”，与水母一致；吸引与冲击波留到喂食版本。
4. **鲨鱼要进图鉴**：用户整理的 50 条里 28 条是鲨鱼，我最初的 6 种鱼里一条鲨鱼也没有，这是失误；已改（见第 5 节）。

## 3. 技术选型

**结论：第一版用 Canvas 2D，与水母共享同一块画布；Three.js 不用于第一版，保留为升级路径。**

查过的事实：

- 项目已有 `vendor/three`（锁定 `three@0.170.0`，`three.module.min.js` 约 688 KB，立体方块与知识图谱按需动态加载），但背景体验、水母、壁纸转场、液态时钟全部是 Canvas 2D 或原生 WebGL，没有用 Three.js。
- 用 Three.js 会新增第二块 WebGL 画布与第二套渲染循环；鱼和水母分处两块画布，只能固定“鱼在水母后面”，而且 3D 鱼的质感与已定的“发光半透明、和水母同一语言”不一致。
- 常驻背景特别在意功耗（见“视频工作台省电”）；真实 GPU 与品牌版 Chrome 156 仍未验收，不宜新增常驻 WebGL。
- Boids 现成库：`boids@2.0.0`（2022 年后无更新、无 README）、`boid@0.3.3`、`three-boids@0.0.7`（绑定 Three.js）、`flocking`（音频库，不相关），均不值得引入。二维数十条鱼的群游约百行，自写，不属于“重造上游引擎”。
- 表格里 #44 证明了 Three.js + WebGPU 计算着色器能跑 6144 条鱼，但它依赖 WebGPU，本项目真实 GPU 与品牌版 Chrome 156 尚未验收；#48 的 80 条剪影鱼群才是我们需要的规模，且已看到它只靠大小与灰度做出远近。
- 深度感用 2D 伪深度实现：每条鱼有深度 `z`，影响尺寸、透明度、速度和绘制顺序。

升级路径：`aquarium-core.js` 只输出位置、朝向、深度，不依赖渲染方式，将来要真 3D 鱼时可换渲染层，不动逻辑与存储。

## 4. 架构

新增三个文件，不改水母物理：

| 文件 | 职责 | 依赖 |
|---|---|---|
| `js/aquarium-core.js` | 纯逻辑：鱼种表、群游、避光标、避水母、边界、深度带、数量上限、放入/捞出状态。不碰 DOM 与 `Date`，随机数可注入 | 无 |
| `js/aquarium.js` | 控制器：存储读写、托盘、居民列表、网兜区、指针抓取状态机、画法 | `AquariumCore`、`JellyfishSkin`（只读钟罩位置） |
| `css/aquarium.css` | 托盘、居民列表、网兜样式 | 无 |

- **宿主接入点只有两处**：`drawJellyfish` 中在水母 `frame` 之前先调鱼层（鱼在水母后面）；`tryGrab / endGrab / cancelGrab` 增加鱼的路由。宿主仍是唯一 RAF。
- **鱼读水母，水母不读鱼**：`JellyfishSkin` 只新增一个只读接口，返回各钟罩的 `{x, y, r}`；水母行为不变。
- **设置**：界面名称改为“水族馆”，内部 `visualEffect` 仍为 `jellyfish`（旧设置兼容）；新增布尔开关 `aquariumFish`（`backgroundExperienceSettings`，只有明确 `false` 才关）。没有放入过鱼时零绘制。
- **新增后台加载**：无。鱼层只在首页，不进 `js/background.js` 的 `importScripts`。
- **存储**：`chrome.storage.local` 的 `aquariumV1 = {v:1, fish:[{id, species, addedAt}]}`，不存位置，重开时随机入场。

## 5. 鱼与行为

- **起步 8 种，鲨鱼进图鉴**（用户整理的素材里 28/50 是鲨鱼）：
  - 群居小鱼：霓虹灯鱼、蓝吊（一次放入一小群，约 5 条，算 1 个条目）。
  - 单条：小丑鱼、河豚、神仙鱼、小锤头鲨（卡通圆润，参考 #2、#12 的锤形头部与摆尾）。
  - 大型（同屏合计最多 2 个条目）：蝠鲼（参考 #1、#45、#47）、鲸鲨（带斑点，参考 #1、#23）。
  - 鲨鱼原先只是性格温和的居民，**没有捕食行为**（见 2A 节，避免“鱼被吃掉”与“只有捞出才是移除”冲突；2026-10-19 起用户要求规划捕食，设计稿见 `2026-10-19-aquarium-predation-design.md`，2026-10-20 已实现：**只有小锤头鲨捕猎小鱼，鲸鲨与蝠鲼不捕食，水母不会被吃**，见 `docs/technical/aquarium-predation-20261020.md`）。
  - 具体尺寸、速度、群游参数在实现计划里定。
- 画法：鱼身是 3 到 4 节脊柱链，摆尾由正弦波驱动，转弯时弯身（参考 #11、#13）；远处的鱼降低绘制细节（参考 #26 的 LOD）。
- 行为：同种群游（分离/对齐/聚合）、避开快速移动的光标（沿用水母“指针快于阈值才惊动”的规则）、避开水母钟罩、边界回推、纵向分带。**纵向分布必须有测试**：水母曾因推力无高度反馈而 84% 的时间挤在屏幕最上方，鱼不得重蹈。
- 主次：鱼比水母小一档、更淡，深度在水母后面，不画任务名。
- 数量分两层管：**条目**（用户放入的单位）总数上限 12、省流量 6；**渲染条数**（群居种每个条目含多条）上限 40、省流量 16。具体数字必须在真实 Chromium 里测帧耗时后确定，不得凭估算写死。
- 夜晚荧光复用 `JellyfishCore.nightAmount` 与现有 `jellyfishNight` 开关，不新增曲线。
- 不新增权限、网络、依赖、CDN。

## 6. 放入与捞出

- **放入**：背景底部一个小按钮，点开横向图鉴托盘（真 DOM，可键盘操作，有读屏文字）；点一种鱼，从托盘位置游入。达到上限则按钮禁用并提示。按钮位置在实现时看真实截图后定，避免与 Dock 重叠。
- **居民列表**：托盘里列出当前每条鱼，每条有“捞出”按钮——键盘、触屏、找不到鱼时的等价操作。
- **捞出（手势）**：在空白背景按下鱼，拖过约 6 px 后出现**网兜区**，松手落在网兜内即移除并写存储，随后那次 click 被吞掉；落在网兜外则放回。Esc、失焦、`pointercancel`、页面隐藏、关闭皮肤或总开关只放开，不捞出。已提交的捞出不可撤回。
- **与“抓水母完成任务”的优先级**：重叠时**水母优先**，保持现有行为。`tryGrab` 先问水母，没命中再问鱼；抓取状态记录对象类型，松手与取消按类型路由；一次只抓一个，所以纸篓与网兜不会同时出现。
- 不抢任务条、卡片、Dock、时钟文字的点击；悬停鱼时光标变 `grab`。

## 7. 错误处理

- 读取存储失败或数据损坏：显示空水族馆，**不覆盖**原数据。
- 种类不在白名单：丢弃该条；超出上限：截断。
- 写入失败：回滚到写入前的状态并提示，不假装成功。写入经串行队列“先读最新值再改”，避免多标签页互相覆盖。
- 画法抛异常：只停掉鱼层，水母不受影响，并留一条警告。
- 水母皮肤未加载或被关闭：鱼层不画，托盘不显示。

## 8. 测试与验收

- 纯逻辑：群游不出界、纵向分布不堆在顶部、避开钟罩、数量上限、随机种子可复现。
- 控制器：存储、时钟、随机数全部注入；放入、捞出、取消、写入失败回滚。
- 接入层：源码扫描（无 `innerHTML`、网络、自建 RAF、内联事件处理）；宿主路由（水母优先、各取消路径）；`?v=` 版本钉子与 `test/csp-no-inline-handler.test.js`。
- 变异检查：对群游边界、优先级、上限、写入回滚逐个做，只改 `/tmp` 里的副本。
- 真实环境：真实 Chromium 的 HTTP 预览里看截图并测分布。**不能声称已验收**：品牌版 Chrome 156、真实 GPU、触屏、长时间占用、真实账号数据。
- 交付时新增 `docs/technical/aquarium-20261017.md`，并同步 `AGENTS.md`。

## 9. 不做（YAGNI）

喂食与点击冲击波（#43、#44）、拉鱼尾（#37）、布景（珊瑚、海草，#43）、稀有来访者（海龟、海豚，#32）、捕食行为（#3，当时写“永久不做”，2026-10-19 被用户推翻、改为规划，2026-10-20 已实现，见 `2026-10-19-aquarium-predation-design.md` 与 `docs/technical/aquarium-predation-20261020.md`）、捞出后的收藏/鱼篓、任务解锁稀有鱼、桌面水母里的鱼、真 3D 鱼（2026-10-20 按用户要求调研了 three.js 等库，结论仍不做；侧视大鱼转身改用零依赖的伪 3D 投影，见 `docs/technical/aquarium-yaw-20261020.md`）、保存鱼的位置。
