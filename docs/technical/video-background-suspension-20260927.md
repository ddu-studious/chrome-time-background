# 视频工作台的首页背景暂停

日期：2026-09-27

## 问题与范围

观看 B 站视频时，首页被工作台覆盖但标签页仍可见。旧背景 Canvas 循环仅检查 `document.hidden`，持续请求 RAF；视频壁纸也只随标签页隐藏暂停。静态皮肤甚至关闭背景效果后仍逐帧清屏。工作台打开后没有暂停背景 CSS 动画或自动壁纸轮换。

诊断时实际页面为 1080P、2 倍速、关闭弹幕。GPU 驱动 5 次读数为 89%～90%，Chrome 图形进程及 WindowServer 持续活跃；这是整机统计，不能直接归因于扩展，也不是本次优化的降温或功耗对照结果。

## 复用与实现

- 复用现有 `bili-panel-open`、`youtube-workbench-open` 状态，不修改视频控制器及 B 站完整页面的嵌入方式。
- 复用浏览器原生 Page Visibility、MutationObserver、requestAnimationFrame/cancelAnimationFrame 和 HTMLMediaElement.play/pause；没有新增 SDK、依赖、权限或后台模块。
- `main.js` 仅观察 body 的 class 属性，按“标签页隐藏或任一视频工作台打开”计算暂停状态。同状态通知直接返回，状态类自身变化不产生循环调度。
- 暂停时只操作 `#background-video`、背景体验实例及专用 CSS 类。视频壁纸保留来源和播放位置；暂停期间跳过定时轮换，不累积补执行。两种工作台重叠时，直到全部关闭并且标签页可见才恢复。
- 移除壁纸的原生 autoplay，由同一可见性判断启动；异步背景加载在工作台已打开时也不播放。play 代次隔离旧请求，暂停导致的 AbortError 不触发静态降级，当前来源真实失败仍回退静态图片。
- 背景体验保留单条可取消 RAF。静态皮肤与关闭效果时没有空转帧，液态、动态天气和主动手势仍能启动；暂停清理未结束的指针手势，恢复重置帧计时。
- 专用 CSS 隐藏被遮挡的背景层，并暂停背景颗粒与首页两条滚动轨道的动画。前景视频、音乐 Offscreen 与助手朗读保持各自生命周期。
- 页面资源版本升级为背景 CSS/JS v4、main.js v13。已有页面需刷新后加载新代码；本轮未强制刷新正在播放的视频。

## 验证

- Node VM 执行实际背景脚本和 main.js 背景段：覆盖打开/关闭、两工作台重叠、标签页隐藏、初始化竞态、异步 play 失败、来源切换、轮换、静态/动态效果切换及恢复进度。调度替身确认暂停后无待执行 RAF，模拟 60 个刷新机会不增加 Canvas 清屏调用。
- 定向背景、视频入口、B 站及 YouTube 回归共 86 项；背景 Demo、地区过滤、音乐、朗读及控制台回归共 78 项，合计 164 项通过。
- 修改 JavaScript 的 `node --check` 与 `git diff --check` 通过。
- 尚未验证真实 Chrome 重新加载后的 GPU/温度下降、真实视频壁纸解码恢复及账号播放器交互。Node 替身结果不代表实机功耗验收；未运行真实模型、未操作播放队列或账号。

## 后续实机对照

刷新应用页面后，固定同一视频、1080P、2 倍速及窗口尺寸，在应用内和 B 站原页分别采样。应用内还应核对背景是否静止、关闭工作台后是否恢复，并验证切换到其他标签再返回时不会提前恢复背景。记录整机 GPU、Chrome CPU 与热状态，区分其他程序负载；没有该对照前不宣称具体降温幅度。

## 安全自查

本次新增逻辑只读本页状态并控制固定的背景元素；没有新增外部请求、动态 HTML、身份/权限、存储、文件或秘密处理路径。观察器范围限定为 body class，RAF 可取消且不会并行积累，旧异步失败受到代次校验。本次相关差异未发现新增安全风险。
