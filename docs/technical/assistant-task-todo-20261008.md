# 任务 Todo：属性分组、参数合同与保存幂等

## 原因

2026-10-08 的“Blender 学习 + B 站搜索链接 + 换行截止时间”在 Todo 分析阶段两次失败，尚未调用 `task.create`。本机模型的首次 JSON 使用了不存在的 `note` 和 `due`，恢复后仍使用 `note`。真实字段为 `title/description/priority/dueDate`。

分析目录原来只提供工具标题和枚举，没有提供字段名，也没有加载任务技能的字段与日期说明。原文按每个换行生成独立来源，要求每个来源都对应目标，使截止日期被拆成第二项新增任务。未知字段和禁止预填引用共用“不能预先指定引用或版本”的错误，没有向模型指出可修正的具体字段。

两次规划均先发生30秒低思考超时，再由既有关闭思考路径取得 JSON；最终失败原因是参数校验，恢复第二次同类失败按原规则停止。后一次用户输入成功保存了一条任务，本次没有重新执行该真实任务。

## 修改与复用边界

- `AssistantTodo.create()` 仅对任务应用或 `task-add` 将前一来源之后明确以冒号标注的截止时间/日期、优先级、描述、备注和链接合入同一来源。完整 `goal` 不变，属性文字及分隔符保留。普通独立任务行仍拆分，其他应用、来源覆盖和12项上限保持原规则。未说明归属的属性不能凭空附加；自由语义和同一行内的多目标仍由模型分析。
- `AssistantTodo.completionFields()` 从唯一的 `AssistantContract.tools` 投影验收字段，排除 `ref/expectedRevision/projectRef`。服务分析目录复用该投影，并加载已有任务技能与本地日期，明确 `description` 和 `dueDate` 的字段/格式。验收参数可为空，不要求提前构造执行参数；执行阶段仍经过完整工具合同。
- `definitions()` 将未知字段、运行时引用、类型、长度和枚举错误区分反馈，包含条目编号、工具和允许字段。未知字段仅回显有界 ASCII 标识符，其他字段文字用占位符代替，不回显参数值。仍抛出 `ASSISTANT_PLAN_INVALID` 并进入原 Engine 的恢复预算，没有别名自动转换、放宽校验或新增重试通道。
- 回归发现 `task.create/worklog.create` 的保存 ID 原来使用每轮重置的 `task.index`，第二个目标会碰撞为第一条已有记录。现以当前 Todo 编号生成稳定 ID，复用 `QuickCapture.append()` 的写入和回读核对。不同目标分别写入，同一目标重复调用不重写；旧无 Todo 路径沿用原下标。副作用标记、取消、版本、unknown 和12工具/12轮/5分钟边界不变。
- 新规则仅用于建立新 Todo；不会改写已经安装的清单、完成回执或既有任务数据。

本次没有新增依赖，也没有新模型入口、业务工具或摘要引擎。复用本仓库 Contract、Todo、Engine、Gateway 与 QuickCapture。现有上游仍为锁定的 MIT 许可 `@earendil-works/pi-coding-agent@0.85.1`，本次不新增 SDK 调用；公开 Todo 能力的核验与不适用证据见 [原 Todo 技术说明](assistant-todo-tips-20260928.md)。审批和压缩继续使用原公开 API。
