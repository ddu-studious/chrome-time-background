# 第七轮：可连续体验的海洋陪伴 Demo

2026-10-23。用户确认“小鱼清爽自然，水母柔软淡彩、带少量梦幻感，可切回自然版”，并要求继续 demo。本轮沿用 V6 美术、V5 鱼体净空与导航，将单体对照整理为可直接游玩、可随时返回观察的隔离体验。正式首页、背景配置和真实任务数据不改。

## 这轮交付与复用

1. 默认打开自然游动：原有六条小丑鱼的总长分别为 2.5、3.2、4.0、4.8、6.0、7.4 cm，保留同一物理档案。任务水母使用 V6 淡彩柔软材质；固定造景默认关闭。
2. 底部快捷操作提供自由水域、浅礁漫游、动物近景、喂食和沉浸观察。浅礁与自由水域调用现有 `setScene/setMode/setReef`，不重新建立 World、不删除居民、不重建任务。近景仍可选择鱼与水母对照、自然版与轻动漫版。
3. 喂食直接复用本仓库 `AquariumPlay.mountFeed` 公共接口，沿用点击、拖动、Esc、失焦、pointercancel、禁用时取消及松手后吞掉重复 click 的交互。没有另写一套拖放喂食控制器。按钮与跟随饲料样式复用原 `css/aquarium.css`。
4. 沉浸观察隐藏设置、任务列表和标题，保留时钟、任务水母、底部操作与操作反馈；按钮或 Esc 可返回。未增加全屏色层、自动镜头、独立动画循环或常驻特效。
5. 追逃与体型实验折叠到单独区域，仍明确说明会重置为两条演练鱼。固定造景开关和20–42%范围位于常用设置。快捷切景保留镜头距离和范围，避免替用户覆盖观察选择。

继续固定 Three.js 0.180.0、Yuka 0.7.8、three-mesh-bvh 0.9.16、esbuild 0.28.1 和原 Deskworlds 提交。无新增依赖。`mountFeed` 来自当前仓库公开导出，只有交互与展示，不读写存储、执行工具或访问网络。

## 数据与交互路径

`AquariumPlay.mountFeed` → `api.feed(screen|null)` → `foodDropPoint`（拖动时）→ 原 `OceanWorld.feed(point)` → 固定步长 World 觅食/口部距离与视线判定 → `stats.eaten` → 界面计数。

点击保持原上方随机撒食；拖动使用现有相机平面投影到中层水域（参考 z=0.3m 的朝向相机平面），不改变鱼的大小或位置。屏幕坐标须有限且在视口内，投影须在原水域边界留4cm余量；使用既有 BVH `firstHit` 拒绝礁石后方投放，`clearCorridor(p,p,0.038)` 检查整个随机散布范围。原散布每轴最大2.5cm，加上2mm粒子半径，小于3.8cm。

鼠标在面板、快捷栏、按钮、链接或任务纸篓界面上松手，由原组件取消，不投食。暂停、非自然观察、场景载入中、停止/失败或没有活跃小丑鱼时禁用按钮；执行入口再次检查宿主状态。投放成功仅表示食物已创建，不能替代实际吃到的计数。仍使用原冷却、24粒上限、寿命和摄食规则；没有修改 `world.mjs`。

`enterExperience` 只编排已有 View：进入浅礁先成功取得原完整场景资料，再回自然模式并开启造景；若加载失败或 disposed，不报告进入成功。载入期间暂时禁用会冲突的场景/尺寸控件。场景改变仍按原规则清路线、核对合法位置和结束旧追击，因此“保留居民”不等于保留每条旧路线或保证位置完全不动。

任务路径仍是 `BackgroundExperience` → 原 Jellyfish Core → `memoManager.completeTaskById` 演示替身 → 原成功/失败回执。新增快捷入口不写任务。完成水母任务后切景也不会重置成未完成；只有“重置演示”刷新页面恢复初始内存数据。

## 验收与后续落地

本轮结果、截图、构建和源码指纹以[第七轮验收记录](../../../output/aquarium-review-20261023/reef-3d-v7/RESULTS.md)为准。V5 的36组体型矩阵没有在本轮重跑；动物顶点、动作、World、导航与碰撞源不改，不能把旧矩阵标为本轮新测。

此阶段解决实际体验入口和投喂手感，未新增鱼模型、水母物理位移、自然共栖群落、年龄推断或流体模拟。3D水母仍由任务核心控制屏幕位置；透明材质没有真实 DOM 壁纸折射。程序化参考动物仍需用户审美验收。

安全自查：仅隔离demo和资料；固定本地组件与资源白名单、textContent输出、有界饲料与原任务回执，无新增权限、依赖、外部请求或真实数据写入。
