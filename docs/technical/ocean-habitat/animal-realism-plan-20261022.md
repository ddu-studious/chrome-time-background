# 海洋动物外形与动作写实化方案

执行更新：用户已授权并完成[第四轮单体对照样板](implementation-v4.md)。P0 对照工具、P1 身体动作、P2 视觉适配和 P4 水母样板已在隔离页实现；随后[第五轮](implementation-v5.md)完成新版包围与有限前视连续绕行；真实参考标定和 P5 自然群落仍待完成。下面保留方案形成时的核查依据。

用户体验完整浅礁 demo 后确认：**外形和动作都需要改善**。本轮只读核查现有源码、已有截图和一手资料，保存下一轮方案；没有修改运行代码、下载模型、安装工具或重新执行原型测试。V3 的导航验收不等于动物写实验收。

目标仍是隔离原型。正式首页、原背景、真实任务数据保持原样；保留造景开关、喂食、拖拽与任务回执。先做可比较的单体样板，通过后再扩展群落。

## 1. 已确认的原因

下列路径相对 `test/demos/reef-3d-lab-20261021/`，行号为 2026-10-22 工作区读取结果。旧视觉证据见 [V3 截图](../../../output/aquarium-review-20261021/reef-3d-v3/full-reef-final.png)。

| 观察 | 证据 | 对真实感的影响 |
|---|---|---|
| 小丑鱼转弯弯身输入未使用 | `world.mjs:209` 固定 `f.bend=0`；`view.mjs:136` 已传入；上游 `fish-model.js:572–585,805–806` 支持弯身与胸鳍划动 | 整条鱼转向，身体缺少随转弯改变的姿态 |
| 完整礁区采用停下再转向的保守规则 | `world.mjs:182` 航向差超过 0.08 rad（约 4.6°）将速度设零；`199–206` 检查原地旋转 | 易出现停、转、走的节奏；不能只删掉这条规则，否则原来的净空保证会改变 |
| 身体动画主要由单一速度强度控制 | `world.mjs:208–209` 相位、尾幅、胸鳍都由 effort 计算，尾幅至少 0.012 | 悬停、滑行、巡游、急转缺少清楚的动作差别 |
| 尖吻鲈为静态资产加尾部 shader | `view.mjs:110–122` 无骨骼动画混合；`world.mjs:82–88` 捕获后暂时离场 | 身体、各鳍、嘴部缺乏协作；可保留作追逃测试资产，不能作为写实捕食成品 |
| 同种体型仍是同一网格等比例缩放 | `view.mjs:129`；`catalog.mjs:11–13` 固定宽深比例，阶段和年龄未知 | 有大小差别，尚无幼体/成体形态证据；不能仅按大小标注年龄 |
| 水母是通用几何组合 | `jelly-3d.mjs:8–19` 规则钟罩、圆环与 12 根管；`31–36` 固定前景投影、钟罩整体缩放 | 缺少物种特征、伞缘局部卷曲、口腕层次；身体脉动和位移并非同一生物推进模型 |
| 当前物种组合服务行为测试 | `catalog.mjs:6–7`、原型 `README.md:34` | 小丑鱼与尖吻鲈追逃不代表已还原自然浅礁群落 |

现有小丑鱼确实是有体积的模型，且上游已包含眼、鳍、程序材质和身体变形。应先核对参考、接通已有能力，再决定哪些资产必须更换。提高面数、增加发光或切换引擎不能单独解决上述问题。

## 2. 外形、材质和尺寸的目标

**小丑鱼先固定为上游对应的 Amphiprion percula。** 用同物种的侧面、正面、俯视参考检查头身关系、吻部、眼位、背腹鳍轮廓、尾柄、体厚和条纹。澳大利亚博物馆提供该物种的识别、分布、宿主海葵和照片；它同时区分外观相似的 A. ocellaris，不能混用两种名称。[物种资料](https://australian.museum/learn/animals/fishes/eastern-clown-anemonefish-amphiprion-percula/)

照片、影片用于观察和比较，网页可访问不代表可以把媒体打包进产品。体型测量需要来源中的长度定义；不把未说明 TL/SL 的数值直接当作模型总长校准。

材质先用中性光检查，再放回现有背景：鱼体、眼睛、鳍膜分别调整粗糙度、反射和透明程度；检查法线、纹理色彩空间和不同视角的高光。减少整只动物统一发光、统一塑料光泽。近景资产优先选择有正确轮廓、拓扑和可编辑绑定的模型，纹理清晰不能弥补错误形体。

个体保存稳定体长，沿用米制世界和相机投影。头身比、体厚、鳍形与条纹的变体必须受物种参考约束，不逐帧随机改变。没有年龄资料时继续标为小/中/大体型；真正的幼体与成体需要对应形态资产或经过参考校准的形态插值。

**任务水母建议先选海月水母属 Aurelia 作为形态样板，具体物种待资产确认。** 参考重点为薄而有层次的伞体、内部组织、中央口腕与短的伞缘触手。现有长细管造型不能直接换名为海月水母。若以后选海刺水母，则须另按其长触手与褶皱口腕建立档案。[海月水母与近景参考](https://www.montereybayaquarium.org/animals-the-ocean/animals-a-to-z/moon-jelly)、[海刺水母结构参考](https://aquarium.org/animals/pacific-sea-nettle/)

任务水母仍承担可读、可拖拽的界面功能，前景显示尺寸不冒称生态物理尺寸；将来加入自然水母居民时再使用伞径、栖境和米制位移。当前 DOM 壁纸不在 Three 的透射缓冲中，继续采用透明合成，不能以全屏不透明海水背板换取折射效果。生图仅辅助外观探索，不作为三维拓扑、骨骼或生物形态正确性的证明。

## 3. 动作与导航如何配合

继续由现有 World 拥有位置、速度、姿态、追逃状态；增加一层有限的“运动状态 → 身体动画参数”适配。渲染器不能再积分一份位置，也不能让动画片段的根位移绕过碰撞。

| 动作 | 下一轮要呈现的变化 | 驱动依据 |
|---|---|---|
| 悬停与警戒 | 小幅胸鳍调节，身体稳定，尾部活动较弱 | 当前速度、行为状态，后续用本物种录像校准 |
| 巡游与滑行 | 有推进、有收尾滑行，节奏连续 | 实际速度/体长、加速度；相位连续累积 |
| 转弯与绕礁 | 身体弯曲、胸鳍配合，提前减速后沿可行弧线移动 | 有符号角速度、曲率与身体长度 |
| 受惊与逃离 | 有限时的加速与转体，随后回到持续游动 | 已有威胁状态与有界动作时长，不每帧重新抽动作 |
| 躲藏与探出 | 进入后悬停，探出时逐步加速，身体方向与出口一致 | 已有 refuge/hide/emerge 状态 |

首先使用 Deskworlds 已公开的 `bend / tailAmplitude / pectoral / rowing / phase`，不访问未导出的材质工厂、不改 vendored 上游。`bend` 从实际接受的转向估计并做限幅和平滑；滑行可降低尾幅，但是否归零及持续多久需按物种和参考校准。普通转弯弯身不宣称已经实现生物学 C-start。

**连续转弯必须与净空一起修改。** 对原 A* 路线做有界的转弯预判与圆滑连接；只有弧线路径及整个身体姿态可通过现有 BVH 检查时采用。弯身、鳍摆和换模型会扩大包围范围，应先更新保守运动包络，再筛路线和验证姿态。狭窄处允许减速、悬停和调整方向；不能把“任何情况下不停顿”作为验收条件，不能只平滑视觉让鱼身穿礁。

此门槛从 P1 接入弯身时就生效。当前 `spatial.mjs:41–46` 的刚性胶囊不会自动感知 shader 变形：P1 可先在无障碍单体对照中验收；进入任何带礁场景前，必须证明现有包络覆盖全部允许变形，或先更新包络及路线筛选并完成窄缝回归，不能等到 P3 才处理。

鱼类运动研究表明，三维鳍与身体的协作具有物种和动作差异；这些论文用于确立观察维度，不能把其他鱼种的频率和速度直接复制给小丑鱼。[三维鱼类运动研究](https://journals.biologists.com/jeb/article-pdf/211/2/187/1263462/jeb008128p187.pdf)

水母采用“收缩—舒张—间歇漂移”的连续相位，伞缘形变、口腕/触手滞后由同一相位和运动方向驱动。研究支持分阶段的钟罩运动与相间推进，但本项目下一轮只做参考驱动的动画近似，不求解真实流体涡环。[Gemmell 等，2013](https://pmc.ncbi.nlm.nih.gov/articles/PMC3816424/)

任务水母第一步只改善形态和局部形变，位移仍由原 Core 控制；“推进与位移耦合”须另有显式运动注入接口并通过拖拽、投篮、等待、失败、取消回归后才启用。不能在视觉适配中偷偷修改任务核心状态。自然水母居民未来则由米制 World 统一驱动。

## 4. 可复用能力与资产候选

本机已锁定 Three.js `0.180.0`、Yuka `0.7.8`、three-mesh-bvh `0.9.16`，Deskworlds 为 `335d6c1aeb59b338b1cc59d734dc6eb87a596a88`。本轮核对了已安装 Three 的公开 `GLTFLoader`、`AnimationAction.crossFadeTo`、`SkeletonUtils.clone`；后两项尚未接入当前动物。无需为骨骼播放先升级引擎或增加新运行依赖。

## 6. 如何证明改善

- **外形**：同体长、同相机、同光照下保存正/侧/俯视与转身对照；参考为真实动物独立来源。自己的程序模型对照自己的投影，只能验证几何一致，不能验证生物写实。
- **动作**：观察悬停、慢游、加速、左右转、躲藏、探出完整过程；保存可复查的浏览器演示与位置/速度/角速度/动画参数轨迹。真实参考的动作节奏和关节配合由人工对照，测试通过不能替代视觉评价。
- **尺寸与碰撞**：沿用 2.5/4/6/7.4 cm 小鱼和 18/25/45 cm 捕食者测试档位；这些是工程矩阵，不是年龄标签。记录每个模型与动作的保守包络，复验 36 组、喂食、抓取、遮挡、关闭造景及隐藏后恢复。
- **性能**：同设备、Chrome、分辨率、相机和背景，分别记录 8/20/40 条鱼及 1/3 只任务水母的帧间隔、CPU 提交耗时、纹理/几何量与释放情况。优先通过少量近景动物，随后才考虑远景简化；不能假定 InstancedMesh 自动支持独立骨骼动画。建议沿用 30 fps 目标并比较 P95，实际预算须用同条件新旧测量决定，不沿用旧样本宣称新模型达标。
- **交付**：新版证据放独立目录，保存源文件与最终构建指纹、对照图/演示、测试输出、资产清单及未验收项；旧版结果保留。本轮没有产生这些新版验收证据。

## 7. 本轮结果与边界

完成：源码原因定位、已安装公共 API 核对、官方生物与动画资料检索、候选资产目录、分阶段方案。未完成：候选文件取得/许可最终核验、真实影片逐帧测量、新动物建模或绑定、新动画实现与浏览器验收。本轮未重跑 V3 的 35 项原型检查、333 项相关回归或 36 组矩阵，旧结果只能对应原版本。

安全自查：仅更新文档；方案沿用现有任务权限与回执边界、唯一世界状态及有界碰撞检查，要求本地可追溯资产与资源限额；未新增接口、网络权限、依赖、运行配置或真实数据写入。
