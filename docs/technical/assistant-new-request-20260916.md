# 快捷助手待命与快速新需求

## 使用体验

- 成功后约 1.8 秒收成“需求名称 · 已完成”回执，输入框保持可输入。正在查看结果时不会强行收起；回执按钮可手动展开/收起。
- Enter：明确的独立搜索、创建提醒、切换应用等自动开启新会话；序号、代词、修改、翻页、当前播放控制继续原会话。不确定表达保留上下文。
- Cmd Enter / Ctrl Enter：原子地新建会话并发送当前输入，优先于建议菜单补全和候选选择。Shift Enter、中文输入法组合状态不触发。
- 新需求成功受理后才清空输入。空输入、无效应用或旧版本提交不会先清空旧会话；执行中不会因快捷键取消或重放当前动作。
- 输入旁显示“新需求”或“接着上次”，提示本次普通 Enter 的行为。
- 自动继承的应用/动作与用户本次显式选择分开：旧“音乐”标签不会拦截“明天九点提醒我开会”。用户本次明确输入 @应用 或选择动作仍生效。
- 新会话不继承上一项的候选、执行观察、待执行计划或业务草稿；会话历史按原留存设置保留，也不会停止已有播放或删除已保存提醒。

## 实现与边界

`AssistantContract.routeRequest` 是 UI 提示和后台路由的共同纯函数，使用本地保守规则，不增加一次模型请求。普通业务规划仍走已有统一 AI 网关。

显式新需求和明确跨应用优先；同一应用下的独立查询或新建动作也新开。引用性表达继续当前上下文。无法明确识别为独立需求的表达默认继续，可以用快捷键强制新开；并非声称任意自然语言都能准确分段。

`assistant-engine.js` 在提交锁内创建新任务并分配会话 ID，记录旧会话结束事件；快捷键不会采用“先清空，再提交”的两次请求方式。

`assistant-timeline.js` 维护待命回执及展开状态。候选、对话和轨迹仍然留在当前会话，可从回执展开；输入新需求后才切换。
