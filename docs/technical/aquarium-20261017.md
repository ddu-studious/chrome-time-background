## 1. 做了什么

首页“水族馆”背景（设置里的视觉风格，取值仍是 `jellyfish`；第一版叫“深海水母”）里可以放入小鱼，也可以捞出。水母仍是主线、仍是唯一与任务挂钩的东西；鱼只是装饰：不绑任务、不吃水母、不读写任务数据。

- **放入**：右下角（背景玩法按钮正上方）一个小鱼按钮，点开托盘，点鱼种名放入；托盘里同时是“居民列表”，每条带“捞出”按钮（键盘/触屏的等价路径）。
- **捞出**：鼠标按在空白背景上的一条鱼，拖过 6 px 后屏幕下方出现“拖到这里捞出”的网兜，松手在网兜里就捞出；松在别处、Esc、失焦、`pointercancel`、页面隐藏都只是放开，鱼原样放回。
- **8 种鱼**：霓虹灯鱼、蓝吊（成群，每条目 5 条）、小丑鱼、河豚、神仙鱼、小锤头鲨（单条）、蝠鲼、鲸鲨（大型，合计最多 2 个条目）。鲨类性格温和，没有捕食。
- **上限两层**：条目 12 个（省流量 6）；渲染条数 40（省流量 16）。托盘显示“已放 n/上限 · 大型鱼 m/2”，放不下时按钮禁用，并在面板里直接写明原因（`full/large/render`，第二轮 §5.5）。
- **行为**：同一条目内的鱼做群游（分离/对齐/聚合）；每个条目有“家”，家在本种的纵向带里，只在越界时才有回推力（避免像早期水母那样挤到屏幕顶端）；单条鱼在“家”附近缓慢漂移而不是绕着家打转（第二轮 §5.1）；软/硬边界；指针快于 240 px/s 时惊动鱼（与水母同一规则）；避让水母钟罩；深度 z 决定大小、速度、命中顺序与透明度；转弯时鱼身略弯，朝左朝右的翻面带滞回与缓动（§5.2）。
- **外观**：Canvas 2D 画在宿主共享画布上，先于水母画（鱼在水母后面）；半透明渐变 + 夜晚微光，复用 `JellyfishSkin.PALETTE` 与 `JellyfishCore.nightAmount`，没有新增曲线。远处/省流量时不画渐变、眼睛与鳍的细节。第二轮重画了小丑鱼、河豚、蝠鲼并微调神仙鱼，见 §5.4（含一个影响全部鱼的发现：宿主画布是 `screen` 混合，深色眼睛原来几乎看不见）。
- **设置**：`backgroundExperienceSettings.aquariumFish`（默认开，只有明确 `false` 才关；设置页“水族馆小鱼”）。视觉风格下拉框里叫“水族馆”，内部 `visualEffect` 仍是 `jellyfish`（旧设置兼容）。关闭只停鱼层，已放的鱼仍保存在本机。

## 2. 结构与边界

| 文件 | 职责 |
| --- | --- |
| `js/aquarium-core.js` | 纯逻辑：鱼种表、条目白名单与上限、世界与群游、避让、命中/抓取状态；不碰 DOM/存储/`Date`，随机数来自 `world.random`，可确定性测试 |
| `js/aquarium.js` | 控制器：存储、托盘与居民列表、网兜、指针抓取状态机、画法 |
| `css/aquarium.css` | 托盘（`z-index:100`，高于右侧快捷操作区的 99）、面板、网兜 |
| `js/background-experience.js` | 宿主只多出：设置 `aquariumFish`、`drawJellyfish` 里先调鱼层、`grab = {id, kind}` 抓取路由、光标悬停 |
| `js/jellyfish.js` | 只新增只读 `bells()` → `[{x,y,r}]`；水母与 `jellyfish-core.js` 的源码不出现 `aquarium`/`fish`（测试守住） |

- **宿主仍是唯一 RAF**：鱼层不自建 RAF/定时器/画布；页面隐藏、被工作台遮挡、减少动态效果时与水母一起停（宿主 `needsAnimation`/`setSuspended` 原有逻辑）。
- **鱼读水母，水母不读鱼**；重叠时**水母优先**（`tryGrab` 先问水母，没抓到才问鱼；悬停同理），一次只抓一个，所以纸篓与网兜不会同时出现。
- **存储**：`chrome.storage.local` 的 `aquariumV1 = {v:1, fish:[{id, species, addedAt}]}`，不存位置；唯一写入点是 `mutate()`（串行、先读最新值再改、写入成功才应用）。读取失败或看到未来版本（`v≠1`）时拒绝写入（`reason:'storage'`），避免覆盖看不懂的原数据；损坏条目只在内存里丢弃、不写回。捞出先让鱼淡出（乐观），写入失败则放回并提示。省流量只限制绘制，不会截断已存条目。`storage.onChanged` 只认 `local` 区。
- **DOM**：只用 `createElement`/`textContent`，没有 `innerHTML`；托盘按钮带 `aria-label`、状态区 `role="status"`。没有 `document` 的环境（受限）下照常运行，拖动开始时因没有落点而放回，绝不在没有网兜时捞出。
- **故障**：画法抛错只停鱼层（`warn` 一次、收起托盘、`isActive()` 为 false），不影响水母与宿主帧循环，也不动存储。
- **没有新增权限、网络、依赖、`importScripts`**；没有第三方代码，参考项目只借创意（#48 剪影景深、#44 光标驱散，均未复制代码；无许可证的 #31 没有使用）。

## 4. 已知限制与后续

- 鱼是装饰，不会自己出现；清空存储键 `aquariumV1` 就是“清空水族馆”（设置页没有单独入口）。
- 托盘按钮位置固定在右下（`bottom:130px`），与右侧快捷操作区、Dock 之间没有按窗口高度自适应；窗口很矮时可能互相靠近。
- 鱼的摆尾是正弦脊柱动画，不是真实游泳物理；锤头鲨、鲸鲨的轮廓仍是简化画法（第二轮只重画了小丑鱼、河豚、蝠鲼与微调神仙鱼）。
- 颜色在宿主的 `screen` 混合下偏暗偏灰：默认强度 65% 时小丑鱼的橙色在青蓝壁纸上偏棕。“鱼比水母淡”是第一版就有的设计选择，没有为单个种类单独提亮；想更鲜艳要整体调 `drawFish` 里的透明度并重看所有种类。
- 托盘面板固定在右下 `bottom:130px`，实测高 404 px（视口 900 / 700 / 620 / 560 px 时上沿分别距顶 366 / 166 / 86 / 26 px），所以视口高度低于约 534 px（404 + 130，按实测高度推算，没有在更矮的视口里实测）时上沿会顶出屏幕，没有做按高度收缩。
- 小而快的鱼不好抓：真实 Chromium 里（最终代码，种子 29，脚本追踪鱼的位置、指针落后约 0.1 秒）移到鱼上按下 31 次，抓中 26 次；没抓中的 5 次里 4 次是鱼游到了日期/任务条/农历文字等页面元素下面（设计上不抢这些点击），1 次是霓虹灯鱼（体长约 15 px）已经游开 39 px。成群小鱼尤其如此（1440×900 下，8 个种子里全部个体的体长：霓虹灯鱼 13.6–17.5 px，蓝吊 18.7–24.1 px；其余：小丑鱼 25.4–32.3、河豚 27.1–34.4、神仙鱼 28.8–36.6、小锤头鲨 47.5–60.3、蝠鲼 81.4–103.3、鲸鲨 110.2–139.9 px）；不用瞄准的替代路径是居民列表里的“捞出”按钮。
- 用户的设计文档里“放入时的游入起点”实现为从托盘按钮位置淡入游出（按钮不可见时随机入场）。

## 5. 第二轮改进（2026-10-17 晚）

回看第一版预览时我列出了若干不足，用户选了六项：单条鱼原地打转、转身时镜像翻面太突兀、网兜把被拖着的鱼盖住、几种鱼不像、入口命名与托盘提示不清楚、再想新玩法。前五项在这一轮做完；新玩法另行讨论，没有写任何功能代码；我同时提出的“遮挡关系”“放一条小船”没有被选中，没做。

数字分两组，口径不同、不要互相比较：**node 仿真**（确定性，逐帧统计，60 帧/秒，除特别说明外是 8 个种子、每个 40 秒），与**真实 Chromium**（无头、软件渲染、真实 rAF，固定随机种子）里录的轨迹。

### 5.1 单条鱼原地打转

- **现象与证据（真实 Chromium，3 条鱼、20 秒、每 50 ms 取样；修复前的轨迹是第一轮代码在同一页面、同一种子下录的）**：

| 鱼 | 朝向转圈占比（> 3 rad/s）修复前 → 后 | 平均速度 px/s 修复前 → 后 |
| --- | --- | --- |
| 小丑鱼 | 69.6% → 0% | 25.4 → 43.5 |
| 神仙鱼 | 42.3% → 0% | 28.8 → 33.2 |
| 小锤头鲨 | 66.7% → 0% | 24.7 → 48.6 |

- **根因（由代码与下面的变体对照得出）**：旧核心把合力向量每帧都归一成满巡航速度（`dvx = sx / sl * speedT`）。“家”近在咫尺、合力只剩残余时，期望速度仍是满速，鱼冲过家、掉头、再冲回来，围着家几个像素转小圈。群居种有分离/对齐/聚合力，合力不会小到只剩残余，所以一直正常（修复前转圈 0.7%–1.3%）。
- **修复**：每个条目有一个缓慢旋转的漫游向量（`WANDER_W 0.7`、`WANDER_RATE 0.45`；相位 `wp` 在条目生成时定下并不再变，同一条目的鱼共用，顺/逆时针由相位决定），并把期望速度从“恒为满速”改成随合力大小连续变化：`gain = clamp(|合力| / STEER_FULL, STEER_MIN, 1)`（`STEER_FULL 0.25`、`STEER_MIN 0.4`）。合力小时慢游，不再冲过家。
- **评估过的变体（小丑鱼，8 个种子 × 40 秒，node）**：目标点绕家旋转——转圈 8.7%、空闲 8%；只加漫游向量——转圈 2.8%，家钉死时 6.0%；漫游 + 朝向转速上限——朝向转圈 0.0%，但速度方向转圈 3.6%、空闲 7%；只做期望速度连续化 + 转速上限——空闲 64%、速度/巡航速度 0.35（鱼几乎停着）；漫游 + 连续期望速度（第一版参数）——转圈 0.8%、空闲 6%、速度/巡航 0.79；最终参数空闲 1%、速度/巡航 0.91。
- **被否决的“只给朝向加转速上限”**：朝向转圈确实降到 0.0%，但速度方向转圈仍是 31.6%–55.2%（小丑鱼 54.5%）、空闲 27%–52%、速度/巡航速度 0.48–0.63，家钉死后离家至多 0.28 倍 `HOME_NEAR`（5 种在 0.01 倍，几乎没离开家）——和修复前一模一样，只是头不转了。对应的两条测试对这个变体真的失败（实测断言信息：“速度方向转圈占比 60% 应小于 5%”“钉住家后速度方向转圈占比 80%”），所以测试同时断言朝向与速度方向的转圈占比、空闲占比、平均速度，以及钉死家时“既不转圈也不停住也不飘远”。
- **node 实测（打转 = 朝向角速度超过 3 rad/s 的逐帧占比；“家钉死”= 把家固定 60 秒、统计后 40 秒）**：

| 种类 | 打转 修复前 → 后 | 空闲帧 修复前 → 后 | 速度/巡航速度 修复前 → 后 | 家钉死时的打转 修复前 → 后 |
| --- | --- | --- | --- | --- |
| 小丑鱼 | 63.0% → 1.0% | 50% → 1% | 0.48 → 0.91 | 96.5% → 0.0% |
| 河豚 | 52.1% → 0.8% | 36% → 1% | 0.56 → 0.95 | 89.7% → 0.0% |
| 神仙鱼 | 55.5% → 0.9% | 40% → 1% | 0.54 → 0.94 | 92.5% → 0.0% |
| 小锤头鲨 | 63.3% → 1.1% | 52% → 1% | 0.48 → 0.89 | 97.3% → 0.0% |
| 蝠鲼 | 49.7% → 0.9% | 37% → 1% | 0.56 → 0.92 | 88.8% → 0.0% |
| 鲸鲨 | 37.9% → 0.8% | 27% → 1% | 0.63 → 0.92 | 75.1% → 0.0% |
| 霓虹灯鱼 | 1.3% → 0.6% | 0% → 0% | 0.92 → 0.95 | 0.1% → 0.3% |
| 蓝吊 | 0.7% → 0.8% | 0% → 0% | 0.93 → 0.95 | 0.1% → 0.1% |

- **复核（最终代码，12 个种子，6 种单条/大型鱼；群居 2 种 × 6 个种子）**：朝向转圈平均 0.7%、最大 2.6%；速度方向转圈平均 0.7%、最大 2.4%；空闲平均 1%、最大 4%；速度/巡航速度平均 0.92、最小 0.82；家钉死时（6 个种子）空闲最大 8%、离家最远 0.83 倍 `HOME_NEAR`（最小 0.57）；群居种转圈最大 2.2%。
- **真实 Chromium 里的整缸复核（最终代码，无头、软件渲染）**：8 个条目（全部鱼种，共 12 条鱼）+ 5 只水母，指针不动，每个种子 60 秒模拟时间（约 65 秒墙钟），种子 7 与 29 各一次，页面没有报错。统计在每次 `Core.step` 之后按模拟时间做（不受帧率影响，约 37 步/秒）：单种“朝向角速度 > 3 rad/s”的步数占比为 0%–1.47%（种子 7：0%–1.16%，最高是鲸鲨；种子 29：0%–1.47%，最高是小锤头鲨），单次连续超过 3 rad/s 最长 0.5 秒，连续超过 1 秒的“持续打转”为 0 次。这些应是正常转身与避让水母（没有逐次归因），和 node 仿真的 0.8%–1.1% 同量级；它只覆盖指针不动的静置状态，指针快速移动时鱼会被惊动、更频繁转向，那是设计行为，不计入打转。
- **副作用，如实记录**：家被钉死时，群居鱼离家的最远距离从 0.81（霓虹灯鱼）/0.94（蓝吊）倍 `HOME_NEAR` 变成 1.94 / 1.71 倍（整群一起漂，不再粘在家上）。正常运行时家每 10–20 秒就换一个，纵向带与边界回推也都还在，所以不是问题；“钉死家”只是测试用的极端条件，群居种也没有对应的离家距离测试。

### 5.2 转身翻面

- **旧画法**：按 `cos(朝向)` 的正负瞬间翻面（现在 `flip` 字段缺失或非法时的回退仍是这个）：朝向在竖直线附近来回晃时一帧一翻。旧核心（打转修复之前）在 96 条鱼·分钟的样本里每条鱼每分钟翻 29.1 次，最短间隔 0.05 秒，其中 584 次与上一次相隔不到 0.4 秒。
- **现在**：核心维护目标面 `flipTo`（±1；`cos` 越过 ±`FLIP_HYST 0.3` 才换）与当前面 `flip`（−1…1，每帧向目标面按 `FLIP_RATE 9` 缓动）；画法对 Y 方向缩放 `flip`，正中间夹在 `FLIP_MIN 0.06`（不让画布矩阵退化）；`flip` 缺失或非法时才按朝向取正负。游动中（含入场）与被抓着时都会更新；离开中（被捞起、被移除）的鱼保持离开前的那一面，不再更新。
- **node 实测（同一批 96 条鱼·分钟：6 个种子 × 8 个种类 × 60 秒）**：打转修复之后，朝向正负的原始翻转本身降到每条鱼每分钟 8.26 次（最短间隔 0.017 秒，20 次短于 0.4 秒）；加滞回后目标面换边每分钟 7.21 次，最短间隔 0.233 秒，短于 0.4 秒的 7 次；当前面的单帧最大变化 0.3（旧画法是瞬间变 2），|flip| < 0.3 的偏薄帧占 0.8%，朝向明显偏向一侧（|cos| > 0.6）且 flip 已稳定时与朝向同侧（翻错面 0 帧）。
- **真实 Chromium**：把朝向从 50° 匀速转到 130° 的模拟转身（蓝吊与小锤头鲨、8 个时刻）新旧画法并排的对照图看过：旧画法在 88°→92° 之间一帧翻到另一面；新画法越过竖直线后仍保持原来的一面（101° 时当前面还是 1.00），到 108° 才缓动到 0.70、130° 时 −0.67。这是用 `Core.updateFlip` 驱动的模拟转身，不是鱼自己游出来的转身。

### 5.3 网兜与捞起动画

- **看不见**：第一轮的网兜内部发暗发糊（磨砂模糊加半透明深色底），鱼是画在网兜下面的背景画布上，被拖进去的鱼被盖住，看起来像消失了（第一轮与现在的真实 Chromium 截图对比过：旧图里光标处看不到鱼，新图里能看到）。现在网兜只是“网线”：没有 `backdrop-filter`，底色 `rgba(139,207,255,.05)`（靠近时 `.1`），网线 1 px、不透明度 `.22`，提示文字单独成胶囊浮在网兜上方。`test/aquarium-integration.test.js` 的 CSS 契约守住：两个状态都不得有 `backdrop-filter`、实心底色不透明度 ≤ 0.16、网线不透明度 ≤ 0.3、网线保持 1 px、标签绝对定位在网兜上方且是圆角胶囊。
- **捞起**：松手在网兜里时，鱼不再原地淡出，而是游向网兜中心：`dismiss(world, id, { to })` 给每条鱼记 `leaveTo` 与进度 `scoopT`（成群的鱼落点在中心附近错开，范围 `SCOOP_SPREAD`＝30 px × 视口缩放的方形，免得 5 条叠成一条）；位置每帧按 `SCOOP_PULL 8`（每秒）向落点靠近；体长按平滑曲线缩小，最终缩小 `SCOOP_SHRINK 0.55`（只剩原体长的 45%）；进度过了 `SCOOP_FADE_AT 0.4` 才开始淡出（总时长 `SCOOP_S 0.6` 秒），先让人看清鱼落进了网兜。网兜在动画期间继续显示（控制器的 `netHold = { world, until }`，`until` 是世界时间，没有定时器；世界重建、动画结束或新的抓取结束时收起）。列表里的“捞出”按钮没有落点，仍是原来的原地淡出；写入失败时鱼被放回（原有行为不变）。
- **真实 Chromium**：真实鼠标把一条鱼拖到网兜上方、拖进网兜、松手，网兜上方、网兜里与捞起动画 9 个分格都截了图，页面没有报错。注意：驱动脚本事先挑的那条鱼（神仙鱼）在最后一次运行里仍活着，而存储条目数从 10 变成 9，所以实际被抓的应是另一条鱼（推断，没有逐条核对是哪一条）；这次运行只能说明“有一条鱼被拖进网兜并被捞起”，不能当作对某条指定鱼的追踪。

### 5.4 鱼的外观

- **重画**：小丑鱼（圆胖橙色身体、3 条带黑边的白带只画在身体里、圆尾、较高的背鳍、胸鳍）；河豚（接近圆球、浅色肚皮、一圈 12 根短刺、小圆尾、胸鳍）；蝠鲼（前缘圆润外展、后缘内凹的大翅膀，两翼同步拍动，头前两片头鳍，细长的尾）；神仙鱼微调（高而向后掠的背鳍与臀鳍围成三角、3 道深色竖纹、腹鳍两根长丝）。霓虹灯鱼、蓝吊、小锤头鲨、鲸鲨的登记数据（站位半宽、尾型）没动，但都用上了下面的平滑轮廓与可见的眼睛。“近处才画”的细节（白带、竖纹、腹鳍丝、胸鳍、刺、头鳍、眼睛）在远处（z < 0.55）与省流量时跳过，测试守住：远处与省流量不裁剪、不建渐变。
- **发现并修复：深色细节在宿主的 `screen` 混合下几乎看不见**。`background-experience.js` 整张背景画布都在 `globalCompositeOperation = 'screen'` 下画，`screen` 只会变亮，深色（眼睛、白带的黑边、竖纹）叠上去几乎没有可见的变化——第一轮的鱼因此看不出眼睛，这是我在放大图里发现的。现在这些暗色细节临时切到 `source-over`（白带块、竖纹块在各自的 `save/restore` 里，眼睛在外层 `restore` 之前），身体与鳍仍沿用宿主的 `screen`，画完还原，不会污染后面画的水母。`test/aquarium-shapes.test.js` 用带 `save/restore` 栈的记录型 ctx 逐种类断言：所有暗色填充/描边都在 `source-over` 下、身体与鳍在 `screen` 下、画完混合模式回到 `screen`。**以后新增任何深色细节都必须这样画**。
- **轮廓更圆**：5 个站位直接连线会得到“六边形”的身体（胖鱼最明显）。现在 `bodyOutline` 对半宽与脊柱按 Catmull-Rom（`smoothAt`，端点复制）平滑插值，沿体长取 11 个点（两头密、中间疏），头部 16% 内半宽按四分之一椭圆收到 0（`noseCap`），鼻子是圆的而不是被竖着切平。这些纯函数（`geometry.{halfAt, spineAt, bandCenters, spineMarks, bodyOutline, noseCap, smoothAt}`）都有单元测试：`smoothAt` 经过每个站位、站位处斜率连续、端点复制、线性数据原样复现；`noseCap` 的四分之一椭圆值；`bodyOutline` 过了头部的半宽就是站位的平滑插值、中线沿脊柱平滑插值、上下对称、沿体长单调、没有明显过冲。
- **图鉴对照（真实 Chromium）**：8 种鱼同屏的图鉴（放大 2.6 倍）改动前后各出一张；重画的四种（小丑鱼、河豚、神仙鱼、蝠鲼）另有放大 6 倍与放大 2.2 倍（z=0.8）的逐种对照；在真实页面（HTTP 预览）里也看过。

## 6. 互动：戳、拉鱼尾、喂食（2026-10-17，第三轮的第一个子项目）

设计规格 `docs/superpowers/specs/2026-10-17-aquarium-interaction-design.md`（含 §11 写计划时的修正），实现计划 `docs/superpowers/plans/2026-10-17-aquarium-interaction.md`。三种互动都是**纯视觉**：不存储、不读写任务数据、不新增设置，水母不受影响，仍是唯一与任务挂钩的；跟随已有的 `aquariumFish` 开关。

### 6.1 做了什么

- **戳**：点一下鱼（按下到松开没拖过 6 px）——这条鱼朝点击处的反方向窜出去（`POKE_DASH` 倍巡航速度，点在正中心 `POKE_CENTER` 个体长以内则沿自己的朝向窜），`SHOCK_R` 范围内的邻鱼被向外推（线性衰减，大型鱼只受 `SHOCK_LARGE` 倍），点击处荡开一圈涟漪，嘴边冒两三个泡；同一条鱼 `POKE_COOLDOWN_S` 秒内不重复。**不吞 `click`**（`drop` 在没拖过时返回 `false`），空白水面的点击与原来一样。
- **拉鱼尾**：按住非成群鱼的**后半身**（鱼本地 `x ≤ 0`，含正中心）拖动——被抓点留在指针下，鱼头朝远离指针运动的方向，尾巴按指针速度被拉长（上限 `min(0.35 体长, 40 px × 视口缩放)`）；松手后尾巴带阻尼回弹一次，鱼朝鱼头方向冲一下并冒泡。拖进网兜捞出时静悄悄收起（没有回弹、冲刺和泡）。霓虹灯鱼、蓝吊（成群小鱼）太小，不做拉尾，按哪里都是普通抓取。按前半身仍是原来的抓取。
- **喂食**：托盘里一个“喂食”按钮——点一下从屏幕上部落下 6 粒，或按住拖到水里松手（落在松手处）、键盘 Enter/空格；饲料下沉、过期（`PELLET_LIFE_S`）、被游着的鱼吃掉（每粒只被吃一次），吃到的鱼冒泡并变亮约 `FED_S = 20` 秒（只是 0…1 的画法数值，不存储）；附近的鱼会朝最近的一粒游过去并加速。同屏最多 24 粒（省流量 8），`FEED_COOLDOWN_S` 内连点被忽略，放不下时状态栏写“饲料还没吃完”。没有鱼时按钮禁用，原因写在居民列表的“还没有鱼”里并由 `aria-describedby` 指向。

### 6.2 结构与边界（复用与自有）

- **没有引入任何第三方库、权限、网络或 CDN。** 弹簧是一个二阶阻尼公式，冲击是速度叠加，吸引点是 `Core.step` 里的一个可选目标；本仓库没有通用物理引擎依赖，这里也不需要碰撞。复用的是仓库已有的东西：`AquariumCore` 的游泳/抓取/命中、`aquarium.js` 的抓取状态机与托盘、宿主 `background-experience.js` 的共享画布与唯一 RAF、`isBackgroundTarget` 的指针路由。
- **自有代码**：`js/aquarium-play-core.js`（纯逻辑：涟漪、气泡、饲料、变亮记录、拉尾弹簧与三种规则，不碰 DOM 与存储）、`js/aquarium-play.js`（涟漪/饲料/气泡的画法 + 托盘喂食按钮）、`js/aquarium-core.js` 的两个钩子（`step` 的 `attractors`、`grab` 的 `tail` 选项）与导出的 `cruiseSpeed`、`js/aquarium.js` 的画法钩子与接线。不传新参数时核心与画法的行为与改动之前逐位一致（黄金轨迹与绘制序列哈希测试守住）。
- **隔离**：玩法层可注入（`env.playCore` / `env.play`），任何玩法调用都包在 `playGuard` 里，抛错只走 `disablePlay`（销毁喂食按钮、丢弃玩法状态、`state().playFailed` 为真），鱼的游动、抓取、捞出、存储不受影响；下次 `start` 再试。宿主 `background-experience.js` 与水母文件没改。
- **状态**：玩法状态（涟漪、气泡、饲料、变亮记录、拉尾弹簧）只在内存里，换 world、停止、出错或鱼全被捞出时丢弃，**不写任何存储键**，也不读写任务、备忘录、设置。
