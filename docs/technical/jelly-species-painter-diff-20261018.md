# 桌面水母物种：绘制层的“画与不画”差分渲染检查

建立在 Step D（`docs/technical/jelly-species-whaleshark-20261018.md`）的离屏语义渲染检查之上。起因是 Step D 的系统性变异检查给绘制层（`desktop-reminder/jelly-species-painter.swift`，**只由渲染检查把守**）的结论是“这一层的检查不够锋利”：270 个通用变异体只杀死 87 个、存活 176 个，手写的 25 个里“高光太亮”“高光没画”“笑线的线帽”存活——渐变色标、描边的线宽与透明度、眼睛/腮红/微笑的几何与透明度、斑点与高光的透明度，都被整只图上的取样点与容差吸收了。用户 2026-10-18 在 Step D 报告后选择做这一项（“给绘制层加‘画与不画’的差分渲染检查，让检查更锋利”），同时选择 Step B 与 Step D 先不提交、由用户看过代码与文档再说，所以写本文时本步骤同样没有提交；之后用户在差分检查的报告后选择把 Step B + Step D + 本步骤合成一个提交，即本地提交 `1b29af1`（**不推送、不合并、不发布**）。分支 `feat/jelly-appearance`（独立 worktree）。

## 做了什么

给渲染检查加了一层“元素”检查：**每个元素单独画一遍**，把它自己画上去的东西从整只图里隔离出来，再逐项量。

| 项 | 做法 |
|---|---|
| 绘制层的接缝（只给测试用） | `SpeciesPainter.draw(…, show: SpeciesVisibility = .all)`：`show` 可以只画某几个部件（`g.parts` 的下标集合）、关掉躯干与肢体的描边、关掉眼睛 / 腮红 / 微笑。**产品里恒为默认值 `.all`**，唯一的产品调用点 `JellyView.drawAnimal`（`jelly-companion.swift:416`）一个字没改；`show` 只影响“画哪些”，不影响放置（放置只看几何的并集包围盒），所以隔离出来的元素与整只图里的位置逐像素对得上 |
| 渲染工具的 direct 模式 | `species-render.swift` 的用例多了 `direct`（不经过 `JellyView`，直接调用 `SpeciesPainter.draw` 画进全透明位图：没有光晕、涟漪、“z”、气泡）与 `show`；清单回报 `direct` 与 `show`，脚本逐个用例核对“请求的与实际生效的一致”（渲染工具忽略了 `show` 就会让“只画一个”的检查拿到整只图，这种情况按基础设施错误退出码 2，不当成检查失败） |
| 检查脚本新增两组 | **元素**：每个部件的形状与透明度（正面与朝左抬头划水两种姿态）、躯干与肢体的描边、躯干与肢体渐变的两端、眼睛 11 种姿态、腮红 3 种、微笑 4 种（只有侧视动物）；**叠层**：各层按绘制顺序叠起来必须等于整只图，直接画必须与产品视图（`JellyView`）画的逐像素相同 |
| 每个动物的条数 | 小锤头鲨 114 → 150、蝠鲼 106 → 142、鲸鲨 128 → 172，全部 **348 → 464 项**；`CHECK_MANIFEST` 多了“元素”（33 / 33 / 41）与“叠层”（3 / 3 / 3）两组，条数是契约 |
| 单元测试 | `test/species-render-check.test.mjs` 39 → 61 项：每个判定函数用合成图像做正反两面验证（真实形状的图判通过；改大小、改透明度、位移、多画、少画、改颜色、改线宽的图判失败），再加一个接线测试；变异检查之后又补了 9 项（见“补强一轮”） |

## 复用与新增（对照 AGENTS.md“优先复用”）

- 没有适用的开源 SDK（AppKit/CoreGraphics 自绘）。**整条验证管线复用 Step D**：渲染工具编译与运行、用例协议、`poseGeometry`（形状数据 → 窗口里的多边形）、`rasterize/dilate/hueOf` 等像素工具、`CHECK_MANIFEST/reportSpecies`、`judges` 注入接缝；没有新增依赖、权限、网络或协议字段，产品的设置键与 `jelly` 回执一个字没动。
- 新增的只有：绘制层的 `SpeciesVisibility` 接缝（默认值不变）、渲染工具的 `direct/show`、检查脚本的元素与叠层判定、`PAINT_SPEC`（见下）与对应测试。
- 变异检查的执行工具（`/tmp`，不入库）加了 `--skipops`（跳过某类变异算子）与按运行器区分的预编译二进制，方法不变。

## 关键决定与理由

1. **用测试专用的 `show` 接缝，而不是“整只图 A 与去掉某部件的图 A−X 求差”。** 差分的直觉做法有两个问题：放置用的是并集包围盒，去掉一个部件会让动物整体挪位，A 与 A−X 的像素对不上；后画的部件不透明地盖在先画的上面，A 与 A−X 的差不是“X 自己”。接缝让“只画 X”与“什么都不画（全透明）”相比，差就是 X 自己；放置因为不看画哪些而保持不变。**接缝没有改变产品输出**：改前基线的 90 张图（三种动物各 30 种用例）与改后逐字节相同（SHA-256 逐张核对，见验证结果）。
2. **直接画与产品视图画的是同一个东西，用“叠层”组证明。** 隔离出来的元素是 `SpeciesPainter.draw` 直接画的，而产品是 `JellyView` 画的；检查要有意义，二者必须一致。“叠层”组有三条：静止与朝左抬头划水两种姿态下，把各个元素的隔离图按绘制顺序叠起来，必须等于整只图（每个预乘通道最大相差 ≤ 3/255；实测 1.74–2.13，来自逐层舍入）；直接画的整只图与 `JellyView` 画的整只图**逐像素相同**。任何一个元素的绘制状态（变换、裁剪、线宽、颜色）漏到下一个元素上，叠起来就对不上。
3. **用“预测光栅”比，而不是用取样点比。** 每个元素的期望 alpha 光栅 = 形状数据（按姿态放好的多边形，4×4 子采样的覆盖率）× 规格里写明的透明度；渲染结果与它比三个量：**alpha 质量比**（大小 × 透明度对不对）、**质心偏移**（位置对不对，单位 pt）、**形状外多余像素**（别处多画了东西）。取样点只能看到几个像素，质量比把整个元素的每个像素都算进来。
4. **填充：每个内部像素的 alpha 都必须在规格范围里，且整体要走到两端。** 躯干填充是 0.93 → 0.97、肢体是 0.92 → 0.95 的竖直渐变，平铺层（腹部 0.92、斑点 0.72、高光 0.40）是常数。内部像素（离边缘至少 2 个像素，避开抗锯齿）逐个核对；另有一条“渐变的两端”：同一角色全部部件的内部像素合起来，最小 alpha 要靠近范围下端、最大要靠近上端。**这一条是变异检查逼出来的**：`NSGradient` 不夹取色标位置（实测色标放在 2，终点颜色只走到一半），把色标 1 改成 2 之后每个内部像素仍在范围里、整体质量也只差一点点，只有“走到两端”看得出来。
5. **描边 = “画描边”的图与“只有填充”的图之差。** 同一个部件分别用 `strokes: true/false` 画，差就是描边自己；它的质量应等于 α × (半线宽 × 周长 × (2 − 填充均值) + π × 半线宽² × 填充均值)——外侧半条带盖在透明处、内侧半条带盖在填充上、圆头拐角的面积在最后一项（第一版漏了最后一项，质量比系统性偏高 1–5%；补上后实测 0.997–1.010）。描边之外（外扩半线宽 + 3 个像素）不能有差；盖在透明处的那一圈要与主色同色相、比填充暗。线宽、透明度、颜色走样都会改变这一项。
6. **颜色只做结构性核对，透明度精确核对。** AppKit 把“calibrated”颜色转进位图时数值会变（实测墨色 (0.16, 0.22, 0.30) 变成约 (0.21, 0.29, 0.38)），拿规格里的原始数字去比绝对颜色会误报；alpha 通道不受影响，所以：斑点与高光必须是白的（最小通道 ≥ 0.97）、墨色必须是深色（亮度 < 0.45）、腮红必须是粉色（色相 350° ± 25°、色度够）、描边与填充同色相且更暗；腹部是唯一核对绝对颜色的（主色向白色靠 0.72，最大差 ≤ 0.06，因为主色本身就在同一个色彩空间里转换）。**所以“只改颜色常量一点点”的变异体不会被抓住，这是有意的取舍**（见已知边界）。
7. **脸的每个元素按姿态算期望形状。** 眼睛：圆（朝向变窄 `max(0.35, |facing|)`、眨眼 `max(0.12, 1 − blink)`、警觉半径 ×1.25、瞳孔偏移 (look.x·1.4, look.y·1.0)）、高光（只在睁开时检查：面积比与质心偏移、比圆更亮）、睡着时的弧（线宽 1.3、半宽 = 半径 × 1.25 × 变窄系数、两端比眼中心高 0.8、控制点在 ±0.6 个半宽、低 2.2）；腮红（粉色椭圆，随朝向变窄）；微笑（1.2 pt 圆头墨色细线；睡着时应什么都没有，被抓住时即使睡着也有）。11 种眼睛姿态覆盖静止、朝左抬头划水、转身途中、眨眼、警觉、瞳孔看向右下、睡着、睡着又被抓住、睡着时转身途中、睡着时警觉、几乎正对；其中三种是变异检查逼出来的：`asleepHalf`（睡着的弧，宽度也要随朝向变窄）——把弧的半宽 `radius * 1.25 * narrow` 里的乘号改成除号，之前没有任何姿态能看出来；`asleepAlert`（睡着时警觉无效，弧不放大）——此前没有姿态让“睡着也放大眼睛”露出来；`turned`（朝向 0.2，低于变窄下限 0.35）——此前最窄只到 0.5，下限 `max(0.35, …)` 里的数字改成 0.20 毫无反应。
8. **`PAINT_SPEC` 是产品画法常量的独立一份。** 检查脚本里的 `PAINT_SPEC`（各层透明度、渐变范围、描边线宽、眼睛/腮红/微笑的几何系数）与 `jelly-species-painter.swift` 里的常量各写一份：改画法要两处一起改，改漏了检查失败——这是有意的“两把钥匙”，不是重复。代价是改美术取值要多改一处。
9. **容差全部来自实测基线，并写明余量。** 一次完整真实渲染下各项的实测范围与阈值（`LIMITS`）：

   | 量 | 实测 | 阈值 |
   |---|---|---|
   | 部件质量比（肢体 / 躯干 / 高光 / 腹部 / 斑点） | 0.995–1.004 / 0.999–1.012 / 0.996–1.005 / 1.001–1.002 / 0.981 | 1 ± 0.03 |
   | 部件质心偏移 | ≤ 0.101 pt（躯干，渐变使质心略偏） | ≤ 0.15 pt |
   | 描边质量比（肢体 / 躯干） | 0.997–1.007 / 1.002–1.010 | 1 ± 0.03 |
   | 眼睛、腮红、微笑质量比 | 0.960–0.992、0.974–0.983、0.970–1.000 | 1 ± 0.055 |
   | 眼睛、腮红、微笑质心偏移 | ≤ 0.041、≤ 0.030、≤ 0.023 pt | ≤ 0.07 pt |
   | 眼睛高光面积比 / 质心偏移 / 比圆更亮 | 0.838–0.932 / ≤ 0.024 pt / 0.331–0.575（取到 ≥ 2 个像素时；只取到 1 个像素的 0.262 不判，见补强一轮第 7 条） | 0.72…1.12 / ≤ 0.05 pt / ≥ 0.25 |
   | 躯干渐变两端（最小 / 最大 alpha） | 0.929 / 0.969 | ≤ 0.942 / ≥ 0.958 |
   | 肢体渐变两端 | 0.922 / 0.949 | ≤ 0.932 / ≥ 0.938 |
   | 叠层误差（每个预乘通道） | 1.74–2.13 / 255 | ≤ 3 / 255 |
   | “z” 到头端锚点的距离 | 13.4–15.1 pt | ≤ 22 pt |

   眼睛的质量比系统性小于 1（0.96–0.99）、高光面积比系统性小于 1（0.84–0.93）：CoreGraphics 对几个像素大的小圆做抗锯齿时，覆盖率偏低；所以这两类用了单独的、更宽的阈值，而不是放宽所有元素。
10. **渲染检查的判定函数仍可被替换（`judges`），元素检查通过 `checkElements` 单独导出。** 接线测试用假判定逐项翻转 `judgeLayer / judgeFillEnds / judgeStroke / judgeEyeImage / judgeBlushImage / judgeMouthImage / judgeComposite`，断言每个检查行的通过/失败来自对应的判定、调用次数等于预期；元素检查导出后不用跑整套检查（整套在空白图上要 23 秒，单独跑 5.5 秒）。

## 补强一轮（变异检查之后）

第一轮变异检查（检查脚本新增代码 652 个变异体：杀死 516、存活 136；绘制层手写 87 个：杀死 76、存活 11）之后只做了**一次、有界**的补强，不再循环：

1. **判定函数的单元测试补了 5 项新测试**（另在叠层判定的测试里加了“只差一个方向的尺寸”），钉住在真实渲染里被别的检查顺带兜住、单独坏掉时没有任何测试会报的分支：只有一个内部像素的 alpha 不对（平铺层与渐变层、偏高偏低各一，质量比与质心都还在容差里，所以拦住它的只能是逐像素这一项），以及小到没有内部像素时不通过并写明；圆里完全覆盖的像素不足 8 个时不估计高光（圆心放在像素角上得到 4 个，放大后够 8 个就估计）；睡着的弧、转身途中的圆画成“不够深”的颜色（形状与透明度都对，高光仍比圆亮）也不通过；转身途中与眨眼时不估计高光面积、只靠对比度，没有高光的画法要被拦住（高光很小，质量与位置拦不住它）；几乎没有颜色的淡粉色不算粉。
2. **睡觉的 “z” 的六个条件抽成纯函数 `judgeSleepMark`**，逐条做反例（每一行只做错一个条件，其余五个仍满足；朝左是镜像；一个 “z” 都没有时质心是 NaN，不通过也不抛错）。这些条件此前内联在 `checkSpecies` 里，第一轮里 11 个变异体全部存活。
3. **脸的姿态表逐项钉住**：检查与渲染用的是同一张表，表自己被改坏（比如把 `alert: true` 改成 `false`）时两边一起变、谁也发现不了；另加“没有形状数据的动物给出名字，而不是一个 `TypeError`”。
4. **删掉死代码**：没有任何调用方的导出 `alphaOf`（6 个变异体存活的来源）。
5. **两种新的眼睛姿态** `asleepAlert`、`turned`（见决定 7），每个动物 +2 项（458 → 464）。**试过又放弃的第三种**：完全闭眼（`blink: 1`）——闭眼的眼睛只剩约 1.2 个像素高的细条，CoreGraphics 的抗锯齿与 4×4 超采样预测相差约 ±7%（三种动物的质量比 0.925 / 0.953 / 1.055，阈值 ±0.055），也取不到一个完全覆盖的像素来判颜色，没有可靠的逐像素判据；眨眼下限 `max(0.12, …)` 改由下面的源码钉子守。
6. **绘制层源码钉子**（`species-render-check.test.mjs`）：`let narrow = max(PAINT_SPEC.eye.narrowMin, …)` 与 `let open = max(PAINT_SPEC.eye.openMin, …)` 里的数字必须与 `PAINT_SPEC` 一致；渐变与七彩两处白色叠层（α 0 → 0.32）必须**同时**还在（数个数）。叠层强度在渲染层没有判据（颜色只做结构性核对），已有的源码绊线也守不住它（见下一节第 2 条）。
7. **高光只取到 1 个像素时不判对比度**（`LIMITS.glintMinPixels = 2`）。补强之后刷新实测基线表时发现：新加的“几乎正对”姿态里，蝠鲼的高光只落在 **1 个**像素里，对比度 0.262，离阈值 0.25 只差 0.012——是整套检查里余量最薄的一项，而且这一个像素的亮度取决于高光落在它里面的亚像素位置，不是证据，换一个系统版本的抗锯齿就可能误报。改为取到的高光像素少于 2 个时不判这一项（详情里写明“只取到 1 个像素，不判”）；其余姿态至少 2 个像素、对比度 ≥ 0.331，照常判；该姿态的圆的大小、位置、颜色照样核对。单测从真实形状数据里取前提（蝠鲼几乎正对 = 1 个像素、小锤头鲨眨眼 = 2 个像素；形状数据变了前提断言会先失败），断言“1 个像素没有高光也不因此失败、2 个像素没有高光被拦住、1 个像素时圆小 20% 与浅色圆仍被拦住”。这是补强之后才改的代码，所以最终的变异检查是在改后的代码上整条重跑的。

## 验证中发现并修复的问题

1. **全量 `node --test` 里有一个源码绊线失败：接缝改了源码文字。** 绘制层加 `show` / `stroked` 参数后，`test/jelly-appearance-settings.test.js` 的“示意图取色规则与原生 SpeciesPainter 一致（源码绊线）”要求源码里有字面上的 `case .limb: paintLimb(ctx, path, tone: p.paint.limbTone(u: part.u))` 与 `case .body: paintBody(…, paint: p.paint)`，现在多了 `, stroked: show.strokes`，两条正则不再匹配（全量 2723 项里 1 项失败）。我在接缝落地之后只单独跑过渲染检查和几个相关测试，没有立刻跑全量，所以拖到最后一轮才发现。只改了这两条正则的文字（并写明“描边由检查用的 `show.strokes` 控制，产品默认全画”），所有取色、透明度、线宽的规则一个字没动；改后该文件 71/71 通过。**结论：改绘制层源码的形状（哪怕不改任何常数），要跑一遍这个文件；接缝类改动之后先跑全量。**
2. **我以为“叠层强度已被这个源码绊线钉住”，实测不是。** 它的一条正则 `white.withAlphaComponent(0), white.withAlphaComponent(0.32)], [0, 1])` 只要求“至少匹配一处”，而渐变与七彩各有一处同样的叠层——只改其中一处，另一处仍然匹配。渐变叠层 α 0.32 → 0.70、七彩叠层 α 0.32 → 0.70 两个手写变异体因此在渲染层和这个绊线上都存活（第一轮已存活的 `[0,1]` → `[0,2]` 同理）。补了“两处必须同时在”的计数钉子。另外把渲染层存活的 11 个手写变异体放到这个旧绊线上跑过：只杀死 3 个（肢体渐变不提亮、躯干中间色标 0.55 → 0.20、腹部提亮 0.72 → 0.60），其余 8 个存活——“有静态层兜底”不能想当然。
3. **命令行测试的措辞探针误伤**（第一轮发现并修复）：新检查的名字里带“全部”（如“全部躯干部件合起来……”），旧断言用 `includes('全部')` 判断“没有写全部通过”，被误伤；改为匹配精确的汇总文字 `/全部 \d+ 项通过/`。

## 与设计稿和计划的差异

- 每个动物的检查条数上限不是设计稿规定的，是“元素 + 叠层”两组带来的 +36 / +36 / +44 项。

## 已知边界与未做

- **颜色只做结构性核对，所以“颜色常量差 0.01”这类变异体渲染检查抓不住**（有意取舍，见决定 6）。AppKit 把 calibrated 颜色转进位图会改数值，拿规格里的原始数字比绝对颜色会误报；腹部是唯一核对绝对颜色的，容差 0.06（实测基线误差 0.027）——腹部提亮 0.72 → 0.60 的颜色误差仍在容差里，渲染层没抓住（旧的示意图取色源码绊线抓得住）。
- **两层都没抓住的绘制层变异体还有 40 个**（270 个有效变异体里：渲染检查杀死 171、存活 99；存活的放到两个静态层——本步骤加的源码钉子与旧的示意图取色源码绊线——上，又杀死 59、两层都存活 40）。逐类：
  - **颜色或透明度只差 0.01，按设计只核结构（16 个）**：墨色的三个通道与 α（8 个）；七彩躯干前两个色标的透明度与提亮（8 个，该行第三个色标由旧源码绊线钉着、前两个没有）。
  - **高光 α 0.85 ± 0.01（2 个）**：高光只有几个像素，质量与亮度对比都吸收得掉。
  - **低于分辨力的几何（12 个）**：警觉放大系数 1.25 ± 0.01（2 个）、睡着的弧半宽系数 1.25 ± 0.01（2 个）、弧端点高 0.8 → 0.9（1 个）、弧的控制点 0.6 / 2.2 ± 0.1（7 个）——相差 ≤ 0.1 pt，约 0.2 个像素（2×），在抗锯齿噪声里。
  - **“z” 的锚点系数 0.12 ± 0.01（2 个）**：“z” 的位置判据是离头端锚点 ≤ 22 pt（实测 13.4–15.1），锚点移动 0.01 个宽度吸收得掉。
  - **等价或防御（8 个）**：`setLineCap(.round)` 被删（闭合路径没有线端）、`look.y * 1.0` 改成除、两处退化包围盒守卫（`>` ↔ `>=`、`0` → `1`，共 6 个，真实形状不会走到）。
- **叠层强度 α 0 → 0.32 与七彩/渐变躯干的色标位置，渲染层仍然没有判据**（躯干“上浅下深”只用阈值 0.01 判，叠层减半仍通过）。现在它们只由**静态层**守：叠层两处必须同时在（数个数，`species-render-check.test.mjs`），旧源码绊线钉着躯干与七彩色标——而旧绊线的那条正则只要求“至少匹配一处”，不能想当然地以为它钉住了全部（见“验证中发现并修复的问题”第 2 条）。要在渲染层守住，需要按“白色 α 叠在主色上”的模型预测七彩/渐变躯干（约 1–1.5 小时，未做，是候选的下一步）。
- **完全闭眼没有逐像素判据**：闭眼的眼睛只剩约 1.2 个像素高的细条，抗锯齿与预测差 ±7%（质量比 0.925 / 0.953 / 1.055，阈值 ±0.055），所以不检查；下限 `max(0.12, 1 − blink)` 只由源码钉子守。**高光只落在 1 个像素里的姿态也不判对比度**（蝠鲼几乎正对，见补强一轮第 7 条），这一条的代价是该姿态下“没有画高光”看不出来——其他姿态（至少 2 个像素）看得出来。
- **阈值来自这台机器（macOS 26.5、Apple M3 Max）的实测基线，余量不大**：眼睛质量比最小 0.960 对阈值 0.945（余量 0.015）、躯干渐变两端 0.929 / 0.969 对 0.942 / 0.958、高光面积比最小 0.838 对 0.72；换系统版本出现边缘失败时先看实测数字再改阈值，**不要顺手放宽**。只验证了缩放 2 与一种窗口大小；渲染工具里缩放的夹取（1…4、默认 2）的变异体存活，就是因为所有检查都用缩放 2。
- **`PAINT_SPEC` 是画法常量的第二把钥匙，维护成本是改美术取值要多改一处**（还有绘制层源码钉子要核对的几个数字，它们直接读 `PAINT_SPEC`，不是第三份）；改 `jelly-species-painter.swift` 的源码形状（哪怕不改常数）要跑 `test/jelly-appearance-settings.test.js` 的源码绊线。
- **渲染工具新增代码的 17 个存活变异体**（53 个里杀死 35、1 个编译失败）：缩放的夹取与默认值 `max(1, min(4, scale ?? 2))`（14 个：三处各一份，所有检查都用缩放 2）、`view.jellyAppearance = appearance`（材质取默认值时看不出，1 个）、`restoreGraphicsState`（短命进程里无害，1 个）、`item.show != nil` 的防御分支（没有用例会让非直接画带上 `show`，1 个）。
- **检查脚本新增代码的 103 个存活变异体**（658 个里：结构类 652 个杀死 549、存活 103，手写的 6 个全部杀死）：逐个读过，按算子归并——**比较边界 66 个**（`>→>=` 14、`<=→<` 13、`>=→>` 17、`<→<=` 22）：十几个是循环上界（多迭代一次只读到数组外的 `undefined`，比较为假，结果不变），其余是阈值恰好取等号（质量比、颜色、像素个数等），真实渲染的数值不会恰好落在边界上，要杀它们得构造“恰好等于阈值”的合成图，成本高于价值；**算术 23 个**（`+→-` 7、`-→+` 5、`*→/` 8、`+=→-=` 3）：像素中心 `+ 0.5` 与 y 翻转、预测与测量两边同时偏移而相互抵消、`facing` 恒为 ±1 时乘与除等价、`rasterize` 的默认宽高（只有两个单元测试用到默认值，检查脚本自己的调用方都显式传了尺寸）、只拼接说明文字的 `+=`；**守卫与语句 14 个**（`if` 恒真 5、恒假 2、`&&→||` 4、`===→!==` 2、删语句 1）：互相重复的双重守卫、真实数据下恒成立的条件、只改详情文字而不改通过与失败的语句。我没有发现“在真实渲染里会露出来、却没有任何检查拦住”的缺口，**但这是逐个人工判断，不是另一套工具的交叉验证**。命令行回显核对另有 12 个变异体：杀死 11、存活 1（去掉“渲染工具报告了一个没有请求过的用例”那句明确的报错——下一行读取 `request.direct` 仍会抛 `TypeError` 而失败，只是少了说明文字）。
