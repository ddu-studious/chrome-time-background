## 做了什么

设置页“动物”下拉多了第四项：**鲸鲨**。选中后桌面上只出现这一只，8 色、4 种花纹、“每天换一只”“随机一只”照常起作用（后两者仍然只换颜色与花纹）。

| 项 | 取值与行为 |
|---|---|
| 物种 | `jelly`（默认）、`hammer`、`manta`、`whaleshark`（本步骤新增）可用；`turtle` 仍只在设置模型与协议里占位，没有形状数据，下拉里不出现，原生退回水母 |
| 鲸鲨的样子 | 侧视（斑点与长身只有侧视才看得清）：长身、宽扁的头（吻端在 +47）、背上四排共 **60 个**白斑（13 / 17 / 20 / 10 个，六角晶格：行内间距 3.3、行距 2.86，斑径 1.09–1.35、中段略大，头部一带留空给眼睛、腮红与嘴）、浅色腹部、两片背鳍、一片会轻摆的胸鳍、会摆的尾鳍、背上一道细高光；只看得见一只眼睛（半径 2.2，在 (37, −3)），**笑着**，脸红红的。缩放 0.9，并集包围盒 **89.82 × 33.62 pt**（含摆动的尾与鳍；在批准的 76–92 pt 内，宽度紧贴上限）。悬在窗口标准高度（并集顶端离窗口底边 91 pt） |

| 游动 | 纵向最平稳、比小锤头鲨慢：`SwimProfile(period: 1, thrustX: 0.6, thrustY: 0.3, sink: 0.4, dragX: 0.65)`；判据与标定见下 |

## 复用与新增（对照 AGENTS.md“优先复用”）

- 没有适用的开源 SDK（AppKit/CoreGraphics 自绘）。**整条管线复用 Step A/B**：形状数据 → 生成器 → 严格解析 → `SpeciesGeometry/Placement/Pose/SwimProfile` → `SpeciesPainter` → 设置页示意图；协议、设置键、权限、网络、依赖都没有新增。新增一种动物只动了：形状数据（JS 一份）、生成物、`swimProfile` 的一个分支、设置页下拉一项、测试与验收脚本——与 Step B 相同，这次多出来的两项机制（`mouth`、`dots`）都是**可选字段**，没有它们的数据逐位不变。
- 新机制只有两个：侧视动物的 `mouth`（数据字段 → 生成器 → Swift 几何 → 画法 → 设置页示意图 → 渲染检查）与 `dots` 写法（JS `expand` 把它展开成与 `ellipse` 同一类的路径；原生端看到的仍是普通路径，**Swift 解析器与几何一行没有为 `dots` 改**）。
- 验证工具：`species-render.mjs` 的判定函数（微笑、腹部、斑点、被抓住时醒来）；`checkSpecies` 增加只给测试用的 `judges` 参数（见“关键决定”第 7 条）；物种功能系统性变异检查的执行工具与方法（在 `/tmp`，不入库）。

## 关键决定与理由

1. **斑点用 `dots` 写法，不手写 60 段路径。** 60 个圆手写成 `d` 路径要 360 条命令的数字，容易写错，也无法在数据里表达“斑径中段略大、六角排布”这类规律；`dots` 让数据直接是 `[x, y, r]`，`expand` 用与椭圆同一个 `ellipsePath` 展开（四段三次贝塞尔、`KAPPA = 0.5523`），所以原生解析器、几何与绘制都不需要知道斑点的存在。代价是生成物里 accent 路径很长（10170 字符），由 `MAX_PATH_CHARS = 16000` / `MAX_COMMANDS = 800` 兜住，超限整种动物不可用，生成器报告。
2. **斑点颜色用固定的半透明白，与设计稿 §4 不一致。** 设计稿 §4 写的是“`accent`：与口腕同一规则，纯色 a，其余 b，再提亮”；而 Step A 的画法里 accent 就已经是固定的半透明白（0.55，当时没有任何动物用 accent，Step A 文档与设计稿都没有记这个偏离）。鲸鲨是第一个真正用到它的动物，所以这里把它写明并**保留固定白色的做法**：白斑是鲸鲨最好认的特征，要在 8 种主色与 4 种花纹下都成“一排排白点”；按主色提亮会在浅色主色上对比不够，在七彩下还会随位置变色。**不透明度从 0.55 调到 0.72，整条路径一次填充**（斑径只有 1.09–1.35 pt，直径约 2.2–2.7 pt，0.72 读起来更清楚）。0.72 是美术取值，没有量化的可读性实验，观感要用户确认；设置页示意图原来同样是 0.55，已同步改成 0.72，两处相同。渲染检查按 0.72 验收斑点与躯干的亮度差（见验证结果）。
3. **一个部件有且只有一种形状写法。** `d`、`ellipse`、`dots` 同时写了几种，`expand` 以前会按固定顺序悄悄只认一种。现在返回 `null`（该物种不可用、回水母，生成器退出码 2）：数据坏了就整种动物不画，不猜——和 Step A/B 对路径串、`squash` 的处理一致。
4. **微笑是数据，不是画法里的常量。** `mouth` 是四个点的三次贝塞尔，坐标与其他部件同一个系统（缩放前、y 向下；Swift 里缩放后、y 向上）。合规条件：只有侧视动物可以有，必须正好四个点、每点两个有限数字；不合规让整种动物不可用。嘴**不参与**并集与躯干包围盒（放置不受影响），自测里钉住“四个点都落在躯干包围盒里”。睡着时不画（睡着的鲸鲨没有笑容），**被抓住时即使睡着也画**（`asleep = p.asleep && !p.grabbed`）——被抓是醒来的反应，保持与眼睛一致。画法是 1.2 pt 圆头墨色细线（取 `ink`），只有这一条线，没有嘴形填充。
5. **鲸鲨的游动：纵向压到最低，横向比小锤头鲨慢。** 系数用种子化模拟标定，判据与前两种动物同一套（逐阶段 soon/imminent/final，水母为对照，种子 42、600 秒）：不沉到泳线以下、不越过屏幕边界；超过 60 pt 的时间 < 5%、顶到上限 < 2%；平均高度 > 3 且 < 愿意停留的高度 + 18；会水平游动（范围 > 150）；平均横向速度是水母的 0.7–1.4 倍；最大纵向速度比水母小。**鲸鲨另有两条**：平均横向速度低于小锤头鲨；最大纵向速度**比小锤头鲨与蝠鲼都小**（侧视时上下起伏最容易被看见，所以压得最低）。
   - 最终系数下三个阶段的读数（soon / imminent / final）：平均高度 16.6 / 26.8 / 33.7（愿意停留的高度 14 / 20 / 24，比它高 2–10 pt，不贴着泳线）；超过 60 pt 的时间与顶到上限的时间都是 0.0%；平均横向速度是水母的 ×0.87 / ×0.82 / ×0.88（小锤头鲨 ×1.09 / ×1.02 / ×1.09，蝠鲼 ×0.85 / ×0.80 / ×0.83）；最大纵向速度 13.5 / 9.3 / 7.6（水母 45.1 / 31.1 / 27.3，小锤头鲨 24.8 / 17.1 / 15.2，蝠鲼 22.5 / 15.6 / 12.8）；水平范围 1252 / 1301 / 1272。**鲸鲨不是三种动物里横向最慢的**：蝠鲼更慢一点（16.0 / 33.8 / 25.4 对 16.4 / 34.4 / 27.3），所以代码注释与文案只说“最平稳”，不说“最慢”（早先一处注释写成了“游得最慢最稳”，已改正）。
   - 稳健性：标定时在仓库之外扫描了 30 个种子 × 三个阶段共 90 次模拟，全部满足通用判据（这个扫描脚本不入库；自测里钉的是 12 个种子 × 三个阶段的同一套通用判据）：平均横向速度是水母的 ×0.81–0.90，平均高度比愿意停留的高度高 1.9–9.8 pt，最大纵向速度不超过水母的 0.30 倍。同样跑过两组邻近的候选，也都是 90/90 通过：横向冲量 0.55、阻力 0.6 的速度比范围 ×0.79–0.89，纵向冲量 0.32、下沉 0.42、阻力 0.6 的 ×0.84–0.97、最大纵向速度上限 0.32 倍；最终这一组的纵向起伏上限最低（0.30），速度比范围（×0.81–0.90）稳定低于小锤头鲨（×1.00–1.13）。三组之间的差别很小，选择是美术上的（要“慢而稳”），不是判据能分出来的。
   - **改这些系数必须重跑逐阶段检查并同步自测与本文。** 海龟的 `swimProfile` 仍是全 1，没有标定过。
6. **背上的高光必须整条落在躯干里（测试守住）。** 第一版高光是 `[8, -9.6, 16, 1.3, -3]`；躯干背线向尾部是降下去的，高光左端越出背线约 0.34 pt，会在描边外沿多出一道半透明白色的“毛边”。这个缺陷由几何分析发现（见“验证中发现并处理的问题”第 1 条），现取 `[11.5, -9.6, 16, 1.2, -3]`（偏向头一侧、更细），并加了一个对**所有**动物通用的测试：每个高光多边形的每个点到躯干轮廓的有符号距离都 ≥ 0。该测试对原来的数据做过反向验证（会失败，指出越出 0.34 pt）。像素级渲染检查看不出这个问题（越出部分最多约 0.34 pt、不透明度 0.4，在抗锯齿噪声之内），这是几何测试的价值所在。
7. **渲染检查的判定函数可以被替换，只为证明“结果真的进入结论”。** `species-render.mjs` 的 `checkSpecies(species, images, palette, judges = {})` 是纯函数（图像 → 检查行）；`judges` 只给测试用，可以替换 `judgeSmile / judgeBelly / judgeSpots / strayPixels`。变异检查发现原先**没有任何测试证明判定结果被接进了输出**（把某个判定的结果丢掉、或写反，检查依然全绿），所以加了一个接线测试：注入返回固定结论的假判定，逐条断言每个检查行的通过/失败来自对应的判定、调用次数对（醒着 11 次、睡着 2 次，蝠鲼没有微笑行也没有调用）。不传 `judges` 就是真实判定，生产路径不受影响。
8. **JS 与 Swift 的相位表逐项对照。** 并集包围盒按 `WAVES = [−1, −0.5, 0, 0.5, 1]` 取样，JS 与 Swift（`SpeciesGeometry.waves`）各有一份。变异检查发现原来的对拍只遍历 JS 这一份，**两边不一致或某一边悄悄少了一个相位时没有测试会失败**；现在 `test/desktop-companion-logic.test.mjs` 把 Swift 打印的相位与 JS 的 `WAVES` 逐项比较，`test/jelly-species-shapes.test.js` 另把 JS 表钉成 −1、−0.5、0、0.5、1 且冻结。
9. **设置页示意图跟着改。** 示意图是静态 SVG，按宽度 84 拟合（鲸鲨并集宽 89.82，拟合系数 0.935，拟合后恰好 84.0 / 100），斑点不透明度 0.72、腹部、微笑（同一条贝塞尔、线宽按缩放折算）都画；`settings.html` 的 `jelly-species-shapes.js` 与 `settings-jelly-appearance.js` 版本钉子都升到 `?v=3`（带版本钉子的测试同步）。

## 与设计稿和计划的差异

- **斑点颜色**：设计稿 §4 的“accent 与口腕同一规则”在 Step A 的画法里就已经是固定半透明白（0.55）；本步骤保留并把不透明度调到 0.72（关键决定第 2 条）。
- **微笑**是设计稿没有的特征（设计稿 §6 只说俯视动物看不见嘴）；侧视动物的脸需要一个表情，所以做成了通用的可选 `mouth`。
- **`dots` 写法与“有且只有一种写法”的校验**：设计稿没有，来自斑点的实际需要。
- 并集包围盒 89.82 × 33.62（设计稿估的是长度 92 左右）；渲染检查里鲸鲨**没有**设计稿 §8 要求的“躯干 50% 处”取样点：取样规则要求点不在后画的部件里、且离它们至少 1.1 pt，而鲸鲨躯干的中段被腹部、斑点与高光盖满，找不到这样的点（10% 与 90% 处各有一个，躯干中心代表点与腹部取样点也都有）；躯干沿长轴的渐变方向由小锤头鲨与蝠鲼的 10%/50%/90% 取样核对，鲸鲨改为单独的“斑点”“腹部”检查。
- **性能**：设计稿 §8 写的上限参照是“S1a 的水母七彩，白天比纯色多约 +0.056 ms/帧，超过它再决定是否缓存静态部件”。鲸鲨**超过了**这个参照（见“验证结果”的性能一节），本步骤**没有做缓存**，理由与依据写在那里，需要时可再做。

## 验证中发现并处理的问题

1. **背上的高光越出躯干 0.335 pt**（几何分析发现，像素检查看不出来）：改数据，并加了对所有动物通用的“高光整条落在躯干内”测试（见关键决定第 6 条）。
2. **相位表只有 JS 一侧被对拍**：Swift 悄悄少一个相位也没有测试会失败；改为 Swift 打印、JS 逐项比较，并把 JS 的 `WAVES` 钉死且冻结（关键决定第 8 条）。
3. **生成器的成功信息没人断言**：报错信息有测试，成功时的“已写入 …（3 种动物：hammer、manta、whaleshark）”没有——删掉那行信息语句的变异体存活；补了断言（写到了哪里、列出写入的动物）。同一个测试里“生成结果与入库文件相同”早先就用 `assert.ok` 而不是 `assert.equal` 比较两份几十 KB 的文本（不一致时 `equal` 会去算整份文本的差异，实测要几分钟），这是同一类问题的第一次出现。
4. **检查函数的判定结果有没有接进结论，没有任何测试证明**：把某个判定丢掉或写反，渲染检查照样全绿；加了 `judges` 接缝与接线测试（关键决定第 7 条）。
5. **“动物在深色/浅色外观下逐像素相同”这条检查是空的**：渲染工具根本没有切换外观时它同样通过（删掉那行赋值，348 项全绿）。现在渲染工具把产品自己判断的外观名（`JellyView.appearanceName`）写进清单，脚本逐个用例核对“请求的与实际生效的一致”；手写的 4 个变异体 3 个被杀，第 4 个（让渲染工具转述请求里的 `dark` 而不取产品的判断）等价、存活——只要产品真的切换了外观，两者相同。
6. **删掉任何一条 `add(…)` 检查都不会失败**：输出少一条，仍然“全部通过”。加了 `CHECK_MANIFEST`（每种动物每一组应有的条数）与纯函数 `reportSpecies`：条数与清单不一致就多出一条失败，未登记的动物也失败。
7. **命令行的退出码与错误路径没人看过**（真实渲染从来全过）：用桩渲染工具驱动的 CLI 测试覆盖：检查没有通过时退出码 1（逐组“通过/总数”与汇总行一致、失败项带说明、`--verbose` 才打印通过项）；渲染工具给出的东西不对（输出不是合法清单、物种或外观与请求不符等）时退出码 2 并说明原因，不当成检查失败；没有 `--out` 时用临时目录并在结束时删掉、`--keep` 才保留；`--sheet` 与 `--sheet-dark`（九张图按顺序、半透明图叠在白底或深底上）。
8. **`flatten` 的 Q 分支没人把守**（形状数据从没用过 Q，37 个变异体全部存活）：补了测试；复跑时发现补的数据太“规矩”（起点在对角线上、终点 y 都是 0），把起点 x/y 互换或改坏终点 y 的项仍看不出来，又加了一组不对称数据（起点 (2, 6)、控制点 (10, −2)、终点 (6, 4)）和一条没有 `Z` 的开放路径，5 个存活变异体被杀。
9. **Swift 的路径还原（C/Q 命令）在纯逻辑层没有断言**：只有渲染层抓得到，纯逻辑层改坏它不会失败；在自测里加了一块（合成 M/L/C/Q/Z 路径，还原出的 CoreGraphics 路径元素类型与点逐个核对），1190 → 1194 项，6 个变异体因此被杀。
10. **`node --test` 汇报长失败信息时卡住**：见上面的方法教训。新加的测试用 `brief()`；旧的对拍断言 `assert.equal(swift, '-')` 改成 `assert.ok`。**这是我们自己测试在失败路径上的可用性问题**：真出了回归，原来的写法会让测试久久不出报告。
11. **文档与注释里的不实说法**：鲸鲨注释写过“游得最慢最稳”（蝠鲼其实更慢，改成“最平稳”）；冒烟场景数写成了 32（把读数明细行也算进去了，实为 29）；设计稿 §4 的 accent 一行与 Step A 起的画法不一致（改为“固定半透明白”）；设计稿 §10 的性能一节原先写“待测”（现已实测）。
12. **变异检查工具自身的坑**（只影响验证质量，不影响产品）：① “杀死但没有失败信息”的条目要逐个审（审出 6 个误杀）；② `--targets` 的行号会随编辑漂移，后来用按“行文本 + 前后文 + 替换物”配对的复跑；③ `ranges: []` 的意思是整份文件而不是“没有”；④ 运行器要把编译失败归为 `invalid`，不能算杀死；⑤ 同一个镜像目录不能同时跑两个变异任务（工作目录会撞）。
13. **隔离验收的两个环境坑**：① 隔离构建把扩展 ID 编进了组件，`appearance-smoke` 固定使用 32 个 `a`，用别的 ID 构建出的组件会在 0.2 秒内静默退出（退出码 1、没有任何输出），冒烟只报“原生组件超时：jelly”；② 刚构建的组件第一次启动要约 5 秒（实测 4.8 秒，之后 0.3 秒），第一次会撞上冒烟的 5 秒请求超时，再跑一次即可。两点已写进 `desktop-reminder/README.md`。

- **（本文写成时的状态；这一条已由后续步骤处理，见 `docs/technical/jelly-species-painter-diff-20261018.md`）绘制层的变异检查几乎只靠渲染检查把守，而这一层的检查不够锋利**：渐变色标、颜色常量、描边颜色与线宽、眼睛/腮红/反光的几何与透明度、墨色不透明度等变异体大量存活（上表：通用 176 个存活 / 87 个被杀），渲染检查的取样点、色相差与亮度差容差把它们吸收了。**这不是“确认没问题”**，所以鲸鲨斑点的颜色、笑线的粗细这类细节主要靠人眼。当时的后续建议是给 `species-render` 加“画与不画”的差分检查；用户随后选择了这一项，已做（元素与叠层两组，离屏渲染检查 348 → 464 项；绘制层通用变异杀死数 87 → 171，再加两个静态层共 230 / 270，两层都存活的 40 个已逐类说明），剩余的存活者与新发现的缺口写在那份文档的“已知边界”里。上面验证结果表里的数字（348 项等）是 Step D 当时的状态，没有改写。
- **渲染检查脚本里 716 个阈值与判定内部细节的存活变异体（463 个没复测、253 个复测后仍存活）没有逐个处理**（边界差一个单位、采样半径与环宽、`&&` 改 `||` 让检查变宽松的几处——睡觉标记的位置判定与眼睛弧线判定、新斑点判定的采样细节尤其值得以后补合成图像的单元测试；**后续步骤已补一部分：睡觉标记抽成 `judgeSleepMark` 并逐条做反例，眼睛弧线/颜色、腮红、高光的合成图单测见 `jelly-species-painter-diff-20261018.md` 的“补强一轮”，其余边界类变异体仍没有逐个处理**）。这些检查的阈值是按实测加了余量定的，变宽松不会让现在的 348 项失败，但可能放过以后的退化。
- **性能**：只量了离屏绘制耗时；鲸鲨超过设计稿 §8 的参照、没有做缓存。**真机上的 CPU 占用要用户先在活动监视器里看一下**（常驻 + 夜晚荧光是最重的组合，估算约一个核的 2%），不理想再做静态部件缓存。
- **没验证的**：带真实鼠标的冒烟阶段没跑；真实 Chrome 156、真实账号、重装后的真实组件（要用户重装组件并重载扩展）、多显示器组合、全屏 Space、Stage Manager、真实壁纸叠加下的观感、VoiceOver 真机播报都没有验收。`bridge-smoke` 第一次运行的偶发超时没有查明原因（见验证结果）。
- **美术需要用户亲眼确认**：斑点排布与 0.72 的不透明度、笑线、浅色腹部、89.82 pt 的长度、游动的“平稳”程度都是实现方的美术取值，没有可读性的量化实验。
- **没做**：海龟（Step C，设置模型与协议里有占位、没有形状数据，原生退回水母）；材质（gummy / wire / pencil / pixel / plush）、尺寸、节日换装、右键菜单“换一只”、互动与玩法、收集系统。Step B 与本步骤的改动都没有提交，由用户看过再决定。
- **等价变异体（逐个核对过，不是遗漏）**：Swift 纯逻辑 5 个、`flatten` 的 `Z` 分支 3 个、`jelly-desktop.js` 物种行 2 个、`gen-species.mjs` 不可达的防御分支 3 个、harness 里“转述请求外观”的手写变异 1 个。
