# 首页水族馆岸线冲刷（潮起潮落风格 B）

**用户的选择（2026-10-20，AskQuestion）**：潮起潮落用 **B：底部岸线冲刷**（“像站在水里看海浪拍沙滩”）；接受它在画面底部占一条带、会与 Dock/任务栏抢位置、鱼的下沿要避让；**仍然不能遮住壁纸**。拖拽时鱼被拖出水面的现状**保持不变**（§5）。

这份文档取代 `aquarium-tide-size-drag-20261019.md` §3 的风格 A（顶部水线）。风格 A 的代码已经删除；为什么当初只做 A、B/C 为什么没做，见那份文档的 §3.3 与它的修订说明。

## 1. 画面

自下而上（页面底边在最下）：

| 层 | 内容 |
|---|---|
| 干沙 | 最靠页面底边，最不透明 |
| 湿沙（冲刷区） | 浪能冲到的范围：更深更实，带一层映着天光的薄水膜和退水留下的泡沫纹 |
| 水线 | 一圈白色浪花；浪冲上去时是“冲流”泡沫、退下去时是“回流”泡沫 |
| 浅水 | 水线上方：青绿、沙面上有水光斑，往上越来越薄，渐隐到完全透明 |
| 下一道浪 | 正从海里推过来的浪线，越近越白，贴近水线时与退水相撞 |

夜里（晚 8 点到早 6 点，需开着“夜晚荧光”）整体变冷蓝、亮度降下来；“效果强度”滑块仍然作用于总亮度；省流量时少算水下光斑与水面碎光。着色器全部自写（GLSL ES 1.00，无纹理、无外部资源），参考的只是“沙滩浪花的冲流/回流/湿沙反光/浪花碎纹”这类**做法**，没有引用任何第三方代码。

## 2. 时间线（全是时间的确定函数，没有随机数）

高度都是**页面高度的比例，从页面底边往上量**。数字集中在 `js/aquarium-water-core.js` 的 `PARAMS`，着色器里的同名常量是它的副本（单测有源码钉子核对一致）。

| 参数 | 值 | 含义 |
|---|---|---|
| `BAND` | 0.34 | 水层画布只占页面底部的 34%（样式里 `.aq-water` 的 `height: 34%`，单测核对两处是同一个数） |
| `TOP_MID` / `TIDE_AMP` | 0.15 / 0.035 | 浪“退得最远”时水线的高度 = `0.15 − 0.035 × high`，在 0.115–0.185 之间 |
| `TIDE_PERIOD` | 60 秒 | 潮位 `high = clamp((sin θ + 0.2·sin(2θ+0.8)) / 1.2, −1, 1)`，倍频分量让波形**快涨慢落**（峰值 1.167，所以夹取是达不到的保险）；涨潮时水线低（水漫上沙滩）、浪冲得更深 |
| `WAVE_PERIOD` | 9 秒 | 每个浪的周期 |
| `RISE` | 0.26 | 冲上沙滩占周期的 26%（先快后慢），其余时间退回（先慢后快，指数 1.6） |
| `SET_AMPS` / `AMP_WOBBLE` | 0.55 / 0.80 / 1.00 / 0.68 / ±0.22 | 一组四个浪，大小依次是它；每个浪沿横向再有 ±22% 的强弱 |
| `REACH` / `REACH_TIDE` | 0.085 / 0.10 | 大小为 1 的浪冲下去的深度 = `0.085 × (1 + 0.10 × high)` |
| `SHEAR` | 0.22 | 浪是斜着来的：右边比左边晚 0.22 个周期 |
| `APPROACH` / `APPROACH_DIST` | 0.55 / 0.14 | 下一个浪在上一个退水的后半段就从海里推过来，起点在水线上方 0.14 处 |
| `LAT_A` / `LAT_B` | 0.0065 / 0.0040 | 水线沿横向的缓慢起伏（周期 36 / 27 秒） |
| `RILL` | 0.020 | 指状水舌（只在着色器里，噪声）的幅度 |

- **水线的高度只有一份公式**：`水线 = top − reach × 浪的大小 × 浪的一生 + 横向起伏`。着色器按它画，JS 的 `frontAt` 用同一条公式（不含水舌噪声，它的幅度有上界），单测把它逐项钉住并用数字钉子守形状。
- 三个周期（60、9、36/27 秒）都整除 `TIME_WRAP`（21600 秒），着色器时间每 6 小时回绕时水线连续（泡沫纹理的滚动没有这个保证，每 6 小时跳一下，纯装饰）。
- 画布只有 `BAND` 那一条，像素数上限 30 万（`MAX_PIXELS`），内部边长是页面的 0.5（省流量 0.3），30 帧/秒（省流量 15）；其余保护（软件渲染识别、帧率监护器、失败即关）与 `aquarium-water-20261019.md` 相同，没有改。

## 3. 为什么仍然不遮壁纸

1. **范围**：画布只有底部 34%，带子之外**没有这层的任何像素**；上方 66% 的壁纸原样。`P.BAND < 0.5`、岸线最高处留出渐隐空间、下一道浪的起点不超出带子，都有单测。
2. **合成方式**（2026-10-19 修的根因，没有变）：WebGL 输出**预乘 alpha**，页面用普通 source-over 混合；不用 `mix-blend-mode: screen`（壁纸是 `position: fixed` 的 `body` 的背景，`screen` 看不到它）。
3. 底部这一条按设计会变（沙与浪就是画在那里的）；变与不变的量化见 §6.2。

## 4. 岸线 API 与接线

```
AquariumWaterCore.shoreTopAt(time) = tideOf(time).top + SHORE_PAD     // SHORE_PAD = LAT_A + LAT_B + RILL·0.5·0.3 = 0.0135
AquariumWaterCore.shoreTopMax()    = TOP_MID + TIDE_AMP + SHORE_PAD   // 0.1985，常数上界
AquariumWater.shore(now)           // 页面高度的比例，从底边往上量；没在运行 / 失败 / 没有画布 / 还没画出第一帧 → null
```

- **`shoreTopAt` 只跟潮位走（慢，H = 720 时约 3.7 px/秒），不跟单个浪走**：它是“任何横向位置、任何相位水线能到的最高处”，取浪退得最远、横向起伏与水舌都在最高的情形；单测核对任何时刻、任何横向位置的 `frontAt` 都不高过它，且它不虚高（范围 0.1285–0.1985）。鱼要躲的是这条“最高处”，所以鱼不会随每个浪忽上忽下。
- 宿主 `background-experience.js` 的 `drawJellyfish` 每帧取 `shore = water.shore(now)`（水体层不存在则为 `null`），交给 `aq.frame({ …, shore })`；控制器把它换成“从屏幕顶往下量”的像素 `(1 − shore) × height`，再传给 `Core.step(world, dt, { pointer, bells, attractors, shore })`；核心把它夹在屏高的 50%–100% 写进 `world.shoreY`（非有限、缺失 → `null`）。
- **没有水层**（关闭、失败、省流量降级、还没画出第一帧）时 `shore` 为 `null`，鱼完全按原来的方式游；小型物种在没有岸线信息时的轨迹与改动前**逐位一致**（核心黄金轨迹守住）。
- `seabedOf(world, spec, lenPx) = shoreY − lenPx × half − SHORE_GAP(6) × 缩放`：鱼心最大纵坐标，使身体下缘留在岸线之上；没有岸线信息返回 `null`。
- `ceilingOf(world, spec, lenPx) = lenPx × half + TOP_PAD(6) × 缩放`：**只对大个子**（体长超过 `AGILE_LEN × 缩放`），身体上缘不探出屏幕顶；小鱼返回 `null`，与加入这条之前逐位一致。（风格 A 时“上限”是水面，现在水在底部，上限只剩屏幕顶。）

## 5. 鱼的规则（`js/aquarium-core.js`）

1. **纵向带**：每个物种有自己的活动带 `[上沿, 下沿]`。岸线避让线 `seabedY` 低于带的下沿时，带的下沿取 `min(seabedY, 下沿)`（大个子的带下沿在屏高的 60%–65%，真实潮汐最高处在 80%–87%，所以它们**从不碰到岸线**，轨迹与没有海水层时逐位相同，有测试）；大个子的带上沿取 `max(上沿, ceilingOf)`。
2. **换家**（`pickHome`）：岸线压低了带下沿时，新家取在 `[max(带上沿, 屏幕顶上限), 岸线避让线]` 里（`low = ceilY > top ? ceilY : top`；蝠鲼的下界是屏幕顶上限、鲸鲨的下界是带上沿，两种情形各有测试，两端都取得到）。
3. **家的拉力**：家在岸线以下（潮水涨上来了）时，鱼朝岸线上方的那一点游，而不是一直往沙滩里顶（没有这条规则时小丑鱼平均只高出避让线 9 px，有了以后约 42 px）。
4. **硬约束平滑压回**：身体越过上限或下限的部分按 `LIMIT_EASE 4`（1/秒）平滑压回，并把朝外的速度一起收掉（贴着岸线横着游，而不是往沙滩里“游”）；每帧位移有上限，不瞬移。上下限互相矛盾（屏幕很矮、动物很大）时**屏幕顶说了算**：`lowest = max(seabedY, ceilY)`，身体不探出屏幕。
5. **第一次知道岸线**（海水层刚启动）：只有**家落在沙滩里**的群重新挑家；家已经在岸线之上的群，家与换家计划都不动。被捞走的条目（`dismiss` 丢了它的群、鱼还在淡出）在这个循环里被跳过，不抛错。
6. **被抓着的鱼豁免**（用户确认，见下）：抓着时不受避让约束，松手后按第 4 条平滑落回。

**拖拽取舍（用户 2026-10-20 选“保持现状”）**：抓着的鱼跟着指针走，可以被拖出水面、拖进沙滩；松手后落回岸线之上。要改成“拖着也留在水里”必须有意识地更新 `test/aquarium-heavy-animals.test.js` 里“岸线 × 抓取”那条测试。

### 6.3 变异检查（岸线相关代码，只改 `/tmp` 副本，核对仓库哈希）

- 第一轮 325 个：杀死 274、存活 51。
- 存活者的处理：**真缺口 3 处，已补测试**——`pickHome` 里 `low` 的取法（两种情形）、首次出现循环里对“群已被丢掉”的跳过、`bandSize` 对非数字高度的拒绝、`rushVel` 超出 0…1 的夹取、`frontAt` 的 `xn` 夹取与非正宽高比的缺省（竖屏 0.56 与方屏 1 现在也核对）；**等价或达不到**——恰好相等时两边结果相同的比较边界（`>`↔`>=`、`<`↔`<=`）、`Math.max(1, BAND_SOFT·H)` 与 `Math.min(1, LIMIT_EASE·dt)` 里的 1（前者 `0.1·H ≥ 1`、后者 `≤ 0.2`，达不到）、`tideOf` 里 `clamp(raw/1.2)` 与 `clamp(dRaw/1.4)`（实测最大 0.973 与 0.965，夹取达不到）、`rush(NaN)` 的缺省（0 与 1 处 `rush` 都是 0）、`shore()` 里的四个互相冗余的守卫（`!started`、`failed`、`!canvas`、`frames < 1` 在可达状态下都蕴含 `!canvas`，除非浏览器同步触发上下文丢失事件）、页面只有 1 像素宽高才有区别的比较。**这是我逐个读代码得出的人工判断，不是交叉验证。**

## 7. 与 Dock/任务栏的关系、限制与未验收

- 这是你接受的取舍：岸线区占页面底部（最高处约 13%–20% 页高，浅水渐隐到 34%），首页底部的 Dock 会叠在沙与水之上；鱼的下沿避让的是**岸线**而不是 Dock。**全 UI 页面截图（不隐藏界面，真实 Chrome，3 个潮位 × 2 个视口）的观察**：Dock（`#dock-bar`，56 px 高）顶边距页底 70 px（1440×900 时 y 830–886，1280×720 时 y 650–706），低于岸线上界的最低值（12.85% 页高：900 px 时 116 px、720 px 时 93 px），所以 Dock 始终整个落在湿沙与浪花区里；水层画布 `z-index: 1`、在 Dock 之下，Dock 图标和左下角的壁纸署名文字目视仍清晰可读；浪的白色泡沫线时而在 Dock 之上、时而从它背后掠过。取样时 `shore()` 在 0.1401–0.1596 之间（页高比例），水层状态 `started`、`failed:false`，页面无报错。截图是我看的，Dock 图标在沙上的对比度没有量化，**请你自己看一眼**。
- 美术观感（沙的不透明度、泡沫的浓淡、浪的节奏、潮涨潮落的速度）没有量化判据，是看真实截图调的数值，**请你亲眼确认**；数字都在 `PARAMS` 里，改完必须重新看截图。
- 岸线上界取“任何横向位置、任何相位”的最高处，所以平静相位里鱼离水线的距离会比“恰好够”多出一点（浪退得最远时最多约 `SHORE_PAD` 加上起伏）；鱼的下缘最多会越过原始岸线约 `vy / LIMIT_EASE`（稳态约 5 px），都落在 `SHORE_GAP` 的间隙里。
- 弱 GPU / 集成显卡 / 高分屏的真实表现、用户自己的 Chrome 配置、真实 GPU 长期占用与电量、触屏未验收。
- 回滚：设置页关掉“海水效果”（立即销毁画布，鱼回到没有岸线的老样子）；或把 `aquariumWater` 默认值改 `false`；风格 A 从未提交过（HEAD `b7e2c91` 里的水层是 v1.0 的整屏水下光影，会遮壁纸，不能当回滚目标），所以没有可回到的“风格 A”版本；想要它只能按 `aquarium-tide-size-drag-20261019.md` §3.1 的描述重写。
