# 本地队列按歌手批量移除

## 调研结果与原失败路径

能力可实现，复用现有本地队列及其歌手字段，不需要新增网易云 API 或 SDK。原会话 `0fc2e5d4-0dc3-40ae-aa3c-e7b76c3fd010` 输入为“清除队里中许嵩的歌曲”。本地单动作解析先将它交给 `music.intent`，实际云端搜索词为“清除队里中许嵩”，没有得到有效对象。

后续模型读取了150首本地队列，记录中50首为许嵩参与的歌曲，包含合唱。旧合同只有分页 list、逐首 remove 和全队列 clear。模型曾请求超过20的分页大小，被纠正后又逐页读取，最后超过执行时限/被用户停止，没有移除回执。因此问题在路由和批量工具缺口，不是缺少歌手数据。

## 实现

- `music.queue.removeArtist(artist, expectedRevision)` 加入原 `music.edit` 工具组。模型先生成 Todo，再读状态取得真实版本，调用该工具准备确认；不需要逐页 list、逐首 remove 或云端搜索。
- 本地路由在歌手单动作解析之前识别清除/移除等编辑动词，支持“队里”“队中”等口语。明确的新队列编辑请求作为独立需求处理，避免继承旧失败任务的 `music.intent` Todo。
- 匹配/过滤复用 `MusicQueuePolicy`，优先使用结构化艺人名称，否则使用仓库标准的 ` / ` 展示分隔。按规范化后的完整名称匹配，含合唱，不做子串模糊删除。最多300首，队列不完整、过期、不可用或缺少歌手信息时拒绝推测；私人FM不作为普通队列批量操作。
- `assistant-management.js` 准备完整匹配集合，存入已有任务绑定、限时且可消费的引用。确认卡展示总数、前10首及余量，并明确是否会停止当前曲目。无匹配直接返回真实零条回执。
- 确认时重新读取队列，核对版本及完整匹配集合。复用现有 `editMusicQueue` 依赖和 `editAssistantMusicQueue` 后台入口，扩展 `remove-many`，单次写入剩余队列；不用50次独立删除。其他曲目顺序和未被移除的当前播放保留；命中当前曲目时先停止，不自动切歌。
- 沿用现有播放器 epoch、缓存快照、任务版本和取消检查。`editMusicQueue` 已处于副作用标记范围，回执丢失仍为 unknown，不自动重放。只有真实移除/零条回执可以勾选对应 Todo。

无新增依赖、模型调用通道、权限或外部网络请求；原 pi 0.85.1 仍承担已接入的上下文/审批能力，此处业务队列操作由既有模块负责。

## 验证

- 401项助手、工具、上下文、规划恢复、HTTP鉴权及播放器状态回归通过。覆盖完整姓名/合唱/相似姓名、150首中批量移除50首、当前播放保留或停止、零匹配、确认过期、取消、unknown、一次后台写入、私人FM拒绝等分支。最后的边界同步和FM保护另作专项复核。
- 真实 Qwen3.8 27B + 鉴权 HTTP/Gateway + 生产 Engine/Tools 全流程通过；音乐依赖及确认点击均为替身，真实用户队列未修改。4轮规划、95333ms，模拟150首一次移除50首、剩余100首，当前曲目和播放状态保留。报告：`.local/evaluations/assistant-remove-artist-1790583954322.json`。
- 可复验入口：`node local-ai/evaluate-assistant-todo.mjs --live --remove-artist`。不带 `--live` 不调用模型。
- 本机服务已加载新目录；真实 Chrome 扩展需重载并刷新宿主页。真实账号删除未验收，不将替身结果描述为真实删除成功。

## 同次 UI 修复

右侧大片磨砂来自宿主在整个 iframe 外接矩形上应用 backdrop-filter，与 Tips 实际高度无关。现在宿主只为主面板和 Tips 建立两个独立磨砂底板，按受来源/nonce校验且有限数值的实际边界定位；iframe 点击区域同样裁到两张卡片，空白处不再拦截页面点击。窗口尺寸变化时重新投影位置，避免居中面板在收起后被旧坐标裁切。

已通过用户指定的 Chrome 在隔离页面检验展开、收起、长条背景消失、原空白区域点击及重复展开/收起。截图：`output/playwright/todo-surface-chrome.png`、`todo-surface-collapsed-chrome.png`。UI 为生产 HTML/CSS/JS，Chrome API 与业务状态为替身。
