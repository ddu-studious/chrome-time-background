## 做了什么

设置页“动物”下拉多了第三项：**蝠鲼**。选中后桌面上只出现这一只，8 色、4 种花纹、“每天换一只”“随机一只”照常起作用（后两者仍然只换颜色与花纹）。

| 项 | 取值与行为 |
|---|---|
| 物种 | `jelly`（默认）、`hammer`、`manta`（本步骤新增）可用；`turtle`、`whaleshark` 仍只在设置模型与协议里占位，没有形状数据，下拉里不出现，原生退回水母 |
| 蝠鲼的样子 | 俯视（侧视只是一条细扁的东西，菱形的翼与长尾才是蝠鲼）：整片菱形的翼是躯干（`body` 角色，用主色），中央一条浅色的身体带（带着眼睛与腮红）、前端两只头鳍、后面一根长尾。缩放 0.85，并集包围盒 **85.8 × 58.0 pt**（含尾的长度与翼展；设计稿估的是 82 × 61，仍在批准的 76–92 pt 内）。悬在窗口标准高度（并集顶端离窗口底边 91 pt） |
| 拍翼（新运动） | 划水时整片翼“一胖一瘦”：绕身体中心把 y 方向缩放到 `1 − 0.1 × wave`（0.9…1.1 倍），尾巴只左右摆（±8°）；静止、停下与“减少动态效果”（`wave = 0`）时没有任何变形，画面就是数据里写的形状 |
| 游动 | 最慢、滑得最远：`SwimProfile(period: 1.35, thrustX: 0.6, thrustY: 0.5, sink: 0.5, dragX: 0.5)`，比小锤头鲨慢、仍不低于水母速度的 0.75 倍；判据与标定过程见下 |
| 其余行为 | 与 Step A 的动物完全一样（睡着、眨眼、看向鼠标、被点、被抓、倒计时读数与阶段色覆盖所选颜色、响铃涟漪以动物为中心、喝水/起身气泡里称“蝠鲼”——这一条走 Step A 的同一套称呼机制与名字表，名字表三份逐项对照，但没有专门针对蝠鲼的气泡用例——、夜晚荧光）；Step A 的 AppKit 绘制与物种接线（`jelly-companion`、`jelly-controller`、`jelly-species-painter`、`jelly-paint`、`jelly-swim`）一行没改；`main.swift` 只多了 `ping` 里一个只读诊断字段 |
| 验收诊断 | `ping` 回执新增 `displaysActive`（有几块活动显示器），只作验收读数，见“验证中发现并处理的问题”第 1 条 |

## 复用与新增（对照 AGENTS.md“优先复用”）

- 没有适用的开源 SDK（AppKit/CoreGraphics 自绘）。**整条管线复用 Step A**：形状数据 → 生成器 → 严格解析 → `SpeciesGeometry/Placement/Pose/SwimProfile` → `SpeciesPainter` → 设置页示意图；协议、设置键、权限、网络、依赖都没有新增。**新增一种动物只动了：形状数据（JS 一份）、生成物、`swimProfile` 的一个分支、设置页下拉一项、测试与验收脚本**——这是 Step A 建这条管线时要验证的事，Step B 是第一次真正检验它。
- **唯一的新机制是 `squash`（拍翼）**，加在已有的 `motion` 上，是可选字段（默认 0），所以小锤头鲨和所有已有数据逐位不变（生成物里小锤头鲨的尾鳍是 `squash: 0`）。
- 验证工具：`species-render.mjs` 的期望值多了一份拍翼公式（有意与形状模块各写一份，见下）；`ping` 的 `displaysActive`；两个冒烟脚本对休眠显示器的识别。

## 关键决定与理由

1. **拍翼 = 同一个转轴上的 y 向缩放，不是分块转动。** 设计稿写的是整片翼 `scale(1, 1−0.14·flap)`；实现把它做成通用的可选字段 `motion.squash`（0…`MAX_SQUASH = 0.3`，默认 0）：在 `wave ∈ [−1, 1]` 的相位上，绕 `pivot` 先把 y 缩放 `1 − squash·wave`，**再**绕同一个 `pivot` 转 `maxAngle·wave`。分块转动会在翼的接缝处裂开，缩放不会；先缩放后转动，是让“只转不缩”（尾巴，`squash = 0`）与“只缩不转”（翼，`deg = 0`）都能表示成同一条公式的特例。`wave = 0` 是空操作（静态形状就是数据本身）。蝠鲼的翼取 `squash = 0.1`，比设计稿的 0.14 小——这个数是美术取值，没有量化依据（没做过对比实验；验收时用离屏渲染的联系表——把各姿态拼成一张图——目测过形状），**观感要用户确认**。
2. **非法的 `squash` 让这个物种不可用，而不是被夹到合法范围。** 非数字、非有限、负数、大于 0.3 的值：JS 的 `expand/native/bounds/union` 返回 `null`，Swift 的 `SpeciesGeometry.init?` 返回 `nil`，该物种 `isAvailable == false`，原生退回水母、回执如实报告；生成器遇到坏数据以退出码 2 失败。和 Step A 对路径串的处理一致：数据坏了就整种动物不画，不猜。
3. **同一条公式在三处各写一份，各自对着不同的东西被核对。** JS 的 `movePoint`（给 `bounds`/并集算包围盒，取样 `wave ∈ {−1, −0.5, 0, 0.5, 1}`，放置按并集居中，所以最胖与最瘦的极端姿态都不会越出窗口）、Swift 的 `SpeciesMotion.apply(to:wave:)` / `transform(wave:)`（实际绘制与包围盒）、`species-render.mjs` 的 `moved`（渲染检查的期望值，**有意不借用形状模块的函数**，这样产品绘制出来的像素才是被独立核对的对象）。JS↔Swift 的包围盒与转轴、最大转角、`squash` 逐项对拍由 `test/desktop-companion-logic.test.mjs` 做。`wave` 超出 −1…1 夹到边界，非有限（NaN、±∞）当 0——这两条也有自测钉住。
4. **蝠鲼的部件分工**（`js/jelly-species-shapes.js` 的 `manta` 条目）：长尾（`limb`，`u = 0.05`，转轴在尾根，±8°，自己不缩放）→ 翼（`body`，转轴在中心，`deg = 0`、`squash = 0.1`）→ 高光 → 中央身体带（`limb`，`u = 0.55`，椭圆）→ 头鳍（`limb`，`u = 0.95`，沿 x 轴镜像）；眼睛半径 2、在 (18, ±3.6)，腮红在 (13.5, ±5.2)。取色沿用 Step A 的规则：翼是主色，身体带、尾与头鳍按位置 `u` 取色（双色时第二色，七彩沿尾→头铺开），所以 8 色 × 4 花纹对蝠鲼同样有效。
5. **游动系数用种子化模拟标定，判据与小锤头鲨同一套**（逐阶段 soon/imminent/final，水母为对照，种子 42、600 秒）：不沉到泳线以下、不越过屏幕边界；超过 60 pt 的时间 < 5%、顶到上限 < 2%；平均高度 > 3 且 < 愿意停留的高度 + 18；会水平游动（范围 > 150）；平均横向速度是水母的 0.7–1.4 倍；垂直起伏（最大纵向速度）比水母小。**蝠鲼另有两条**：平均横向速度**低于**小锤头鲨（“游得最慢”要能被测出来），且**不低于水母的 0.75 倍**（离 0.7 的下限留一点余量，不至于慢得像停住）。
   - 最终系数下三个阶段的读数：平均高度 18.3 / 27.4 / 33.9（愿意停留的高度 14 / 20 / 24）；超过 60 pt 的时间与顶到上限的时间都是 0.0%；平均横向速度是水母的 ×0.85 / ×0.80 / ×0.83（小锤头鲨 ×1.09 / ×1.02 / ×1.09）；最大纵向速度 22.5 / 15.6 / 12.8（水母 45.1 / 31.1 / 27.3）；水平范围 1258 / 1292 / 1286。
   - 走过的弯路：第一批候选（周期 1.2–1.3、横向冲量 0.6–0.8，m1–m4）平均速度都在水母的 ×0.97–1.11，和小锤头鲨几乎分不出来，其中两个在 soon 阶段平均高度只有 6.3 与 4.0（贴着泳线游）；再把横向冲量降到 0.55 会掉到 ×0.74（低于我自己加的 0.75 下限）。最后一组（周期 1.35、冲量 0.6 / 0.5、下沉 0.5、横向阻力 0.5）满足全部判据。
   - **改这些系数必须重跑逐阶段检查并同步自测与本文。** 海龟与鲸鲨的 `swimProfile` 仍是全 1，没有标定过。
6. **设置页示意图的“宽动物拟合”第一次被真实数据触发。** 示意图按宽度 84 拟合，蝠鲼并集宽 85.8 → 缩放系数 0.9785、拟合后恰好 84.0 / 100（小锤头鲨 81.9，没触发）。Step A 只用合成的宽动物测过这条逻辑，现在有真实数据的数字和 HTTP 预览里的截图（版面内完整居中）。
7. **休眠显示器的验收环境问题当作一类事故处理**（见下“验证中发现并处理的问题”第 1 条）：不是改产品，是让验收脚本在这种环境里明说“这不是验收失败”，而不是给出会误导人的超时。

## 与设计稿和计划的差异

- 拍翼写成了通用的 `motion.squash`（设计稿只说蝠鲼翼用 `scale(1, 1−0.14·flap)`），翼取 0.1 而不是 0.14，上限 0.3。这样以后别的动物（海龟的前鳍、鲸鲨的尾）也能用，且校验、对拍与变异检查只做一遍。
- 并集包围盒 85.8 × 58.0（设计稿估 82 × 61），仍在已批准的长度范围内。设计稿里的尺寸是估算；实际数字来自形状数据，由测试里的并集包围盒和离屏渲染检查共同守住。

JS 的 3 个存活者（都是等价变异）：`if (motion.squash)` 改成 `if (true)`（`squash` 为 0 时乘数恒为 1，没有可观察差别）；`squash` 校验里去掉 `Number.isFinite(squash)`（`NaN` 过不了后面的 `>= 0`，`Infinity` 过不了 `<= MAX_SQUASH`）；去掉 `typeof squash === 'number'`（`Number.isFinite('0.1')` 对字符串仍是 `false`）；**两者同时去掉**会被杀死（字符串 `'0.1'` 能通过数值比较），所以这两个守卫合起来是必需的。

## 验证中发现并处理的问题

1. **休眠的显示器会让动画收尾回调不触发，验收脚本给出“等待超时”的假失败。** 开始本轮冒烟时，“响铃结束后动物游走并消失”场景连续 5 次确定性超时。排查：`CGDisplayIsAsleep` 为真（`online = 1`、`active = 0`），键鼠空闲时间约 17200 秒，即屏幕在休眠；此时 `NSAnimationContext` 的完成回调不触发，响铃退场的“淡出后隐藏”停在半途。**这是由干预确认的**（`caffeinate -d -u -t N` 唤醒显示器后同一场景稳定通过），回调为什么依赖显示器是推断，没有读系统源码。仅 `caffeinate -u` 只能短暂唤醒（约 40 秒后又睡），要用 `-d`。处理：`ping` 新增 `displaysActive`（只读诊断）；`appearance-smoke.mjs` 里依赖动画的场景在 `displaysActive == 0` 或系统开着“减少动态效果”时**跳过并写明原因**，而不是失败；`jelly-smoke.mjs` 在开跑前探测，没有活动显示器就打印“DISPLAY_ASLEEP……请先唤醒屏幕……这不是验收失败。”并以退出码 75 结束；`until` 的超时信息里也带上活动显示器数。这不是 Step B 引入的回归（Step A 最终验证时屏幕是亮的）。
2. **变异检查暴露了两处 Swift 测试缺口**：`SpeciesMotion.squash` 的默认值（改成 1 没人发现，因为所有数据都显式给了值）、`transform(wave:)` 对非有限 `wave` 的处理（改成别的值没人发现）。已补 3 项自测（非有限与越界的 `wave`、直接构造的 `SpeciesMotion` 默认不缩放且 `apply` 等于纯旋转），两个变异体随后都被杀死。
3. **一个测试把 50 KB 字符串交给 `assert.equal`，失败时计算差异要几分钟**：变异检查里 6 个生成器变异体因此“超时”。`test/jelly-species-gen.test.mjs` 的“入库生成物与重新生成的一致”改成 `assert.ok(a === b, 说明)`（通过与失败的判定不变，只是不再做差异展示），随后 6 个变异体都在秒级被杀死。
4. **用 `sed` 提升脚本版本号漏了一处**：`settings.html` 的 `?v=` 与测试里的字符串钉子一起改了，但同一个测试里还有一条正则形式的钉子（转义点号），没被 `sed` 匹配，全量测试时才发现并改正。
5. **验证环境里遗留了我自己之前起的两个本地预览服务**（都只监听回环地址，各运行了约 7 小时：一个以本 worktree 的根目录为根，另一个以 `/tmp` 下的预览目录为根）：前者在本轮预览前发现并关闭，后者在收尾时发现并关闭；新的预览服务用完即停，`/tmp` 临时目录里指向仓库的符号链接已删除，唤醒显示器用的 `caffeinate` 也已结束。以后起预览服务要在同一步里记下 PID 并在结束时关掉。
6. 变异检查工具的两个小坑：个别手写变异体的“查找字符串”没匹配上（0 次）要改写；被信号杀死的 `node --test` 子进程要手动清理，并用 `cmp` 核对工作副本与镜像一致——仓库文件始终只在最后用 `cmp` 核对过未被改动。

## 已知边界与未做

- **只有水母、小锤头鲨、蝠鲼。** 海龟（侧视，六边形壳纹）、鲸鲨（侧视，约 60 个白斑）是 Step C/D；每一种都要标定游动系数（现在默认全 1）、加下拉选项、形状数据、示意图与测试；系统性的全量变异检查安排在 Step D。
- **美术观感需要用户亲眼确认。** 自动检查证明形状、颜色、方向、外圈与拍翼公式对，不证明“好看”；拍翼幅度 0.1 与翼的形状是美术取值（联系表目测过，没有量化依据）；检查在白、黑两种底色与自家窗口截图上做，真实壁纸叠加没有测。
- **带真实鼠标的冒烟没跑**（只跑了 `--no-mouse`）：瞳孔跟随、点一下、被抓住的真实鼠标路径对蝠鲼没有真实鼠标验证。
- 渲染检查只测静态姿态（含拍翼的两个极端相位，不含帧间过渡）、颜色只比色相；拍翼的帧间动画只有自测的数值与冒烟里 `jellyPose` 读数的核对，没有逐帧像素；腮红浓淡与 AppKit 口腕颜色没有自动检查（Step A、S1a 已记录）。
- 游动里的“平静期在泳线上休息”是水母原有行为，动物沿用：距响铃超过 10 分钟时不游动，所以只有设了倒计时（或响铃、点一下）才看得到蝠鲼游动。
- 验收环境前提：动画类冒烟需要**活动的显示器**；脚本会明说，必要时用 `caffeinate -d -u -t 900` 先唤醒（临时、会自己结束）。
- 材质、尺寸、节日换装、右键“换一只”、互动（子项目 2）、收集（子项目 4）都没做。
- 未验收：真实 Chrome 156 与真实账号（含过午夜自动换一只）、重装后的真实桌面组件与重载扩展（由用户做）、多显示器、全屏 Space、Stage Manager、VoiceOver。验收入口：设置页打开“桌面水母常驻”后，在“桌面水母形象”里选“蝠鲼”，设一个几分钟后的闹钟或倒计时，观察桌面上的动物；更新组件后须重载扩展。
