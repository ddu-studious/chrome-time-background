# AI 工作台 Laya 工具组预加载与降级

2026-09-24。Laya 只作为首轮规划前的工具目录建议器。当前接入复用已锁定的官方 `laya[serve]==0.3.11`、`convaiinnovations/laya` 多语言权重和公开 `POST /v1/systemone` 协议；自有代码仅负责固定本机端点、有限问题构造、响应校验、Gateway 控制和降级。Qwen3.8 27B 仍生成计划，`AssistantContract.validatePlan()`、Engine、Tools 仍掌握应用范围、参数、确认、版本、取消、副作用及真实回执。Laya 的概率和答案不能证明用户授权或动作完成。

## 开关与运行范围

AI 控制台的「Laya 工具预加载」有三个模式：

- **关闭（默认）**：不请求 Laya；已有规则预加载、`tools.load` 和 Qwen 规划路径保持可用。旧策略文件缺少 `layaMode` 时也按关闭处理。
- **只观察**：与 Qwen 并行做只读判断并记录结果；不改变工具目录，也不等待 Laya 才返回 Qwen 结果。
- **参与预加载**：Laya 仅可建议当前已选应用的已登记工具组；建议多于两个组时弃权。建议只增加可见的工具说明，不生成计划、不发起工具执行。现有规则预加载仍运行。

2026-09-27 起，AI 工作台输入框下方也独立显示「Laya 决策辅助」模式与简短说明，可在关闭、只观察、参与预加载之间切换；“模型”下拉框仍只选择 Qwen 等生成模型。这里的 Laya 是本机 Jev 类模型，**不是原厂 Jev 服务**。工作台从鉴权 `ai_control_get` 读取当前模式，保存前再读取最新策略版本，只改 `layaMode` 并复用 `ai_control_save` 的版本检查；切换按现有控制面语义取消正在处理的本机 AI 请求。控制面未连接或版本过旧时，工作台禁用该选择器，原规划路径继续可用。执行过程会显示本轮 Laya 是参与、只观察、弃权还是已降级，不把“配置为参与”写成“每轮实际调用”。

只对明确选定应用、带文本、尚无执行观察或已加载工具组的首轮规划请求调用。规则直接完成的简单请求、跨应用待选请求、恢复轮和没有可延迟工具组的应用均不调用。浏览器不直连 Laya，不接受用户提供的服务地址或任意模型名；服务固定 `127.0.0.1:19085`、本机令牌及已校验 `multilingual` 检查点。Laya 不自动启动，启停仍用 `./local-ai/models.sh laya start|stop|status`。

## 故障隔离

Laya 的 HTTP 错误、令牌缺失、响应格式错误、超时或目录外组，均记录 `execution.layaPrefetch` 的状态/错误码，并继续原来的规则 + Qwen 规划。参与模式最多等待 2 秒；只观察模式不等待。Laya 有独立的 `usage.json.laya` 预算与连续失败冷却，沿用控制台的每日上限、失败阈值和冷却时长，但不消耗 Qwen 的计数。冷却或预算耗尽时直接走原路径。控制台 `GET /v1/control` 展示 Laya 模式与独立用量；最近运行记录保留无正文的降级状态。

用户取消或策略版本变化不是可继续的服务故障：现有 Gateway/HTTP job 会使本轮请求失效，不允许迟到的 Laya 或 Qwen 结果更新任务。切换开关会按原有控制台语义取消未消费请求；下一次提交使用新模式。Laya 不接触提醒确认、pi 自动确认、音乐 revision、`unknown` 写回执或业务工具调用。服务故障降级是可观察的，不能被写成 Laya 成功。

## 验证与启用条件

`test/local-ai-laya-prefetch.test.mjs` 覆盖默认关闭/持久化/回滚、只观察不阻塞、参与预加载、过宽弃权、服务故障和目录外输出降级、独立计数损坏、预算隔离、熔断、2 秒超时、取消、策略切换、官方 HTTP 格式和提醒规则误路由。真实本机 Laya CPU 服务已核对就绪；四条短合成音乐请求的 HTTP 端到端耗时约 1.16–1.82 秒，其中「把队列里的第二首歌去掉」建议四组，「看看更多音乐搜索结果」未建议所需 `music.library`。一次真实 Laya + Qwen 替身的 Gateway 规划验证了过宽建议被弃权，Qwen 仍收到原工具目录。这只是短样本的只读推理，不是质量或完整任务提速验收；因此策略保持默认关闭，参与模式不建议在日常任务上启用。

本机 AI 服务更新时，第一次 `service.sh restart` 在 launchctl bootstrap 阶段返回错误并使旧实例停止；随后 `service.sh start` 按现有恢复流程成功。恢复后的鉴权 `/v1/control` 已确认服务就绪、无运行中 job、策略 revision 仍为 6、`layaMode=off`、独立 Laya 用量为 0。扩展页面需重新加载才能显示新的控制台下拉框；本轮未打断正在使用的 Chrome 页面。
