# 工作台打开性能与缓存复核

日期：2026-10-20。用户要求复核上下文修复、尤其缓存命中，并修复工作台出现前的载入白条和等待。

## 发现与修改

截图白条来自 `assistant-overlay.js`：等待 `assistant_ready` 超过400ms时，宿主在卡片上方叠了64px高、浅色半透明且不断动画的载入条。HTML/CSS先绘出，脚本与草稿读取尚未完成时就会遮住卡片标题。原代码已经不等模型和控制面就绪，但仍等 `chrome.storage.local.get(DRAFT)`；正式页面还需要加载11个经典脚本。

确认并修复了一个实际竞争问题：用户在草稿读出前点击输入框并打字，迟到的旧草稿会覆盖这段新文字。仅隐藏白条无法修复这个问题。

本次调整：

1. 完成事件注册与基本渲染就通知宿主可编辑。草稿、任务快照、模型目录和策略读取并行，均不阻塞输入焦点。
2. 迟到草稿只有在用户尚未编辑/选择且输入框仍为空时才能恢复。模型目录先返回时，恢复草稿后重新投影保存的模型选择。若草稿尚未读出且用户未编辑，关闭浮层只关闭，不写入空草稿。
3. 第一次任务快照返回前允许编辑，执行与新需求清空按钮暂不可用，回车也受同一判断约束；显示“读取任务中，可先输入”。服务端确认、版本、任务与unknown边界仍由原执行器拥有。
4. 初始化/聚焦引起的策略读取、存储变化/心跳引起的快照读取，各自合并同一时刻的未完成请求。请求完成后下一次读取仍取最新状态，不使用过期策略或缓存执行结果。
5. 载入反馈改为卡片上方的小状态提示，移除遮挡白条、额外模糊和无限动画。15秒上限、主动收起、超时兜底、来源与nonce核验继续保留。
6. 固定 `esbuild@0.28.1` 为本机AI工程开发依赖，使用公开 `transform` API，将原11个脚本按既有顺序合并为本地 `js/assistant-workbench.bundle.js`，只压缩空白，不转换UMD为CommonJS运行器、不改标识符。源文件继续分别维护，产物入库且带源清单摘要；没有增加浏览器权限或远端资源。

构建前源文件190328字节，产物161638字节，约减少15%；脚本资源由11个变为1个。这是资产规模变化，不能直接换算为用户设备上同百分比的提速。

```sh
node local-ai/scripts/build-assistant-ui.mjs
node local-ai/scripts/build-assistant-ui.mjs --check
```

`test/assistant-ui-bundle.test.mjs`重新生成并核对产物，防止只改源代码却让扩展继续加载旧文件。`assistant-preview.mjs`展开相同源清单后插入Chrome/业务替身；同时补齐其原先漏放行的Todo、队列策略等脚本。真实扩展加载的是单文件产物，不能把展开预览的请求数当作生产请求数。

esbuild为项目原有公开构建工具，本次固定到已有pi工具链同版本0.28.1，MIT，安装未执行脚本。npm审计仍为之前的pi、undici、brace-expansion三项，没有新增告警。[公开API说明](https://esbuild.github.io/api/#transform)。

## 缓存复核

上一轮已修复的准确计数、短来源跳过摘要、无收益摘要不覆盖检查点仍在，测试通过。本轮未改变模型提示文本、静态前缀、规划思考策略或模型驻留设置。

当前统计要分清三个口径：

- 真实使用、修复前的当天19次请求：缓存token占比18.8%，包括短请求、清单分析、摘要和冷启动。
- 上一轮隔离的推荐音乐完整流程：6次请求中4次命中，缓存token占比41.4%。
- 其中已有相同前缀的后4次执行规划：每次实际命中2048 tokens，合计占输入约53.8%。剩余包含动态工具目录、回执等。整体比例低于该数字有明确的冷启动与请求组成原因。

不能拿混合日常与测试的整日日志合计27.3%证明修复后日常命中提升。查询本次已重载之后（15:45起）至检查时的日志，没有新的生成请求，因此暂无新真实业务样本。`inspect-prompt-cache.mjs`已增加时间窗口，按日志本地时间的缓存恢复时刻筛选；没有样本显示null，不冒充0%。

```sh
node local-ai/inspect-prompt-cache.mjs \
  --since=2026-10-20T15:45:00 --until=2026-10-20T16:59:59 \
  ~/.lmstudio/server-logs/2026-10/2026-10-20.1.log
```

后续需要在真实工作流里观察同一场景、相近长度、相同思考档位的命中与新算token，避免把反复重放测试的暖缓存当作日常水平。当前不为凑缓存检查点填充规则，也不强制大模型常驻；模型卸载会清除其缓存。冷模型首请求仍采用明确标记的保守估算，SDK模板与生成接口计数差异仍用512余量保护，详见 [上下文修复记录](assistant-context-fix-cache-20261020.md)。

本次安全自查：新增构建只处理固定本地源清单；运行时无新增权限或网络目标；编辑提前就绪不提前授权执行；草稿竞争、取消、来源校验和原有写入边界保留。没有测量整机功耗。
