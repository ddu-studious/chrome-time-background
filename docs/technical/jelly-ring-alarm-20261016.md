# 到点提醒由桌面水母报时（响铃气泡）

## 背景与用户决策

2026-10-16 用户看到原生到点提醒卡片（深色纯色底圆角面板，橙色“⏰ 时间到了”、24pt 标题、两枚系统圆角按钮、一行“当前桌面提醒 · 不切换应用”，440×250）后说样式不好看，要求一起重新设计。用户在六个不满里**全选**：太暗太闷、信息层次乱、按钮难看、没有仪式感、太大、太无趣。“要仪式感又嫌大”的矛盾按“**面积缩小，靠动效和水母出镜来补**”解决。

逐项确认的选择（可视化稿为临时文件，不入库，结论如下）：

| 问题 | 选择 |
|---|---|
| 方向 | **A 水母来报时**（水母本人带气泡），不选“右上角玻璃小卡”和“顶部灵动横幅” |
| 响铃时水母站哪儿 | **A2 游到屏幕底部正中**，点按钮后游回原位（不选“原地”和“浮到下三分之一”） |
| 气泡长相 | 采用稿面：时间最大 → 标题 → 通栏胶囊按钮；**去掉**“晚了 N 分钟 / 共 N 个”小标签，内容居中 |
| 深色模式 | **所有水母气泡一起跟随系统深浅色**（倒计时读数、点一下的详情、喝水/起身提醒、响铃） |

## 范围

- **改**：macOS 原生桌面组件里的到点提醒（`desktop-reminder/`）。旧的深色卡片界面（`main.swift` 的 `buildPanel/position/springIn`，以及标题、时间、状态三个文本和两枚按钮）删除；`ReminderPanel` 类保留，仍是水母窗口的类型。
- **Chrome 侧**：`js/alarm-desktop.js` 的 `show(session)` 只多发三个可选字段，业务逻辑、铃声、系统通知、`desktopAlarm` 的连接与动作回执路径不变。
- **不改**：闹钟与倒计时的业务、声音、网页版响铃页 `alarm-ring.html`、闹钟中心的响铃浮层。原生组件不可用或拒绝时的退路（系统通知 → `drawAttention` → 重要闹钟的网页窗口）原样保留；原生端校验不通过仍回 `ok:false`，Chrome 据此退回。
- **不做（记录为可选后续）**：停止后气泡“啵”地散成小泡泡；喝水气泡的按钮也换成胶囊样式（本次只有响铃气泡用胶囊）；网页端响铃页统一风格。

## 职责边界（不变量，沿用）

- Chrome 仍是闹钟、贪睡次数、会话结束的唯一所有者。原生端只显示与转发，不保存业务状态（只存水母窗口位置 `CompanionX`，响铃**不改写**它）。
- 按钮动作发 `action {sessionId, actionId, action, minutes}`，**收到匹配的 `actionResult` 才显示成功**；`actionId` 幂等；8 秒无回执只提示“Chrome 尚未确认，请重试或在浏览器中处理”并恢复按钮，不声称成功；迟到、不匹配的回执一律忽略。
- 响铃不使用摄像头、麦克风、`chrome.idle`，没有新增权限、网络、依赖。

## 外观规格（最终取值；与设计初稿的色值差异见“实现与验证”）

响铃气泡为水母的一种新气泡 `ring`，与已有的 `clock / note / detail / nudge` 共用窗口、尾巴、夹屏与按钮定位逻辑。

| 项 | 取值 |
|---|---|
| 气泡 | 宽 `min(300, 可见区宽 − 2·edge)`，内边距 16，圆角 18，尾巴 6 指向钟罩顶；高约 150（随内容增长，只向上、向两侧长） |
| 层次 | 时间 40pt 圆体等宽数字粗体（`clock`）→ 标题 15pt 半粗（多个提醒时 14pt 中等，一行一个名字，超过 3 个只列前 2 个，第 3 行写“等共 N 个”）→ 状态行 11.5pt（同步中/错误）→ 通栏胶囊按钮 |
| 按钮 | 高 30、圆角 15、间距 8；左“N 分钟后再提醒”（淡灰，宽度权重 1.6），右“停止”（实心青色渐变，权重 1）；`canSnooze=false` 时只剩通栏“停止”，不放占位 |
| 间距 | 时间→标题 8，标题→状态 7，→按钮 14 |
| 阴影边距 | 响铃气泡阴影模糊半径约 10，窗口 `edge` 取 28（现有 14 只够模糊半径 5）；仍以“窗口最外 8 点 alpha ≤ 1”验收，边距按 kind 区分 |
| 水母 | 沿用 `due`（到点）阶段色金黄、睁眼、“哦”嘴；按钮保持青色 |
| 涟漪 | 3 圈，周期 2.2 秒、间隔 0.73 秒，半径约 20→62、alpha 0.55→0、同水母色，画在气泡**之下**；“减少动态效果”时画成静止的两圈（alpha 0.3 / 0.18） |
| 浅色 | 底 白 0.97→(246,252,254) 0.94 渐变，金色细描边（230,176,64，α0.5），时间 `#16394f`，标题 `#1f4047`，次按钮底 α0.09 `#1f4047` / 字 `#2c4b52`，状态青 `#14708a`、成功 `#1d7348`、错误 `#bd3027` |
| 深色 | 底 (48,58,73) 0.97→(34,41,54) 0.96，金色细描边 α0.42，时间 `#f4fbff`，标题 `#e6f1f4`，次按钮底白 α0.13 / 字 `#dbe8ec`，状态 `#6fd0e6`、成功 `#7ddbb0`、错误 `#ff9087`；主按钮两种模式相同：渐变 `#14809b → #0b6b86`、白字 |
| 文案 | 主按钮“停止”；次按钮“N 分钟后再提醒”（N 来自 `snoozeMinutes`，1–60，缺省 10）；成功确认“已停止”“好的，N 分钟后再叫你”；标题缺失显示“时间到了” |

深浅色规则：去掉 `JellyView` 里强制的 `.aqua` 外观，调色板按 `effectiveAppearance` 取值，并在 `viewDidChangeEffectiveAppearance` 重绘；调色板抽成纯数据（`JellyBubblePalette`），自测计算“文字对底色”的对比度（正文 ≥ 4.5:1、大号时间 ≥ 3:1，两种模式都要过）。已有的喝水气泡按钮仍是系统圆角按钮（随外观自动适配），不换样式。隔离验收用环境变量 `TIMEKEEPER_APPEARANCE=light|dark` 强制外观（只用于测试，与 `TIMEKEEPER_REDUCE_MOTION`、`TIMEKEEPER_NIGHT_HOUR` 同类，正式使用不读）。

## 行为与流程

状态机由 `JellyController` 持有（新增 `ring`），`main.swift` 只路由 `show / hide / actionResult`（按 `sessionId` 区分响铃回执与倒计时回执）。

1. **出发**：Chrome 发 `show`。原生校验失败回 `ok:false`。常驻的水母从原位出发；没常驻的从鼠标所在屏幕可见区右边游入；正在显示倒计时的水母从当前位置出发并做一次“炸开”（`burst`）。
2. **落点**：鼠标所在屏幕可见区的底部正中。游动用距离相关的时长（约 0.7–1.4 秒）与三次缓动，钟罩按 0.5 秒节奏收缩、随水平速度倾斜。缓动是 `JellySwim` 里的纯逻辑。
3. **到位**：水母停在泳线上（窗口不再上下晃，按钮不会从鼠标下跑掉），气泡带弹性弹出（约 0.32 秒），涟漪开始循环；钟罩收缩与触手摇摆只是视觉，不移动窗口。**弹出后 0.5 秒内忽略点击**，防止用户正好在点别处时误触。
4. **操作**：点按钮发 `action`，进入同步中（两个按钮变灰，状态行“正在同步到 Chrome…”）；成功回执 → 显示“已停止”或“好的，N 分钟后再叫你”约 1.2–1.6 秒；失败或 8 秒无回执 → 红字并恢复按钮，铃声与涟漪继续。
5. **收尾**：水母游回。常驻，或没常驻但仍有倒计时（下一个闹钟）→ 回到响铃前的位置，继续休息或显示读数；没常驻且没有倒计时 → 游向右边后消失。收到 `hide`（Chrome 在别处处理了，如通知按钮或网页）同样收起并游回，不显示确认语。
6. **用户拖动水母**：以拖到的位置为准，不再覆盖；响完回到放下的位置（`CompanionX` 由既有的拖放逻辑更新，响铃自身不写）。
7. **同一会话重复 `show`**（重连后 Chrome 重发）：只更新内容，不重新播放入场、不重新计 0.5 秒。**不同 `sessionId`** 替换内容，旧会话的 `hide/actionResult` 忽略。
8. **优先级**：`bubbleKind` 增加 `ring`，高于 `nudge`。响铃期间到来的喝水/起身提醒气泡直接拒绝（回 `false`，Chrome 退回系统通知）；倒计时读数让位；`shouldShow` 加入“有响铃”。原先“响铃时提醒卡片接棒、倒计时气泡让位”的逻辑与 `isRinging` 回调随卡片删除。
9. **减少动态效果**：水母不游动，直接淡入到底部正中；涟漪静止；其余不变。
10. **多显示器**：落点取鼠标所在屏幕；水母若在别的屏幕，在原屏上直接隐藏（不记位置），再从目标屏幕泳线右端淡入（设计稿写的是“先在原处淡出”，实现为直接隐藏，见“实现与验证”）；返回时回到响铃前的横坐标（夹进当前屏幕泳线）。
11. **状态栏“显示当前提醒”**：响铃进行中把水母重新游到落点；没有响铃时保持原行为（刷新水母可见性）。**`--demo`**：以测试数据直接显示响铃气泡，点任一按钮后退出进程（沿用卡片时的行为）。
12. **无障碍**：胶囊按钮是真正的 `NSButton` 子类（键盘与辅助功能可用，帮助文字含时间与标题）；响铃出现时发 VoiceOver 播报（`announcementRequested`，**未做真机验收**）。

## 协议（仍为 v6，向后兼容）

`show` 命令新增三个**可选**字段，旧扩展不发时原生自行兜底，旧组件忽略它们：

| 字段 | 内容 | 校验与兜底 |
|---|---|---|
| `clock` | 计划时间 `HH:mm`（Chrome 用 `session.scheduledAt` 按 `zh-CN`、`hourCycle: 'h23'` 本地格式化，避免午夜出现 24:xx） | 只认 `^\d{1,2}:\d{2}$`；缺失时从 `timeText` 里取第一个同格式片段；仍没有就不画大时间，标题放大 |
| `labels` | 最多 3 个提醒名字，每个清洗后 ≤ 40 字符 | 缺失时用 `title` 整段作为单个名字（清洗后 ≤ 80 字符，最多 2 行） |
| `more` | 超出 `labels` 的个数 | 整数夹在 0…99，非数字按 0 |

既有字段与校验不变：`sessionId` 非空 ≤ 200、`title` ≤ 320 字符、`canSnooze` 只有明确 `true` 才算、`snoozeMinutes` 夹在 1…60。回执 `respond()` 新增 `ringId`、`ringBusy`、`ringButtons`（按钮屏幕坐标，供验收脚本做真实点击）、`ringFrame`，`jellyBubble` 可取 `"ring"`；原有 `visible / onActiveSpace / focusStayed` 改为反映响铃气泡与水母窗口，`countdown*` 字段保持。

## 风险与边界

- **位置不如右上角显眼**：底部正中靠游动、涟漪、铃声和系统通知补偿；“人是否容易注意到”无法自动验证，需要用户实际使用后判断。
- **气泡弹在鼠标附近的误触**：0.5 秒内忽略点击缓解，不能完全消除。
- **响铃期间每秒 30 帧重绘**（涟漪）：只在响铃期间，减少动态效果时为零。实测原生进程 CPU 约 5–10%（`top` 区间采样均值，每次运行一个样本，随机器负载浮动；未做优化，仅记录，不是性能验收）。
- 泳线沿用“可见区底边”：Dock 在左右侧、自动隐藏、Stage Manager、刘海屏的实际表现未验收。
- 真实 Chrome 156 整条链路、真实闹钟到点、全屏 Space、VoiceOver 播报未验收；多显示器只在本机两块屏幕（一块 2×、一块 1×）上用合成鼠标验证过“水母在 A 屏、指针在 B 屏时响铃”这一个场景。
- 所有水母气泡随系统深浅色，会改变现有倒计时/详情/喝水气泡的外观，是用户明确选择的范围。

## 实现与验证（2026-10-16）

### 做了什么

- **Chrome 侧**：`js/alarm-desktop.js` 的 `show` 多发 `clock`（`AlarmDesktop.clockText`，只接受 `H:mm/HH:mm`，区域设置把结果变成“上午09:30”之类时当作缺失）、`labels`（≤3 个名字，每个 ≤40 字）、`more`（0…99）；响铃会话结束后 `holdUntil = 现在 + 5 秒` 内不因空闲断开连接。其余业务、铃声、通知、`alarm-ring.html`、降级路径不变。
- **原生侧**：新增 `jelly-palette.swift`（配色与对比度，纯逻辑）、`jelly-ring.swift`（响铃版式、气泡绘制、胶囊按钮）；`jelly-model/swim/companion/controller`、`main.swift` 改接响铃；旧卡片界面与 `jelly.isRinging` 回调删除；`mouse-helper.swift` 增 `screens` 子命令（只用于验收）。所有水母气泡去掉强制 `.aqua`，随系统深浅色。
- **复用**：水母窗口的内容增长/夹屏/气泡尾巴与按钮定位、`nudge` 的“等回执 / 8 秒重试 / 回执只认匹配 actionId”、`due` 阶段色、`burst`、`TIMEKEEPER_*` 隔离钩子、合成鼠标与窗口外圈 alpha 检查；没有新增权限、网络、依赖。

### 与设计稿的差异（实现时的取舍，以此为准）

存活者逐个说明：

- **Chrome `c16`（等价）**：拿掉 `clockText` 里 `Number.isFinite(date.getTime())` 的提前返回，无效日期的格式化结果是 “Invalid Date”，后面的 `^\d{1,2}:\d{2}$` 正则同样拒绝，两道检查冗余。
- **AppKit `a13`（等价）**：`ringArrived` 里的 `ringToken == token` 检查。落点冲刺只有 `dashCompletion` 一个槽位，新的冲刺会替掉旧的完成回调，旧回调不可能再来，该检查是纵深防御。

- **AppKit `a25`（无法观察）**：去掉 `NSAccessibility.post(…announcementRequested…)`。没有 VoiceOver 或辅助功能观察者就看不到这一调用；播报文字本身由纯函数 `ringAnnouncement` 的自测守住（并有 4 个变异体，全部被抓到）。

### 验证中发现并修复的缺陷

1. **回家路上被隐藏后残留旧“家”**：水母响完正在游回响铃前的位置，此时取消常驻（或倒计时结束）把它当场隐藏，`ringReturning/ringHomeX` 没清；下一次响铃会沿用过期的家并把“路过的位置”当成记住的位置。由 AppKit 层变异检查 `a18` 存活后补的场景（回家路上取消常驻 → 改记另一个位置 → 再响一次）暴露，修复为隐藏分支同时清掉两者，并补了 `a35` 变异体确认该场景会失败。
2. **读屏播报重复“时间到了”**：没有名字时标题行本身就是“时间到了”，旧拼法会读成“时间到了，09:30，时间到了”。抽成纯函数 `ringAnnouncement` 时发现并修复，补了自测。
3. **Chrome 先 `hide` 后回执**（联调发现）：见上“差异 8”。
4. **验收脚本自身的两处问题**：“拖开水母”场景的容差按“距离的四分之一”算，快甩时松手速度被夹在 260 pt/s、水平阻尼 1.2/s，水母最多再滑行约 217 点，距离小于约 870 时必然超出容差——改为不小于 280 点；`screencapture` 偶发给出 1×1 图像（原因未查明），改为最多重试 3 次，仍取不到则报告跳过、不当作通过。

### 间歇失败的原因：指针被外部挪动

水母按**鼠标指针所在屏幕**选落点，验收脚本又依赖真实合成鼠标。本机有两块屏幕，收尾验证期间出现过两类间歇失败：① 无鼠标的响铃场景里水母忽然出现在另一块屏幕（场景中途指针被外部挪到了另一块屏幕，自家窗口截图的像素倍数从 2× 变成 1× 可以看出屏幕变了）；② 真实点击到按钮正中央却没有送达。把指针停在固定屏幕上重跑同一批场景全部通过（主屏 / 外接屏各一次），整轮冒烟第二次运行通过。没有证明是谁挪动的指针；已让失败信息带上原生端看到的指针位置与屏幕数，下次可以直接判断。**运行验收脚本期间请不要碰鼠标**。
