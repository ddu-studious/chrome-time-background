# 首页触感实验：壁纸转场、液态时钟、弹簧手感、揉纸入篓、水母背景与解压果冻

> 文件名沿用首轮的 `touch-feel-weave-liquid-clock-20261014.md`（代码注释与 `AGENTS.md` 已引用，不改名）。
> 全部在实验分支 `experiment/touch-feel-20261014` 上开发，**未合并、未提交**。

## 1. 来源与取舍

灵感来自 X 上 [一条分享 7 个“触感”网页交互实验的推文](https://x.com/Xian0063/status/2110315122627620977)。
核对结果（2026-10-14，GitHub API 与实际观看视频抽帧）：

| 项目 | 许可证 | 本次处理 |
|---|---|---|
| Unwoven（图像编织） | MIT | 借用创意；**不复制代码**（它用 three r128 + gsap 的 CDN 脚本，MV3 不能加载），自行实现，并扩展为 8 种转场 |
| Fluid Glass（液态玻璃，视频里“时间被划坏又恢复”的那个） | **无 LICENSE** | 只借用“划过去会变形、停手后自愈”的创意，不读取、不复制其代码，用公开的通用技术（阻尼波动方程）自行实现 |
| Aurelia（水母） | MIT | 借用创意；原作用 three + WebGPU，这里不引入，用 Canvas 2D 自写简化版，做成背景皮肤 |
| Paper Crumple（揉纸） | MIT | 借用创意；不复制代码，自写几何与时间线，做成任务完成动效 |
| Squishy（果冻） | **无 LICENSE** | 只借用“软体手感”的创意；物理（Verlet 轮廓 + 形状匹配）自写 |
| Disfigure / Textile Alchemy | MIT / 无源码 | 没有做，见“后续” |

视频里 Fluid Glass 的视觉是“水珠状玻璃”，本实现是“涟漪 + 涂抹”的液态玻璃，**效果相近但不相同**。

## 2. 范围

| # | 功能 | 位置 | 开关 |
|---|---|---|---|
| 1 | 壁纸转场（8 种，默认每次随机） | 首页换壁纸时 | `wallpaperTransition`（`'on'` 默认 / `'none'`）+ `wallpaperTransitionStyle`（`'random'` 默认 / 某个风格 id） |
| 2 | 液态时钟 | 首页时间、日期、农历、节日整块文字；触发带与画布横向铺满视口 | `clockLiquid`（默认 `true`） |
| 3 | 弹簧手感 | Dock 拖拽排序回弹 + 7 个面板的入场 | 无独立开关，尊重 `prefers-reduced-motion` |
| 4 | 任务完成揉纸入篓 | 任务条目勾选完成时 | `taskCrumple`（默认 `true`） |
| 5 | 水母背景皮肤（八色七彩，纯色与多色都有；一只水母对应一个待办，可抓去完成） | 背景视觉效果新选项 | `visualEffect: 'jellyfish'`（默认不选中）；任务名与抓取另有 `jellyfishTasks`（默认 `true`，设置页“水母显示任务名，可抓去完成”） |
| 6 | 解压果冻 | 游戏中心第四款；番茄钟专注自然结束后的“歇 60 秒”提示 | `localStorage.jellyRestOffer`（`'off'` 关闭提示，默认开） |

字段都在 `backgroundExperienceSettings` 里（功能 6 的偏好另存 `localStorage`）。“启用背景体验”总开关关闭时，功能 1、2、4、5 都不生效（该开关的既有含义是“只保留原始壁纸或视频”）。设置页的“壁纸转场”是一个下拉框，取值 `none | random | 某个风格`，落到上面两个字段（`choiceFromSettings` / `settingsFromChoice`）。旧版保存的 `wallpaperTransition: 'weave'` 与新值 `'on'` 都视为开启。

## 3. 设计

### 3.1 为什么不用 three.js

仓库已有 `vendor/three/three.module.min.js`（0.170.0，3D 俄罗斯方块用）。但壁纸转场只是一个全屏四边形 + 片元着色器，three 约 700 KB 且是 ES Module，要为一次 1.5 秒的动画加载它不划算。因此转场直接用原生 WebGL（无依赖）。液态时钟、水母、果冻都用 Canvas 2D：没有 CORS 限制、不占 GPU 上下文、核心可在 Node 中测试。

### 3.2 壁纸转场

模块：

- `js/wallpaper-weave-core.js`：纯函数（是否适用、风格注册表、随机选择、`cover` 铺放换算、分带延迟、缓动），UMD，Node 可测。
- `js/wallpaper-weave.js`：DOM + WebGL 控制器，全局 `WallpaperWeave`。

**风格**（id 即设置里保存的值与着色器的键；`weave` 排第一，也是着色器失败时的回退）：

| id | 名称 | 时长 |
|---|---|---|
| `weave` | 编织 | 1600 ms |
| `ripple` | 水波 | 1500 ms |
| `swirl` | 旋涡 | 1500 ms |
| `mosaic` | 马赛克 | 1400 ms |
| `ink` | 水墨 | 1800 ms |
| `zoom` | 穿越 | 1300 ms |
| `blinds` | 百叶窗 | 1300 ms |
| `flip` | 方块翻转 | 1600 ms |

**选择**：`pickStyle({ preference, previous, exclude })`——设置为具体风格就固定使用；`random`（或任何未知值，升级后旧设置、被手改的值都安全）时在可用风格里随机，**不与上一次连续重复**，排除本页已确认编译失败的风格；只剩一个就用它，一个都没有就回退 `weave`。每次播放另有由种子决定的随机参数（中心点、斜向方向、百叶窗朝向），着色器只读。

流程（`main.js` 的 `changeBackground` 接入，`_applyBackground` 语义不变）：

1. 仅当：当前与目标都是静态图、设置未关闭、未 `reduce-motion`/`saveData`、页面可见且未被工作台遮挡、WebGL 可用、两张图的来源没有被标记为“不可跨域读取”。
2. 以 `crossOrigin='anonymous'` 加载目标图（限时 6 秒）；失败则把该 URL 记入本页的“不可跨域”集合，直接走原来的 `_applyBackground`（**没有任何视觉回归**）。
3. 在 `z-index:0`（与 `#background-video` 同层，位于 `body::before` 压暗层之下）放一个 `<canvas>`，用选中风格的着色器播放；某个风格编译失败只把它记入排除集合，下次不再选它。
4. 结束后先 `_applyBackground(target)`（设置 body 背景、署名、背景体验的 detail 层等全部沿用原逻辑），下一帧让画布淡出并释放 GL 资源。

取消：新的 `changeBackground`、被遮挡/隐藏、设置变更、`_applyBackground` 被其他路径调用，都会取消正在进行的转场（旧回调靠运行序号失效，不能覆盖新背景）；WebGL 上下文丢失则直接收尾。动画期间页面被遮挡时不空转。

### 3.3 液态时钟

模块：

- `js/clock-liquid-core.js`：纯模拟与渲染函数。
  - 高度场：阻尼波动方程 `v += c²(avg4(h) − h); v *= damping; h += v`，边界吸收。
  - 涂抹场 `(sx, sy)`：鼠标速度推动，指数衰减并轻微扩散（这是“划坏”的主要来源）。
  - 渲染：偏移 = 涂抹 + 梯度折射；高光/暗边由高度梯度计算。活跃格才做双线性取样，静止格直接复制。
  - `isSettled` 判定自愈完成。
- `js/clock-liquid.js`：控制器，全局 `ClockLiquid`。

交互：`pointermove` 落在时钟文字区域并且移动足够快时，才启动；用 `Range`/`measureText` 量文字范围，覆盖一块 `<canvas>`，把文字设为透明，画布自己绘制同样的文字（字体、字号、字距、颜色读取 `getComputedStyle`）。文字每秒变化时用 `MutationObserver` 刷新源文字。静止后画布淡出、DOM 文字恢复。

**2026-10-15 扩大范围**（用户反馈“还挺好玩的，可以范围一些”）：

- 作用对象从只有 `#time` 扩大为**整块**：时间、日期、农历、节日四行的并集（带短缓存，避免每次移动都强制布局），这一整块像压在同一层液态玻璃下被涂抹。
- 笔刷随速度变大：`brushGrowth 0.85`，快速划动时涂抹/涟漪半径最多放大到 1.85 倍（`brushFor(speed)`）。
- 渲染成本控制：第一轮是整块区域同时被搅动时每帧逐像素取样，耗时与画布像素数成正比，当时画布总像素上限是 `MAX_PIXELS = 1,000,000`（第二轮改为分层渲染并提高到 2,400,000，见下一节）；单帧渲染（含上传）平滑耗时超过 `SLOW_RENDER_MS = 11` 就隔帧绘制，物理仍按真实时间推进，降到 `FAST_RENDER_MS = 7` 以下恢复。
- 收尾：能量低于 `tailPeak 0.2` 时改用更大的阻尼尽快收尾；新增回复力 `leak 0.004` 把整体下陷的“平台”也拉回水平（均匀下陷没有梯度，光靠扩散要十几秒）。
- 空闲预热：页面空闲（`requestIdleCallback`，超时 5 秒）时用一块 8×8 小画布提前付掉首次创建的成本，否则第一次划到时钟时会肉眼可见地卡一下；预热失败不影响功能。

**2026-10-15 第二轮：横向铺满视口 + 分层渲染**（用户反馈“液态时钟：横向改成全屏幕吧”）：

- 理解为：画布与触发带**横向铺满整个视口**（`left: 0`，宽度取 `documentElement.clientWidth`，不含滚动条，取不到再用 `innerWidth`；两者都量不到就不启动，绝不留下透明的时钟），纵向范围没有改动，仍是文字块上下各外扩 `PAD = 64`。从屏幕任意横向位置划过时钟那一行（纵向落在文字块上下各 `TRIGGER_MARGIN = 14` 以内，且指针真的落在页面上、没被浮层盖住）都会触发；涟漪与水痕留在整条横带上；文字被推走的距离仍受 `PARAMS.maxSmear = 64` 限制。
- 铺满之后的性能回退：单层逐像素渲染（`Core.render`）在 1512 CSS px 宽的 2 倍屏上约 20–22 ms/帧，86% 的帧超过 `SLOW_RENDER_MS = 11`，一划就进隔帧绘制、效果变粗（真实 Chromium、无头软件渲染实测；JS 部分对这台 Mac 有代表性，GPU 光栅成本没有）。
- 做法（`Core.renderLayers`；`Core.render` 保留为参考实现与测试基准，不删）：
  - **文字层**：只有“文字附近”的像素需要取样位移与高光。附近矩形 = 文字包围盒（`Core.textBounds` 扫描源图 alpha 得到）± 当前最大位移 + 2 px 余量；只处理这个矩形，并用脏矩形 `putImageData` 上传。
  - **涟漪层**：暗边与高光不需要取样，每格（`CELL = 3` CSS px）一个非预乘 RGBA 像素，画在不进 DOM 的 cols × rows 小画布上，由 `drawImage` 双线性放大铺满整幅（与核心里“像素到格子”的映射同一对齐、边缘钳位），再叠在文字层上；场里没有可见涟漪时这一层整个不画。
  - 每帧成本只与文字块大小有关，不随视口宽度增长；静止首帧在挂进页面之前画好，避免闪。
- 画布像素上限 `MAX_PIXELS` 由 1,000,000 提高到 2,400,000：整行铺满后，14/16 寸 MacBook 的 2 倍屏约 2.0–2.4M 像素，上限不能低于它，否则一唤醒文字就从原生分辨率掉到约 1.4 倍而发糊；超宽屏才会降分辨率。
- 实测（真实 Chromium，HTTP 预览，无头软件渲染，1440/1512 宽 × 1 倍/2 倍多种配置）：每帧渲染平均 ≤ 4.5 ms，超过 7 ms 的帧 0%（不再触发隔帧绘制）；一次唤醒（首帧）≤ 17 ms；与单层参考渲染逐像素比较，均值差 ≤ 0.6 级（8 位）。单元测试里合成结果与 `Core.render` 的容差为：均值 < 1 级、差 > 8 级的像素 < 0.5%、最坏 ≤ 24 级——来源是涟漪层的 8 位量化与二次舍入（用拆解脚本确认不是缺陷）。
- 变异检查：32 个变异体抓到 31 个。幸存的 K6（去掉近区外扩的 `+2` 浮点余量）是等价变异体：推导上取样点不会越过该余量，并用 3000 个随机场景验证 0 次违反。两个真实的测试缺口都在变异时暴露后补了测试：K10（暗边不计入“可见”，只有暗边可见的场被整层丢弃）、K16（`textBounds` 尾部少扫一格，补了相邻两像素与整行用例）。
- 验证方法的坑：Playwright 的 `page.screenshot` 会把视口重置为默认并触发 `resize`，控制器按设计立刻停止，所以性能测量不能夹带截图；截图要在测量之外单独拍，并先 `Emulation.clearDeviceMetricsOverride`。

约束：

- 空闲时**零成本**：没有 RAF、没有定时器，只有一个被动 `pointermove` 监听，且命中文字区域前提前返回。
- 唤醒背景玩法（`BackgroundExperience.active`）、按下鼠标、`reduce-motion`、`saveData`、页面隐藏、工作台遮挡时不触发；运行中遇到这些状态立即收尾并还原文字。
- 画布 `pointer-events:none`，不改变时钟的任何交互。

### 3.4 实现后的调整（真实 Chromium 截图驱动）

1. **文字对齐**：Canvas 2D 不支持 `font-variant-numeric: tabular-nums`，数字“1”在画布里比 DOM 窄，约错位 8 px。改为用 `Range` 逐字符量出 DOM 里每个字符的格子，画布按格子中心（`textAlign:'center'`，扣除字距）绘制。
2. **效果强度**：第一版的涂抹场半径 6 格（约 18 px）远大于笔画粗细，数字像整体平移而不是被撕扯，截图里数字几乎没变。现在集中在 `PARAMS`：`smearRadius 4.5`、`splashRadius 4`、`smearDecay 0.952`（约 1.3 秒衰减到 1/10）、`smearDiffuse 0.1`、`maxSmear 64`，推力系数 0.55→1.1，折射/高光/暗边加强。**调整参数必须以真实浏览器截图判断，不能只看单测。**
3. **高刷屏**：120 Hz 下一个渲染帧不一定凑够一个 60 Hz 模拟步；没有前进的帧不再重绘，也不计入“静止帧数”。
4. **转场肉眼调整**：`flip`（方块翻转）与 `blinds`（百叶窗）按肉眼检查调柔；八种风格都在真实 Chromium 里做过着色器编译、起止端点、帧间连续性、联系表比对、`play()` 路径、结束清理与帧率检查。

### 3.5 弹簧手感

模块：`js/spring-feel.js`（公式与 FLIP）、`css/spring-feel.css`（令牌与各面板样式）。

- 阻尼弹簧的单位阶跃响应 `x(t) = 1 − e^(−ζωt)·(cos ωd·t + ζω/ωd · sin ωd·t)`，采样 56 点生成 CSS `linear()`；三档预设：`snappy`（ζ 0.72、0.42 s，约 3.8% 过冲）、`soft`（ζ 0.56、0.6 s，约 12.6%）、`bouncy`（ζ 0.38、0.75 s，约 27.5%）。不支持 `linear()` 的浏览器（Chrome < 113）退回单次过冲的 `cubic-bezier`。
- CSS 里的 `--spring-*` 令牌由 JS 公式生成，`test/spring-feel-css.test.js` 校验两边一致；不要手改曲线数字，改 `PRESETS` 后按测试提示重新生成。
- **只作用在独立的 `scale` / `translate` 属性上**，与 `transform` 叠加而不是覆盖：群组弹层被 JS 写了内联 `transform: translateX(-50%)`，Dock 的放大/果冻效果会逐帧写按钮的内联 `transform`。
- 只覆盖“打开”状态的 transition（入场用弹簧），关闭状态保留短促的 `ease`，离场不拖泥带水。
- 覆盖对象：Dock 拖拽排序（目标按钮让位 + 松手后 FLIP 回弹）；7 个面板入场——应用启动台（soft）、群组弹层（snappy）、休闲游戏、诗词电台、常用信息详情、写作空间弹窗、闹钟中心。
- `prefers-reduced-motion: reduce` 下不缩放、不位移，沿用各面板原有的淡入淡出。`spring-feel.css` 必须在 `dock-manager.css`、`product-ui-v4/v5.css`、`alarm-center.css` 之后加载（同权重按顺序覆盖）。
- 修过的一个问题：游戏中心等面板首次创建后同步加 `visible`，浏览器来不及提交“关闭态”样式，第一次打开没有入场过渡；`ensurePanel()` 里用 `void panel.offsetWidth` 先提交关闭态。

### 3.6 任务完成揉纸入篓

模块：`js/task-crumple-core.js`（几何与时间线）、`js/task-crumple.js`（DOM 控制器，全局 `TaskCrumple`）、`css/task-crumple.css`。

- 用户点任务条目的勾选框时，那张卡片的**视觉副本**揉成纸团、划一道抛物线（飞行 ≤ 620 ms）扔进右下角的纸篓，落下后纸篓晃一下。纸篓分前后两层 SVG，纸团夹在中间，下落时像掉进篓里；只用纯色填充（多组同时出现时 SVG 渐变 id 会重名）。
- **纯视觉层**：只读 DOM（位置、样式、克隆），不读写任何任务数据、不改 `memo.js` 的完成流程；完成与否仍由 `memo.js` 决定。列表重绘后用 `.completed` 条目确认“确实完成了”，没确认就撤掉动效。
- 同时最多 3 组（`MAX_ACTIVE`），更多的完成动作只正常完成、不再播动效。受 `taskCrumple` 开关、总开关、`reduce-motion` 控制。
- **借给水母皮肤的纸篓 `TaskCrumple.holdBin()`（2026-10-15 第三轮）**：用户抓着水母时，皮肤向它借同一个纸篓当落点。句柄只暴露 `mouth()`（纸篓口坐标，水母被吞时游向这里）、`rect()`、`contains(x, y)`（是否在落点范围）、`setNear(on)`（对准时放大到 `NEAR_SCALE = 1.16` 并发薄荷色光）、`gulp()`（晃一下后收起）、`release()`、`isActive()`；同样是纯视觉——不读写数据，落没落进去、任务完不完成由调用方决定。复用同一个动效层、同一套槽位与几何，所以抓着水母时恰好有揉纸动效，两个纸篓会向左错开而不是叠在一起；同一时刻只留一个“抓取纸篓”，`HOLD_MAX_MS = 120000` 兜底自动收起。与揉纸不同，它**不看** `taskCrumple` 开关（那是另一个效果；落点是否启用由 `jellyfishTasks` 决定），但仍受总开关、`reduce-motion`、页面隐藏限制；不能用（被限制、槽位满、构建失败）时返回 `null`，调用方据此不开始抓取。

### 3.7 水母背景皮肤

模块：`js/jellyfish-core.js`（物理）、`js/jellyfish.js`（画法与控制器，全局 `JellyfishSkin`，只创建实例不自动启动）。

- 在背景视觉效果里新增 `jellyfish`（与 `depth/weather/memory/liquid/time` 并列，默认不选中）。画在背景体验的**共享画布**上（宿主已设 `screen` 混合，发光会叠加）；不自建 RAF 与画布，调度、隐藏即停、被工作台遮挡即停、省流量降帧都沿用宿主 `background-experience.js`。
- 数量 = 未完成且非失败的待办数（规则与首页任务滚动条一致），同屏上限 8 只（省流量 4 只）。只读 `chrome.storage.local` 的任务表，任务一变（`storage.onChanged` 自带新值）就让名单跟上；皮肤自己**不写任何数据**（唯一的写出口是下面“抓取完成”里注入的 `complete`）。第三轮起**一只水母对应一个待办**（见下）：多了从屏幕下方游进来，少了（任务在别处被完成或删除）**对应的那一只**往上游走并淡出——此前是随机挑一只。
- **颜色（2026-10-15 由 3 种改为八色七彩，每只不同）**（用户反馈“能更多颜色吗？七彩。每只颜色都不太一样”）：
  - 调色板 `Skin.PALETTE`（`js/jellyfish.js`）共 8 个色位，**按色相环顺序**排列：红 `[255,100,92]`、橙 `[255,150,56]`、黄 `[240,222,70]`、绿 `[88,228,100]`、薄荷 `[79,239,194]`、冰蓝 `[112,205,255]`、紫 `[170,111,255]`、洋红 `[245,105,225]`。薄荷、冰蓝、紫是原来的三种颜色（保留，用户已经看惯了），其余五种按亮度接近来选；相邻色相间隔 25°–72°。
  - 每只水母出生时由核心的 `pickColor(world)` 挑一个色位编号（`PARAMS.COLORS = 8`，不得小于 `MAX_COUNT`），**一生不变**：待办增减、别的水母游走、改变窗口大小都不会让已有的水母换色（不闪色）。挑法：先排除存活的和正在淡出的（淡出不到两秒，新来的不撞上它），在剩下的里取“与在场颜色在色相环（色位编号的环形距离）上最近距离最大”的，并列再随机。所以只有两只时落在半圈两端，三四只时相邻色位至少隔一个，第一只是随机起点。8 个色位被存活 + 淡出的占满时才借用正在淡出那只的颜色（存活数 ≤ `MAX_COUNT` ≤ `COLORS`，总能找到）。省流量模式最多 4 只，同样各不相同。
  - 宿主 `background-experience.js` 不再向水母传 `colors`：宿主的 `COLORS` 只有三种、是给其他皮肤用的，传过去会盖掉七彩；`frame({ colors })` 作为可选覆盖保留。
  - **测试抓不住的审美问题**：第一版把红做成偏玫红 `[255,104,128]`、粉做成 `[255,112,214]`，色相只差约 33°，“相邻色相间隔 ≥ 25°、两两 RGB 距离 ≥ 55”的测试都过了，但真实 Chromium 截图里深色底上这两只看起来一样。改成正红 + 偏紫的洋红（RGB 距离 86 → 133）后才分得开。调色板改动必须看真实截图，不能只看单测。
  - 已知：暖色（橙、黄、红）在很暗的底上偏棕/橄榄（亮度低时的黄就是橄榄色）；水母的混合方式与透明度没改，所以在暗壁纸上暖色比冷色略暗。
- **外观：纯色与多色都有（2026-10-15 第三轮）**（用户反馈“一个水母，好几种颜色？纯色和多色都有”）：每只水母出生时由核心 `pickLook(world, primary)` 定下 `look = { kind, colors }`，`colors` 是色位编号、第一个永远是 `pickColor` 挑出的主色（所以“同屏存活的主色互不相同”不变），**一生不变**。四类：
  - `solid` 纯色：只有主色；
  - `duo` 双色：钟罩主色、触须是另一种（与主色隔 `DUO_OFFSETS = [2, 3, 4]` 个色位，每位约 45°，至少 90°，一眼就是两种颜色；正反方向随机）；
  - `blend` 渐变：钟罩由边缘的主色渐变到中心的另一种、触须由根到尖也渐变（隔 `BLEND_OFFSETS = [2]` 位 = 90°；真机截图里只隔 1 位时几乎看不出在渐变，再远中段会混成灰色）；
  - `rainbow` 彩虹：三种颜色沿钟罩横向铺开——主色，再朝同一个方向（正反随机）每隔 `RAINBOW_STEP = 2` 个色位各一种（触须按同样顺序着色）。
  - 同屏**总是纯色和多色都有**：新来的补上在场（不含正在淡出的）人数较少的那一类，相同时随机；多色里同理轮流用三种样式。所以只有一只时随机，两只时一纯一多，之后大致对半。别的水母来去不会让已有的水母改变外观。
  - 画法在 `js/jellyfish.js`：`paintOf(jelly, palette)` 把外观解析成 `{ kind, a, b, c, halo }`（颜色编号对调色板长度取模；外观缺失、样式未知、颜色数不够——`duo/blend` 要 2 种、`rainbow` 要 3 种——一律退回纯色）。`duo`：钟罩用 a、触须用 b；`blend`：钟罩顶部到裙边竖向线性渐变（a→b，边线同样渐变），触须由根到尖继续渐变；`rainbow`：在钟罩路径上叠一层横向三色色带（左 a、中 b、右 c，边线同样），触须按横向位置取同一条色带；多色时体内发光用第二种颜色，钟罩底色的玻璃感让位给渐变层；光晕颜色 `duo` 取 a、`blend` 取 a 与 b 的 0.4 混合、`rainbow` 取 b。多色时触须混白的比例由 0.5 降到 0.32（真机截图里混一半时第二种颜色几乎是白的）。`PALETTE` 与 `pickColor` 的约束沿用上一条；`blend` 的色位间隔取 2 位也是看真机截图定的（只隔 1 位时几乎看不出在渐变）。
- **一只水母 = 一个待办，隐约显示任务名（2026-10-15 第三轮）**：
  - 名单由核心 `pendingTasks(memos, today)` 生成：规则与 `pendingCount` 相同（未完成且非失败，两者数量必须相等），排序与首页任务滚动条一致——过期的优先，再按优先级（高/中/低/无），再按截止日期（有日期的在前），其余保持任务表顺序。多于上限（8，省流量 4）时取前面的：任务被完成后排在后面的会顶上来，更紧迫的新任务出现时会挤掉最靠后的那只（被抓着或停在篓口等回执的水母，不管任务名单怎么变都不会被赶走——赶走了就抓不回、也没法完成）。每项 `{ key, id, label }`：`key` 在名单内唯一（数字 `7` 与字符串 `'7'` 是两个任务；重复 id 加 `~N` 后缀），`id` 是任务原 id（没有可靠 id 的为 `null`——水母照样出现，但不能被抓取完成）。
  - `reconcile(world, 名单)` 按 `key` 绑定：已有的保留（任务改名时刷新文字）、不在名单里的离开（被抓着的不离开）、新的从屏幕下方游进来；离开中的水母不会被复活（同一个任务又出现时新来一只）；传入数字（旧调用）时仍按数量对账，旧行为不变。
  - 任务名取标题（缺则取正文），空白折成一个空格，去掉控制字符与方向控制符（`CONTROL_CHARS`，防止任务名里的 U+202E 之类改变画布上的排版），空了叫“无标题”；最多约 `LABEL_EM = 9` 个汉字宽（拉丁字母、数字按 0.55 个汉字宽），超出截断加省略号，按码点迭代不拆 emoji。**文字只用 `fillText` 画在画布上**，不进 DOM、不经 `innerHTML`，所以任务名里的 HTML 不会被解析。
  - 画法（`drawLabel`）：钟罩上方居中，字号 `clamp(r × 0.3, 11, 15)` px、字重 500，颜色是主色与白按 0.72 混合；平时亮度 `LABEL_BASE = 0.34`（隐约知道是哪件事）、指针靠近（距钟罩中心 < `r × HOT_REACH(2.4)`，`jelly.hot` 0→1）时升到 `LABEL_HOT = 1.15`，透明度上限 0.95；水母贴着屏幕顶边时任务名不被切掉（`max(size + 4, …)`）。真实壁纸上平时能读出但很淡，在刻意做成很亮的壁纸（遮罩 0.55）上仍可辨认；画在背景层，会被半透明卡片盖住一部分，也可能与卡片文字重叠（既有层级，未改）。
- **抓取完成（与“任务完成扔进纸篓”合并，2026-10-15 第三轮）**（用户想法：“可以抓到水母，完成任务；就可以跟任务完成扔进垃圾桶合起来了”）：
  1. **悬停**：指针靠近一只绑定了任务的水母（抓取范围 = 钟罩椭圆 × `HIT_SCALE 1.25` + `HIT_PAD 8`，加上裙边下方一小段、不含触须），光标变 `grab`（html 上的 `jellyfish-grabbable` 类）。**只有指针在“空白背景”上才抓得到**：`isBackgroundTarget` 只认 `body/html/#background-video/.main-layout/.main-content/.time-wrapper/.time-container`，指针在任务条、卡片、Dock、时钟数字文字上时按 UI 处理，不抢点击。
  2. **按下**抓住：水母由弹簧拉到指针（`HOLD_STIFFNESS 240 / HOLD_DAMPING 26`，甩动速度上限 `THROW_MAX 900`），仍会挣扎拍动（光标 `grabbing`）。此时**不发任何请求**。
  3. **拖过 `DRAG_PX = 6` 像素**才算“拖”：这时才向 `TaskCrumple.holdBin()` 要纸篓（升起），指针进入落点范围时 `setNear(true)`（放大发光）。要不到纸篓（被限制/槽位满）就放回去，绝不在没有落点时去完成任务；没拖够的算“戳了一下”，放回去，且不吞掉随后的点击。
  4. **松手**：在纸篓外——放回去（吞掉紧随的 `click` 450 ms，免得误点到下面的 UI）；在纸篓里——水母被牵到纸篓口并发出**恰好一次**完成请求（`Core.setBusy`，等回执）。
  5. **完成回执**：`result.ok === true` → 水母被吞（`Core.consume`，0.5 s 缩小）、纸篓 `gulp()` 晃一下后收起；列表与计数由 `memo.js` 原有流程更新，名单少了这个任务，这只水母不会再生。非 ok → 水母放回去（零速度），`memo.js` 已用 Toast 说明原因。等回执超过 `BUSY_MAX_MS = 6000` 也放回去（任务若稍后真的完成了，名单变化会让它自己离开）。
  6. **取消**：Esc、窗口失焦（`blur`）、`pointercancel`、页面被隐藏、切到别的皮肤或关闭总开关、关闭“任务名与抓取”开关，都等同“放回去”——放开水母、收起纸篓、**不判定落点、不完成任务、也不吞随后的 click**。**例外**：松手后已发出完成请求、水母停在篓口等回执期间不打断——请求已发出、无法撤回；这时即使皮肤被停用或世界重建，晚到的回执也只由 `memo.js` 决定任务是否完成，皮肤不再有动画。只有主指针（`isPrimary`）的主键（`button 0`）能抓。抓着时指针拖出窗口外也继续跟着（按住时窗口外仍会收到移动事件），在窗口外放开按“放开”处理（`pointerup` 丢失时由 `buttons === 0` 的移动事件兜底）；没抓着时指针离开页面，水母不再躲一个看不见的指针。
  - **唯一的写出口**：控制器里没有任何 `storage.set/remove/clear` 与计时器（测试用源码扫描守住）；完成只经注入的 `complete`，默认实现是 `memoManager.completeTaskById(id)`（`js/jellyfish.js` 的 `defaultComplete`），页面上没有这个入口时按失败处理。
  - **`MemoManager.prototype.completeTaskById(id, { waitMs = 3000 })`**（`js/memo.js`，本轮新增）：**不另写一套完成逻辑**，直接调任务列表自己的入口——每日习惯走打卡 `toggleHabitCompletion`、其他走 `toggleSidebarTaskComplete`，所以保存、活动日志、列表重绘、日历刷新、进度补满都与手点完全一致。这两个入口都是“切换”，因此先挡住不该切换的情形：已完成的只回报 `already`（**绝不取消完成**）、失败态拒绝（列表里失败任务的勾选框同样不响应）、找不到的回报 `missing`。切换会先在内存里改好再等保存（`saveMemos` 去抖 100 ms，被后一次保存顶替的那次 Promise 永远不结束，是既有行为），所以最多等 `waitMs` 就按内存里的结果判断；切换抛错时把改过的字段（`completed/completedAt/updatedAt/progress/habit`）原样放回，不留“内存里完成了、存储没存上”的状态。失败统一 Toast 说明原因。返回 `{ ok, reason?, already? }`（`reason`：`missing / failed / error / not-completed`）。
  - **开关 `jellyfishTasks`**（`backgroundExperienceSettings`，默认 `true`，设置页 `set-bgJellyfishTasks`）：关闭后水母不画任务名、`canGrabJelly()` 为假（指针不转发、光标不变、按下抓不住），水母数量与外观不变。真实 Chromium 对比：关闭时 1.2 秒内 `fillText` 调用 0 次、悬停无 `jellyfish-grabbable`、按下 `grab=false`；打开时 432 次（6 只水母约 72 帧）、悬停有类、按下 `grab=true`。
- **纵向位置：水母会一路游到屏幕顶端贴边（第一版就有的物理缺陷，2026-10-15 第三轮修复）**：
  - **现象**：真实 Chromium 里抓取测试找不到“位于空白背景上”的水母——全漂到了 y ≤ 121 px，躲在任务条和卡片后面。模拟器统计：84%–93% 的时间在屏幕最上面 20%。
  - **原因**：每次拍动的推力是固定值（`THRUST 120`），而下沉只有 `SINK 14`（阻力 `DRAG 1.45`）：每只水母每隔 `PERIODS = [2, 3]` 拍（一拍约 1 秒）收缩一次，只需推力的约 0.23 倍（周期 2）或 0.35 倍（周期 3，随钟罩大小略有不同）就能抵消下沉；实际给的是 1 倍，净效果是持续上浮。漫游点 `home`（`y ∈ [0.16H, 0.76H]`）只通过“朝向”影响推力方向，而朝向被 `HEADING_LIMIT = 1.2` rad 限制在正上方两侧（设计意图是“只往上方半圆游，靠下沉回落”），推力因此永远带着向上的分量；水母对自己的高度没有任何负反馈，顶到屏幕边缘后只靠“不穿出边界”停住。
  - **修复**：按与漫游点的深度差调节推力——`thrustScale(world, jelly) = clamp(HOVER_THRUST + depth × (1 − HOVER_THRUST), HOVER_MIN, 1)`，`depth = (jelly.y − home.y) / max(1, H × HOVER_SPAN)`；参数 `HOVER_SPAN 0.25`、`HOVER_THRUST 0.3`（正好在漫游点高度时取在“刚好抵消下沉”所需 0.23–0.35 的中间，水母在漫游点上下小幅起伏）、`HOVER_MIN 0.12`（比漫游点浅得多时基本不再上游，靠下沉回落）。深于漫游点时按比例加大推力（上限 1，不超过原来的推力），所以刚从屏幕下方游进来的水母不受影响。作用于自由游动的拍动和受惊的逃跑脉冲；被抓住时挣扎的拍动不按深度缩放（`stepCarried` 保持原样）；进入/离开中的水母不经过调节（推力系数恒为 1，刚从屏幕下方游进来的不会被收住）。`home` 缺失或非有限数时回到 1（不改变其他调用者的行为）。
  - **验证**：核心模拟器（3/11/23 号种子 × 3/6/8 只 × 180 秒）在屏幕顶部 20% 以内的时间占比 84%–93% → 2–3%（测试断言 < 10%），平均高度（占屏高比例）0.12 → 0.43–0.45（测试断言在 0.3–0.6，且标准差 > 0.08，即仍分散在不同高度）；真实 Chromium 50 秒采样 0% 的时间 < 120 px、56% 在 300–500 px。**视觉上的变化**：水母现在大多在屏幕中部游动，而不是贴着上沿；这也使“抓得到”这件事成立。
  - 原来的“没有拍点时一次收缩…”等既有测试里的水母位置须放到比漫游点深处才保持语义（改了一处夹具：`j.y = j.home.y + w.height × P.HOVER_SPAN × 2`）。
- “秒针”拍点来自首页时钟数字的真实变化，数字不是每秒变就用整秒墙钟。单步最长 50 ms（标签页刚恢复时不会一步跳很远）。
- `reduce-motion` 下皮肤从不启动（等同 `none`）。没选中时没有任何观察者或监听。

### 3.8 解压果冻

**定位**：不计分、不会输的“捏一捏”，作为游戏中心的第四款；另外在番茄钟专注**自然走完**后提示“歇 60 秒，捏捏果冻？”。灵感是 Squishy，物理自写。

模块：

- `js/jelly-core.js`：纯物理。28 点 Verlet 轮廓 + 形状匹配（保持整体形状并能被压扁、拉长），地面 `floor = height − 12`，抓取/戳/甩/重置/缩放/睡眠。UMD，Node 可测。
- `js/jelly-game.js`：Canvas 2D 控制器，全局 `JellyGame`，对外 `mount(rootEl, { rest, onDone })`（成功返回句柄，失败返回 `null`）、`unmount()`（幂等，结算累计时长并清空容器）、`statText()`、`restOfferEnabled()` / `setRestOfferEnabled()`、`isMounted()`。
- `css/jelly-game.css`：舞台、画布、颜色选择、按钮、休息倒计时条、番茄钟提示卡片，以及游戏中心网格从 3 列扩为 4 列（≥1100 px 四列、≤760 px 一列，其余两列；父级宽度上限放宽到 1180 px）。
- 接入：`js/games-v5.js`（第四张卡片 + `showJelly`）、`js/memo.js`（番茄钟提示）、`index.html`（样式在 `spring-feel.css` 之后；脚本顺序 core → controller → `games-v5.js`）。

**玩法**：拖动抓起、甩出去、戳一下（按钮 / 空格 / 回车）、重新掉落、6 种颜色（草莓/柠檬/薄荷/葡萄/海盐/蜜桃）；没有声音。颜色、累计放松时长、提示开关存 `localStorage`（`jellyColor`、`jellyPlaySeconds`、`jellyRestOffer`），不上传。时长每段最多计 30 分钟、页面隐藏时结算分段，总量有上限，读取时逐项校验。

**空闲成本**：果冻睡着后**自身零 rAF**；被碰到才醒，实测被戳一下后约 3 秒（359 帧 @120 Hz）重新睡着；只在醒着且页面可见时用一条 rAF。

**不登记** `ProductPagesV5` 与 App 注册表：`ProductPagesV5` 是固定的 19 个业务 / 122 个页面设计合同，果冻只是游戏中心里的一个视图（`data-origin` 白名单 `lobby | pomodoro`，其他值按大厅处理）。

**游戏中心接入**：

- `showJelly({ origin, rest })` 在已有的 `#games-v5-panel` 里渲染，不新建面板；每次替换面板内容或隐藏前先 `releaseJelly()`（卸载才会结算时长、停掉动画和倒计时），卸载抛错只记一条警告、不挡关闭。
- 从番茄钟进入：面板 `games-v5-above`（z-index 10010，盖过番茄钟的 10002），打开期间番茄钟被 `inert`；头部没有“游戏大厅”按钮；Esc 直接关闭游戏中心回到番茄钟。从大厅进入：Esc 回大厅。
- `games-v5-above` 每次打开重新决定，关闭时不摘（淡出过程中不能沉到番茄钟下面）。
- 果冻脚本没加载、`mount` 返回 `null` 或抛错：显示一句“解压果冻没有加载成功，可以刷新页面后再试。”，焦点落在关闭按钮。

**番茄钟入口**（`memo.js` 的 `initPomodoroTimer`）：

- 只在**专注自然走完**时出现（`complete(true)`，且刚完成的是专注）；“跳过”、重置、切标签都不算（跳过按钮的点击事件对象是真值，所以单独包一层 `() => complete(false)`）。
- 提示是固定字符串模板（只插入 `REST_SECONDS` 常量），位于控制按钮之后；“去歇一下”→ `showJelly({ rest: 60, origin: 'pomodoro' })`，提示保留在原处，关闭游戏中心后焦点回到这个按钮；“不用了”→ 清除提示、焦点回到开始按钮；“不再提示”→ 写 `jellyRestOffer='off'` 并给出一句说明（可在果冻页底部重新打开）。
- 下一次开始计时、切标签、重置、再次完成都会清掉旧提示，任何时刻最多一个。休息倒计时按墙钟时间算（`endsAt = now + 60 s`），倒计时结束后出现“回去继续”，不会自动关闭。

**真实 Chromium 暴露的两个坑（已修）**：

1. **画布尺寸与缩放入场**：游戏中心面板入场有 `scale: 0.95 → 1`，`getBoundingClientRect()` 返回缩放后的尺寸，若用它量舞台，世界尺寸会偏小。控制器的 `measure()` 用 `clientWidth/clientHeight`（布局尺寸），指针映射 `toWorld` 才用变换后的 rect。画布 CSS 必须 `position:absolute; width/height:100%`，否则画布固有尺寸反过来撑大舞台，触发 `ResizeObserver` 逐帧循环。
2. **面板打开后焦点留在 `body`（原有缺陷，果冻入口放大了它）**：`openHost` 原来只在一次 `requestAnimationFrame` 里 `focus()`，而 `.games-v5-panel` 的 `transition: .2s ease` 包含 `visibility`，刚加 `visible` 的第 0 帧元素仍是 `hidden`，不可聚焦，`focus()` 静默无效。**干净的真实 Chromium 复现**：从 Dock 打开大厅（原有路径）、从番茄钟打开果冻，`document.activeElement` 都停在 `body`；只有“面板已可见时从大厅切到果冻”能成功。键盘用户因此要多按一次 Tab，空格戳果冻也没有反应。修复是 `focusWhenReady(host, selector)`：逐帧重试，最多 `FOCUS_RETRY_FRAMES = 8` 次；面板已关闭、目标不存在、或焦点已在面板内（用户 Tab 过）就停，不抢焦点；焦点停在面板容器本身（`tabindex=-1` 的兜底焦点）不算“已放好”。修复后实测两条路径都是“第 1 次被拒、第 2 次成功”，在画布上按空格重心从 496 摆动到 506/498/487…。

### 3.9 Dock：固定“休闲游戏”后不显示（原有缺陷，2026-10-15 修复）

用户在“应用启动台”里把“休闲游戏”固定到 Dock，卡片上显示“已固定”，但 Dock 上没有出现图标。

- **根因**：`index.html` 里的 `#games-hub-dock-btn` 原来是一个放在 `#dock-bar` 之外的隐藏占位（`<button id="games-hub-dock-btn" type="button" hidden aria-hidden="true"></button>`，没有图标、没有 `dock-btn` 类）。`DockManager._backupOriginalButtons()` / `render()` 按 id 复用页面里已有的原生按钮元素来渲染固定的应用，复用到的恰好是这个占位，结果是“渲染了一个看不见的按钮”。其他应用的静态按钮都是完整的 `.dock-btn`，所以只有它出问题。该占位随提交 `7307ca1` 引入，与实验分支的改动无关。

## 4. 已知限制

- 画布里的文字阴影用固定值近似 CSS 的 `text-shadow`，换主题后可能与 DOM 文字有轻微色差；还原时靠 150 ms 淡出掩盖。
- 壁纸转场对不允许跨域读取的壁纸来源（如部分 NASA/Wallhaven 地址）自动退回瞬间切换；视频壁纸没有转场。
- 数字字形由 Canvas 绘制，与 DOM 文字不是同一套渲染：dpr 2 下静止帧与 DOM 的 SSIM 为 0.991，dpr 1 为 0.951；起止时 160 ms 淡入淡出掩盖，未做像素级一致。
- 浏览器控制台会出现不允许跨域读取的壁纸来源的 CORS 报错（一次性、不影响功能，已自动退回瞬间切换）。
- 液态时钟画布像素上限 240 万（第一轮为 100 万）；慢机器上隔帧绘制，效果会略“粗”但不卡主线程。整行铺满视口后，每帧耗时只在无头软件渲染的真实 Chromium 里测过（平均 ≤ 4.5 ms）；GPU 光栅化成本、品牌版 Chrome 156、超宽屏（画布会降分辨率）都没有验证。
- 水母的暖色（橙、黄、红）在很暗的壁纸上偏棕/橄榄、比冷色略暗；调色板只在“壁纸 + 压暗层”和纯深色底两种背景上看过截图，真实壁纸轮换下的观感没有逐一确认。
- **水母抓取只在空白背景上有效**：水母游到任务滚动条、卡片、Dock、时钟数字文字后面时抓不到（那些是 UI 的点击区域，不能抢）；修复纵向漂移后水母大多在屏幕中部游动，多数时间抓得到，但不是任何时刻、任何位置都行。任务名画在背景层，会被半透明卡片盖住一部分，也可能与卡片文字叠在一起（既有层级，未改）。
- **完成请求一旦发出不可撤回**：松手落进纸篓后水母停在篓口等回执，期间 Esc、失焦等取消不再生效；回执超过 6 秒水母放回原处，但任务若稍后真的完成了，名单变化会让它自己离开。`completeTaskById` 在 3 秒内按内存里的结果判断，存储保存是去抖异步的（`saveMemos` 100 ms，被后一次保存顶替的那次 Promise 永远不结束，既有行为），所以“回执 ok”不等于“已落盘”。
- **每日习惯任务**走 `toggleHabitCompletion` 打卡，水母只跟任务表当前的 `completed` 状态走，不额外处理习惯的重置。
- **触摸屏/触控笔未验证**：悬停光标只对鼠标有意义；`tryGrab` 对任意主指针放行（`button 0`、`isPrimary`），但真实触摸事件、手指拖动时页面是否滚动、`touch-action` 都没有在真机验证。
- 水母不再贴着屏幕上沿：这是修复，不是回归，但**空闲时的观感变了**（旧版 84%–93% 的时间在屏幕最上面 20%，模拟器统计）。如果更喜欢旧观感，可以调 `HOVER_THRUST` / `HOVER_MIN`（调大会更靠上；`test/jellyfish-core.test.js` 里有纵向分布的断言——顶部 20% 以内的时间占比（< 10%）、平均高度（0.3–0.6）与分散度——调参会让它失败，须有意识地一起改，并用真实截图复核；调得过大水母会重新贴上沿、抓不到），见 §3.7。
- 解压果冻的累计时长在页面一直开着时每段最多计 30 分钟；休息倒计时依赖墙钟，系统睡眠后醒来会立即显示“歇好了”。
- 游戏中心的贪吃蛇、立体方块卡片图标使用 `fa-worm`、`fa-cubes-stacked`，这两个图标不在已本地化的 Font Awesome 6.0.0 里，**图标不显示**（原有问题，非本次引入，未改）；果冻用的 `fa-droplet` 存在。
- 旁注（原有行为，未改）：番茄钟用 `totalFocusMinutes += 1/60` 浮点累加后 `Math.floor`，满 25 分钟会显示“专注分钟 24”。
- 真实 Chrome（品牌版 156）下的帧率、GPU 占用、长时间驻留内存，以及真实账号/真实壁纸 API 配置，均尚未验收。
