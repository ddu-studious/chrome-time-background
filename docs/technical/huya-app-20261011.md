# 虎牙直播 App（关注列表与热门推荐）

日期：2026-10-11

## 目标与范围

- 独立 App `huya`（虎牙直播），与 Bilibili / YouTube 同级：出现在启动台和 Dock，可固定，设置页“功能开关”中有 `enableHuya`，关闭后不初始化控制器、不注入面板并隐藏 Dock 按钮。
- 只做用户明确要的两件事：**我的关注**（含直播状态）与**热门推荐**，加官方嵌入播放器。
- 不做：登录/关注/取消关注等账号写操作、弹幕/礼物/聊天、AI 助手工具（没有注册到 `assistant-*`，也没有接入 `app-video.js` 深链）、v5 页面注册表（`ProductPagesV5` 是设计矩阵合同，虎牙不属于）。
- 2026-10-11 使用反馈后的第二轮优化（详见下文“第二轮优化”“试看限制调研”“图标”）：播放器放大并提供宽屏 / 网页全屏 / 弹窗观看，应用图标换成小老虎，关注列表增加本地搜索与按人气排序，修复实际体验中发现的布局与滚动问题。
- 2026-10-11 第三轮（详见下文“第三轮”）：最近观看与“继续观看”提示、关注列表的自定义分组筛选、“弹窗优先”打开方式。三项都是纯前端能力，数据只保存在本机浏览器（`chrome.storage.local`），不经过后台、不进 AI、不联网，没有新增权限、网络请求或依赖。
- 2026-10-12 第四轮（详见下文“第四轮”）：用户在内嵌播放器里再次看到“试看结束”。这是虎牙官方嵌入页自己的策略，**不能也不应该去除**；本轮把“弹窗优先”改为**默认开启**（只有用户明确关闭才内嵌），让默认路径走不受站外试看限制的虎牙官方页面。
- 2026-10-14 第五轮（详见下文“第五轮”）：弹窗里的官方房间页是普通布局，用户要的是播放器铺满窗口的“剧场模式”。弹窗新建或复用换房间后，扩展在房间页提交后替用户点一下**虎牙自己的**“剧场模式”按钮（与手动点击等效），不新增权限、没有常驻脚本，任何一步失败都只是保持虎牙默认布局。

## 行为

- 左侧导航：我的关注 / **最近观看** / 热门推荐 / 8 个分类（网游竞技、单机热游、手游休闲、娱乐天地、英雄联盟、王者荣耀、和平精英、户外）。最近一次视图和分类写入 `chrome.storage.local` 的 `huyaSettings`。顶栏有“弹窗优先”开关（见“第三轮”）。
- **我的关注**
  - 以虎牙网页登录为准；没有检测到登录时给出“去虎牙登录”的引导，不会换成别的内容。
  - 分“直播中 / 重播中 / 未开播”三组；未开播默认折叠（没有任何直播或重播时展开），展开选择会被记住。卡片展示封面、昵称、标题；直播中显示人气，未开播/重播显示粉丝数，未开播且有预告时显示开播预告。
  - 3 分钟内用缓存；超过后先显示旧列表并标注“更新于……”，同时后台刷新（首次读取约 10–20 秒），刷新成功后自动替换。可手动刷新，可“清除缓存”（需二次点击确认）。
  - 虎牙在“请求失败”和“确实没有关注”时渲染同一个空列表提示，所以空结果只显示“虎牙页面没有返回关注的主播”，**不覆盖**已有缓存。
  - 关注超过 300 个主播时只取前 300 个并提示列表不完整。
  - 工具栏有本地搜索框和“按人气”开关，都只重排已读取的列表，**不发网络请求**。搜索匹配昵称、标题、游戏，空格分隔的多个词必须同时命中；经 NFKC 归一化，不区分大小写与全半角；输入法组合期间不过滤；`Esc` 先清空搜索（再按才关闭工作台）。搜索时未开播分组自动展开，统计文字改为“匹配 N / 共 M 位 · 其中 K 位直播中”，无结果显示“没有匹配的主播”和“清除搜索”。“按人气”把直播中、重播中按人气从高到低排列，并列保持虎牙原顺序，没有人气数据的排最后，未开播分组不参与。排序偏好写入 `huyaSettings.followSort`；搜索词不保存，重新打开工作台时清空。
  - 工具栏下方是“分组”筛选条：用户自己建的本地分组（芯片显示人数）。每张关注卡片右下角有“设置分组”按钮，可勾选多个分组；筛选与搜索叠加，也不发网络请求。筛选只在本次打开期间有效，不保存。有“继续观看”提示时显示在筛选条上方。
- **最近观看**
  - 列出用户在工作台里打开过的直播间（最多 30 个、保留 30 天、按时间倒序、同一主播只留一条），只保存在本机。卡片状态来自 10 分钟内读取到的关注 / 推荐数据；没有这样的数据就显示“状态未知”，点击仍会打开直播间，不假装在播。每条可单独移除，也可“清除记录”（需二次点击确认）。
- **热门推荐**
  - 每页 120 个直播间，“加载更多”最多 8 页、1000 个，按主播去重；同一分类在 60 秒内直接复用已加载内容，超过后先显示旧内容再后台刷新（只存在于页面内存，不落盘）。
  - 这是虎牙公开热门列表，**不是账号个性化的网页首页推荐**，界面不暗示是。
  - 刷新失败时保留旧列表并提示“显示的是缓存内容，更新于……”。
- **播放**
  - 使用官方嵌入页 `https://liveshare.huya.com/iframe/<房间>`，只在房间标识匹配 `^[A-Za-z0-9]{1,64}$` 时嵌入；`yy/…`、`video/u/…`、私密或付费房间显示“在虎牙打开”，不猜测地址。
  - 播放页操作栏：返回、**宽屏**（隐藏侧栏，默认开启，偏好写入 `huyaSettings.playerWide`）、**网页全屏**（只在扩展页面内铺满，不触发浏览器全屏；按钮文字写“网页全屏”以免与浏览器全屏混淆；`Esc` 先退出网页全屏）、**弹窗观看**、在虎牙打开、复制直播间链接（复制的是 `https://www.huya.com/<房间>`，不是嵌入地址）。画面下方常驻试看限制说明，再往下是最多 14 个同列表“继续浏览”，切换时只保留一个 iframe。嵌入页 30 秒仍未加载完成时提示。
  - 播放画面宽度按可视高度限制，返回按钮和整个 16:9 画面同屏可见，避免嵌入页聚焦把工作台滚走；播放时隐藏页面大标题和（宽屏下）侧栏，把空间让给画面。三种模式只切换 class / 属性，**不重绘舞台，iframe 不会重新加载**（真实 Chrome 中用节点标记核对过）。
  - 弹窗观看：用 `chrome.windows.create({type:'popup'})` 打开该房间的虎牙官方页面（`tabs` 为既有权限，无新增权限；本地预览没有该 API 时退回 `window.open(…,'noopener,noreferrer')`），成功后移除嵌入播放器（避免两路声音）并在原位置显示“已在独立窗口打开”，提供“回到这里观看”和“返回列表”；失败（弹窗被拦截等）只提示并保留嵌入播放器。顶栏“弹窗优先”打开后，点击可内嵌的直播间会直接走弹窗（复用同一个窗口，失败时退回内嵌），详见“第三轮”。弹窗里的房间页提交后会自动进入虎牙自己的“剧场模式”（第五轮，见下文）。
  - 返回列表时回到进入播放器前的滚动位置并聚焦刚才的卡片；从滚动过的列表进入时播放器回到顶部（此前播放器顶部和返回按钮会被卷到可视区上方）。
- 无障碍与省电：打开后焦点进入工作台，`Esc` 关闭整个工作台并还原焦点；`Tab` 不离开面板；背景用 `inert`。`js/main.js` 的 `_isBackgroundSuspended()` 把 `huya-workbench-open` 与 Bilibili/YouTube 同等对待，暂停首页视频壁纸和背景动画；不影响音乐。

## 第二轮优化：使用反馈与体验审计（2026-10-11）

用户在已登录真实账号上试用后反馈三件事：播放器太小、App 图标不满意、希望整体体验一遍并优化；随后又问“看一会儿为什么出现‘试看结束’”（见下一节）。本轮在真实 Chrome 扩展 + 虎牙替身站点 / 真实公开服务里逐项体验、量化并修复：

**播放器尺寸**（真实 Chrome 中量取 `.hy-frame-wrap`；“优化前”是上一版的实测值，且进入时顶部被卷出可视区 41 px、不是完整可见）：

| 视口 | 优化前 | 宽屏（现默认，完整可见） | 提升（面积） | 网页全屏 |
| --- | --- | --- | --- | --- |
| 1440×900 | 1102×620 | 1269×714 | +33% | 1440×810（+71%） |
| 1920×1080 | 1422×800 | 1589×894 | +25% | 铺满 |
| 1280×720 | 782×440 | 949×534 | +47% | 铺满 |
| 1024×640 | 640×360 | 807×454 | +59% | 铺满 |

宽度 = min(可用宽度, (可视高度 − 面板边距、顶栏、操作栏等固定占用) × 16/9)，所以操作栏与完整画面总能同屏可见；关闭宽屏（显示侧栏）时 1440×900 为 1158×651。关于“参考 YouTube / B 站”：按样式规则推算（**没有逐一实测**），YouTube 工作台的 `.yt-frame-wrap` 是内容区全宽 16:9（需要滚动才能看到下方操作区），Bilibili 的 `.bili-player-frame` 填满播放区；本页宽屏与前者同量级且保证同屏完整可见，网页全屏相当于后者的铺满形态。

**审计中发现并修复的问题**（修复后在 4 个视口、44 项→46 项体验检查中复测）：

1. 从滚动过的列表进入播放器时，内容容器沿用了列表的滚动位置，播放器顶部与“返回”被卷到可视区上方 → 进入时归零。
2. 返回列表后回到最顶部，用户要重新滚到刚才的位置 → 记录首次进入前的滚动位置，返回时还原并聚焦刚才的卡片；在播放器里经“继续浏览”换房间时沿用最初的位置。
3. 网页全屏下面板背景有 2% 透明度，底下的 Dock 与文字隐约透出（窄屏全屏时更明显）→ 面板背景改为不透明，网页全屏为纯黑。
4. 关注工具栏在 1440 宽度下“刷新”“按人气”被压成两行竖排、统计文字被折断 → 按钮与链接 `white-space: nowrap; flex: none`，左侧一组允许整体换行，搜索框可收缩（160–280 px）。
5. 窄屏（≤620 px）返回按钮被网格 `1fr` 列拉成长条 → 只留图标并靠左。
6. “网页全屏”按钮的可见文字曾写成“全屏”，与浏览器全屏混淆；且名称与状态同时变化（`aria-label` 变“退出…”又加 `aria-pressed`）会让读屏用户听到“退出网页全屏，已按下” → 可见文字固定为“网页全屏”，名称不变、状态只由 `aria-pressed` 表达，提示文字（`title`）随状态变为“退出网页全屏（Esc）”。
7. 对 `huya-core.js` 的新辅助函数 `filterItems` / `sortByViewers` 做异常输入探测时发现：传入 `null` 会抛异常（参数默认值只覆盖 `undefined`）→ 改为非数组一律按空列表处理，并补测试。
8. 窄屏与中等宽度（≤900 px，侧栏只剩图标或变成底部导航）下，“我的关注”的“正在直播”人数角标靠静态位置加外边距定位，会压住居中的心形图标 → 导航按钮改为 `position: relative`，角标固定在按钮右上角；用 390 / 600 / 900 px 实测角标与图标不重叠（重叠面积 0）、角标在按钮范围内，并检查 390–1440 px 五个宽度下关注工具栏按钮文字不折行、无横向溢出（按文本节点的行矩形判断，不用高度估算）。

**审计中确认没有问题、保留不动的行为**：搜索时焦点与光标留在输入框（后台刷新整块重绘时也会放回光标）；输入法组合期间不过滤；恶意昵称与恶意搜索词只作为文字；模式切换不重载 iframe；Tab 不离开面板；Esc 顺序（退出网页全屏 → 清空搜索 → 关闭工作台）。

## 站外嵌入的“试看”限制（2026-10-11 调研）

**现象**：嵌入播放器看几分钟后画面暂停，出现“试看结束，到虎牙直播接着看吧～ [立即前往]”。这是虎牙官方嵌入播放器自己的策略，不是扩展缺陷，也不是网络问题；扩展不能、也不应该去除它。

**证据**（脚本是 2026-09-07 版 `https://a.msstatic.com/huya/h5player/room/h5outstation/202609071716/vplayer.js`，压缩后的第三方脚本，随时可能改版，下面的函数名只用于说明机制）：

| 来源 | 内容 |
| --- | --- |
| 脚本阅读 | `play()` 在 `tWatchLimit.iIsLimit === 1` 时调用 `needShowTips()`：等待 `tWatchLimit.iLimitSecond` 秒（客户端默认 300 秒，由服务端接口 `webLiveUI.getLiveShareOpenConfig` 下发）后 `stop()` 并显示“试看结束”浮层；“立即前往”打开 `https://www.huya.com/<房间>` |
| 脚本阅读 | 当天计数：到点时把 `localStorage.liveLimit` 写成当天日期（`toLocaleDateString()`）；之后同一嵌入来源下再进入任何房间，倒计时为 0、立即显示浮层，次日自然恢复 |
| 脚本阅读 | `isViewLimitCancel()`：`document.referrer` 属于虎牙域名，或带 `inPc` / `wangba` 标记时，不应用服务端下发的限制与码率（码率默认与上限 2000 kbps，来自查询参数或默认值）。扩展页面的来源是 `chrome-extension://…`，所以受限 |
| 实测 A：匿名、扩展页内嵌入（真实 Chrome for Testing，房间 1995） | 视频时间 300 s 时暂停，浮层出现，`liveLimit` 由 `null` 变为当日日期；“立即前往”在沙箱内打开 `https://www.huya.com/1995`；同一天改播另一房间，9 秒内就显示浮层；画面 800×450 |
| 实测 B（对照）：匿名、直接打开第一方页面 `https://www.huya.com/257085` | 起播后连续播放到视频时间 322 s，没有暂停、没有“试看结束”，也没有写 `liveLimit`（画面也是 800×450，所以 800×450 不是嵌入页独有）。再做一次对照，连续观看 410 秒（视频时间 421.7 s）同样没有暂停和试看提示。两次的末尾截图都出现匿名“密码登录 / 短信登录”弹窗（起播约 22 秒时的截图没有），说明未登录时第一方页面会提示登录，但不会暂停播放；弹窗出现的精确时间没有记录（探测脚本按 DOM 选择器没有命中该弹窗，只靠截图确认） |
| 嵌入页与宿主 | 嵌入页启动后向宿主发 `postMessage {code:'UserInfoReq'}` 索要用户信息，扩展不监听、不回应；iframe 内 `document.cookie` 长度为 0；试看结束时没有任何 postMessage，宿主无法可靠知道“试看结束了” |
| 官方文档 | 检索 `dev.huya.com`、`open.huya.com`、`blog.huya.com` 没有发现关于站外嵌入试看策略的公开说明（`blog.huya.com/product/877` 讲的是付费直播试看，是另一个功能） |

**结论与处理**：

1. 站外嵌入播放每天累计约 5 分钟（时长由虎牙服务端下发，可能变化），换房间不重置（同一天换房间实测 9 秒内出现浮层），次日恢复（来自脚本里按日期比较 `liveLimit` 的阅读，没有跨天实测，所以界面说明写“通常次日恢复”）。
2. 合规出路只有两条，都已做进界面：**弹窗观看**（独立小窗口里的虎牙官方页面；第一方页面按上面的对照不受站外试看限制，登录态沿用浏览器里的虎牙登录）和**在虎牙打开**（新标签页）。播放器下方常驻说明并指向这两个入口；弹窗打开后移除嵌入播放器，避免两路声音。
3. **不做规避**：不伪造 Referer 或 `inPc` / `wangba`、不清除 `liveLimit`、不改写请求头或加 DNR 规则、不替嵌入页回应 `UserInfoReq`。这些做法等于绕过虎牙对站外播放的限制，可能违反使用条款，也随时会失效。契约测试检查源码里没有相关字符串与监听。
4. **未验证**：“弹窗观看”在已登录真实账号上的表现，以及已登录账号在嵌入页内的试看时长（脚本里的取消条件与登录态无关，服务端是否按身份下发配置无法从客户端判断；两次自行实测都是匿名）。2026-10-12 用户在自己的 Chrome 配置（此前反馈时已登录虎牙）里再次截到嵌入页的“试看结束”，说明至少在该配置下已登录并不能让内嵌播放器免于限制；但截图时的登录状态没有单独确认，也没有测量时长。界面说明里“约 5 分钟”是匿名实测值，已写明“时长由虎牙决定”。

## 图标

- Dock、启动台、设置页“应用选择”和工作台标题统一使用自绘的小老虎头 SVG（`assets/huya/tiger.svg`：黄色虎头、白色“屏幕”和棕色播放三角、脸颊条纹、小獠牙），由 `css/huya-icon.css` 的 `.hy-tiger-icon`（CSS 背景图，随 `font-size` 缩放，彩色不随文字色）渲染。应用注册表的 `icon` 就是 `hy-tiger-icon`，所以启动台、Dock 和设置页中所有 `<i class="${app.icon}">` 自动生效；该样式在首页和设置页都要加载（设置页的应用选择里 `<i>` 本身是 32 px 底块，图标作为第一层背景叠加）。封面占位、“继续浏览”缩略图占位和接力提示复用同一资源。

## 第三轮：最近观看、关注分组与弹窗优先（2026-10-11）

用户看到“试看结束”后，在后续功能问卷里选了三项：**最近观看 / 继续观看**、**关注列表分类或分组**、**默认用“弹窗观看”打开直播**。问卷里没选的“开播提醒”“自动刷新”“先用真实账号验收”本轮没有做。

### 复用与边界

- 没有新依赖，也没有可复用的虎牙 SDK（本来就没有）：窗口管理只用 Chrome 公开的 `chrome.windows.get / update / create` 与 `chrome.tabs.update`，不需要新增权限声明（`windows` 方法无需权限，`tabs` 为既有权限）；后台与 `huya-follow.js` 没有改动。
- 新逻辑分两层：`HuyaCore`（`js/huya-core.js`，纯函数：白名单投影、清洗、合并、过滤）与 `HuyaController`（界面、串行存储读写、窗口复用）。数据存在 `chrome.storage.local`，不进 `storage.sync`，不发给后台、AI 助手、历史留存、日志或任何网络请求。

### 为什么不能“按游戏自动分类”

- “我的关注”来自虎牙 `/myfollow` 页面渲染的 DOM，条目里只有昵称、标题、状态、人气/粉丝、房间链接，**没有游戏或分区字段**（关注条目的 `game` 恒为空字符串，是既有行为，页面结构见下文“实际路径”里 `readFollowPage` 依赖的选择器）。
- 公开直播列表接口 `getLiveList` 带游戏名（`sGameFullName`），但它只含当前热门且正在直播的房间，不含未开播的主播，也不保证包含用户关注的人；拿它反查只会得到不完整、不稳定的分类，所以不做。
- 取而代之的是**自定义本地分组**：用户自己给主播打标签（比如“聊天”“比赛”“电台”），再按标签筛选。分组只在本机，不会同步到虎牙，不改变虎牙上的关注关系。

### 数据与存储

| 键（`chrome.storage.local`） | 内容 | 校验与上限 |
| --- | --- | --- |
| `huyaRecent` | `{version:1, items:[{id, uid, nick, title, game, avatar, cover, host, url, locked, watchedAt}]}`，字段是白名单 | 最多 30 条、保留 30 天、同一主播只留最新一条；读取时逐条重新校验：`id` 只接受 `u<uid>` 或 `h<房间路径>`，`url` 必须是虎牙房间地址，图片域名白名单，文本截断，`watchedAt` 来自未来（超出当前时间 60 秒）或过期的丢弃。**不含**直播状态、人气、播放地址、Cookie、登录票据、当前账号标识 |
| `huyaGroups` | `{version:1, groups:[{id, name, members:[条目 id]}]}` | 最多 12 个分组；名称清洗后最多 12 个字（按字符数），按“不区分大小写与全半角”去重；每组最多 400 位；读取时丢弃非法分组、重复分组、非法或重复成员 |
| `huyaSettings.openMode`、`huyaSettings.openModeChosen` | `embed` / `popup`；布尔，用户点过“弹窗优先”开关才为 `true`（第四轮新增）。默认弹窗：只有 `openModeChosen === true` 且 `openMode === 'embed'` 才内嵌（见“第四轮”，第三轮时默认是 `embed`） | 其他值、旧版本自动写入的 `openMode` 都按默认（弹窗）处理 |
| `huyaSettings.resumeDismissed` | 已隐藏的继续观看提示键 `<条目 id>:<观看时间>` | 其他值按默认处理 |

- 所有读-改-写都经同一个串行队列，并且**每次先读存储里的最新值再修改**，所以同时打开多个新标签页时，一个页面不会用旧内存覆盖另一个页面刚写入的内容（真实 Chrome 中验证：另一个标签页写入分组后，当前页再勾选，两边的改动都保留）。存储内容损坏（类型不对、不是数组等）按空处理，工作台仍可打开。
- 成员用条目 id 存储。某位主播取消关注后仍留在分组里、只是不再出现在筛选结果和人数里，重新关注后自动恢复；没有自动清理，避免一次读取失败就误删用户的分组。

### 最近观看

- **什么算“观看”**：在工作台里内嵌播放、弹窗观看（卡片或播放器里），以及点击“在虎牙打开”（卡片的外链图标、不能内嵌的房间；含只能在虎牙观看的加密房间）。未开播的房间只算点开看看，不记录。用鼠标中键 / 右键菜单打开外链、或直接在地址栏访问虎牙的，扩展看不到，不记录。
- **状态不冒充**：记录里不存直播状态。显示时只用 10 分钟内读取到的关注 / 推荐数据补全（同一主播多处出现时，直播中优先于重播、重播优先于未开播）；没有这样的数据就显示“状态未知”，点击仍可内嵌或打开。
- **移除与清除**：单条移除后焦点落到原位置的下一张卡片（没有就落到上一张），状态栏提示；“清除记录”第一次点击只进入确认状态（“再次点击确认清除”，焦点不丢），5 秒内没有再点就地还原。

### 继续观看提示

“我的关注”和“热门推荐”页面顶部，在最近一次观看满足全部条件时出现一条提示（“刚刚看过 昵称 · 标题 ｜ 继续观看 ｜ ×”）：

1. 最近一次观看在 12 小时内；
2. 本次打开工作台期间还没有看过任何直播间（避免刚看完回到列表又被催着回去；关闭工作台后重置）；
3. 该主播当前不是已知的“未开播”；
4. 用户没有关闭过这一次观看的提示（关闭只记这一次，之后看了新的直播间会再次提示）。

按钮与列表卡片一致：按“弹窗优先”决定内嵌还是弹窗；关闭提示后焦点回到内容区，状态栏说明。

### 关注分组

- **操作**：筛选条上的“新建分组”“管理”，每张关注卡片右下角的“设置分组”（标签图标）。分组面板是工作台里的模态对话框：`role="dialog"`、`aria-modal`、背景 `inert`、焦点在面板内循环、`Esc` 先关面板（不关工作台）、点遮罩关闭、关闭后焦点回到触发按钮。勾选立即保存，没有“保存”按钮；在面板里直接新建分组会同时把当前主播加进去。
- **管理**：改名（回车或离开输入框时提交）；删除是两步确认——第一次点击变成“确认删除”，5 秒内再点才删，同一时间只有一个分组处于待确认。重名、空名、超长、超过 12 个分组、分组已满都会就地给出错误并还原输入框。删除分组不影响关注关系，也不影响虎牙上的任何数据。
- **筛选**：选中分组只显示该组仍在关注列表里的主播，统计与状态栏同步（“分组「…」· N 位直播中 · 共 M 位”），与搜索、排序叠加；组内没有匹配时提示指出范围。正在筛选的分组被删除会回到“全部”。筛选只在本次打开期间有效，下次打开默认“全部”。
- 分组名称、昵称等都按文本渲染（恶意文字在真实扩展页中只显示为文字），输入框 `maxlength` 只是键入限制，真正的校验在 `HuyaCore`。

### 弹窗优先

- 顶栏的“弹窗优先”开关（`aria-pressed`，写入 `huyaSettings.openMode`；第三轮时默认关闭，**第四轮起默认开启**，见下文）。开启时，点击**可内嵌**的直播间卡片（关注 / 推荐 / 最近观看 / 继续观看按钮）直接打开独立窗口里的虎牙官方页面——第一方页面不受站外嵌入的试看限制（依据见上文实测 B）；卡片按钮名称改为“弹窗观看 …”并换成窗口图标，不能内嵌的房间仍是“在虎牙打开”。
- **复用同一个窗口**：第一次 `chrome.windows.create({type:'popup'})`，之后再点别的直播间，就把同一个弹窗里的标签页导航到新房间并聚焦（不会攒出一堆窗口）；该窗口被用户关掉后下一次重新创建。窗口 id 只存在于当前新标签页的内存里，刷新或关闭这个新标签页后不再记得（旧弹窗不会被复用，也不会被扩展关闭）。
- **失败回退**：弹窗被拦截或创建失败时，退回工作台内嵌播放，并在画面上提示 9 秒“弹窗被浏览器拦截或无法打开，已改为在这里内嵌播放”（提示不拦截点击），不让点击落空。
- 已经在内嵌播放器里时（“继续浏览”、“回到这里观看”）一律内嵌，不再弹窗；播放器里仍可手动“弹窗观看”。
- 窗口创建期间用 `popupBusy` 防重复点击；等待期间用户关闭工作台、返回列表或换了房间，晚到的结果不会更新界面。

### 验证（第三轮）

见下文“验证”表中的第三轮行；其中“真实 Chrome 扩展 + HTTPS 替身站点”的新增脚本覆盖了弹窗模式（窗口创建、复用、失败回退、旧窗口关闭后重建）、最近观看（顺序、去重、移除、清除、清洗、状态补全）、继续观看（各出现 / 不出现条件）、分组（创建、勾选、筛选、改名、重名 / 空名 / 超长、两步删除、12 个上限、多标签页写入合并）与窄屏布局。

## 调研与上游核对（2026-10-11）

| 对象 | 结论 |
| --- | --- |
| 虎牙官方 SDK / 面向个人的公开 API | 没有发现可取得“我的关注”或个人推荐的官方入口 |
| `/myfollow` 页面脚本 | 关注列表来自私有 Taf/WUP 调用 `commui.getUserSubscribeToInfoList`，由虎牙页面自己渲染到 `#J_MOD_LIST` |
| npm `@huyafed/taf-network` | 公共 registry 返回 404，不可安装；不复制其源码，也不自研 Taf/WUP 协议 |
| npm `huya-danma-listener` | 只覆盖弹幕，与本需求无关，未引入 |
| 官方嵌入播放器 | `liveshare.huya.com/iframe/<房间>`，在扩展页面内实际起播（见验证） |
| 公开列表 `live.cdn.huya.com/liveHttpUI/getLiveList` | 虎牙列表页同源使用，CORS 开放；以 `https://www.huya.com/l` 前 6 个卡片按昵称对照，页面人气与接口 `lUserCount` 在实时波动范围内一致（相差 0–1.6%），当前 `lUserCount` 与 `lTotalCount` 取值相同；未核对两者的排序是否一致 |

结论：没有可复用的 SDK，因此采用“上游页面 + 薄适配层”：关注列表由虎牙自己的页面完成登录态、签名和协议，扩展只读取它渲染好的 DOM。**没有新增 npm / vendor 依赖。**

适配层承担的职责（`js/huya-*.js`）：

- `huya-core.js`（UMD，浏览器/Service Worker/Node 共用）：所有不可信输入的白名单投影与校验——文本清洗、人气/粉丝数解析、图片域名与缩略图、房间标识（沿用虎牙页面 `TT.createRoomHost` 的取舍）、直播列表与关注快照规范化、缓存校验，以及被注入页面执行的 `readFollowPage`。
- `huya-follow.js`（Service Worker）：`HuyaFollowService`——来源校验、登录判断、缓存、后台标签页生命周期、取消、超时与清理。
- `huya-controller.js` / `css/huya-workbench.css`：界面、状态、键盘与焦点。推荐列表与播放不经过后台。
- 复用本仓库已有能力：`app-registry.js`、启动台/Dock、设置管理、`chrome.scripting` / `tabs` / `cookies`（均为已有权限）。

## 实际路径

```text
HuyaController（follow）
  → huya_follow（chrome.runtime.sendMessage）
  → HuyaFollowService.read（后台；owner 校验为本扩展 index.html）
  → chrome.cookies.get(udb_uid)        仅判断登录并派生缓存账号摘要
  → chrome.tabs.create(active:false, https://www.huya.com/myfollow#tk-follow-<时间>-<uuid>)
  → chrome.scripting.executeScript(world: ISOLATED, func: HuyaCore.readFollowPage)
  → normalizeFollowSnapshot → chrome.storage.local.huyaFollowCache → 关闭后台标签页

HuyaController（recommend）
  → fetch live.cdn.huya.com/liveHttpUI/getLiveList?iGid=<分类>&iPageNo=<n>&iPageSize=120
    （credentials: 'omit'，referrerPolicy: 'no-referrer'）
  → HuyaCore.normalizeLiveList → 卡片
```

`readFollowPage` 依赖的虎牙页面结构（页面改版时首先要核对这里；无法识别时表现为 `huya-format-changed` 或读取超时，不会显示成“没有关注”）：

- 容器 `#J_MOD_LIST`；条目 `li.subscribe-live-item`，主播 UID 在 `data-lp`。
- 房间链接 `a.video-info` / `a.nick`；封面 `img.pic`（`data-original` 优先）；头像 `a.avatar img`；标题 `a.intro`。
- 状态 `.tag-living` / `.tag-replay`；人气 `.num.total`；粉丝 `.num.activity`；预告 `.schedule-msg`。
- 分页 `.btn-more`（耗尽时带 `all` 类）；空提示 `.subscribe-list-none`。只点击页面自己的“加载更多”，最多 20 页 / 300 项，不触发任何关注、取消关注或其他操作。

## 安全与隐私边界

- **权限**：只新增 `host_permissions` 的 `https://www.huya.com/*`；`cookies`、`scripting`、`tabs` 已有。没有声明式 content script，没有 DNR / Referer 改写。
- **Cookie**：只通过 `chrome.cookies.get` 查询 `udb_uid` 这一个 Cookie，并读取它的值（正整数即视为已登录，与虎牙页面自己的判断一致）。不读取其他 Cookie 或密码、登录票据，该值不保存、不返回前端、不进日志；缓存账号键是 `SHA-256('huya-follow:' + uid)`，只用于隔离不同账号的缓存，**不是保密手段**（UID 取值空间小，可以穷举）。界面与设置页文案据此写成“只检查登录标记”，不声称“完全不读取 Cookie”。推荐接口请求不带 Cookie 和 Referer。
- **消息入口**：`huya_follow` / `huya_follow_release` / `huya_follow_clear` 只接受本扩展 `index.html`（校验 `sender.id`、协议、主机、路径及 `documentId` / `tab.id`），其他扩展页面、内容脚本、网页无法触发后台读取。后台只返回 `{ ok, data }` 或错误码，不回传页面文本或异常原文。
- **存储**：缓存只含白名单字段（主播 UID、昵称、标题、状态、人气/粉丝文本、头像/封面 URL、房间路径），不含 HTML，也不含当前用户的 UID 或其他账号材料；读出后再次校验，账号不一致即忽略。只写 `chrome.storage.local`，不进 `storage.sync`，不进入 AI 服务、助手记忆或历史留存。同一配置只保留最近一次账号的缓存；**缓存没有自动过期删除**，只在刷新成功覆盖或用户点击“清除缓存”时变化。第三轮新增的 `huyaRecent`、`huyaGroups` 同样只写 `chrome.storage.local`，字段白名单、读取时逐条重新校验，不含直播状态、账号标识或播放地址（详见“第三轮”）；契约测试检查控制器没有使用 `localStorage` / `sessionStorage` / `indexedDB`，后台与 AI 助手、视频深链的源码里没有这两个键。
- **输出编码**：界面用模板字符串生成 HTML，所有来自虎牙的文本和属性值都先经 `escapeHtml`，不使用内联事件属性（契约测试检查），替身站点里的恶意昵称在真实扩展页中只作为文字显示，用户输入的分组名称同样转义（输入框 `maxlength` 只是键入限制，真正的校验在 `HuyaCore`）；房间路径只接受固定正则；图片只接受 `https` 且域名属于 `msstatic.com` / `huya.com` / `myqcloud.com`，仅对 `live-cover.msstatic.com`、`v-huya-img2.msstatic.com`、`image.myqcloud.com` 追加缩略图参数，带签名的域名原样使用。
- **嵌入页**：`sandbox="allow-scripts allow-same-origin allow-popups allow-popups-to-escape-sandbox allow-forms allow-presentation"`，不含 `allow-top-navigation`、`allow-modals`、`allow-downloads`；`allow="autoplay; fullscreen; picture-in-picture; encrypted-media"`，`referrerpolicy="strict-origin-when-cross-origin"`。
- **资源限制**：推荐请求 12 秒超时、失败后 700 ms 重试一次、响应不超过 3 MB；关注读取整体 70 秒、页面读取 40 秒、等待导航提交 20 秒；关注最多 300 项 / 20 页；推荐最多 8 页 / 1000 项；缓存与列表均去重。

## 失败、取消与后台标签页

- 后台标签页以 `active:false` 在来源窗口创建，不进入网站工作区的分组监控；读取期间可能在标签栏短暂出现（约 10–20 秒）。
- 关闭工作台或页面会发送 `huya_follow_release`：读取在下一个检查点以 `huya-cancelled` 结束，并立即关闭后台标签页；取消的读取不写缓存。
- 后台标签页在所有结果下都会关闭，**除非用户已经激活过它**（标签页处于活动状态，或 `lastAccessed` 晚于创建时间 + 5 秒）。不按当前地址判断归属，因为虎牙可能把它重定向到登录页，加载失败时还会是 `chrome-error` 页面。
- Service Worker 被回收后遗留的标签页：下次读取前在 `https://www.huya.com/*` 范围内查找带本扩展标记、创建超过 70 秒、同隐私模式且从未被激活的标签页并关闭；同源重定向会保留 `#tk-follow-…` 片段，所以能识别。
- 错误码与中文提示：`huya-login-required` 显示登录引导；`huya-redirected`（被重定向，多半需要重新登录）、`huya-load-failed`、`huya-timeout`、`huya-format-changed`、`huya-tab-closed`、`huya-busy`、`huya-cookie-unavailable`、`huya-network`、`request-timeout` 等显示对应中文说明；`huya-cancelled` 静默。失败时有旧列表就保留并标注“显示的是缓存内容”，否则给出重试，不会用推荐内容冒充关注列表。

## 第四轮：试看限制仍然出现，把“弹窗优先”设为默认（2026-10-12）

用户反馈：在内嵌播放器里（网页全屏）再次出现“试看结束，到虎牙直播接着看吧～ 立即前往”，问能不能解决。

### 结论

- **内嵌播放器里的试看限制解决不了，也不应该解决**：它是虎牙官方站外嵌入页自己的策略（证据与不能规避的清单见上文“站外嵌入的试看限制”）。能做的只有不使用嵌入页，改走虎牙官方页面。
- 所以把“弹窗优先”改为**默认开启**：没有明确选择过时，点击直播间直接在独立窗口里打开虎牙官方房间页；用户在顶栏关掉开关才改回内嵌，并记住这个选择。第三轮时这个开关默认关闭，而用户之前的问卷选择是“默认用弹窗观看”，默认关闭与那次选择不一致。

### 默认值怎么定

- 新增 `huyaSettings.openModeChosen`（布尔）。`HuyaCore.isOpenModeChosen(settings)`：必须是布尔 `true`，且 `openMode` 是 `embed` / `popup` 之一。`HuyaCore.resolveOpenMode(settings)`：只有“明确选择了 `embed`”才返回 `embed`，其余一律 `popup`。控制器的初始化只用这两个函数，不直接信任保存的 `openMode`。
- **迁移**：第三轮代码每次保存视图偏好都会把当时的 `openMode`（默认 `embed`）写进 `huyaSettings`，但没有 `openModeChosen`。这些旧值不是用户的选择，所以升级后一律按默认弹窗处理，不需要手动清理；用户点过开关后才记住选择，之后保存其他偏好也不会改写它。损坏或形状异常的设置（取值不认识、`openModeChosen` 不是布尔值、设置对象是数组）同样回到默认，并且不会被保存成“明确选择”。
- 点击开关后无论开还是关都算明确选择。关闭时状态栏提示“已关闭弹窗优先：点击直播间会在这里内嵌播放（有试看限制）”。
- 没选过、第一次经默认弹窗打开直播间时，状态栏追加“（弹窗优先默认开启，可在右上角关闭）”，免得被当成故障；明确选择过后不再重复。
- 内嵌播放器下方的试看说明改成与开关状态无关的写法：“右上角的‘弹窗优先’决定点击直播间时直接弹窗，还是像现在这样在这里内嵌。”
- 弹窗创建失败（被浏览器拦截等）仍退回内嵌并提示 9 秒（沿用第三轮），点击不会落空；退回后就是有试看限制的内嵌播放。
- 刷新或升级后，已经保存了 `openMode:'embed'` 的用户会看到开关变为“开启”、点击直播间改为弹窗。想继续内嵌的用户需要在顶栏点一次开关。

## 第五轮：弹窗里自动进入“剧场模式”（2026-10-14）

用户反馈：弹窗观看打开的虎牙官方房间页是普通布局（顶部导航、横幅广告、标题栏、右侧聊天栏，播放器只占中间一块），想要的是点了播放器控制条上“剧场模式”按钮之后的样子（播放器铺满窗口，礼物栏在画面下方）。

### 结论

- **能做，且不需要新权限**：弹窗里的房间页提交后，扩展替用户点一下虎牙自己的“剧场模式”按钮（`#player-fullpage-btn`），效果与手动点击一致（`body` 加 `mode-page-theater`，按钮变成“退出剧场”）。虎牙页面没有“默认以剧场模式打开”的 URL 参数或设置（见下表），只能等页面起来后触发它自己的按钮。
- **只作用于扩展刚创建或复用的弹窗标签页**：用户自己打开的虎牙页面、“在虎牙打开”的新标签页、内嵌播放器都不受影响。
- 这只是切换虎牙页面自己提供的显示模式，**不涉及试看限制**：不改写请求头、Cookie、页面脚本或存储，也不影响虎牙对播放、登录、试看的任何判断（第四轮的“不规避”清单不变）。
- 用户随时可以点“退出剧场”按钮、按 `Esc` 或双击画面退出，退出后扩展不会再拉回（真实 Chrome 中验证）。**没有加开关**：用户要的就是弹窗观看的默认形态；以后需要的话，在 `huyaSettings` 增一个布尔字段，由 `createPopupWatcher` 决定是否调用即可。
- 聊天栏在不在画面上取决于虎牙自己的 `isShowChatScreen` 偏好（点击后真实页面里该偏好为 `false`，聊天栏在右侧；偏好为开时页面会用 `mode-page-full`，聊天叠在画面上）；扩展不改这个偏好。

### 设计与实际路径

```text
弹窗打开（HuyaController → popupWatcher.open(url, size)，返回值与此前完全一致，也不等下面这一步）
  新建：chrome.windows.create({type:'popup'}) → 只在返回的窗口恰有 1 个标签页时取 tabs[0].id
  复用：chrome.windows.get → webNavigation.getFrame 记下导航前的文档标识 → chrome.tabs.update(url)
  → createTheaterAssist.enter(tabId, 导航前文档标识)
      循环（最长 30 秒，每 200 ms 一次）：chrome.webNavigation.getFrame({tabId, frameId:0})
        · 取不到框架且标签页已不存在 → closed
        · 文档处于 active、没有加载错误、不是导航前的旧文档、来源恰为 https://www.huya.com → 只对这一份文档注入一次（最多 3 次）：
            chrome.scripting.executeScript({ target:{tabId, documentIds:[该文档]}, world:'ISOLATED',
              injectImmediately:true, func:HuyaCore.enterTheaterPage, args:[{timeoutMs:45000}] })
              页内：每 250 ms 查 #player-fullpage-btn；已在剧场模式 → already；行内 display 已被设置 → click()，
              核对按钮 class / body；没生效才隔 1.5 秒再点，最多 3 次；45 秒仍未就绪 → timeout
```

- **复用了什么**：虎牙没有可用的 SDK 或开放接口来控制网页播放器的显示模式（开放平台只有企业认证路径，见“调研与上游核对”），所以是“虎牙页面自己的按钮 + 薄适配层”，没有新增依赖，也没有复制或改写虎牙脚本。Chrome 公开 API 全部是既有权限：`chrome.windows.create / get / update`、`chrome.tabs.get / update`、`chrome.webNavigation.getFrame`（取 `documentId`、`documentLifecycle`、`errorOccurred`）、`chrome.scripting.executeScript`（`documentIds`、`injectImmediately`、ISOLATED 世界）；沿用 `readFollowPage` 的“自包含函数经 `executeScript` 注入”写法。`manifest.json` 无改动，没有 content script、没有 `MAIN` 世界注入、没有 CSS 注入。
- **只注入核对过的那一份文档**：按 `documentId` 绑定，页面已经跳走不会误注入别的页面。复用弹窗换房间时，旧页面在新页面提交前一直是“当前文档”，所以导航前的文档标识与注入过的文档都进入排除集合（同一地址再次打开时地址不变，只能靠 `documentId` 区分）。页面自己跳转替换文档会让注入失败，循环再对新文档重新注入，共最多 3 次。`about:blank`、`chrome-error://`、他站、同名子域（`www.huya.com.evil.example`）、`http`、加载出错、非活动文档都不注入。
- **有界**：等房间页提交最多 30 秒（`THEATER_COMMIT_TIMEOUT_MS`）；页面内等控制条就绪最多 45 秒（`THEATER_PAGE_TIMEOUT_MS`）；最多 3 次注入、每次页内最多 3 次点击。最坏情形（页面不断被替换且每份文档都等满）约 30 秒 + 3 × 45 秒，实际几秒内结束。
- **同一标签页只保留最近一次请求**（按标签页的代际计数）：连点换房间时前一次等待立即作废（结果 `superseded`），不会对已被取消的导航注入。
- **失败静默、不影响打开**：标签页已关、接口缺失、注入被拒、虎牙改版认不出按钮，都只是保持虎牙默认布局；没有未处理的拒绝（测试里监听 `unhandledRejection` 验证）。
- **不读取或回传页面数据**：页内函数只按 id 取一个按钮并返回 `{state, clicks}`；单测检查它不含 `querySelector`、`location`、`cookie`、`Storage`、`fetch`、`postMessage`、`dispatchEvent`、`innerHTML`、`eval(` 等字样，也不引用模块作用域变量；契约测试检查控制器里只有这一处注入、没有 `MAIN` 世界、`registerContentScripts`、`insertCSS`。
- **运行位置**：协调逻辑在打开弹窗的扩展新标签页（`HuyaController` 所在页面）里，不在 Service Worker，不新增消息入口；用户在等待期间关闭或刷新这个新标签页，这次就不会进入剧场模式（保持默认布局）。
- `index.html` 里 `js/huya-core.js` / `js/huya-controller.js` 的缓存参数从 `?v=4` 升到 `?v=5`（沿用项目约定）；更新后需要在 `chrome://extensions` 重载扩展。

## 已知限制与验收

- **真实登录账号的关注列表尚未验收**：上面的页面结构来自对虎牙页面脚本的阅读，已对本地替身和匿名真站验证，但没有在已登录的真实账号上逐项核对；`udb_uid` 的登录语义同样来自页面脚本阅读。请用已登录虎牙的 Chrome 配置实际打开“我的关注”，对比 `https://www.huya.com/myfollow`。
- **真站检查不能用真实存在的 UID 当替身 Cookie**：`/myfollow` 页面按 `udb_uid` 渲染列表。验证时曾把伪造的 `udb_uid` 设为 `1`（这是真实账号），页面据此渲染出 25 条关注并被读取器解析成卡片（读取器的容器与行选择器在当前真实页面上能解析，但这不是已登录账号的验收，也不代表授权路径）；当天较早同样的检查得到的是空状态，说明虎牙服务端对同一 UID 的返回会变化。之后真站检查改用不对应任何账号的超大数字，只让扩展通过“登录存在性”检查并走空状态，不再读取任何真实账号的列表，也不要把这类结果保存进文档或缓存。
- 虎牙改版会让关注读取失效（表现为 `huya-format-changed` 或超时）；推荐接口与嵌入地址同样是非承诺接口。
- 关注读取依赖浏览器后台标签页加载虎牙重页面；真实有头 Chrome 对隐藏标签页的节流表现尚未单独验收。
- 新增的 `host_permissions` 会让商店更新触发一次权限确认；本地解压加载的扩展需要在 `chrome://extensions` 重载。未实现“可选主机权限”的运行时授权方案。
- 嵌入页自身会产生控制台噪声（如 `http://www.huya.com/` 混合内容、移除 iframe 时的 `ERR_ABORTED`），不是扩展代码错误。
- 推荐页是公开热门列表，未做按账号个性化；播放不读取或写入账号数据（不关注、不送礼、不发弹幕）。
- **嵌入播放有试看限制，扩展无法也不应去除**（见“站外嵌入的试看限制”与“第四轮”），所以默认走弹窗。用户在自己的配置里仍看到嵌入页“试看结束”（登录状态没有单独确认，时长未测量）；弹窗观看在已登录真实账号上的表现未验证；说明文字里的“约 5 分钟”是匿名实测值。
- 网页全屏下，`Esc` 只在焦点不在嵌入播放器内时能退出（嵌入页是跨域 iframe，按键不会冒泡到扩展页面）；焦点在播放器内时请点操作栏按钮。
- 弹窗观看用 `chrome.windows.create`，只在新无头模式（`--headless=new`）的 Chrome for Testing 中验证过窗口创建（第五轮核对启动参数时发现，此前这里写成“有头”不准确）；在用户真实 Chrome 配置与不同系统窗口管理器下的表现未验证。
- 关注列表搜索与排序只作用于已读取的列表（上限 300 个主播）；搜索词不保存。
- 小老虎图标是自绘的，不是虎牙官方素材；与官网图标的相似度只做了人工对照（用户提供的参考图），没有像素级比对。
- **第三轮功能只在替身站点与匿名环境验证过**：最近观看、继续观看、分组和弹窗优先都没有在已登录的真实虎牙账号上验收；尤其是已登录时第一方页面是否仍不受试看限制、虎牙是否限制多个窗口同时观看，都没有验证。
- 最近观看只记录经工作台打开的直播间（内嵌、弹窗、卡片上“在虎牙打开”的点击）；用鼠标中键 / 右键菜单打开外链、在地址栏或其他入口访问虎牙，扩展看不到。状态补全只用 10 分钟内读取的数据，所以刚打开工作台、还没读取关注 / 推荐时，记录里显示“状态未知”是预期行为。
- 弹窗窗口复用靠当前新标签页内存里的窗口 id：刷新或关闭这个新标签页后，旧弹窗不会再被复用（再点会新建一个），也不会被扩展关闭。“弹窗优先”开关在工作台顶栏，不在扩展“设置”页。
- 观看记录与分组存在 `chrome.storage.local`，不跨设备同步，清除扩展数据或换浏览器配置后丢失。取消关注的主播会留在分组成员里（不显示、不计数），重新关注后恢复。
- `huyaSettings` 沿用整体写入：同时打开多个新标签页时，后写入的页面可能覆盖另一页刚保存的偏好（包括已隐藏的继续观看提示、视图、排序）；最近观看与分组走串行“先读后写”，不受这个问题影响。
- **剧场模式（第五轮）依赖虎牙页面的约定**：`#player-fullpage-btn`、按钮类 `player-narrowpage`、`body` 类 `mode-page-theater` / `mode-page-full`，以及“按钮行内 `display` 与点击处理函数同时就绪”的时序。虎牙改版后表现为弹窗保持默认布局，**没有任何提示、日志或界面状态**（页内函数返回的 `timeout` / `unconfirmed` 只在协调逻辑里消化，不上报）；排查时先核对这几项。
- 弹窗先以默认布局显示，房间页提交后约 1–4 秒（取决于虎牙页面加载与控制条初始化）才切换成剧场模式，中间有一次布局跳变；用户在切换前自己点了“剧场模式”时扩展不会再点。聊天栏、礼物栏的位置完全由虎牙自己的模式与 `isShowChatScreen` 偏好决定，扩展不改。
- 在等待期间关闭或刷新打开弹窗的扩展新标签页，该次不会进入剧场模式；在 30 秒内把弹窗标签页导航到别的网站也不会注入。
- 剧场模式只在新无头模式（`--headless=new`）的 Chrome for Testing 151 + 匿名真实页面里验证过；**已登录的真实账号**（控制条是否多出元素、登录或权益弹窗是否盖住按钮）、品牌版 Chrome 156、有头真实窗口都没有验证（该模式下 `popup` 的 `width/height` 没有体现，窗口报告 1440×900）。

真实验收步骤：在 `chrome://extensions` 重载扩展并刷新新标签页，先在同一 Chrome 配置登录 `huya.com`；通过启动台打开“虎牙直播”，进入“我的关注”并等待首次读取；核对直播中数量与顺序、封面和人气；点击卡片确认能在内嵌播放器播放；刷新后确认标签栏没有遗留的后台标签页；再检查“热门推荐”分页和分类。第三轮功能的验收：“弹窗优先”默认开启（第四轮起；之前保存过 `openMode:'embed'` 的配置也按默认开启处理），点击一个直播间应出现独立小窗口（官方房间页），再点另一个直播间应在同一个窗口里切换；点一下顶栏开关关闭后应改为内嵌，刷新后仍保持；到“最近观看”核对记录与状态；在“我的关注”里新建分组、给几位主播勾选并筛选；关闭再打开工作台，应出现“继续观看”提示。已登录账号下请特别留意：弹窗里是否仍出现“试看结束”。第五轮的验收：重载扩展并刷新新标签页后，点一个直播间，弹窗先显示房间页，约 1–4 秒内应自动变成播放器铺满窗口的剧场模式；再点另一个直播间应在同一窗口里换房间并同样进入；点“退出剧场”或按 `Esc` 退出后不应被拉回；已登录账号下留意控制条与登录弹窗是否遮挡。
