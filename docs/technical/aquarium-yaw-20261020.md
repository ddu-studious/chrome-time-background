# 水族馆侧视大鱼转身的伪 3D 投影（已实现）

日期：2026-10-20　状态：**已实现，全部未提交。** 为什么不用 three.js、物理引擎或 Yuka（以及 WebAssembly 库在本扩展里被 CSP 拒绝的实测）见 `docs/research/research-aquarium-physical-realism-libs-20261020.md`；这份文档记录**实际落地的东西、参数、验证到什么程度、限制**。

## 0. 结论先行

1. **问题**：侧视的小锤头鲨、鲸鲨转身时，旧画法只把整只鱼沿屏幕横向压扁成 `|cos(π·yaw)|` 倍，转到正对观众时只剩一条细线，像一张翻面的纸片（你说的“拖纸片”在拖拽和自由游转身里都存在，`aquarium-tide-size-drag-20261019.md` §5.4 当时记为已知限制）。
2. **做法**：新增零依赖的纯几何模块 `js/aquarium-yaw.js`，用“椭圆剖面”近似把已求值的骨架图层投影成转了某个角度的样子：正对观众时是圆滚滚的身体，两侧伸出胸鳍，锤头鲨是 T 形的横锤头。`js/aquarium-real.js` 在近处、不省流量时使用；数据不合规或投影抛异常，退回旧的压扁画法。
3. **效果**（体长 260 px，真实 Chrome 156 的扩展页里直接调用产品的 `AquariumReal.draw`）：转到正对（yaw 0.5）时外接框，小锤头鲨 **98×85**（旧画法 12×130）、鲸鲨 **89×70**（旧画法 12×97）。与 three.js 真 3D 模型的轮廓重合度（IoU）：90° 时小锤头鲨 0.980、鲸鲨 0.973，旧画法 0.129 与 0.169（§4.2）。
4. **限制**：①**只在网页端**；桌面原生画法（`desktop-reminder/jelly-species-painter.swift`）没有这套投影，转身的那几秒（起始速度 0 的实测：小锤头鲨约 3 秒、鲸鲨约 10 秒以上）两端不对齐；②IoU 的参照与投影共用同一份剖面数据，**只证明实现与“椭圆剖面体”模型一致，不证明鱼真的是这个形状**；③美术观感（正对时鲸鲨躯干上的横向明暗条纹是否自然、锤头横杆的比例）需要你亲眼确认。

## 1. 问题与根因

核心（`js/aquarium-core.js` 的 `advanceYaw`）让侧视的大个子想换面时在水平面里转半圈：进度 `yaw` 0→1，沿屏幕横向的投影 `xs = |cos(π·yaw)|`，过半（`yaw = 0.5`，`xs` 最小）换面。旧画法（`js/aquarium-real.js`，现在是退路）`ctx.scale(max(xs, XS_MIN), 1)`，`XS_MIN = 0.04`——这个下限只是避免画布矩阵退化，不改变“正对时是一条线”。

真鱼转到正对观众时不是一条线：是圆滚滚的身体、两侧张开的胸鳍；锤头鲨还有一根横着的锤头。要的是这种体积感。

## 2. 做法（`js/aquarium-yaw.js`）

纯几何：没有 DOM、存储、网络、时钟、随机数、`eval`，没有第三方代码；浏览器里挂全局 `AquariumYaw`，CommonJS 也可用（有源码合同测试）。

### 2.1 约定

- 坐标是骨架坐标（吻端朝 +x、y 向下、体长 100 单位，与 `js/marine-rig*.js` 一致）。输入是 `MarineRig.evaluate` 已求值的图层（含游动弯曲与拉尾），输出是同样结构的图层，交给 `Painter.drawOps`。
- 转角 θ = π·min(yaw, 1 − yaw)，范围 0…π/2：核心在转半圈的后一半换了面（`face` 取反），后一半用同一套投影再加水平镜像（`stateOf` 给出 `theta/mirror/pitch`，`pitch` 是换算成“鼻朝右”的等价俯仰角）。`yaw` 不在 (0, 1)、`face` 不是 ±1、`ang` 非有限时 `stateOf` 返回 `null`，调用方走旧路径。
- 数据不合规（缺躯干、坏图层、站位太少、非有限值）返回 `null`，**不抛异常**；转角越界夹取、非有限转角返回 `null`。

### 2.2 椭圆剖面

`stationsOf(poly, tau)`：躯干多边形把体轴分成 `STATIONS = 96` 段（97 个等距站位）；每个站位的竖向范围取多边形与竖线交点的上下界，得到中心 `yc` 与半高 `ry`（下限 `MIN_RY = 0.15`，避免尾端退化成线）；横向半宽 `rz = ry × tau(x)`。`tau` 是分段线性表：小锤头鲨取常数 0.85；鲸鲨头部扁而宽，头部处 `tau` 升到 2.6。有效站位不足 80% 或出现非有限值返回 `null`。

### 2.3 躯干轮廓

`silhouetteOf`：矢状面薄片（沿体轴压缩 cosθ）与各站位椭圆剖面的屏幕投影（横向占 `rz·sinθ`）取并集，按 `SAMPLES = 112` 个采样取上下包络。θ = 0 时与原轮廓一致，θ = 90° 是一个圆身体。

### 2.4 体表图层

背腹明暗、鳃裂、斑点、眼睛等：每个点按所在剖面的深度 z 横向位移 `x' = x·cosθ + TOWARD·z·sinθ`（`TOWARD = −1`：鼻端朝观众转，近侧体表向尾侧移）；背向观众的部分（体表法线在视线方向上的分量 ≤ 0）按 `facing` 标量场用 `clipClosed/clipRuns` 裁掉，免得前后两半的图案叠在同一块屏幕上；远侧体表只在转角超过 `FAR_FLANK_FROM = 0.85` rad（约 49°）才处理（再小的转角远侧整片背向观众）。**未登记的图层一律按体表图层处理**（不会被丢，也不会被当成矢状面压扁，有测试）。

### 2.5 鳍

背鳍、臀鳍、尾鳍在矢状面里：只压缩 cosθ，正对时是一条线（真鱼的这几片鳍正对时也是一条线）。胸鳍、腹鳍是离体表向外张开的片（`plates`：`root` 根部位置、`spread` 每离根部 1 个单位向外多张开多少）；远侧那一片在身体后面，颜色乘 `FAR_SHADE = 0.72`（鲸鲨的 `pecFar` 用骨架里已有的远侧图层）。

### 2.6 锤头

小锤头鲨美术里的锤头是竖着的一根杆（略俯拍），转身时绕体轴滚成横杆（`roll`：`bar/barEdge/nostril/eyeNear/eyeNearGlint/eyeFar`）；眼睛是球（`balls`），只挪中心，形状不跟着滚成一条线，正对时左右各一只眼，整体是 T 形。侧面才看得见的横杆厚度由 `hammer` 剖面给（`x0 = 41, x1 = 50.2, half = 14.5, ry = 3.6, yc = 1.2`）。

### 2.7 体积感

躯干上再叠一层暗色渐变（`volumeOp`）：远侧（屏幕右侧）最暗，深度 ∝ sinθ（θ = 0 时没有），暗色是躯干颜色乘 `VOLUME_TINT = 0.4`，最深压 `VOLUME_DARK = 0.42`。

### 2.8 物种与数据

`PROFILES` 只登记 `hammer` 与 `whaleshark`——核心里“侧视且体长超过 `AGILE_LEN` 的大个子”，有测试守住这个对应关系；蝠鲼（俯视）、海龟、小鱼没有，`has()` 为假，走旧路径。所有数字（`tau` 表、鳍根部、`FAR_SHADE`、`VOLUME_*` 等）都是美术取值，没有外部真值。

### 4.2 与 three.js 真 3D 模型的轮廓对照（2026-10-20 重跑；脚本与 three.js 在 `/tmp/aq-lib`，不入库）

把投影模块用的**同一份剖面数据**在 three.js 0.186.1 里建成真 3D 模型，用正交相机取轮廓，与旧压扁画法（legacy）、产品投影（product）在同一像素网格里比 IoU（真实 Chrome，1600×1200 视口）：

| 转角 | 0° | 20° | 40° | 60° | 75° | 90° |
|---|---|---|---|---|---|---|
| 小锤头鲨 旧压扁 / 参照 | 0.928 | 0.829 | 0.747 | 0.732 | 0.653 | 0.129 |
| 小锤头鲨 产品 / 参照 | 0.928 | 0.931 | 0.944 | 0.959 | 0.943 | **0.980** |
| 鲸鲨 旧压扁 / 参照 | 0.993 | 0.923 | 0.877 | 0.832 | 0.703 | 0.169 |
| 鲸鲨 产品 / 参照 | 0.993 | 0.993 | 0.991 | 0.989 | 0.985 | **0.973** |

90° 时外接框（宽×高，旧 / 产品 / 参照）：小锤头鲨 16×179 / 164×139 / 163×139；鲸鲨 17×140 / 147×112 / 146×113。0° 的 IoU 不是 1 是参照模型（椭圆剖面、三角网格）与美术轮廓本身的差异，旧画法与产品在 0° 是同一条路径。

**这个检验的意义有限**：参照与投影共用同一份剖面数据，它只说明投影实现与“椭圆剖面体”这个模型一致，不说明模型像不像真鱼；像不像要靠剖面数据（来自美术骨架）与你的眼睛。

### 4.4 成本

- Node（同一份图层、游动弯曲姿态，26 / 27 个图层，2000 次平均）：单次 `project` 小锤头鲨约 **0.24 ms**、鲸鲨约 **0.35 ms**（同一姿态下求值骨架 `MarineRig.evaluate` 分别 0.08 / 0.11 ms）；Node 里的冷启动第一次调用 3.8 ms、100 次之后稳定在约 0.3 ms。**测量时机器负载很高（load average 约 23，来自一个不是我启动的 `rg` 进程），这些数字是偏高的上限量级。**
- 无头 Chrome（原型页，**这台机器负载很高**，load average 约 21–26，主要来自一个不是我启动的 `rg` 进程）：弯曲姿态、转角 0.9 rad 下 `project` 小锤头鲨 2.749 ms、鲸鲨 1.213 ms（含上色的整条 `paint` 1.415 与 0.311 ms，旧压扁画法 0.649 与 0.211 ms）。
- **冷启动**：在这台机器的无头 Chrome 里第一次调用要 1–2 秒；Node 里同样的代码第一次只要 4 ms。排查后我归因于这台机器上 Chrome 的内存分配慢（2×10⁵ 个小对象分配 182 ms，Node 里 1.9 ms），而且 2026-10-20 在扩展页里的核对中，**不走投影的**旧路径第一次绘制同样要数秒（负载下，与上面是同一原因）——**这是推断，没有在无负载机器上复测，真实用户的 Chrome 里首次转身有没有卡顿没有验证**。
- 只有“正在转身”的侧视大鱼（小锤头鲨、鲸鲨）才调用投影；核心里一次转身会持续几秒（起始速度 0 的实测：小锤头鲨约 3 秒、鲸鲨约 10 秒以上，见 `aquarium-tide-size-drag-20261019.md` §5.4；真实巡航更快），每帧的其余成本不变。

### 4.5 变异检查（只改 `/tmp` 副本、核对仓库哈希；脚本与结果在 `/tmp/aq-mut`、`/tmp/aq-gap`，不入库）

## 5. 限制与未验收

- **桌面原生端没有这套投影**，转身仍是压扁；要对齐须把同样的几何移植到 Swift（`desktop-reminder/jelly-species-painter.swift`），另立一轮，并注意桌面目录里已有你未提交的改动。
- 蝠鲼（俯视）、海龟、小鱼没有转身投影（它们不走“缩短—换面—伸长”的转身）。
- 远处（`far`）与省流量（`lowPower`）的鱼不投影，转身时仍是压扁，这是有意的成本取舍。
- `TOWARD = −1`（鼻端朝观众转）是一个选择：转到另一个方向，近侧体表会向头侧移动，看起来像倒着转；测试只钉住了公式方向，**哪一个更像真鱼没有量化判据**。
- 美术观感（鲸鲨正对时躯干上的横向明暗条纹、锤头横杆的比例与粗细、鳍的张开角度、体积感暗层的深浅）未量化，**请你亲眼确认**；数字集中在 `PROFILES` 与顶部常量里，改了必须重新看真实截图。
- 真实用户 Chrome 里的转身手感、操作系统级真实鼠标与触屏下的拖拽转身（只用 Playwright 派发的鼠标事件看过，见 §4.3）、真实 GPU、高分屏与长期占用均未验收。

## 6. 回滚

- 只想让它不起作用：在 `index.html` 里去掉 `aquarium-yaw.js` 的脚本行（`aquarium-real.js` 在 `Yaw` 缺席时本来就走旧路径，有测试）；
- 或让 `PROFILES` 变空 / 让 `Yaw.has` 返回假；
- 投影抛异常时已经自动退回，不需要人工操作。

纯本地几何计算，无新权限、网络、存储、依赖或动态代码执行；输入全部做有限性与形状校验、失败返回 `null`；没有用户数据进入这个模块。
