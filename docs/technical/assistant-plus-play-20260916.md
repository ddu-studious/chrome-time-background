# 快捷助手加号即播放

用户明确要求覆盖旧的“仅追加”行为：单曲加入并播放，专辑/歌单/歌手Top替换队列并播放。

## 修改

- 保持既有候选动作ID兼容，`music.enqueue` 改走真实单曲播放链路；`music.enqueue-collection` 和整组播放走同一条替换队列链路。
- 准备可播放资源后提交新队列；成功回执来自播放器状态检查。返回实际歌曲与队列数量。
- 已存在的歌曲仍会立即播放。满队列拒绝新单曲，不再截断末尾歌曲腾位置。
- 执行中保留候选，禁用操作并显示进度。成功保留回执和结果；失败保留候选以便重试。旧会话的按钮文案自动转换为新语义。
- 任务完成后继续选择音乐只执行新选择，不重放原复合任务中的定时。

## 验证

- 665项 JavaScript/MJS 回归通过。
- 生产后台函数测试验证：单曲追加、已存在歌曲重播、整组完全替换、资源准备失败保留旧队列、满队列不丢曲目。
- 执行器测试验证：准备中和失败后保留候选、成功后可继续点歌、后续定时不重复执行。
- Chrome 隔离界面验证：单曲加号和专辑加号均有准备/成功反馈，结果列表在两阶段均保持可见。音频与账号操作在该页面使用测试替身。
- 真实扩展页面仍受浏览器工具URL策略限制，未完成登录态实际音频验收；需要重载扩展并刷新现有音乐主页。
