# 工作台自动确认判断：pi SDK 接入

日期：2026-09-19。范围：主工作台 `AssistantEngine → AssistantTools` 的提醒确认路径。

## 用户行为

明确的一次性提醒可直接创建，例如“20分钟后提醒我喝水”“明天下午三点提醒我开会”。目标已唯一解析的一次性提醒可按明确原文修改，例如“把喝水提醒改到15:00”“把喝水提醒改到明天下午三点”“把喝水提醒改名为喝茶”。成功后返回真实业务回执，并继续原计划剩余步骤。

以下继续等待：删除提醒、清空队列、移除当前歌曲、重复提醒修改、多个候选目标、无法精确核对原文的表达、预览或先确认要求。暂停、切歌、设置播放模式、查询等继续沿用原有直接执行路径。

本期自动放行是有限的确定性规则，不宣称理解所有自然语言。创建复用 `AlarmIntent.parseLocal/resolve`；修改复用同一解析器及 `wallTime`。模型理解成功但规则无法独立核对时仍显示具体确认卡。之前明确要求预览或确认的原文也阻止自动放行；本期不自动推断旧限制已被撤销。目标选择与授权确认保持分离。

## 上游复用及适配边界

使用仓库已固定、已安装的 `@earendil-works/pi-coding-agent@0.85.1`（MIT，Node >=22.19.0），不改变 package.json/package-lock.json 的版本。只导入公开包入口的 `ExtensionRunner`、`createExtensionRuntime`、`createSyntheticSourceInfo`、`SessionManager`。

实际调用 `ExtensionRunner.emitToolCall()`，由 SDK 分派 `tool_call` handler 和返回 `{ block, reason }`。官方 permission-gate 扩展证明该事件适合执行前拦截；pi 没有内置业务风险分类器。项目只实现单条提醒的业务授权规则、HTTP 桥接和确认卡适配，没有复制 SDK 或另起任务循环。

已检查 `wrapRegisteredTool`：0.85.1 的该函数只做工具上下文适配，拦截由 AgentSession/agent-core 调用，不会自动拦截咱们的浏览器执行器，因此不能仅包装工具后声称权限钩子生效。

策略运行器只注册内建的一个 `Extension` 描述符，不发现本地/全局扩展；不初始化 AgentSession、不绑定 shell 或模型执行入口。内存 SessionManager 只满足 SDK 上下文接口，不存储用户对话或业务状态。模型注册表使用拒绝访问的能力适配，任何访问立即报错，不读取全局凭证、不使用默认 Provider。

## 执行路径与边界

1. 原有工具完成解析、目标选择和准备，返回真实确认参数。删除/队列破坏性动作仍直接保留原确认卡。
2. Tools 将原始用户文本、独立保留的历史限制、任务版本、请求标识、时间锚点与实际候选参数发到鉴权 `/v1/assistant/approval`；不使用模型改写后的工具文本作为授权依据。
3. SDK 返回当次 allow/confirm。Tools 检查请求和任务版本以及策略版本；响应不作为长期授权保存。参数和目标改变必须再次核对。
4. allow 才通过原有 `choose` 路径提交；继续检查时间/时区、资源引用、快照、revision、任务取消状态。自动提交额外计入 12 次工具调用和 5 分钟上限，不重置预算。
5. 实际写入前仍记录 `sideEffectStarted`。已开始但丢失回执时为 unknown，后续只能核对，不能自动重做；成功回执保护提醒准备步骤，阻止同一任务相同参数重复提交。仅完成准备或策略检查不记录成业务成功。
6. SDK、HTTP 或响应合同失败时明确显示“自动判断暂不可用，保留手动确认”，不以本地自研判断静默放行。用户仍能使用原确认卡。

判断不调用模型，因此没有额外 token 或模型预算；原解析/规划仍受 Gateway 的开关、额度和超时约束。策略 HTTP 使用现有 origin、Bearer 和体积限制，扩展桥接固定本机端点及 1.5 秒超时。无业务写入权限的策略服务也不执行提醒操作。执行轨迹保留 `assistant.approval` 及真实提交动作；任务观察记录判断理由。

## 验证与使用

专项 `test/assistant-approval.test.mjs` 使用实际安装的 pi SDK，仅业务依赖和解析回复为替身；包括自动创建/修改、参数误差/额外字段拒绝、原文限制、复合任务、版本变化、取消、unknown、重复副作用、12 次/5 分钟预算、鉴权 HTTP。扩展桥接另有固定端点、令牌、来源限制测试。

这不等于真实模型、真实 Chrome 扩展、账号或系统提醒验收。本次策略本身不需要模型，测试不创建真实提醒或改变播放队列。首次本机监听受沙箱 EPERM 限制，获准运行后 HTTP 用例通过。

本轮验证结果：

- 提醒自动确认专项 13/13 通过，包含真实 SDK 和临时鉴权 HTTP。
- 助手/本机 AI 回归 356/356 通过；随后新增的扩展桥接用例也通过，桥接文件共 13/13。
- 10 个修改/新增脚本语法检查及 `git diff --check` 通过。
- 确认当前本机服务没有运行中的 job 后重载；首次 launchd bootstrap 报错，重新 start 后恢复，个人记忆接口就绪。新版真实 19841 鉴权接口分别返回 `allow`（明确一次性提醒）和 `confirm`（先不要创建），均标明 pi 0.85.1。仅判断，无真实业务副作用、无模型调用。
- 尚未重新加载或实测真实 Chrome 扩展。没有提交 Git。

使用最新服务与扩展：在项目根目录执行 `./local-ai/service.sh restart`，并在 Chrome 重新加载扩展。没有新增依赖；新检出仍按项目要求在 local-ai 内执行 `npm ci`。
