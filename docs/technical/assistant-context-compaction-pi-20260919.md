# AI 工作台上下文整理：pi SDK 接入

日期：2026-09-19。实现范围：主工作台 `assistant.plan` 链路。

## 复用决策

用户要求：已有开源能力可用时必须直接复用，优先 SDK，不重复实现。这条要求已写入项目根目录 `AGENTS.md`。

本次采用正式发布的 **`@earendil-works/pi-coding-agent@0.85.1`**，写入 `local-ai/package.json` 和 `local-ai/package-lock.json`。直接导入公开包入口，不复制上游源码，不导入私有路径，不启动 pi CLI、AgentSession 或全局插件。

| 上游公开 API | 真实运行职责 |
|---|---|
| `shouldCompact` | 判断相对于输入预算的压力阈值 |
| `findCutPoint` | 为待整理来源选取合法保留边界 |
| `generateSummaryWithUsage` | 使用 pi 的会话序列化、结构化摘要提示词、旧摘要增量更新与结束原因检查 |
| `streamFn` 扩展点 | 把 pi 的模型请求接回项目 Gateway/LM Studio；不会使用 SDK 的默认远端 Provider |

选择 pi 是因为这些能力可以独立调用、能注入受控 Provider。DSH 的 compaction backend 依赖 Cordis、Session、token-meter 和事件生命周期，本项目接入同一能力需要更大的运行时改造。因此优先使用已验证可独立接入的 pi API；没有另写一个 DSH 仿制实现。

SDK 版本需要 Node >=22.19.0。此次安装新增 165 个包，本机依赖目录约 434 MiB，这是磁盘占用，不是常驻内存或模型显存。使用 SDK 会带来其包依赖体积；后续如果上游发布更小的 compaction 子包，可在相同契约测试下替换，不能通过拷贝源码减包并仍称为 SDK 集成。

## 项目适配层

- `local-ai/assistant-compaction.mjs`：公开 SDK 的薄适配层，负责业务来源校验、源块预算、模型元数据和摘要收缩校验。
- `js/assistant-context-state.js`：浏览器任务上下文适配，保留用户原文、实际回执、原始业务结果和检查点；提供有界回读。不负责生成摘要或重写上游摘要算法。
- `assistant-tools.js`：调用独立 `assistant.compact` 场景、提交检查点、重新请求规划。
- `assistant-engine.js`：沿用原有串行锁、任务版本和取消；存储失败回滚新摘要。副作用重复防护与未知回执归执行器负责。
- Gateway/Provider：摘要使用独立 admission ticket、实际 usage、超时、控制策略和取消信号；默认关闭摘要思考。SDK 自带重试显式关闭，防止绕过计费。

## 实际流程

1. 用户输入在窗口裁剪前记录；成功业务回执独立保存。continue 继承同一会话事实，新需求重新开始，原有候选/资源权限规则继续生效。
2. 工具业务结果先清除凭证/请求头，再保留当前任务来源。给模型的投影移除展示附件、缩短大文本，必要时把大型字段换成 `contextRef`。模型通过 `context.read(ref, offset)` 每次回读最多 1600 字符。
3. 正常短任务不调用摘要。未摘要来源超过 32 条时提前分块整理；规划输入超过约 78% 输入预算、触发本地预算拒绝或模型明确报告输入超限时，也会请求整理。
4. 每批最多 32 条、40 KB 的材料发往摘要场景；服务端再根据实际模型窗口限制源块。保留区由 pi 选择。普通整理近期目标最多 1024 个上游估算 tokens；强制恢复保留最后来源及独立保护状态。
5. pi 生成结构化摘要；来源版本、摘要非空、长度、结束原因和实际收缩均通过后才提交。关键用户原文、回执、待选操作和资源版本不交给模型重写。
6. 超限恢复最多重试当前规划一次，不重放已执行工具。仍不能容纳时保留进度并说明原因，不循环压缩或重置原有 12 轮/12 工具/5 分钟边界。

同一自动整理入口最多处理 4 个增量源块。摘要输出最多 1536 tokens，并受全局输出额度限制；摘要自己的请求也必须留足输出和安全空间。固定合同、必须保留的用户要求或单条不可分来源过大时仍会停止，不能靠有损摘要消除业务约束。

## 存储与恢复边界

本次复用原有 `chrome.storage.local` 中的活动任务快照，将 `contextState` 和任务一起保存；每个上下文设置 **512 KiB / 512 条来源** 上限。没有再引入第二个 IndexedDB 事实库，避免与当前任务快照形成两个提交点。这个实现替代调研草案中的 IndexedDB/10 MiB 设想，是对当前受控任务规模的收敛。

新需求/清理任务沿用原入口，移除活动上下文。历史留存开关未被自动开启，任务摘要不会写入长期个人记忆。迁移只能保留旧任务尚存的记录，无法找回以前已经被 slice 掉的历史。

原始业务结果在当前任务的 `artifacts` 中保留，但凭证和请求头不保留。回读得到的是历史证据，不能复活资源引用或旧 revision。最多向规划器投影 96 条用户要求和 96 条回执，受字节预算约束，超过时明确停止，不默默删除较早限制。

有成功回执的受保护队列动作，不允许同一个任务再次自动执行相同参数动作；明确的新需求仍可以再次操作。操作已经开始但没有收到回执，重启/失败/取消时记为 `unknown`：可以查询核对，不能自动重新提交写入。同一个结果未知的候选不直接重试；用户明确选择其他候选仍沿用已有交互行为。

这不是跨网易云、Offscreen、浏览器存储的分布式 exactly-once 事务。外部动作成功、回执尚未保存即崩溃时，使用 unknown 保守阻断，需要实际核对。

## 开关和界面

- AI 设置新增 `contextCompaction`：`hybrid`（默认，程序精简 + pi 摘要）或 `deterministic`（只精简，不调用摘要模型）。
- `assistant.compact` 是独立注册场景，可以单独禁用；模型总开关、每日预算、失败冷却与策略版本继续约束调用。
- 工作台新增“整理上下文”按钮。执行时保留停止入口；原待选择/待确认状态整理后恢复，不提交业务操作。
- 执行轨迹区分“整理上下文（pi SDK）”与规划调用，分别展示预算和模型用量。完成提示显示本次摘要范围的前后估算，不把这个数说成整个请求或整个任务的压缩率。
- 旧音乐/闹钟独立入口 `assistant-session.js` 的条数限制保持原样，本次不宣称所有 AI 页面都已支持压缩。

- 生产 Engine + Tools + Gateway + pi SDK 的队列流程注入一次输入溢出后继续成功；清空、追加、播放各一次。

## 使用与部署

1. `cd local-ai && npm ci`，Node >=22.19.0。
2. `./local-ai/service.sh restart`（项目根目录）重载服务，保留原连接与策略配置。
3. 重新加载 Chrome 扩展，刷新工作台。后台新增了 `assistant-context-state.js`，旧 Service Worker 不会自动获得新增模块。

本轮未提交 Git，也未修改无关业务文件的既有改动。
