## 问题证据

10月19–20日留存记录中，3个会话有5次 `COMPACTION_NO_GAIN`，另有3次 `no_safe_range`。5次摘要模型均正常返回，耗时合计103.725秒，但整理材料总共只有193–285字符。固定的pi结构化摘要格式让短材料扩写，旧适配层因没有收缩抛错，规划随之停止。

容量预警来自本地估算，不是模型确认超窗。中文按每字符2 tokens、ASCII按每字符0.5 tokens估算，近期同请求的估算约为实际usage的2.72–2.84倍。输入预算10576，提前整理门槛约8249，而系统规则自身粗估8255–9572；整理短历史并不能减少这部分规则。

## 上游复用与适配职责

新增并精确锁定 `@lmstudio/sdk@2.1.0`，MIT，官方npm发布包；`package-lock.json`同步更新。检查过公开导出、类型与实际运行，安装使用 `--ignore-scripts`。依赖审计仍为已有pi依赖链的3项（pi、undici、brace-expansion），新增SDK依赖没有新增告警，本次没有升级pi。

公开能力：`LMStudioClient`、`llm.createDynamicHandle({identifier,deviceIdentifier:null})`、`getContextLength()`、`applyPromptTemplate()`、`countTokens()`。只调用已加载本机模型的模板和分词服务，不使用自动加载的 `model()`、生成、Agent、Shell或插件能力。SDK来源：[官方仓库](https://github.com/lmstudio-ai/lmstudio-js)，[分词文档](https://lmstudio.ai/docs/typescript/tokenization)，[认证文档](https://lmstudio.ai/docs/typescript/authentication)。

`local-ai/model-token-counter.mjs`只是SDK适配：复用Provider已经校验的本机地址与凭据；不新增模型、网络目标、浏览器权限或业务工具。每次计数最多5秒，同一Provider最多1条未完成计数。只读RPC没有取消参数，所以本地取消/超时立即返回，未完成RPC继续占用槽位至结束，后续RPC不会启动，避免连续超时堆积。SDK错误不回显其诊断正文，不静默改用自写分词或放行估算。

API限制与明确例外：

- 分词需要已加载模型。冷模型继续使用已有保守预算并标记 `cold-model-estimate`，不为了分词额外加载模型；真正生成仍沿已有受控原生入口加载。很长的冷启动首请求仍可能被保守拒绝，此边界没有掩盖成准确分词。
- `applyPromptTemplate`没有本次reasoning覆盖参数，使用模型默认模板。此次Qwen样本计数比原生生成usage恒多36 tokens；这不是完全一致的计数，继续保留512 tokens安全余量。换模型或模板需重验。
- 计数服务不是模型生成，不额外占一次生成额度；它仍由Gateway检查总开关、场景、所选模型、策略版本和取消，耗时计入原任务总时限。生成次数和usage继续由原Admission管理。

## 行为变化

1. `prepareModelContext`先保留去重后的完整业务输入并分词，使用 `measuredInputTokens`决定是否超限。原 `estimatedInputTokens`、规则/数据分项粗估与生成usage分别保留，不能混称实际输入。只有计数确实超限才投影展示字段并再次计量，用户限制、回执、资源引用、版本与分页不丢失。
2. 同次请求的输入、系统提示、模型、思考与容量组成指纹。生成前复核容量，指纹相同不重复分词；恢复尝试改变输入或思考、容量变化时重新检查，不跨任务缓存执行结果或授权。
3. 提前整理还要检查可压缩历史量。pi仍负责切分、序列化和摘要；切分后的旧区间加旧摘要粗估不足1024 tokens返回 `changed:false/short_source`，不生成摘要。该阈值是适配层的收益门，不是模型容量上限。
4. 有效但未收缩的摘要返回 `changed:false/no_gain`，不覆盖检查点。空、过长与截断摘要仍拒绝。浏览器保留原记录与回执，并如实提示未缩短。
5. 原来的最多一次规划恢复会重新计量完整请求：容量足够继续，真正超限仍停止。没有放宽12轮/12工具/5分钟限制，也没有重做清空、追加或播放。
