# 多轮规划被固定上下文预算提前拦截

## 本次故障的实际证据

同一请求第一轮成功返回 `music.state`；第二轮还没请求模型就报“当前工具结果超过模型上下文预算”。故障并非原队列的 101 首歌曲全部被传入模型：发给模型的状态回执仅 331 字符，歌曲明细留在执行器。

旧估算：系统说明 5873，第一轮输入 232，合计 6105，勉强低于固定 6200；第二轮即使丢弃旧 turns，输入估算仍为 386，合计 6259，被拒绝。第一轮 LM Studio 实际返回的输入统计是 2158。旧估算明显保守，却被当成固定模型容量，且没有随实际加载上下文变化。

上一轮输出预算修复只验证真实模型首轮计划与失败恢复，没有覆盖此后读取状态的规划，因此未发现本问题。

## 修改

1. 新的 `assistant-context.mjs` 统一规划输入预算。读取所选模型的实际加载上下文；每次预留控制面允许的输出预算和 512 token 安全空间。规划工作窗口最多 32768，避免把大上下文全部铺满造成延迟。当前实例大于此值时，开启思考、输出 4096 对应输入估算预算 28160；不是固定 6200。冷加载与 Provider 统一使用 12288；已加载但容量未知时按 8192 保守处理。
2. 容量读取只是元数据查询，不算一次模型生成。生成前再次检查模型容量，处理用户刚重新加载了较小窗口的情况。全局开关、取消和策略变更继续约束准备和生成。
3. 音乐专用 Skill 已有的规则不重复注入；闹钟/视频专用规则仅在对应应用作用域出现。模型工具目录、权限、参数和输出合同仍由服务端校验。
4. 删除重复的当前用户输入和已有回执的展示消息；保留较早同文的用户要求。预算紧张时压缩标题等展示字段，移除封面等附属字段；保留所有观察、候选引用、selectedRef、revision、分页、数量、用户限制和剩余步骤。移除原先一律只给前五项候选的行为。
5. 工具入口同时传递至多 24 条已完成步骤摘要。最近六条详细观察之外的较早写操作仍可见；摘要只用于避免重复，不作为写入版本或资源引用的来源。
6. 真正无法容纳时返回 `ASSISTANT_CONTEXT_BUDGET_EXCEEDED`，包含容量、输入/输出预算、估算分项和压缩状态；执行记录保留所选模型，显示“规划准备，尚未调用模型”，不再只显示“未返回模型信息”。

估算值仍是保守估计，不冒充 tokenizer 的精确统计。执行回执窗口仍为六条，工具合同和单轮 12 次调用等现有边界保持不变。

## 验证方式

- `test/local-ai-assistant-context.test.mjs`：截图第二轮输入、多个工具组、长 turns、较晚候选引用、展示字段压缩、真正超限诊断、模型切换、已完成摘要及完整七轮生产引擎链路。
- `test/fixtures/assistant-context-scenario.mjs`：生产 Gateway、Planner、Engine、Tools；音乐状态、账号接口、确认、选择、写入和播放均为内存替身。断言从 101 首队列开始，清空、追加 100 首热门歌曲、随机起播各执行一次。
- `node local-ai/evaluate-assistant-context.mjs --live`：用真实本机 Qwen 运行以上完整流程，逐轮记录输入预算与实际 token。不会操作真实账号或播放队列。报告保存于 `local-ai/.local/evaluations/assistant-context-*.json`。

## 全流程发现的第二个问题

真实模型首次全流程验证已通过工具加载、状态读取和清空确认（累计四轮，均未再发生输入预算拦截），但随后把“搜索热歌、添加队列、随机播放”整段交给 `music.intent`。该入口是单动作解析，会丢失复合队列流程的分步控制；隔离验证将其拦截并判为失败。

进一步调整：队列组合任务的可用工具中移除 `music.intent`，提示模型使用原子搜索、集合读取、队列应用和队列播放；普通单动作音乐需求仍保留原入口。目录外调用继续由服务端拒绝，未通过静默重写把多动作请求伪装成单动作。测试覆盖这两类目录边界。

## 本轮结果

- 277/277 本地 AI 与助手相关回归通过；修改脚本语法检查和 `git diff --check` 通过。
- 真实 Qwen low 全流程通过，共 6 次规划、约 160.4 秒；清空、追加、起播各一次，最终测试队列 100 首、shuffle、isPlaying=true。
- 后三轮输入估算为 6491、6622、6738，均超过旧 6200 门槛；实际模型输入分别 2416、2487、2536，现有输入预算 28160，不再提前拦截。
- 完整成功报告：`local-ai/.local/evaluations/assistant-context-1789724409191.json`。早期发现错误路由的失败报告为 `assistant-context-1789724176309.json`，保留作复盘。
- 此验证使用真实模型，业务数据/操作是内存替身；不是网易云真实账号或音频播放验收。Chrome 扩展页面仍需重新加载以使用新的已完成摘要和诊断展示。
