# 快捷助手前端执行过程与连续会话

## 实现

- 输入条在有会话时展开为对话和执行过程两栏，继续输入区位于底部。窄屏上下排列；首页宿主跟随内容调整宽度和高度。
- `assistant-timeline.js` 展示真实 `ctx.trace` 事件的开始、结束、失败、取消和中断，以及工具名、父子关系、耗时、脱敏参数和返回结果。点击步骤可展开详情。
- 成功后约 1.8 秒收成回执；正在查看或聚焦过程时不自动收起。失败/待确认/待补充保持展开。手动展开和当前会话在重新打开后可恢复。
- 会话沿用 `conversationId`，普通提交和候选操作都有独立 `turnId`。完成、失败后继续输入仍属于同一会话；“新需求”才清理当前会话。后台重启不重放副作用。
- 候选采用实际 ID 和固定过期时间。前端展示编号，筛选后的序号回复携带实际显示 ID，后台校验版本、候选成员、作用域和有效期。
- “播放第 2 个”会将歌手、专辑、歌单的浏览候选映射到对应播放动作，读取该 ID 的曲目并等待播放器确认，不重复搜索。普通“打开/选择”保留浏览语义。
- 明确说“直接播放”且搜索只有一个真实候选时自动播放；多个候选保留选择，不编造置信度。
- 模型元数据来自统一网关当次执行回执，包含实际模型、思考设置、耗时及提供者返回的用量。失败调用也携带已有元数据；没有返回时不会以当前配置补写旧记录。

## 留存边界

- 实时工具详情存在执行器内存中；写入 Chrome 当前会话快照时移除工具输入、输出和错误正文。
- 本机历史的长期正文留存继续遵循原有开关，实时 UI 不修改设置。凭证、播放链接继续脱敏。
- Chrome 当前会话包含最近 100 条用户可见消息、最近 400 个动作元数据、候选及运行上下文；超出展示上限明确提示，可查看本机历史的实际留存内容。
- 模型输入仍使用有界近期上下文；候选引用独立存储，不依赖自然语言聊天上下文推测。此版本没有增加跨会话个人偏好记忆。

## 使用

重新加载 Chrome 扩展，打开快捷助手。可先搜歌手，回复“播放第 2 个”，再继续追问。`Esc` 仅收起面板；“新需求”开启新会话。

隔离预览：`node local-ai/assistant-preview.mjs`，访问 `http://127.0.0.1:18765/assistant-preview.html`。
