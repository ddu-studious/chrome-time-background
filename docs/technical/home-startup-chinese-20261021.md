# 首页加载减负、中文与活动提示（2026-10-21）

## 排查结论

使用原仓库目录加载真实扩展，Google Chrome for Testing / Chromium 151，临时空白配置。先在阻断网络的默认模块配置下采集 CPU、初始化调用与定时器，再开放公共网络测冷启动壁纸；未使用用户 Chrome 配置或账号。

1. 实际联网冷样本中，文字首屏 368ms、DOMContentLoaded 389ms，但壁纸列表 4917ms 才返回，图片 6598ms 才可用。体感黑屏主要来自首次远程列表加图片下载，不能把全部等待归因于界面脚本。
2. 首页直接加载约 6.29MB 脚本，包括约 1.8MiB Mermaid 图表库，普通首页未用到图表。
3. `clock.js` 自行 init，`main.js` 又 init，实际留下两条 1 秒定时器；每次格式化日期还重复创建 Intl 格式器。
4. `main.initApp()` 等待天气初始化后才处理其他入口。默认无定位权限时它很快失败，但获得定位许可后定位或接口慢会阻塞后续应用。
5. 上一版提示用固定 opacity，破坏了闲置隐藏；与小鱼托盘又挨得太近。原国际化运行时还会把旧 `language=en` 配置应用到日期和部分任务文案。

## 实现

- **冷列表等待上限 1.2 秒。** `background-provider.js` 复用原有并发合并、设置指纹、7 天旧缓存和 30 分钟后台刷新逻辑。无可用结果时最多等 1.2 秒，慢源继续后台构建，当前页使用原有预设壁纸。回退不写成有效缓存、不覆盖原来好结果；60 秒卡死重建边界、来源过滤和媒体模式不变。首次可能显示预设图，远程列表留给后续打开使用。
- **提前开始同一次壁纸请求。** head 加载已有 `BackgroundWarm` 与薄适配 `home-background-start.js`；调用原 `getBackgrounds`，从实际返回的列表按原规则选图并提前下载，main 消费同一个 Promise 和候选，不再另发请求或重新随机选图。隐藏、省流量、视频等不提前下载，存储不可用不阻断列表传递。无新增壁纸源或缓存。
- **图表按需加载。** 复用仓库原有 `@mermaid-js/tiny@11.13.0` 的本地文件、公开 `initialize` / `render` API；首页和独立任务页首次出现实际图表时才加载。合并在途请求，10 秒超时，失败保留源码及可读提示。保持 HTML 图表标签，使用 strict 和现有 DOMPurify 3.2.5 的 `sanitize` / `ADD_TAGS` / `HTML_INTEGRATION_POINTS` 净化；错误正文使用 `textContent`，没有拼接执行错误中的 HTML。未增加依赖或改 vendor 文件。
- **时钟与天气。** Clock.init 幂等，复用一个中文 Intl.DateTimeFormat；12 小时制显示上午/下午。天气初始化独立执行，继续使用自身定位/网络超时与重试路径，错误不阻塞其他入口；初始化完成时检查更新计时器是否已存在，避免重复建立。
- **中文。** 删除 `js/i18n.js`、英文词库、语言下拉、语言变更监听和整页翻译遍历。任务文本与帮助直接使用中文，日期、节日和预设壁纸说明固定中文，加载旧设置时丢弃 language 字段。其他偏好、用户内容与外部来源数据保留原值。
- **提示样式与行为。** 与小鱼横向间距桌面 18px、390px 窄屏 12px；窄屏提示移到首页卡片上方。鼠标活动显示，停止约 3 秒隐藏；悬停、键盘可见焦点及触屏保留可访问入口。只维护一条有界活动计时器，不增加 RAF 循环，后台页清理计时器；提示隐藏时 `?` 仍可打开面板。

## 交付边界

本轮涉及后台壁纸 Provider，用户已有扩展实例需在 Chrome 扩展管理页重新加载一次，再刷新首页；本机 AI 服务不需要重启。没有替换扩展目录、关闭用户选择的水族馆效果或改动真实账号数据。网络和鉴权仍由已有路径负责；动态图表输出使用成熟净化库，无新增权限、模型调用或远端代码加载。
