# 海洋动物写实化与水族馆海水效果：调研

## 0. 结论先行

1. **新增的四种动物（小锤头鲨、蝠鲼、海龟、鲸鲨）不真实，原因在“画法”，不在颜色**：旧画法是一块刚性的躯干轮廓，加几个绕轴摆动的鳍，配卡通脸和用户可选的调色板；真实动物是**整条脊柱在行波**（头几乎不动、幅度向尾部增大）、**逆荫蔽配色**（背深腹浅）、**物种专属的花纹**（鲸鲨的白斑与纵棱、蝠鲼的腹面鳃裂与暗斑、海龟的盾片），鳍与翼的摆动有**沿展向的相位滞后**。
2. **X 上的作品几乎都是“程序化动画 + 着色器”路线**（#3、#4、#10、#11、#15、#29，帖子文字明说没有烘焙动画）。可借的是**做法的思路**（脊柱行波、转弯时身体弯成弧、水面光学），不是模型、代码或素材。这些作品多是三维模型加三维引擎，而本项目的首页是 2D Canvas、桌面端是原生 CoreGraphics，所以采用**自写的 2.5D 矢量骨架求值器**，两个平台吃同一份数据、同一条公式——这是“桌面与水族馆对齐”的前提。
3. **海水效果的共同套路**（#5、#6、#42、#43、#44、#45、#47 的文字与抽帧）：从水下往上看的水面起伏与镜面波光、从水面射下的光束、海底软边的焦散、悬浮微粒与气泡。首页水族馆用**一张半分辨率的 WebGL 加光层**实现；它画的是“水下看到的水面光影”，**不是“侧面剖开、看得见浪尖”的画法**（取舍见 §6）。
4. **X 不需要登录**：50 条里 48 条用匿名的 `yt-dlp` 取到了元数据，27 条带视频的帖子下载并抽帧查看；#21（80.lv 文章链接，`yt-dlp` 不支持）与 #28（该推文没有视频）取不到。没有读取用户的 Cookie 与浏览器登录态，也没有打开或阅读这些作品的页面源码。
5. **公开参考照片没有出处与许可记录**：只用来量比例，没有描摹，也没有入库，所以不能把它们当作“素材来源”写进产品说明。

## 1. 要回答的问题

用户 2026-10-19 的要求（摘要）：桌面和浏览器里的海洋动物都已实现，但**新增的这些不太真实**；他提供的 X 链接（`X海洋动物创作50帖.xlsx`，同目录有同数据的 `posts.json`）和自己找的素材都可以参考，看怎么做得更仿真实世界；另外让 Chrome 首页水族馆加**海水、海浪**的效果；**桌面端的真实效果与扩展水族馆最好对齐**。

| 步骤 | 做法 | 结果 |

| 公开参考图 | 找每种动物的侧视、俯视照片与科学插图，只做比例测量与结构核对 | 小锤头鲨、蝠鲼、海龟、鲸鲨各 7 张，另有小丑鱼与一般鲨鱼各 1 张；**没有记录出处与许可** |

资料都在 `/tmp/marine-research/`（下载的视频、抽帧、参考图），**不入库**；重启后可能消失，结论以本文为准。

**证据的三种来源要分开看**：① 帖子的文字说明（作者自己说的做法）；② 抽帧里能直接看到的（水面、光束、整体风格，分辨率有限，看不出逐帧的摆幅数字）；③ 通用的动物形态与游泳方式知识。下面的每条结论都标了依据是哪一种。

## 3. 帖子里能借的做法（按主题）

| 主题 | 帖子与依据 | 我们的取舍 |
|---|---|---|
| 程序化游动，不用烘焙动画 | ① #3、#4（“Zero baked clips / Every motion is procedural”）、#10（“100% procedural shark animation in Unity URP”）、#15（Subside 的程序化大白鲨）、#29（Aurelia 水母：verlet 物理 + 假体积光） | 采用同一路线：自写**脊柱行波 + 鳍拍动**求值器 `MarineRig`，没有任何预录动作 |
| 转弯时身体弯成弧 | ① #11（作者说灵感来自 Abzu 的 GDC 演讲，试做“curl turns”顶点偏移）；② #12 的抽帧（锤头鲨的绑定，身体在平滑的 S 形里摆，尾部的偏移看起来明显大于头部） | `bend.turn` 与姿态里的 `turn`：转弯时整条脊柱按同一条曲线偏移 |
| 头稳尾摆 | ③ 鱼类与鲨鱼的体波游泳：横向幅度向尾部增大，尾鳍最后到位；② #12 | `bend.amp = [头, 尾]` 与 `pow`：幅度沿体轴按幂函数增大 |
| 鳍、翼的滞后 | ③ 蝠鲼拍翼时翼尖落在翼根后面；海龟（海龟不是淡水龟）的**前鳍左右同时拍动**，像拍翅膀，后鳍小、起舵的作用；#1、#45、#47 的抽帧分辨率太低，只用来看蝠鲼的外形（翼盘、头鳍、细尾）；#50 的抽帧里是在石头与水草间活动的龟，看起来更像淡水龟，**它的步态没有采用** | 部件 `flap`：转角 + `lag`（离转轴越远转得越晚）+ 俯视拍翼的透视压扁 `squash`；左右部件互为镜像、同时拍动 |
| 背深腹浅、物种花纹 | ① #23、#24（鲸鲨与大白鲨模型的文字）；② #1 抽帧里鲸鲨背上的白斑；③ 逆荫蔽、鲸鲨的斑纹与纵棱、蝠鲼的腹面鳃裂 | 逆荫蔽渐变 + 每种动物自己的花纹层；远近用同一份“偏蓝变淡”的色调叠加 |
| 鱼群对光标的反应 | ① #3（“flee smoothly from the cursor”）、#43（180 条鱼，慢速移动光标才会跟过来）、#44、#46、#48 | **没改**：水族馆核心里已经有成群、避让、喂食吸引 |
| 水体光学 | ① #5（“GLSL shaft shaders makes the water really smooth”）、#6 与 #42（着色器驱动的波浪 + 透明剖面水体）；② #44 与 #1 的光束，#45 与 #47 的“从水下仰视水面”，#43 的浅水光斑 | 自写片元着色器，见 §6 与 `docs/technical/aquarium-water-20261019.md` |
| 软糖、毛绒、线稿、体素等材质风格 | ① #2、#18、#19、#35–#39 | 不是这次的需求（用户要的是“更真实”）；仍在形象设计稿的“材质”待办里 |
| **不适用** | #25（Houdini 流体离线模拟）、#12/#14/#20–#24/#45（Blender、C4D 建模与绑定）、#13（机械鲨）、#30（品牌交互） | 不引入三维管线，也不引入任何外部库；没有依赖或权限变化 |

没有借用任何帖子的代码、模型、贴图、着色器或视频画面，也没有打开作品页面看它们的源码。思路层面的借鉴（行波、滞后、逆荫蔽、水面光学）是通用做法，实现全部自写。

## 4. 真实动物的形态与运动依据

下表是做数据时对照的**结构要点**（来自参考照片与插图的目测与比例测量，属于上面的第 ③ 种依据）。**游动频率与摆幅是视觉取值**，没有拿文献里的真实频率去标定。

| 动物 | 视角 | 要画出来的特征 | 游动（数据里的取值） |
|---|---|---|---|
| 小锤头鲨 | 侧视 | 又宽又扁的头鳍（侧视里只能看见近侧一只眼与头鳍的窄缘）、高而后掠的第一背鳍、镰刀形的胸鳍、尾鳍上叶明显长于下叶；背灰褐、腹白，侧线与鳃裂 | 脊柱行波，尾部幅度最大（体长的 7.5%），头鳍几乎刚性（转角 2.5°、压扁 0.12）；胸鳍 8°、腹鳍 5°，小幅滞后 |
| 蝠鲼 | 俯视（从下往上看腹面） | 菱形的翼盘、翼端后掠；口两侧的头鳍（“角”）；腹面浅色、鳃裂、零散的暗斑；细长的鞭状尾 | 翼不转动，靠**压扁（0.12）与沿翼展的相位滞后**表现拍翼；头鳍 6°；尾幅体长的 4.5% |
| 海龟 | 俯视（背面） | 卵圆的龟甲与盾片（中央一列、两侧各四片、边缘小盾片），桨状的前鳍、较小的后鳍，小头与嘴喙；龟甲偏橄榄褐 | 前鳍转角 24°、压扁 0.2，**左右同时拍**；后鳍 14°、相位落后前鳍 1.3 弧度；头 3°；整体慢而稳 |
| 鲸鲨 | 侧视 | 又宽又平的头、端位的宽嘴、身体侧面的纵棱、深蓝灰背上的白斑与条纹、腹面浅色、新月形的尾 | 脊柱尾幅体长的 7%；胸鳍 7°、腹鳍 5°、背鳍 2.2°，只有轻微摆动 |

**视角的取舍**：写实版是小锤头鲨侧视、鲸鲨侧视、蝠鲼俯视（腹面）、海龟俯视（背面）。与桌面卡通版相比，小锤头鲨（卡通版是俯视）和海龟（卡通版是侧视）换了视角，这是本次的**单方面决定**：侧视才看得出高背鳍、镰刀胸鳍与整体体型，背面才同时看得见海龟的盾片与四只鳍。改视角等于重画这只动物的数据，不是改一个参数。

## 5. 参考素材的使用边界

- **X 帖子**：只作为“做法与观感”的参考，没有复制任何内容；视频与抽帧在 `/tmp`，不入库。
- **公开参考照片与插图**（`/tmp/marine-research/ref/`）：**没有记录来源与许可**。只用来量**比例**（体长与体高、头宽、背鳍与胸鳍位置、尾鳍上下叶比例、花纹排布的大致密度）与核对解剖结构；形状数据是用路径一段段写出来的，没有对任何一张图描边（轮廓与花纹的位置都是数据里手写的站位与随机种子）。**这些图片不入库，也不得在产品里使用**；今后若要入库任何图片类素材，必须先记录出处与许可。
- **自写的部分**：骨架求值器、数据、着色器、画笔、测试全部是本仓库自写；没有新增依赖，没有新增权限，也没有联网。

## 6. 海水与海浪：做法对照与取舍

| 做法 | 出现在 | 效果 | 我们的取舍 |
|---|---|---|---|
| **水面起伏的镜面波光**（从水下往上看，水面是一层不停变形的亮网） | #45、#47 的抽帧；#6、#42 的水体 | 画面顶部有一片流动的亮线网，越往下越淡 | **做**：横向拉长的域扭曲 Voronoi 细胞，只在上部，随时间流动 |
| **从水面射下来的体积光束** | #5（shaft shaders）、#1、#44 的抽帧 | 一束束放射的亮条，随深度变淡、缓慢摆动 | **做**：方位角上的值噪声，起点在水面上方的太阳位置 |
| **海底软边焦散网** | #1、#43 的抽帧 | 晃动的亮网，边缘柔和 | **做**：域扭曲的 Voronoi 边缘，全屏淡淡的一层 |
| **悬浮微粒、上升的气泡** | #32、#43 | 增加景深与空间感 | **做**：几层不同大小与速度的微粒，加少量缓缓上升的气泡 |
| **夜里的冷蓝月光** | 项目自己的夜晚荧光曲线 | 与水母夜晚荧光一致 | **做**：夜里光束与水面波光偏冷蓝，需开着“夜晚荧光” |
| **侧面剖开的透明水体，能看到浪尖与水线** | #6（海盗湾）、#42（北极站）的文字 | 画面上方是空气、下方是水，水线上有起伏的波浪 | **没做**：首页是全屏、上面有时钟与卡片，动物游在“海里”；侧面剖开要再划出空气一半，会与首页布局冲突。若要看得见浪尖，需要另立一个“海面”模式，留给用户决定 |
| **三维水体与 Houdini 流体** | #25 | 离线模拟 | 不适用 |

所以用户说的“海浪”，这次落成的是**水下看到的水面波光与光束**（动态的海水光影），**不是侧视的浪尖**；交付报告里要写明这一点。

## 7. 没有验证的部分

- 动物的**美术观感**（形状、斑点、龟甲、鳍摆幅、色调）只由我在截图上目视确认，需要用户亲眼判断；没有拿真实动物的运动视频逐帧对比频率与摆幅。
- 参考照片的出处与许可没有核实（见 §5）。
- 水体效果在**真实 Chromium（Metal GPU，无头）**上做过截图与耗时测量；真实 Chrome 156 的用户配置、真实 GPU 型号与高分屏、长时间占用与笔记本电量**没有验收**。
- X 上的作品只看了视频与文字，没有对它们的性能或观感做对照实验。

## 8. 后续

- 若用户想要“侧面剖开、看得见浪尖”的海水，另立设计（首页分上下两部分的布局如何处理）。
