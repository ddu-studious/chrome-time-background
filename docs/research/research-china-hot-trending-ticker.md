# 中国主流媒体热搜/热榜信息滚动条调研 PRD

> **调研日期**: 2026-02-08  
> **项目**: 中国风景时钟 Chrome 扩展 — 热榜信息栏  
> **调研目标**: 在现有 Tech Ticker（滚动条）基础上，新增中国主流媒体热搜/热榜数据源（微博、B站、知乎、小红书等），复刻现有滚动条样式  
> **结论**: ✅ **可行**，推荐采用聚合 API 方案

---

## 一、需求分析

### 1.1 核心需求

在现有 Tech Ticker 组件（混合双层模式：上层卡片轮播 + 下层 marquee 连续滚动）基础上，扩展支持中国主流媒体热搜/热榜信息：

1. **微博** — 热搜榜（实时热点话题）
2. **B 站** — 热搜榜 / 热门视频
3. **知乎** — 热榜（热门问题）
4. **小红书** — 热搜词条

### 1.2 用户价值

- 每次打开新标签页即可了解国内热点趋势
- 与现有国际技术资讯（GitHub/HN/Reddit/DEV.to）互补
- 一站式信息聚合，无需打开多个 App
- 不干扰主体功能（时钟、天气、任务），作为轻量信息补充

### 1.3 设计原则

- **复用现有 UI**：完全复刻现有 Tech Ticker 的混合双层样式
- **无缝集成**：作为新数据源接入，与 GitHub/HN 等并列
- **性能优先**：合理缓存策略，不影响页面加载
- **优雅降级**：API 不可用时静默降级，不影响其他数据源

## 二、数据源调研

### 2.1 各平台 API 可行性分析

#### 微博热搜 ✅ 可行

| 属性 | 说明 |
|------|------|
| **官方 API** | 微博开放平台提供，需企业认证 + OAuth 2.0，门槛较高 |
| **非官方端点** | `https://weibo.com/ajax/side/hotSearch` — 直接返回 JSON 热搜列表 |
| **第三方聚合** | aa1.cn、ALAPI、apihz.cn 等提供免费封装接口 |
| **DailyHotApi** | `/{baseUrl}/weibo` — 开源聚合 API，推荐 |
| **数据字段** | 排名、标题、热度值、链接、标签（新/沸/热）|
| **更新频率** | 实时（分钟级） |
| **CORS** | Chrome 扩展通过 host_permissions 可绕过 |

**推荐方案**: 通过 DailyHotApi 聚合接口获取，备选微博 AJAX 端点

---

#### B 站热搜/热榜 ✅ 可行

| 属性 | 说明 |
|------|------|
| **官方 API** | B 站有内部 API，部分可公开访问 |
| **热搜端点** | `https://s.search.bilibili.com/main/hotword` — 返回热搜词 |
| **热门视频** | `https://api.bilibili.com/x/web-interface/ranking/v2` — 排行榜 |
| **第三方聚合** | aa1.cn、pddapi 等提供封装 |
| **DailyHotApi** | `/{baseUrl}/bilibili` — 开源聚合 API，推荐 |
| **数据字段** | 标题、热度、播放量、链接、UP 主 |
| **更新频率** | 约 10-30 分钟 |

**推荐方案**: DailyHotApi 聚合接口

---

#### 知乎热榜 ✅ 可行

| **官方 API** | `https://api.zhihu.com/topstory/hot-list?limit=10` — 移动端 API |

| **第三方聚合** | iStero、CU API、tophubdata 等 |

## 三、技术方案

### 3.1 数据获取方案对比

#### 方案 A：自部署 DailyHotApi ⭐ 推荐

| 属性 | 说明 |
|------|------|
| **项目** | [imsyy/DailyHotApi](https://github.com/imsyy/DailyHotApi)（3.5k Stars）|
| **支持平台** | 54 个平台，包含微博/B站/知乎/抖音/百度/豆瓣等全部主流平台 |
| **部署** | Docker / Vercel / Railway / Zeabur 一键部署 |
| **接口格式** | `/{platform}` → 返回标准 JSON |
| **缓存** | 内置 60 分钟缓存 |
| **CORS** | 可配置允许跨域 |
| **成本** | 免费（Vercel/Railway 免费额度足够）|

**优点**：
- ✅ 一个 API 覆盖所有平台，统一接口格式
- ✅ 自部署可控性强，不依赖第三方服务
- ✅ Vercel 免费部署，零成本
- ✅ 项目活跃（3.5k Stars），社区维护

**缺点**：
- ❌ 需要用户自行部署（或使用公共实例）
- ❌ 公共实例稳定性不保证

**API 调用示例**：
```javascript
// 微博热搜
const resp = await fetch('https://your-api.vercel.app/weibo');
const data = await resp.json();
// data.data = [{ title, desc, hot, url, mobileUrl }]

// B站热榜
const resp = await fetch('https://your-api.vercel.app/bilibili');
// 知乎热榜
const resp = await fetch('https://your-api.vercel.app/zhihu');
```

---

#### 方案 B：直接调用各平台端点

| 平台 | 端点 | 风险 |
|------|------|------|
| 微博 | `https://weibo.com/ajax/side/hotSearch` | 可能需要 Cookie，不稳定 |
| B 站 | `https://s.search.bilibili.com/main/hotword` | 接口随时可能变更 |
| 知乎 | `https://api.zhihu.com/topstory/hot-list` | 需要模拟移动端 UA |

**优点**：
- ✅ 无需额外部署
- ✅ 数据最新最准

**缺点**：
- ❌ 各平台接口格式不统一
- ❌ 接口随时可能变更/封禁
- ❌ 部分需要特定 Headers/Cookie
- ❌ 维护成本高

---

#### 方案 C：第三方聚合 API

| 服务 | 费用 | 限制 |
|------|------|------|
| tophubdata.com | 免费额度有限 | 需注册 API Key |
| aa1.cn | 免费 | 稳定性一般 |
| apihz.cn | 免费 | 需注册 |
| itapi.cn | 0.001 元/次 | 有费用 |

**优点**：
- ✅ 即用，无需部署

**缺点**：
- ❌ 第三方服务稳定性不保证
- ❌ 免费额度有限
- ❌ API Key 暴露风险（Chrome 扩展代码可见）

### 3.4 缓存策略

| 数据源 | 缓存时长 | 存储方式 | 理由 |
|--------|---------|----------|------|
| 微博热搜 | 15 分钟 | session storage | 热搜更新频繁 |
| B 站热榜 | 20 分钟 | session storage | 更新频率中等 |
| 知乎热榜 | 20 分钟 | session storage | 更新频率中等 |
| 小红书 | 30 分钟 | session storage | 额度有限，降低调用 |

### 3.5 性能优化

1. **延迟加载**：中国热榜数据在国际数据源之后 500ms 开始获取
2. **并行请求**：`Promise.allSettled()` 并行获取所有数据源
3. **增量更新**：缓存未过期时只更新过期的数据源
4. **静默降级**：单个数据源失败不影响其他源
5. **数据量控制**：每个数据源取 Top 8，合计不超过 40 条

| 增加扩展体积 | 🟢 低 | 仅新增数据获取逻辑，约 2KB JS |

| 指标 | 目标 | 评估 |
|------|------|------|

| API 请求数 | 每 20 分钟 3-5 次 | ✅ 合理 |
| 内存增量 | < 2MB | ✅ 数据量小 |
| 滚动帧率 | ≥ 30fps | ✅ 纯 CSS 动画 |
| 降级体验 | API 失败时无感知 | ✅ Promise.allSettled |
