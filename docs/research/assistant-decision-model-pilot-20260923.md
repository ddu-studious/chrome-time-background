# AI 工作台判断模型实验：工具组预加载

2026-09-23 的第一轮只检查现有规划路径是否存在值得交给判断模型处理的语义判断。实验脚本为 `local-ai/evaluate-assistant-prefetch.mjs`，调用生产 `assistant-service.mjs` 的 `plan()`，用只返回追问的替身截取模型输入中的预加载工具组。不调用模型，不执行音乐、提醒、视频或账号工具。

## 已运行的基线

22 条手工编写、手工标注的中文表达中，16 条进入模型规划路径，6 条由 `AssistantContract.localPlan()` 直接处理。16 条模型路径里，8 条未预加载标注的工具组，1 条额外加载了工具组。其余 7 条与标注一致。原始逐条结果保存在 `local-ai/.local/evaluations/assistant-prefetch-20260923.json`。样本有意包含同义词和边界表达，因此这些比例不是实际用户流量的错误率，也不代表任务失败；缺少预加载时，现有规划器仍可通过 `tools.load` 继续。

有两条更值得单独处理的规则路径：`把开会提醒延后十分钟` 和 `把开会闹钟关掉` 被 `localPlan()` 投影为 `alarm.prepare`，而该工具的实现仅面向新建提醒并提供“确认创建”。本轮未执行模型解析或提醒写入，不能据此声称真的创建了错误提醒；但这条路径不应由预加载判断模型来掩盖。另两条规则路径 `洗牌模式`、`更多音乐搜索结果` 也绕过了工具组规划，是否能被单动作音乐解释器正确处理尚未实测。

原始探针运行后，工作区的其他未提交改动开始增加 `task`、`worklog` 应用，对应技能文件一度尚未就位，导致一次复跑无法导入生产规划器。文件就位后已再次运行本脚本，仍得到上述 22/16/8/1 的结果。实验没有修改这些并行改动；后续扩大样本时须记录 Git 工作树状态和样本版本。

2026-09-24 规则修正后复跑：`延后/推迟/往后/关掉` 已进入已有提醒管理规划，并预加载 `alarm.manage`。同一组 22 条样本现在有 18 条进入模型路径，其中 8 条缺组、1 条多组；另有 2 条音乐请求仍由本地规则承接但需要核对其单动作解释器行为。此复跑仍没有调用模型或执行工具。Laya 的默认关闭接入及故障降级见 `docs/technical/assistant-laya-prefetch-20260924.md`。

## 判断与下一轮设计

首个判断模型实验放在**工具组预加载的只读影子路径**。给模型用户原文、已选应用、生产工具组目录和一个明确的 `none/uncertain` 选项，让它返回建议组；现有规划器照常运行。只比较建议与人工标注、实际后续使用的工具组及耗时，不让建议直接执行工具或改变确认、回执、预算和任务状态。

先以现有 Qwen3.8 27B 的受控入口建立固定候选基线，再考虑 [Snapjudge](https://github.com/Micha0827/snapjudge) 的公开 `POST /v1/systemone` 接口。Snapjudge 0.1.0 的源码声明 MIT、Python >=3.10、`mlx-vlm>=0.7.0` 等依赖；它可以读取 Qwen3.8 27B MLX 4bit 的候选 logits，但当前仓库没有安装该运行时，且不能从 LM Studio 现用 `/api/v1/chat` 推断已支持 logits。若进入实现，先固定上游 commit 和完整锁文件，通过现有 Gateway 的开关、额度、取消、超时与日志边界接入。不得在用户正在使用工作台时并发加载第二份 27B 权重。

下一轮样本至少包含 100 条独立中文需求，覆盖同义词、否定、跨应用、多步任务、无需扩展工具的任务和 `none/uncertain`。预先冻结标注和评分：必需组召回率、额外加载率、需澄清召回率、调用次数、p50/p95 耗时、占用内存；同时报告完整任务的成功回执和额外规划轮数。选项顺序应交换测试，置信度阈值仅可由留出集拟合。结果如果没有减少总轮数和耗时，或者扩大误路由，就不把判断模型加入执行路径。

验证：`node local-ai/evaluate-assistant-prefetch.mjs` 完成 22 条静态路径探针；`node --test test/local-ai-assistant.test.mjs test/local-ai-assistant-context.test.mjs` 为 14/14 通过；脚本语法、尾随空格检查及 `git diff --check` 通过。生产规划器会加载所有已登记应用的技能文件，新增应用时这些文件必须同时就位。本轮本机 AI 服务与 LM Studio 均未运行，没有真实模型、HTTP 预览、Chrome 扩展或账号验证。
