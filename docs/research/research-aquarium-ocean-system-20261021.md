# 水族馆体验与真实海洋体系设计

> 后续约束（2026-10-21）：用户要求继续调研、仅做隔离 demo，保留现有背景，固定造景默认关闭并可配置遮盖范围。后续以[浅礁隔离原型报告](research-aquarium-reef-lab-20261021.md)为准；本文“完整海洋背景”仅保留为早期提案，不作为实施决定。

本轮完成界面预览体验、X / GitHub / Reddit 一手资料核对和一张海洋概念图。本文是设计提案；没有改动水族馆业务代码、安装新依赖、修改扩展权限或发布。工作区已有大量未提交工作，本轮保留原样。

## 1. 体验结果与证据边界

浏览器工具拒绝导航 `chrome-extension://`，因此没有操作用户正在使用的真实扩展。改用项目当前 `index.html`、真实 aquarium 脚本和已有 `chrome-shim.js`，在仅监听回环地址的隔离 HTTP 预览中体验。工具随后将该预览浏览器标示为 in-app browser；不能据此声称品牌 Chrome 中的真实扩展通过验收。

预览 1280×720，注入 7 个演示鱼条目，打开已有水流、光束，声音关闭；不导入用户真实任务、鱼或账号存储。预览额外 CSP 禁止外部连接和图片，所以远程壁纸未显示，热榜会弹联网失败提示。这是隔离方式产生的现象，不列为扩展缺陷。没有演示任务，因而本轮未验水母任务交互。

| 操作 | 可见结果 | 结论 |
| --- | --- | --- |
| 打开水族馆托盘 | 7/12 个条目、大型鱼 0/2，列出各鱼种 | 预览入口与居民列表可用 |
| 放入鲸鲨 | 8/12、大型鱼 1/2、提示“已放入鲸鲨” | 预览中新增可见；不代表真实扩展存储验收 |
| 点击喂食 | 提示“落下了 6 粒饲料”，画面出现饲料 | 只确认投放，不据此宣称所有鱼完成进食 |
| 对照 Aqua Clock Web | 已实际打开画面并点击喂食，观察到鱼群聚集 | 是公开作品体验，没有测帧率或电量 |

证据：[当前预览](../../output/aquarium-review-20261021/current-preview-fed.jpg)、[参考作品截图](../../output/aquarium-review-20261021/reference-aqua-clock.jpg)、[结构化记录](../../output/aquarium-review-20261021/evidence.json)。本轮没有验收拖拽手感、完整捕食周期、环境音、长期 GPU 占用、桌面原生组件。

### 最值得改的三个地方

1. **视角不统一。** 底部海浪是俯视岸线冲刷，鱼是侧视游动，且主要活动区在海浪上方。即使补上壁纸，这两种空间表达仍容易冲突。应把岸边和水下做成独立场景。
2. **环境缺乏落脚点。** 有鱼、有光、有海洋雪，但缺少让鱼绕行、躲藏、停留的礁石、沙地和海葵，容易显得动物悬浮在界面背后。该判断结合预览和源码，黑色背景本身不作为证据。
3. **真实程度不一致。** 大动物已有写实骨架，小鱼仍较符号化；鱼、水母、海浪的大小和运动未形成同一个可感知的世界尺度。应先统一轮廓、明暗、距离感，再继续增加动物。

## 3. 推荐的产品方向：可切换的海洋栖息地

首个重点做 **浅海珊瑚礁**：固定水下视角、中央开阔水域、两侧低矮礁石、下方沙地，动物围绕栖息地生活。上下视角一致，海面只作为高处的水面背面存在。概念图见[reef-concept-v1.png](../../output/imagegen/ocean-habitat-20261021/reef-concept-v1.png)。这是美术目标，不是已实现效果，也不代表生态模拟准确性认证。

| 场景 | 看见什么 | 动物安排 | 与现有页面的关系 |
| --- | --- | --- | --- |
| 浅海珊瑚礁，优先 | 沙地、礁石、海葵、清澈水体与淡焦散 | 礁鱼在近中景，海龟沿礁边，大型访客从远处经过 | 用户主动选用的完整海洋背景，中央留给时钟 |
| 岸边潮汐，保留为独立场景 | 俯视湿沙、进退水线、泡沫残留、浅水石 | 仅在水域安排适合俯视的少量动物 | 承接现有底部岸线，不叠侧视大鱼制造混合透视 |
| 外海蓝水，后续 | 稀疏粒子、远处明暗层次、缓慢长涌 | 鲸鲨 / 蝠鲼为主，少量远鱼群 | 适合安静陪伴，减少前景物体 |

昼夜是各场景的光照状态，不直接等同换成深海生态。若以后做真正深海，需要另选生物和光照，不把有强焦散的浅礁简单染黑。NOAA 对[浅礁光照条件](https://oceanservice.noaa.gov/education/tutorial_corals/coral05_distribution.html)和[礁区分带](https://oceanservice.noaa.gov/education/tutorial_corals/media/supp_coral04b.html)的介绍可作为布局依据；具体画面分区仍是产品取舍。

现有“壁纸 + 装饰小鱼”继续作为轻量模式；新栖息地作为用户明确选择的完整背景。切换视图不删除现有居民。现存淡水鱼条目不自动替换，迁移展示前须给出可理解的说明与选择。

## 4. 让各层遵守同一套空间与因果

### 4.1 一份世界、一套几何

未来沉浸场景使用一致的世界坐标：海面高度 `surface(x,z,t)`、海底 `floor(x,z)`、局部水深、流速 `current(x,y,z,t)`。水深同时驱动浅水颜色、岸线、破浪、动物活动范围；流速同时影响饲料、悬浮物和柔软生物。现有 Canvas 像素坐标不能直接当作真实米制量，须用明确的投影适配。

共享采样接口是设计要求，不等于当前模块已经双向耦合。先复用已有流场和上游公开能力；不为“真实”直接引入完整流体或刚体求解器。

### 4.2 水与光

- 水下模式用同一个海面法线场驱动水面起伏与透光变化，焦散主要落在浅沙和礁石上，避免整屏贴白色网格。
- 远处减对比、减暖色，近处保留鱼本色；海底、鱼和粒子的深度雾使用一致参数。现有吸收与光束模块是起点，先避免画面各层互不关联。
- 只有砂地和近处物体出现可辨识的接触阴影；背景整体不依赖强泛光。白天通透，夜间保留轮廓和界面可读性。
- 岸边模式让破浪泡沫有短时残留、回水和湿沙边界；泡沫随水流移动后逐渐消散，不每帧重新随机闪烁。海面模式才考虑长涌 + 中波 + 微波，不把 FFT 当所有场景的必需品。

### 4.3 动物像各自的物种

| 动物 | 提议的可感知行为 | 首轮验收重点 |
| --- | --- | --- |
| 小丑鱼 | 在海葵附近停留、短距离探出，受惊后回到掩体 | 不穿礁石，转身后确实回到同一个家 |
| 蓝吊 / 拟花鮨类小鱼 | 小群巡游、群体有松紧变化，避开障碍 | 不沿完全相同轨迹机械绕圈 |
| 海龟 | 鳍划水后有滑行，缓慢改变朝向 | 鳍频率、速度和加速度相关，避免所有部件等幅摆动 |
| 鲸鲨 / 蝠鲼 | 在开阔远景缓慢经过，可暂时游出镜头 | 用距离表达体型，不缩成前景小玩具；不把鲸鲨设计成追咬礁鱼的鲨类 |
| 任务水母 | 保持现有任务含义，活动在可读、可抓取区域 | 海洋造景不能遮掉任务文字或改变完成规则 |

鲸鲨是滤食者，可在沿岸和礁缘出现；[Georgia Aquarium](https://www.georgiaaquarium.org/animal/whale-shark/)给出了食性与栖息地说明。把它安排在远景是构图选择。当前只允许小锤头鲨捕猎、水母不进入猎物输入的项目规则继续有效；不要为生态展示改动任务水母边界。

不增加缺粮死亡、离开页面导致惩罚等负担。自然感主要来自合理栖息区、运动、遮挡和相互响应。所有具体参数都先按美术与互动目标校准，不冒称科研级仿真。

### 4.4 交互形成可见因果

喂食 → 饲料从水面进入并随流漂移 / 下沉 → 附近且食性适合的动物靠近 → 短暂进食 → 恢复巡游。继续复用现有投放限额和条目存储，饲料不成为第二份任务事实库。

指针快速经过 → 近处小鱼短暂分散 → 回到原群或掩体；慢速经过不让全屏动物持续惊逃。动物进入礁后应被遮挡，游回前景才重新出现。拖拽仍使用现有明确放入 / 捞出路径，不因碰到珊瑚自动移除。任务交互优先级和确认 / 回执规则不变。

声音依旧显式开启。岸边用冲刷节奏，水下使用低频环境与稀疏事件声；本轮没试听，暂不把现有合成音判为真实海洋录音。

## 5. 技术路线与复用策略

### 推荐分两步

**近期：用现有 Canvas / WebGL 能力完成一致的浅礁构图原型。** 复用 `AquariumCore`、`AquariumPlay`、捕食、`MarineRig`、现有水层和宿主暂停规则；先验证环境遮挡、动物距离和界面留白。不引入新行为引擎，不再以效果数量作验收标准。

**若目标包含自由转向、真实鳍骨骼和立体遮挡：新增可选 Three.js 沉浸渲染器。** 已核对最新 release `r186` 的 package 版本为 **`three@0.186.1`**，MIT；后续实施须固定版本、锁文件并重新验证真实 MV3 环境，不能把本文当依赖集成验收。

| 能力 | 优先复用 | 项目薄适配职责 |
| --- | --- | --- |
| 3D 场景、材质、相机、深度 | Three.js `WebGLRenderer` 等正式导出 | 读取现有世界的只读姿态、绑定宿主画布层和生命周期 |
| 同种大量小鱼 | [`InstancedMesh`](https://threejs.org/docs/pages/InstancedMesh.html) | 有界批次与姿态投影；骨骼动画不会因实例化自动获得，需另验方案 |
| 少量大动物模型与动画 | [`GLTFLoader`](https://threejs.org/docs/pages/GLTFLoader.html)、`AnimationMixer` | 自有、CC0 或明确可分发模型，动画与真实速度对齐 |
| 珊瑚礁、水下光与柔软生物 | 优先探测 Deskworlds 已公开导出的模块与资产 | 上游提交锁定、MIT NOTICE、依赖边界与宿主接线；没有稳定 SDK 的限制需在探针里解决 |
| 群游、喂食、捕食、居民与任务状态 | 本仓库既有模块 | 保持唯一状态所有者，不同时运行 `ReefSimulation` 和 `AquariumCore` 管理同一批居民 |

Deskworlds 的 `main.js` 有自启、自己的帧循环和全局输入监听，不能原样放进首页；其仿真也依赖自己的水和地形。若只为某个视觉模块而需要移入完整应用，不采用这种接法。可复用范围以最小隔离探针证实；可用就用上游能力与薄适配，不复制源码冒充自研，也不只借思路重造完整系统。

本项目是原生 JS，Three.js 无需 React。React Three Fiber 主要解决 React 场景管理，本次没有理由迁入 React；PixiJS 主要解决 2D 批处理，不能单独补齐真实体积与深度；Babylon.js 也是完整引擎，当前没有必须选它的独有需求。WebGPU / FFT 是后续高画质选项，不作为第一版启动条件。3D Gaussian Splatting 更适合静态环境捕获，不替代需要转身、摆鳍、命中的动态动物网格。

### 生命周期与资源边界

宿主保持唯一帧调度。新渲染器由宿主调用 `step / render / resize / dispose`，不同时启动第二个动画循环。遮挡、隐藏、减少动态效果和省流量继续沿用现有规则；切换场景释放纹理、几何体与监听，GPU 丢失时显示明确状态并回到已存在的轻量模式，不把故障隐藏为成功。

第一轮继续沿用现有条目与渲染数量上限，不因换 GPU 渲染就放大数量。建议目标：正常桌面 60 fps、低功耗 30 fps，隐藏时停止绘制；这些只是验收目标，**本轮没有测得任何新性能提升**。下一轮测页面首次可交互时间、帧时间 P95、GPU / 内存、隐藏后活动、连续切换后的资源回收，而不是只看单张截图。

所有运行资源随扩展打包，不运行远程脚本；最初使用无需 Draco / Basis 解码器的模型与常规纹理，避免隐式引入 WASM。Chrome 官方说明[默认 MV3 CSP](https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy)禁止字符串执行和 WASM；本方案不以放宽 CSP 为前提。上游在普通网页能跑，不证明在当前扩展能跑。

## 6. 图像素材如何参与

本轮使用内置 `image_gen` 生成概念图，未使用 API CLI，未读取或请求 API Key。图片已复制到项目：[概念图](../../output/imagegen/ocean-habitat-20261021/reef-concept-v1.png)，[完整提示词](../../output/imagegen/ocean-habitat-20261021/prompt.txt)。未被任何生产页面引用。

这张图用于确定构图、颜色和深度；里面的鱼已经画死，不能直接当成带交互动物的生产背景，否则会出现重复动物。实施时另出不含动物的环境底图，必要时拆分远景 / 礁石层；前景遮挡、命中与游动由真实渲染对象负责。需要真正转向的动物使用可授权的模型与动画，生图不能提供可验证的三维拓扑或天然正确的骨骼。

## 7. 建议的实施顺序与完成定义

1. **构图样板：** 同一鱼数、同一尺寸比较旧画面与浅礁；时钟区域留白，单一水下视角，鱼能从礁后出现。先看画面决定是否继续，不同时加入新物种。
2. **立体探针：** 只放一条小丑鱼、一块礁和一只海葵；验证 Three.js 正式 API、上游可复用范围、当前 CSP、拖拽投影、一次调度与销毁。探针可在隔离页执行，不能悄悄替换生产渲染器。
3. **栖息与联动：** 加入栖息点、避障、流场中的饲料和少量底栖动物；逐条检查“为什么动、动到哪里、何时回归”。
