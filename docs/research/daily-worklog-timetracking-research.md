# 每日工作日志 & 时间追踪功能调研报告

> 创建时间：2026-04-14  
> 目标：调研市面上「每日工作日志 + 时间追踪」产品与开源方案，为中国风景时钟扩展的新功能提供设计参考

---

## 1. 用户原始需求

- **核心诉求**：每天记录"我干了什么"，提升做事效率
- **结构化诉求**：
  1. 每天提醒维护工作日志
  2. 一个主任务，下面可以添加"今天都干了什么"（子活动/工时条目）
  3. 可记录每个任务的花费时间
  4. 方便回顾每天的产出

## 4. 核心功能清单（行业共识）

| 维度 | 功能 |
|------|------|
| **记录** | 手动计时（启停/手动输入）、项目/标签、备注 |
| **日视图** | 当日条目列表、时间轴、「昨天/今天/阻碍」模板 |
| **任务结构** | 主任务 → 子活动/工时条目、折叠展开 |
| **回顾** | 日/周汇总、图表、导出 |
| **专注** | 番茄钟（已有）、站点限额 |
| **提醒** | 每日提醒写日志、未完成 rollover |
| **信任** | 本地优先、隐私透明 |

## 5. 与现有项目的集成分析

### 5.1 现有能力

| 已有 | 状态 |
|------|------|
| 任务管理（memo.js） | ✅ 完整的 CRUD、分类、标签、优先级 |
| 子任务 | ✅ subtasks 字段已存在 |
| 番茄钟 | ✅ 已实现 |
| 日历面板 | ✅ 已规划/调研（v1.7.0） |
| 统计分析面板 | ✅ 已实现 |
| 习惯追踪 | ✅ habit/habitCard 字段已存在 |
| 重复任务 | ✅ recurrence 字段已存在 |

### 5.2 缺失能力（本次需新增）

| 缺失 | 说明 |
|------|------|
| **工时记录** | 任务没有「开始/结束/耗时」字段 |
| **每日工作日志视图** | 没有按日聚合的"今天做了什么"视图 |
| **日志提醒** | 没有每日提醒用户写日志的机制 |
| **主任务→子活动** | subtasks 只有标题和完成状态，缺少时间信息 |

### 5.3 技术集成方式

- **存储**：`chrome.storage.local` 新增 `workLogs` 键（与 `memos` 并列）
- **模块**：独立 `js/worklog.js` + `window.workLogManager`（不膨胀 memo.js）
- **入口**：侧边栏工具栏新按钮 / 独立面板
- **提醒**：扩展 `background.js` 的 alarms/notifications
- **样式**：复用现有 CSS 变量和磨砂玻璃风格

## 6. 竞品差异化定位

### 我们的独特优势

1. **打开浏览器即可见** — 新标签页天然高频入口
2. **与任务系统联动** — 不是独立app，而是与现有任务/番茄钟深度整合
3. **本地优先** — 无需注册、无需同步，数据在本地
4. **视觉体验** — 中国风景 + 磨砂玻璃，不是冰冷的工具

### 推荐产品定位

> **不做重型时间追踪工具（Toggl），做轻量每日工作回顾助手**

核心理念：
- "每天打开浏览器，花 30 秒记录今天做了什么"
- "一周结束，一键看到本周产出"
- "主任务 + 子活动 + 耗时，清晰回顾"

## 7. 建议方案

### MVP（最小可行产品）

1. **每日工作日志面板** — 按日展示今天的工作记录
2. **工时条目** — 主任务下记录"做了什么 + 花了多久"
3. **手动计时** — 启停计时器绑定到工时条目
4. **每日提醒** — 到点提醒用户写日志
5. **日/周回顾** — 按日期聚合查看历史

### 进阶（后续迭代）

- 导出周报（Markdown / 复制到剪贴板）
- 时间热力图
- 效率分析（高峰时段、分类分布）
- 与日历面板联动
