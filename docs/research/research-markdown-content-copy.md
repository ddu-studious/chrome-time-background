# Markdown 内容复制能力调研报告

**日期**: 2026-04-04  
**范围**: 知识墙卡片 Markdown 渲染内容的复制体验优化

---

## 1. 问题定义

### 1.1 现状


| 内容类型                | 能否选中复制    | 一键复制按钮 | 说明                   |
| ------------------- | --------- | ------ | -------------------- |
| 代码类型卡片（`type=code`） | ✅         | ✅（卡片级） | `copyContent` 复制原始文本 |
| Markdown 渲染后的代码块    | ⚠️ 可选中但不便 | ❌      | 需手动框选，容易多选/少选        |
| Markdown 普通文本       | ✅         | ❌      | 需手动选中 + Ctrl+C       |
| 纯文本卡片               | ✅         | ❌      | 只有 code 类型有复制按钮      |
| 链接卡片的 URL           | ✅         | ❌      | 需右键复制链接              |


### 1.2 用户痛点

1. **代码块复制困难** — Markdown 渲染后的 `<pre><code>` 块无法一键复制，手动选中容易选多或选少
2. **复制按钮仅 code 类型** — 笔记、链接、周记等卡片没有快速复制入口
3. **拖拽头部的 grab 光标** — 已修复（仅 header 触发），但内容区仍缺乏主动复制引导

## 2. 竞品调研

### 2.1 GitHub

- **代码块**: 悬浮显示右上角复制图标按钮，点击后图标变为 ✓（1.5s 恢复）
- **非代码内容**: 无块级复制，依赖系统选中
- **交互**: hover-reveal 模式

### 2.2 Notion

- **块操作**: 左侧 ⋮⋮ 手柄 → 菜单中「Copy」复制块内容
- **深链**: 「Copy link to block」复制块的链接
- **代码块**: 右上角常驻复制按钮

### 2.3 Obsidian

- **预览模式**: 依赖社区插件（Code Block Copy）在代码块右上角注入复制按钮
- **行内代码**: Copy Inline Code 插件，点击行内 code 自动复制

### 2.4 文档站（Docusaurus / VitePress / Redocly）

- 代码块自带复制按钮（构建期由 rehype 插件注入）
- 反馈: 图标变化 + tooltip 文案切换

## 3. 行业最佳实践总结

### 3.1 需要复制按钮的内容优先级


| 优先级    | 内容类型        | 理由              |
| ------ | ----------- | --------------- |
| **P0** | 多行代码块 / 命令行 | 误选成本最高，所有主流平台都做 |
| **P1** | 整张卡片内容      | 快速转发/粘贴，提升产品力   |
| **P2** | 单行命令 / 行内代码 | 可选增强，降低精确选中成本   |
| **P3** | 链接 URL      | 已有右键菜单，优先级低     |


### 3.2 推荐交互模式


| 模式                    | 适用场景   | 本项目适用             |
| --------------------- | ------ | ----------------- |
| **Hover-reveal 角标按钮** | 代码块    | ✅ 首选              |
| **卡片操作栏常驻按钮**         | 整卡复制   | ✅ 扩展现有 action bar |
| **块工具条**              | 编辑器场景  | ❌ 过重              |
| **右键菜单**              | 链接/富文本 | ❌ 依赖系统            |


### 3.3 推荐复制反馈

- **图标态切换**: 复制图标 → ✓ 对勾（1.5-2s 恢复）
- **轻量 Toast**: 项目已有 `_showToast()` 可复用
- **无障碍**: 按钮 `aria-label="复制代码"` + `aria-live` 状态通知

## 4. 技术方案概述

### 4.1 Markdown 渲染器层（`markdown-renderer.js`）

在 `renderer.code` 中注入复制按钮到 `<pre>` 容器：

```
<div class="kw-code-wrapper">
    <button class="kw-code-copy-btn" aria-label="复制代码">
        <i class="fas fa-copy"></i>
    </button>
    <pre><code class="hljs">...</code></pre>
</div>
```

事件委托绑定在卡片容器上，点击时读取 `<code>` 的 `textContent`。

### 4.2 卡片级复制（`knowledge-wall.js`）

将现有仅 `type=code` 的复制按钮扩展到所有卡片类型。

### 4.3 行内代码点击复制（可选增强）

对 Markdown 渲染出的 `<code>` 元素（非 `<pre>` 内的），添加 click 事件自动复制。

## 5. 风险评估


| 风险                         | 影响           | 缓解                   |
| -------------------------- | ------------ | -------------------- |
| `navigator.clipboard` 权限受限 | 非 HTTPS 环境失败 | Chrome 扩展环境天然安全上下文   |
| 复制按钮遮挡代码内容                 | 阅读体验         | hover-reveal + 半透明背景 |
| 过多按钮视觉噪音                   | 界面臃肿         | hover 才显示，保持干净       |


---

**结论**: 推荐分三层实现——(1) 代码块 hover 复制按钮 (2) 全类型卡片复制按钮 (3) 行内代码点击复制。优先级从高到低，核心投入在代码块。
