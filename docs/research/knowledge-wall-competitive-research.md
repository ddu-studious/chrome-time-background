## 三、关键发现

### 3.1 标签/归类方案对比

| 方案 | 代表产品 | 优点 | 缺点 |
|------|---------|------|------|
| **分类 + 标签双维度** | Simply Notes, TextSnip | 结构清晰，一对多归类 | 需额外管理分类 |
| **纯标签组织** | Tag Bookmarks | 灵活，无层级约束 | 无结构化归类 |
| **文件夹 + 标签** | BookmarkCat | 层级结构清晰 | 复杂度较高 |
| **智能分组（按标签自动）** | Bookmarkme | 零手动归类 | 不够精准 |

**推荐方案**：在现有「类型筛选」的基础上，增加「标签筛选」维度（参考 Simply Notes 的下拉/标签云方式），实现 **类型 × 标签** 的交叉筛选。

### 3.2 Markdown 编辑器 Tab 键方案对比

| 方案 | 来源 | 优点 | 缺点 |
|------|------|------|------|
| **indent-textarea 库** | npm 开源库 | 支持 Tab/Shift+Tab/多行缩进，原生 undo | 外部依赖 |
| **setRangeText API** | 原生 Web API | 零依赖，简洁 | 需手动处理多行 |
| **Tiptap CodeBlock** | Tiptap 编辑器框架 | 功能全面 | 重量级框架 |
| **自定义 keydown 拦截** | 通用方案 | 完全可控 | 需注意无障碍 |

**推荐方案**：采用自定义 keydown 拦截 + setRangeText API，在 textarea 内拦截 Tab 键，支持：
- Tab → 插入 2 或 4 空格缩进
- Shift+Tab → 删除行首缩进
- 多行选择时批量缩进/取消缩进
- 代码块内自动检测上下文

### 3.3 好用简单的 Markdown 能力

从竞品中提炼的实用 Markdown 增强：

| 能力 | 描述 | 优先级 |
|------|------|--------|
| **Tab 缩进** | 列表/代码块内缩进 | P0 |
| **快捷键增强** | Ctrl+B/I/K 等标准快捷键 | P0 |
| **自动补全配对** | `**|**`、`[|](url)`、`` `|` `` | P1 |
| **列表连续输入** | Enter 后自动续行 `- ` 或 `1. ` | P1 |
| **拖拽图片** | 拖入图片自动转 base64 | P2 |
| **表格快捷插入** | 工具栏一键插入表格模板 | P1 |
| **全屏编辑** | 编辑器全屏模式 | P2 |

## 四、用户场景分析

### 场景 1：「我想找某个标签下的所有笔记」（本次核心需求）

**现状痛点**：只能通过搜索框输入标签名来找，不直观、效率低。  
**期望体验**：点击卡片上的标签 → 立即筛选出同标签卡片；或通过标签云/下拉选择器快速选择。

### 场景 2：「Markdown 编辑时 Tab 键跳走了」

**现状痛点**：在编辑器 textarea 中按 Tab 键，焦点跳到下一个表单元素（标准浏览器行为）。  
**期望体验**：Tab 键在 textarea 内插入缩进（空格/制表符），尤其在编写代码块和列表时。

### 场景 3：「写 Markdown 列表时需要更好的体验」

**现状痛点**：手动输入 `- ` 前缀，缩进需要手打空格。  
**期望体验**：Enter 自动续行 `- `，Tab 缩进子列表，Shift+Tab 取消缩进。
