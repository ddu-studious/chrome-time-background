# 每日时间计划表调研报告

> 创建时间：2026-04-15  
> 目标：为中国风景时钟扩展新增"每日时间计划表"功能，调研市面产品形态、开源方案、UX 最佳实践  
> 关联需求：辅助用户更好地规划工作、学习、生活

---

## 1. 用户需求分析

### 1.1 原始需求

- **核心诉求**：展示一个时间计划表，帮助规划每天能做什么
- **场景覆盖**：工作、学习、生活三位一体
- **产品目标**：更好地辅助用户的日常生活，与现有时钟/任务/工作日志功能形成闭环

### 1.2 需求拆解

| 维度 | 用户痛点 | 期望体验 |
|------|---------|---------|
| **规划** | 每天不知道该做什么，时间浪费在犹豫中 | 一目了然看到今天的安排 |
| **执行** | 计划了但容易忘、容易分心 | 随时可见当前该做什么 |
| **回顾** | 一天结束不知道时间去了哪里 | 清晰看到时间分配和完成情况 |
| **习惯** | 好习惯难以坚持 | 固定时段提醒 + 打卡追踪 |
| **平衡** | 工作学习生活难以平衡 | 可视化分类，确保各领域都有投入 |

### 1.3 与现有功能的关系

```
现有功能矩阵：
┌─────────────┬──────────────┬──────────────┐
│   任务系统    │   工作日志    │  时间计划表   │
│  (已完成)    │  (已完成)     │  (本次新增)   │
├─────────────┼──────────────┼──────────────┤
│ "我要做什么"  │ "我做了什么"   │ "我何时做什么" │
│  待办导向     │  记录导向      │  规划导向     │
│  任务粒度     │  工时粒度      │  时间段粒度   │
└─────────────┴──────────────┴──────────────┘
                    ↓ 形成闭环
        计划(Plan) → 执行(Do) → 记录(Check)
```

## 2. 市面产品分析

### 2.1 专业时间块规划工具

| 产品 | 核心特征 | 亮点功能 | 适用场景 | 参考价值 |
|------|---------|---------|---------|---------|
| **Sunsama** | 引导式每日仪式 + 时间块 | 晨间规划→执行→关机仪式，工具整合 | 专业人士工作规划 | ★★★★★ 仪式感、每日聚焦理念 |
| **Morgen** | AI 辅助 + 多日历整合 | 自动排程、冲突检测、拖拽安排 | 多工具用户 | ★★★★ 智能排程概念 |

| 产品 | 核心特征 | 亮点功能 | 参考价值 |
|------|---------|---------|---------|
| **Momentum** | 风景+每日焦点+待办 | Daily Focus、极简美学、番茄钟 | ★★★★★ 最贴近场景 |

### 2.3 时间块设计最佳实践（综合 Sunsama/Morgen/Google Calendar）

| 设计原则 | 说明 | 示例 |
|---------|------|------|
| **颜色编码** | 不同类别用不同颜色 | 工作=蓝、学习=绿、生活=橙 |
| **拖拽调整** | 拖拽时间块改变位置和时长 | 长按拖拽到新时段 |
| **当前时刻线** | 红色横线标注当前时间 | 自动滚动到当前位置 |
| **弹性标记** | 区分固定和灵活的安排 | 实线=固定、虚线=灵活 |
| **快速录入** | 点击时间段即可创建 | 单击空白处弹出创建框 |
| **完成状态** | 视觉区分已完成/进行中/未开始 | 半透明=完成、高亮=进行中 |

## 3. 开源技术方案

### 3.1 可集成的日历/时间表库

| 库名 | Stars | 大小 | 框架依赖 | 适用度 | 备注 |
|------|-------|------|---------|-------|------|
| **FullCalendar** | 18k+ | ~200KB | 无(原生JS) | ★★ | 功能最全，但体积偏大 |
| **TOAST UI Calendar** | 12k+ | ~150KB | 无(TS) | ★★ | UI 美观，但同样偏重 |
| **timesheet.js** | 2k+ | ~5KB | 无 | ★★★ | 极轻量，但功能简单 |
| **自研方案** | - | ~15KB | 无 | ★★★★★ | 完全契合需求，无冗余 |

### 3.2 技术选型建议

**推荐方案：自研轻量组件**

理由：
1. 项目采用原生 JS，不引入框架，避免 FullCalendar/TOAST UI 的体积负担
2. 需求聚焦在"每日时间计划"，不需要月/年/多日历等复杂功能
3. 可复用现有的设计语言（磨砂玻璃、Font Awesome 图标）
4. 数据存储复用 `chrome.storage.local`，与任务/工作日志统一
5. 总代码量预估 800~1500 行 JS + 300~500 行 CSS

## 4. 五种产品形态对比

### 形态 A：时间块日程表（Time Block Schedule）

```
┌─────────────────────────────────────────┐
│  📅 今日计划 2026-04-15 周二     [+ 添加] │
├────────┬────────────────────────────────┤
│ 06:00  │                                │
│ 07:00  │ 🏃 晨跑 30min              [生活]│
│ 08:00  │ ─────────── 现在 ──────────── │
│ 08:30  │ 📖 英语阅读 1h            [学习]│
│ 09:30  │ 💻 Chrome扩展开发 2h      [工作]│
│ 11:30  │ 🍎 午餐+休息 1h           [生活]│
│ 12:30  │ 💻 代码Review 1.5h        [工作]│
│ 14:00  │ 📚 算法学习 1h            [学习]│
│ ...    │                                │
└────────┴────────────────────────────────┘
```

**特征**：垂直时间轴 + 可视化时间块  
**参考**：Sunsama / Google Calendar 日视图  
**优势**：最直观看到每天的时间分配  
**劣势**：占用空间较大，需要面板承载

### 形态 B：每日计划仪表盘（Daily Planner Dashboard）

```
┌─────────────────────────────────────────┐
│  🎯 今日焦点：完成扩展 v3.18 开发         │
├──────────────┬──────────────────────────┤
│  上午 AM      │  ☀️ 晨间例程              │
│  ☑ 晨跑 30min │  ☐ 英语阅读 45min        │
│  ☐ 扩展开发   │  ☐ 代码Review            │
├──────────────┼──────────────────────────┤
│  下午 PM      │  🌙 晚间例程              │
│  ☐ 算法学习   │  ☐ 读书 30min            │
│  ☐ 文档编写   │  ☐ 总结复盘              │
├──────────────┴──────────────────────────┤
│  📊 今日进度: ████░░░░░░ 40% (4/10)      │
└─────────────────────────────────────────┘
```

**特征**：上午/下午分区 + 每日焦点 + 进度条  
**参考**：Momentum / Bullet Journal  
**优势**：简洁直观，不需要精确到分钟  
**劣势**：缺乏时间维度的精确感

### 形态 C：周计划看板（Weekly Kanban）

```
┌────┬────┬────┬────┬────┬────┬────┐
│ 周一│ 周二│ 周三│ 周四│ 周五│ 周六│ 周日│
├────┼────┼────┼────┼────┼────┼────┤
│ 扩展│★今天│ 会议│ 测试│ 发布│ 休息│ 阅读│
│ 开发│ 英语│ 复习│ 修bug│ 上线│ 运动│ 总结│
│ 阅读│ 算法│ 运动│ 运动│ 运动│ 学习│     │
│    │ 运动│     │     │     │     │     │
└────┴────┴────┴────┴────┴────┴────┘
```

**特征**：七天看板视图，纵向是任务列表  
**参考**：Notion 周视图 / Thisweek 扩展  
**优势**：全周一览，适合提前规划  
**劣势**：单日细节不够，手机端适配差

### 形态 D：时间轮盘（Time Wheel / Pie Chart）

```
        🕐 今日时间分配
           12:00
      11 ╱───────╲ 1
     10│  学习 2h  │2
      9│ 工作 4h   │3
      8│  生活 3h  │4
      7 ╲───────╱ 5

**参考**：RescueTime 时间报告  
**优势**：一眼看到时间分配比例  
**劣势**：规划功能弱，偏展示分析

### 形态 E：时间线 + 习惯追踪（Timeline + Habit Tracker）

```
┌─────────────────────────────────────────┐
│  📋 每日例程 & 计划                      │
├─────────────────────────────────────────┤
│  🌅 固定例程（习惯打卡）                  │

│  ├ ☐ 07:30 英语阅读    [连续3天]          │
│  └ ☑ 22:00 睡前总结    [连续12天 🔥]      │
│                                          │
│  ⏰ 灵活计划（今日安排）                   │
│  ├ 09:00-11:00 💻 Chrome扩展开发  [工作]  │
│  ├ 14:00-15:30 📚 算法练习        [学习]  │

**特征**：分为"固定例程"和"灵活计划"两层  
**参考**：TickTick 习惯 + Google Calendar 混合  
**优势**：兼顾习惯养成和灵活规划，贴近真实生活  
**劣势**：信息量偏多，需要合理折叠

## 5. 综合评估与推荐

### 5.1 评分矩阵

| 评估维度 | 形态A 时间块 | 形态B 仪表盘 | 形态C 周看板 | 形态D 轮盘 | 形态E 时间线+习惯 |
|---------|:-----------:|:----------:|:----------:|:---------:|:---------------:|
| 与项目契合度 | ★★★★ | ★★★★★ | ★★★ | ★★ | ★★★★★ |
| 用户上手成本 | ★★★ | ★★★★★ | ★★★★ | ★★★★ | ★★★★ |
| 功能完整度 | ★★★★★ | ★★★ | ★★★ | ★★ | ★★★★★ |
| 视觉美观度 | ★★★★ | ★★★★ | ★★★ | ★★★★★ | ★★★★ |
| 开发复杂度 | ★★ | ★★★★ | ★★★ | ★★★ | ★★★ |
| 移动端适配 | ★★ | ★★★★★ | ★★ | ★★★★ | ★★★★ |
| **总分** | **20** | **25** | **18** | **19** | **25** |

### 5.2 推荐方案

**首选：形态 E（时间线 + 习惯追踪）** — 最贴合"辅助工作/学习/生活"的完整需求

理由：
1. **双层结构**完美匹配用户场景：固定例程（习惯）+ 灵活计划（时间块）
2. 习惯追踪的**连续天数和打卡机制**极大提升用户粘性
3. 分类标签（工作/学习/生活）直观展示**时间平衡**
4. 可嵌入现有侧边栏或独立面板，**UI 集成灵活**
5. 开发难度适中，核心 1000 行左右可完成

**备选：形态 A（时间块日程表）** — 可作为 v2 迭代的进阶视图

## 6. 技术实现要点

### 6.1 数据存储

```javascript
// 存储 key
chrome.storage.local: {
    schedulePlans: [...],      // 灵活计划
    scheduleRoutines: [...],   // 固定例程/习惯
    scheduleHabitLog: {...},   // 习惯打卡记录
    scheduleSettings: {...}    // 计划表设置
}
```

### 6.2 模块架构

```
js/schedule.js          — 核心管理器（ScheduleManager）
css/schedule.css        — 样式
index.html              — dock-bar 入口按钮
```

### 6.3 性能考虑

- 延迟初始化：与工作日志同级，可在设置中开关
- DOM 按需渲染：仅渲染当天的计划项
- 存储清理：自动归档 30 天前的数据
