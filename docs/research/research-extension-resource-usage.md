# Chrome 扩展资源占用评估报告

**扩展名称**: 中国风景时钟  
**版本**: v3.4.0  
**评估日期**: 2026-03-20  
**评估人**: AI Agent  

---

## 一、评估背景

随着功能不断丰富（音乐播放器、任务管理、热搜资讯、知识墙、扩展监控等），需要系统评估扩展对用户系统资源的影响，尤其是：

1. 对低配置电脑（4GB RAM / 双核 CPU）的可用性
2. 对高配置电脑是否存在不必要的资源浪费
3. 与同类扩展的资源占用对比

## 三、关键限制：Chrome API 无法精确测量扩展自身资源

### 3.1 当前技术限制

| API | 可用性 | 测量范围 |
|-----|--------|----------|
| `chrome.system.cpu` | ✅ 可用 | 系统整体 CPU |
| `chrome.system.memory` | ✅ 可用 | 系统整体内存 |
| `chrome.processes` | ❌ 仅 Dev Channel | 扩展进程级 |
| `performance.memory` | ❌ Service Worker 不可用 | 页面 JS 堆 |
| `performance.memory` | ✅ 新标签页可用 | 页面 JS 堆 |
| `measureUserAgentSpecificMemory()` | ⚠️ 需跨域隔离 | 页面内存 |

### 3.2 v3.3.1 改进

已实现在新标签页上下文中获取 `performance.memory`，补充 Service Worker 不可用时的扩展内存数据。这样用户在扩展监控面板中可以看到新标签页的 JS 堆内存使用情况。

## 四、对不同配置电脑的影响评估

### 4.1 低配电脑（4GB RAM / 双核 CPU / HDD）

| 场景 | 影响程度 | 说明 |
|------|----------|------|
| 仅打开新标签页 | 🟢 低 | 初始加载 ~15MB，空闲后稳定 |
| 任务管理（<50 条） | 🟢 低 | DOM 操作量小 |
| 任务管理（>200 条） | 🟡 中 | 大量 DOM 渲染可能卡顿 |
| 热搜资讯开启 | 🟡 中 | 定期网络请求 + DOM 更新 |
| 音乐播放中 | 🟡 中 | 1s 状态广播 + 2s 轮询 |
| 关键字扫描（高频） | 🟡 中 | 1min 网络请求 |
| 系统监控面板开启 | 🟡 中 | 3s 刷新 + Canvas 绘制 |
| 所有功能全开 | 🔴 高 | 多个定时器并行，可能影响流畅度 |

**关键建议**：低配用户应关闭关键字扫描高频模式和系统监控面板。

### 4.2 高配电脑（16GB+ RAM / 8 核+ CPU / SSD）

| 场景 | 影响程度 | 说明 |
|------|----------|------|
| 所有功能全开 | 🟢 低 | 对高配几乎无感 |
| 长时间运行（8h+） | 🟢 低 | 内存增长可控 |

**注意**：`extEventLog` 可能随时间积累数据量，已有 200 条上限。

### 4.3 与同类扩展对比

| 扩展 | 类型 | 典型内存占用 |
|------|------|-------------|
| Momentum（新标签页） | 新标签页 | 30-50MB |
| Infinity New Tab | 新标签页 | 40-80MB |
| Todoist Web | 任务管理 | 20-40MB |
| **中国风景时钟** | 新标签页+任务+音乐 | **预估 20-60MB** |

结论：功能更丰富但资源占用在可接受范围内。

## 五、已实施的优化措施

1. **条件运行**：系统监控仅在面板打开时刷新（3s），关闭后停止
2. **条件运行**：音乐轮询仅在音乐 UI 活跃时运行
3. **分页渲染**：任务列表使用分页（20/50/100 条每页）
4. **分块渲染**：大任务列表使用 `requestAnimationFrame` 分块
5. **事件日志上限**：`extEventLog` 最多 200 条
6. **可配置频率**：热搜刷新间隔 5-120 分钟可配置
7. **惰性加载**：Mermaid 仅在检测到图表语法时加载渲染
8. **本地缓存**：天气、热搜数据本地缓存减少重复请求
9. **🆕 v3.4.0 功能开关**：设置面板新增"性能与省电"分组，支持逐项开关：
   - 热搜资讯（enableTicker）— 关闭后停止 6s 轮播 + 网络请求
   - 音乐播放器（enableMusic）— 关闭后停止 2s 轮询 + Offscreen 播放
   - 系统资源监控（enableSystemMonitor，默认关闭）— 关闭后取消 alarm + 面板刷新
   - 系统监控采集间隔（systemMonitorInterval）— 从 1min 放宽到 5min（默认），减少 80% 后台采样
   - 关键字扫描（enableKeywordScan，默认关闭）— 关闭后停止高频网络请求
   - 温情提示（enableWarmTip）— 关闭后停止 2h 定时推送
   - 知识墙（enableKnowledgeWall）— 关闭后不初始化面板
   - 任务提醒滚动条（enableTaskTicker）— 关闭后隐藏滚动栏

## 七、结论

**总体评估：扩展资源占用在合理范围内，v3.4.0 已实现用户可控的省电模式。**

1. 扩展采用了大量条件运行策略，空闲时资源占用很低
2. 主要资源消耗来自：时钟更新（1s）、热搜轮播（6s）、音乐状态（2s）
3. 后台 Service Worker 的 alarm 已合理设计，不会持续占用 CPU
4. **v3.4.0 新增**：设置面板提供 8 项功能开关，低配用户可关闭非核心功能
5. **v3.4.0 新增**：系统监控默认关闭 + 采集间隔从 1min 改为 5min（减少 80%）
6. **v3.4.0 新增**：关键字扫描默认关闭，避免不必要的高频网络请求
7. 当前无法精确测量扩展进程级内存，已通过页面端 `performance.memory` 补充

### 低配电脑推荐配置

| 开关 | 推荐状态 | 原因 |
|------|----------|------|
| 热搜资讯 | ✅ 开启 | 低频请求，影响小 |
| 音乐播放器 | ✅ 开启（按需） | 仅在使用时才有轮询 |
| 系统资源监控 | ❌ 关闭 | 每分钟 alarm + Canvas 绘制 |
| 关键字扫描 | ❌ 关闭 | 高频网络请求 |
| 温情提示 | ✅ 开启 | 2小时一次，影响极小 |
| 知识墙 | ✅ 开启 | 按需加载，影响小 |
| 任务提醒条 | ✅ 开启 | 仅多任务时运行 |
