> 设计基线：18 个业务、112 个页面。本文只记录代码与运行态证据；生成图不等于已实现，代表页不等于页面组完成。

逐页真实扩展证据见 [`product-ui-v5-r4-checklist.md`](./product-ui-v5-r4-checklist.md)。当前有明确页面键级真实 Chrome 证据的页面为 50/112，另有 1 页为 `R4-partial`；未在逐页表中达到 `R4` 的页面不得由业务组代表页推定为完成。

## 证据等级

- `R0`：只有设计图或页面名称。
- `R1`：现有业务控制器中有对应功能，但尚未形成 v5 页面状态。
- `R2`：已形成可访问的 v5 页面/状态，并有契约测试。
- `R3`：已在内置浏览器完成视觉与交互验收。
- `R4`：已在真实 Chrome 新标签页扩展环境完成视觉与交互验收。

只有达到 `R4` 才算该页面完成。业务完成还要求该组全部页面达到 `R4`。

## 当前自动化门槛

- `ProductPagesV5` 必须保持 18 个业务、112 个唯一页面键。
- `ProductUIV5` 当前严格限制 5 个外壳页面和 10 个音乐页面。
- 全量 Node 契约测试必须保持通过；本轮基线为 375/375。
- 内置浏览器关闭全部浮层后，全 DOM 扫描不得存在“`visibility: visible`、`opacity: 0`、包含可交互后代且大于 180×80”的顶层隐藏容器；本轮扫描为 0 个。
- 每新增业务页面组，应同时补充页面键、DOM 契约、状态切换测试、内置浏览器截图和真实 Chrome 交互记录。
