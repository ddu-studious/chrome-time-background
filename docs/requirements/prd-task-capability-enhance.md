## 一、产品概述

### 1.1 背景

当前版本（v2.3.1）已具备时钟、天气、任务管理、热榜资讯、常用信息（知识墙）等功能。为进一步提升用户体验和信息管理能力，本次迭代聚焦三个方向：

1. **音乐控制器**：在新标签页集成迷你播放器，支持控制酷狗/网易云网页版
2. **密码保护**：常用信息卡片支持加密，保护敏感内容
3. **Markdown 渲染**：常用信息支持 Markdown 语法，提升内容表达力

### 1.2 目标用户

- 日常使用 Chrome 浏览器的知识工作者
- 习惯在浏览器中听音乐的用户
- 需要管理敏感信息（账号密码、密钥等）的用户
- 偏好结构化笔记的用户

### 1.3 成功指标

| 指标 | 目标 |
|------|------|
| 音乐控制器日活使用率 | > 30% 新标签页打开时检测到音乐标签 |
| 密码保护卡片创建数 | 每用户 ≥ 2 张加密卡片 |
| Markdown 卡片使用率 | > 40% 笔记/周记卡片启用 Markdown |

## 二、功能需求

### 2.1 音乐控制器

#### 2.1.1 需求描述

在新标签页时间日历下方的空白区域（时间与天气之间），显示一个精致的迷你音乐控制条，用于控制用户已在浏览器中打开的酷狗音乐或网易云音乐网页版。

**UI 位置**：
```
┌──────────────────────────────┐
│          10:58:54            │  ← 时间
│    2026年3月17日星期二         │  ← 日期
│    农历丙午年正月廿九          │  ← 农历
│                              │
│  🎵 [封面] 歌名-歌手 ⏮ ⏯ ⏭  │  ← 音乐控制器（新增）
│                              │
│    🌤 23°C 晴朗 北京市         │  ← 天气
└──────────────────────────────┘
```

#### 2.1.2 技术方案（基于调研结论）

**推荐方案：Content Script 控制网页版**

| 项目 | 说明 |
|------|------|
| 方案 | Content Script 注入到音乐网页，DOM 操作控制播放 |
| 法律风险 | 低（仅控制用户已打开的官方网页） |
| 技术可行性 | 高（Streamkeys 等项目已验证） |
| 维护成本 | 中（需跟踪网页 DOM 变化） |

**架构设计**：

```
新标签页 (index.html)
  └── music-controller.js (UI 模块)
        ↕ chrome.runtime.sendMessage
Background (background.js)
        ↕ chrome.tabs.sendMessage
Content Scripts
  ├── netease-controller.js (music.163.com)
  └── kugou-controller.js (www.kugou.com)
```

**通信协议**：

```javascript
// 新标签页 → Background → Content Script
{ action: 'music_command', command: 'play|pause|next|prev|getStatus' }

// Content Script → Background → 新标签页
{ action: 'music_status', data: { 
    platform: 'netease|kugou',
    isPlaying: boolean,
    title: string,
    artist: string,
    cover: string,     // 封面URL
    duration: number,
    currentTime: number,
    volume: number
}}
```

### 2.2 密码保护（常用信息）

#### 2.2.1 需求描述

在常用信息（知识墙）中，允许用户对卡片设置密码保护。受保护的卡片内容在默认状态下被遮罩，需输入正确密码后才能查看。

#### 2.2.2 用户故事

- 作为用户，我希望对包含敏感信息（如账号密码、密钥、个人信息）的卡片加锁
- 作为用户，我希望输入密码后能在当前会话内持续查看，不需要反复输入
- 作为用户，我希望密码以安全方式存储，不可被简单查看

#### 2.2.3 功能详情

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 设置密码 | ✅ 编辑器中添加"密码保护"开关 + 密码输入 | P0 |
| 查看验证 | ✅ 点击受保护卡片弹出密码框 | P0 |
| 内容遮罩 | ✅ 受保护卡片内容显示为模糊/遮罩状态 | P0 |
| 修改密码 | ✅ 编辑时可修改或移除密码 | P0 |
| 会话缓存 | ✅ 验证通过后本次会话内无需重复输入 | P1 |
| 标签标识 | ✅ 卡片显示锁图标（可点击重新锁定） | P0 |
| 安全存储 | ✅ 密码经 SHA-256 + salt 哈希后存储 | P0 |
| 错误限制 | ✅ 连续错误 5 次后锁定 30 秒 | P1 |

#### 2.2.4 数据结构变更

```javascript
// 卡片新增字段
{
    ...existingFields,
    isProtected: false,     // 是否密码保护
    passwordHash: null,     // SHA-256 哈希值
    passwordSalt: null,     // 加密盐值
}
```

#### 2.2.5 安全方案

1. **密码哈希**：使用 Web Crypto API（`SubtleCrypto.digest('SHA-256')`）
2. **加盐**：每张卡片独立随机盐值
3. **不存明文**：任何位置不保存原始密码
4. **会话缓存**：使用 `sessionStorage` 缓存已验证的卡片 ID（页面关闭自动清除）
5. **导出安全**：导出 JSON 时保留 hash 和 salt，不含明文

#### 2.2.6 UI 交互流程

```
编辑卡片 → 开启"密码保护" → 输入密码 → 保存
                                          ↓
查看卡片 → 内容模糊 + 锁图标 → 点击 → 弹出密码框
                                          ↓
        输入正确 → 内容展开 → 会话内缓存
        输入错误 → 提示错误 → 5次后锁定
```

### 2.3 Markdown 渲染（常用信息）

#### 2.3.1 需求描述

常用信息卡片的"内容"字段支持 Markdown 语法，渲染后以富文本形式展示，提升笔记和周记的表达力。

#### 2.3.2 支持的 Markdown 语法

| 语法 | 示例 | 优先级 |
|------|------|--------|
| 标题 | `# H1` `## H2` `### H3` | P0 ✅ |
| 粗体/斜体 | `**bold**` `*italic*` | P0 ✅ |
| 列表 | `- item` `1. item` | P0 ✅ |
| 代码块 | `` `code` `` ``` ```code``` ``` | P0 ✅ |
| 链接 | `[text](url)` | P0 ✅ |
| 引用 | `> quote` | P0 ✅ |
| 分隔线 | `---` | P0 ✅ |
| 表格 | `| a | b |` | P1 ✅ |
| 任务列表 | `- [x] done` `- [ ] todo` | P1 ✅ |
| 图片 | `![alt](url)` | P1 ✅ |
| 删除线 | `~~text~~` | P1 ✅ |
| 语法高亮 | ``` ```js ``` | P2 ✅ |

#### 2.3.3 技术方案

| 组件 | 方案 | 大小 |
|------|------|------|
| Markdown 解析器 | ✅ marked.js（本地 vendor/marked.min.js） | ~46KB |
| XSS 防护 | ✅ DOMPurify（本地 vendor/purify.min.js） | ~15KB |
| 代码高亮 | ✅ highlight.js（本地 vendor/highlight.min.js）| ~120KB |
| Mermaid 图表 | ✅ @mermaid-js/tiny（本地 vendor/mermaid.tiny.min.js）| ~1.9MB |

**备选方案**：自研轻量解析器（仅支持基础语法，约 5KB），避免外部依赖。

#### 2.3.4 编辑器增强

1. **Markdown 开关**：编辑器增加"Markdown 模式"切换
2. **工具栏**：常用语法快捷按钮（加粗、列表、代码等）
3. **实时预览**：编辑区右侧实时渲染预览（可选）
4. **语法提示**：编辑区底部显示常用语法提示

#### 2.3.5 渲染规则

- 卡片类型为 `note` 或 `weekly` 时，检查内容是否包含 Markdown 语法
- 如果启用 Markdown，渲染为 HTML；否则保持纯文本显示
- 代码类型（`code`）不使用 Markdown 渲染，保持代码块原样

## 五、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 音乐网页 DOM 结构变化 | 控制失效 | 模块化设计，每平台独立 controller，易于更新 |
| 密码遗忘 | 用户无法查看卡片 | 提供"重置密码（清除内容）"选项 |
| Markdown XSS 攻击 | 安全风险 | DOMPurify 消毒 + CSP 策略 |
| 第三方 CDN 不可用 | 功能降级 | 本地打包备份 |
| 法律风险（音乐API） | 被迫下架 | 仅 Content Script 控制，不获取版权内容 |
