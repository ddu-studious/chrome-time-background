# PRD：音乐播放器 — 网易云增强功能集 v3.19.0

**产品名称**: 中国风景时钟

**状态**: active
**依赖**: v3.18.0（歌手/专辑交互导航增强）

---

## 一、产品概述

### 1.1 背景

v3.18.0 的音乐播放器已具备完整的播放、搜索、发现、私人FM、歌词、歌手操作台能力。但与网易云客户端相比，仍缺少以下日常高频功能：

1. **每日签到**：客户端用户每天必做的操作，获取云贝/积分
2. **收藏单曲到指定歌单**：发现好歌后无法直接加入自己的歌单
3. **相似歌曲推荐**：无法基于当前歌曲发现风格相近的新歌
4. **新歌速递**：无法了解最新发行的歌曲
5. **播放记录/听歌排行**：无法回顾自己的听歌偏好
6. **每日推荐歌单**：除每日推荐歌曲外，缺少个性化歌单推荐
7. **搜索建议/联想词**：搜索时无实时建议
8. **歌曲热门评论**：网易云特色功能，缺少展示
9. **精品歌单**：缺少高质量歌单的发现入口
10. **新碟上架**：无法发现最新专辑

### 1.2 目标

- **核心目标**：让用户在 Chrome 新标签页中完成 80% 以上的网易云日常操作，减少切换客户端的需求
- **体验目标**：功能覆盖全但不臃肿，按使用频率分层呈现

### 1.3 优先级与分期规划

| 阶段 | 功能 | 优先级 | 预期版本 |
|:---:|------|:---:|:---:|
| P0-A | 每日签到 | 最高 | v3.19.0 |
| P0-B | 收藏单曲到指定歌单 | 最高 | v3.19.0 |
| P1-A | 相似歌曲推荐 | 高 | v3.19.0 |
| P1-B | 新歌速递 | 高 | v3.19.0 |
| P1-C | 播放记录/听歌排行 | 高 | v3.19.0 |
| P2-A | 每日推荐歌单 | 中 | v3.20.0 |
| P2-B | 搜索建议/联想词 | 中 | v3.20.0 |
| P2-C | 歌曲热门评论 | 中 | v3.20.0 |
| P3-A | 精品歌单 | 低 | v3.21.0 |
| P3-B | 新碟上架 | 低 | v3.21.0 |

### 1.4 成功指标

| 指标 | 目标 |
|------|------|
| 每日签到成功率 | > 95% |
| 收藏单曲到歌单操作流畅度 | 3 步以内完成（右键→选歌单→确认） |
| 相似歌曲推荐命中率 | 接口返回 > 0 首的比例 > 90% |
| 新歌速递加载成功率 | > 95% |

## 二、用户故事

### US-1：每日签到
> 作为用户，我打开新标签页时，想一键完成网易云每日签到，获取云贝奖励。

### US-2：收藏单曲到歌单
> 作为用户，我在搜索结果/队列/推荐中听到一首好歌，想右键直接加到我的某个歌单里。

> 作为用户，我正在听一首喜欢的歌，想看看有哪些风格相似的歌曲。

> 作为用户，我想了解最近发行的新歌，按语种分类浏览。

### US-5：播放记录回顾
> 作为用户，我想查看自己最近/所有时间的听歌排行，了解音乐偏好。

### US-6：搜索歌单收藏
> 作为用户，我搜索到一个好歌单或点开一个歌单详情页，想收藏到自己的账号。

## 三、功能详细设计

### 3.1 每日签到（P0-A）

#### 3.1.1 交互方式

- **自动签到**：首次打开新标签页时自动触发签到（可在设置中关闭）
- **手动签到**：在「发现」Tab 中增加签到入口按钮
- **签到结果**：toast 提示签到成功/已签到/失败

#### 3.1.2 API

| 接口 | 方法 | 参数 | 说明 |
|------|------|------|------|
| `/api/point/dailyTask` | POST | `type: 0`（安卓端） | 每日签到 |

#### 3.1.3 逻辑

1. 使用 `localStorage` 记录当天签到状态，避免重复调用
2. 签到成功后更新按钮状态为「已签到」
3. 跨日自动重置签到状态

#### 3.1.4 UI 规范

- 签到按钮样式与现有私人FM入口保持一致
- 未签到：`fa-calendar-check` 图标 + "每日签到"
- 已签到：`fa-check-circle` 图标 + "已签到" + 灰色调

---

### 3.2 收藏单曲到指定歌单（P0-B）

#### 3.2.1 交互方式

- **右键菜单**：在所有歌曲行的右键上下文菜单中增加「收藏到歌单」选项
- **歌单选择弹窗**：展示用户自己创建的歌单列表，点击即可添加

#### 3.2.2 API

| 接口 | 方法 | 参数 | 说明 |
|------|------|------|------|
| `/api/playlist/manipulate/tracks` | POST | `op: add, pid: 歌单ID, trackIds: 歌曲ID` | 添加单曲到歌单 |
| `/api/user/playlist` | GET | `uid, limit, offset` | 获取用户歌单列表（已有） |

#### 3.2.3 逻辑

1. 复用已有的 `_userPlaylists` 缓存
2. 过滤只展示用户创建的歌单（`creator.userId === 当前用户 ID`）
3. 添加成功后 toast 提示「已添加到: 歌单名」
4. 处理已存在的情况（code 502）

#### 3.2.4 UI 规范

- 歌单选择弹窗使用现有的弹窗样式体系
- 歌单列表展示封面缩略图 + 歌单名 + 歌曲数

---

### 3.3 相似歌曲推荐（P1-A）

#### 3.3.1 交互方式

- **当前播放歌曲**：在播放条或歌词面板中增加「相似推荐」入口
- **右键菜单**：增加「查看相似歌曲」选项
- **展示方式**：在操作台浮层中以歌曲列表展示

#### 3.3.2 API

| 接口 | 方法 | 参数 | 说明 |
|------|------|------|------|
| `/api/simi/song` | GET | `id: 歌曲ID` | 获取相似歌曲 |

---

### 3.4 新歌速递（P1-B）

#### 3.4.1 交互方式

- 在「发现」Tab 中增加「新歌速递」区域
- 按语种分类：全部(0)、华语(7)、欧美(96)、日语(8)、韩语(16)
- 支持直接播放和加入队列

#### 3.4.2 API

| 接口 | 方法 | 参数 | 说明 |
|------|------|------|------|
| `/api/top/song` | GET | `type: 0/7/96/8/16` | 新歌速递 |

---

### 3.5 播放记录/听歌排行（P1-C）

#### 3.5.1 交互方式

- 在「歌单」Tab 中增加「最近播放」入口
- 支持切换「最近一周」和「所有时间」
- 展示歌曲名、歌手、播放次数

#### 3.5.2 API

| 接口 | 方法 | 参数 | 说明 |
|------|------|------|------|
| `/api/v1/play/record` | GET | `uid, type: 0(所有)/1(最近一周)` | 播放记录 |

## 四、技术方案

### 4.1 架构

所有功能均通过已有的 `_neteaseApi()` → `background.js neteaseApiCall()` 调用链实现，无需新增通信通道。

### 4.2 数据缓存策略

| 数据 | 缓存位置 | 有效期 |
|------|----------|--------|
| 签到状态 | localStorage | 当日有效（跨日重置） |
| 用户歌单列表 | 内存 | 会话级，首次加载后缓存 |
| 相似歌曲 | 不缓存 | 每次请求实时获取 |
| 新歌速递 | 内存 | 10 分钟 |
| 播放记录 | 不缓存 | 每次请求实时获取 |

### 4.3 影响范围评估

| 文件 | 修改内容 |
|------|----------|
| `js/music-controller.js` | 新增功能方法、UI 渲染、事件绑定 |
| `css/style.css` | 新增组件样式 |
| `js/background.js` | 无需修改（通用 API 代理已支持） |

## 五、非功能需求

1. **性能**：签到请求不阻塞页面加载，异步执行
2. **错误处理**：所有 API 调用统一 toast 错误提示，不影响核心播放功能
3. **兼容性**：与现有歌手/专辑导航、私人FM、心动模式功能互不干扰
4. **降级**：未登录用户显示登录引导，不显示需登录的功能入口
