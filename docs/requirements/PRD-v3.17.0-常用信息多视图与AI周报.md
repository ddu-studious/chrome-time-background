## 1. 背景与痛点

### 1.1 用户反馈


| 痛点            | 严重度 | 描述                       |
| ------------- | --- | ------------------------ |
| 日常文档越来越多，难以整理 | 高   | 14+ 卡片、8+ 标签，缺乏全局视角      |
| 不好知道最近干了什么    | 高   | 缺少按时间维度的回顾能力             |
| 信息过于分散        | 中   | 卡片/任务/书签/热榜分属不同模块，无法交叉浏览 |
| 缺乏数据洞察        | 中   | 没有统计概览，无法衡量产出            |


### 1.2 竞品参考

- **Notion**: 多视图切换（Board / Timeline / Calendar / Gallery）
- **Obsidian**: Graph View + Daily Notes + Activity
- **iTab**: 仪表盘式新标签页

## 2. 产品方案

### 2.1 核心架构

在「常用信息」面板顶部新增**三视图切换 Tabs**：


| 视图  | 图标             | 用途             | 数据来源                                       |
| --- | -------------- | -------------- | ------------------------------------------ |
| 卡片墙 | `fa-th-large`  | 原有瀑布流 + 分区增强   | `knowledgeWall`                            |
| 时间线 | `fa-stream`    | 按周/天浏览跨模块活动    | `activityLog` + 实体 `createdAt`/`updatedAt` |
| 仪表盘 | `fa-chart-pie` | 统计概览、热力图、AI 周报 | 混合数据源                                      |


### 2.2 活动日志基础设施

**新增模块**: `js/activity-logger.js`

```
ActivityLogger
├── 存储: chrome.storage.local 'activityLog'
├── 保留策略: 90 天
├── 记录 API: log({ type, module, title, targetId, targetTitle, meta })
├── 查询 API: getByDateRange, getWeeklyTimeline, getHeatmapData
├── 混合查询: getHybridWeeklyTimeline（活动日志 + 实体回溯）
└── AI 周报: generateWeeklySummary
```

**埋点覆盖**:


| 模块  | 操作          | 活动类型                                                            |
| --- | ----------- | --------------------------------------------------------------- |
| 知识墙 | 创建/更新卡片     | `note_create` / `note_update`                                   |
| 知识墙 | 删除卡片        | `note_delete`                                                   |
| 任务  | 创建/更新/完成/删除 | `task_create` / `task_update` / `task_complete` / `task_delete` |
| 热榜  | 保存为任务       | `ticker_save`                                                   |


**双轨数据源**:

- 活动日志: 实时记录用户操作
- 实体回溯: 从卡片/任务的 `createdAt`/`updatedAt`/`completedAt` 构建历史事件，去重后合并

### 2.3 卡片墙视图增强

**分区展示**:

- 置顶区: 带 `📌 置顶` 标签和计数，视觉分隔
- 最近区: 带 `🕐 最近` 标签和计数
- 分区间有分隔线

### 2.4 时间线视图

**功能**:

- 按周导航（本周/上周/更早），显示周期标签
- 按天分组，每天显示日期 + 星期 + 活动条目
- 每条活动: 类型图标（彩色）+ 标题 + 时间 + 标签 + 模块徽章
- 统计栏: 笔记/任务/书签/热榜数量
- AI 周报摘要区（内嵌在时间线顶部）

**数据源**: 混合模式（`getHybridWeeklyTimeline`），确保即使 activityLog 为空，也能从实体数据回溯显示历史。

### 2.5 仪表盘视图

**统计卡片（4 格）**:

- 卡片总数: 从 `this.cards.length`，本周新增趋势
- 任务完成: `已完成/总数` 格式，百分比完成率，颜色标识
- 本周活动: 从实体数据计算
- 周记: 按 `type === 'weekly'` 统计

**卡片类型分布**:

- 横向条形图: 笔记/链接/代码/联系人/周记，彩色进度条 + 数量 + 百分比

**活动热力图**:

- 12 周 × 7 天矩阵，GitHub 风格
- 颜色分级: level 0-4
- 今日高亮，hover 显示日期和数量

**最近更新** + **活跃标签**: 两栏布局

### 2.6 AI 周报摘要

**调用链路**:

- 读取 `bookmarkSettings` 获取 AI 服务配置
- 支持: 通义千问 / DeepSeek / OpenAI / Gemini / 自定义
- Prompt: 系统角色 + 活动详情 + 生成要求（3-5 句、关键词加粗、简洁专业）
- 缓存: `activityWeeklySummaryCache`，保留 8 周

**功能**:

- 生成周报: 首次显示 "生成" 按钮，已有缓存直接展示
- 重新生成: 覆盖缓存
- 复制: 纯文本到剪贴板
- 导出: Markdown 文件下载
- 无 API Key 降级: 本地统计摘要

| Key                          | 存储类型                   | 说明            |

## 6. 风险与依赖


| 风险                | 影响     | 缓解措施            |
| ----------------- | ------ | --------------- |
| activityLog 数据量增长 | 存储占用   | 90 天自动清理 + 条目精简 |
| AI API 不可用        | 周报无法生成 | 本地统计摘要降级        |
| 多标签页并发写日志         | 数据丢失   | 单实例设计 + 内存缓存    |
