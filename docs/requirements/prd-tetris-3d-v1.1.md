## 一、产品概述

### 1.1 背景

Chrome 扩展新标签页 Dock 已具备 2D「俄罗斯方块」入口。用户与运营期望增加 **视觉差异化** 的休闲模块，提升 Dock 探索率与 7 日留存，且 **不** 引入独立游戏产品、后端服务或内购体系。

v1.0 PRD 描述的「真 3D 多层井」在旋转直觉、碰撞判定与 QA 用例上存在 **3～5 倍** 复杂度，与「14 日可玩 MVP」冲突。经跨角色评审，MVP 采用 **2.5D**：逻辑与经典 10×20 单层消行一致，表现层呈现立体方块与固定斜视相机。

### 1.2 目标用户

| 用户画像 | 场景 | 核心诉求 |
|----------|------|----------|
| 扩展日常用户 | 打开新标签页等待加载、短暂休息 | 零学习成本、即开即玩、不干扰主功能 |
| 轻度游戏用户 | 熟悉经典方块消除 | 操作手感可预期、分数有反馈、可重复挑战 |
| 运营/产品 | 观察 Dock 模块 ROI | 可度量点击率与留存 uplift，失败可快速回滚 |

### 1.3 产品定位

- **是什么**：Dock 内独立入口的 **单机、无尽、经典模式** 立体方块游戏  
- **不是什么**：独立 3A 游戏、竞技排位产品、变现载体、真 3D 空间解谜  
- **与 2D 面板关系**：**并存**；2D 入口保留，3D 为可选差异化路径，支持 A/B 与 L1 入口关闭回滚

### 1.4 成功指标（90 天观察窗）

| 指标 | 目标 | 未达标动作 |
|------|------|------------|
| Dock 游戏入口点击率 | +15%～+25%（相对基线） | 复盘入口与动效，不启动 Phase 2 |
| 扩展 7 日留存 | +2～4 pp | 评估是否保留入口或仅保留 2D |
| 主功能使用 | 不得下降 >3% | 触发 L0/L1 回滚预案 |
| 单局完局率（P1 埋点后） | 作为辅助观测，不设硬门禁 | 用于 UX 迭代 |

## 四、交互与体验要求

### 4.1 入口与面板

- Dock 注册独立应用 **`tetris-3d-game`**，名称 **「立体方块」**，与 **`tetris-game`（2D）** 并存  
- 打开后面板全屏或大块区域展示 3D 棋盘 + HUD；关闭面板即退出对局（MVP 不保证后台续玩）  
- 首次打开可显示 3 秒以内操作提示，可「不再提示」（P1 本地记忆）

### 4.2 默认键位（桌面）

| 操作 | 默认键 | 逻辑效果 |
|------|--------|----------|
| 左移 | ← / A | `dx = -1` |
| 右移 | → / D | `dx = +1` |
| 顺时针旋转 | ↑ / X / K | `rotate CW` |
| 软降 | ↓ / S | 下移一格；触地锁定 |
| 硬降 | C / End | 落底并锁定 |
| 暂停 | Space / P / Esc | 冻结仿真时间（P1 完整；P0 可仅 Esc 关闭面板） |

**边界**：快捷键仅在对局面板 **聚焦** 时生效，避免吞掉扩展全局快捷键。

### 4.3 视觉预期（用户可感知，非实现约束）

- 每格为 **立体小方块（体素）**，锁定格与活动骨牌颜色可区分  
- 相机 **固定**，用户 **不能** 拖拽旋转场景（避免与左右操作语义冲突）  
- 降级到 2D 时保留 **同一套 HUD 与键位**，用户应能无感完成一整局

## 五、计分规则细则（BR-SCORE）

> **SSOT 对齐**：数值与 `classic_subset_v1.scoringRef` 及现内核 `clearFullLines` 一致。MVP **不** 启用 Guideline 扩展分（T-Spin、Back-to-Back、Combo 加成）。日后扩展须新增 `scoringProfileId`，不得 silent 改分。

### 5.1 单局状态变量

| 变量 | 初值 | 说明 |
|------|------|------|
| `score` | 0 | 当前局总分（整数，只增不减） |
| `lines` | 0 | 累计消除行数 |
| `level` | 0 | 由消行推导，见 §5.3 |

### 5.2 消行得分（Line Clear）

一次锁定后，若检测到 **1～4 行** 同时满行并消除，按 **单次消除行数** 加分（**不** 乘以等级）：

| 单次消除行数 | 加分 | 用户向名称 |
|--------------|------|------------|
| 0 | 0 | — |
| 1 | **100** | 单行 |
| 2 | **300** | 双行 |
| 3 | **500** | 三行 |
| 4 | **800** | 四行（满板） |

**触发顺序（验收用）**：`lock → 检测满行 → 删除行并顶部补空 → 更新 score/lines/level → 生成下一块`

**边界 BR-SCORE-01**：同一次锁定产生多行消除，**只触发一次** 上表加分（按行数查表，非逐行累加 100）。  
**边界 BR-SCORE-02**：连续两次锁定各消 1 行 → 各 +100，共 +200。  
**边界 BR-SCORE-03**：MVP **无** 「消层」「Z 向柱体」「深度连击」计分。

### 5.3 等级与重力（Level & Gravity）

| 规则 ID | 规则 |
|---------|------|
| BR-SCORE-10 | 每累计消除 **10 行**，`level = floor(lines / 10)`（初值 0；消第 10 行后 level 变为 1） |
| BR-SCORE-11 | 等级升高只影响 **自动下落间隔变短**，**不** 放大 §5.2 消行基础分 |
| BR-SCORE-12 | 速度曲线采用 **classic 近似 ms 阶梯**（见参数包 `classic_subset_v1.speedCurve`）；用户感知为「越玩越快」 |

### 5.4 软降 / 硬降（MVP 冻结）

| 规则 ID | 规则 | MVP |
|---------|------|-----|
| BR-SCORE-20 | 软降每成功下移一格 | **0 分**（与现内核一致） |
| BR-SCORE-21 | 硬降落底 | **0 分**；仅触发锁定与消行计分 |
| BR-SCORE-22 | Guideline「硬降每格 +1 分」 | **Phase 2 / tech-debt**，MVP 不启用 |

*产品说明*：MVP 优先 **简单可解释**——分数几乎全部来自消行；避免 HUD 出现「硬降刷分」行为。

### 5.5 对局结束与展示

| 规则 ID | 规则 |
|---------|------|
| BR-SCORE-30 | Game Over 时 HUD **冻结** 最终 score / lines / level |
| BR-SCORE-31 | 重开清零上述三值 |
| BR-SCORE-32 | 本地最高分（P1）：仅当 `score > bestScore` 时更新；同分 **不** 覆盖（先达成者优先） |

### 5.6 计分相关极端情况

| 场景 | 期望行为 |
|------|----------|
| 顶线溢出导致 Game Over 的最后一次锁定 **同时** 消行 | 仍按 §5.2 计分，再进入 Game Over |
| 0 行消除的锁定 | score 不变 |
| 暂停期间 | score/lines/level **不变**；不补发分数 |
| 渲染降级前后 | 分数 **完全一致**（逻辑与表现分离） |
| 快速连按软降 | 每格一次锁定链独立计分；不得重复计同一行 |

### 5.7 Phase 2 计分扩展（Backlog，非 MVP）

- T-Spin / Mini 判定与加分  
- Back-to-Back、Combo 倍率  
- 硬降每格 +1、软降每格 +1（Guideline 向）  
- 真 3D：**Z 层消除**、**柱体坍缩** 独立计分表

## 七、边界条件与极端情况

### 7.1 玩法边界

| 条件 | 处理 |
|------|------|
| 同帧左+右输入 | 净位移 0（不对消以外的方向生效） |
| 同帧硬降+移动 | **仅硬降** 生效 |
| O 块旋转 | 无占位变化（no-op） |
| 四行同时消除 | +800，lines +4，level 按总 lines 重算 |
| 关闭面板 mid-game | 对局丢弃；MVP 不承诺恢复 |

### 7.2 体验边界

| 条件 | 处理 |
|------|------|
| 低端 GPU / WebGL 失败 | Canvas 2D 降级，提示文案可选「已切换经典视图」 |
| 失焦 / 切 Tab | P1：自动暂停；P0：允许继续下落（需在发布说明标注） |
| Dock 入口被 L1 关闭 | 用户仍可通过 2D 入口游玩；无功能损失 |

### 7.3 合规与品牌

- 对外文案：**立体方块**、**3D 方块消除**  
- 避免 Tetris 商标、避免与官方美术高度雷同  
- 不在商店描述中承诺「竞技合规」「官方规则」
