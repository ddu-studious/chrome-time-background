# 闹钟与音乐的连续会话（2026-09-14）

本次需求：清晰展示当前会话是否结束，允许补充、修正，避免丢掉未完成消息或把旧请求带进新会话。

## 用户操作

- 闹钟与音乐各自显示会话状态和可展开的本次对话。
- “编辑当前需求”将当前需求放回输入框，发送后继续修改同一会话。
- “新建另一条”明确清空当前上下文，生成新会话；“结束本次”结束未完成会话。
- 停止解析/处理仅终止当前异步工作，保留会话、草稿、原句和未完成输入。
- 收起面板不结束；同一标签页刷新恢复未完成会话。关闭标签页后不保证恢复，不在不同场景间共享上下文。
- 请求失败保留本次消息。达到上下文上限时明确提示，不静默截断或自动清空。

## 闹钟

保存结构化草稿（事项、日期、时间、时段、重复等）和问答历史。简单时间/时段补充走离线规则，复杂表达携带两者调用本地模型。

示例：“设置一个11点的闹钟，提醒我带外卖”→“上午”→“明天”，得到明天11:00、带外卖。问日期时回答上午，同样保留有效信息再询问日期。补齐后进入待确认，仍可输入“改成下午四点”；只有点击“确认设置”后才保存、结束会话。成功回执前不宣称已创建；保存期间禁用重复确认，使用稳定会话ID防止重试创建多条。

已说出的相对日期转换为绝对日期，跨午夜不漂移；本轮重新说“明天”按本轮日期解释。倒计时保留会话起始基准；解析后和保存前检查过期，不自动顺延。时区变化需用户重新确认新需求。

## 音乐与语音

音乐提交携带本次问答和已知需求，追问后“周杰伦”能补充“晴天”的歌手。候选列表支持点击与“第二个”等序号续选，序号只映射当前真实搜索候选，不让模型产生ID。新搜索、手动播放器操作、新建或结束会话会使旧候选失效；刷新后保留需求但需要重新搜索候选。

推荐列表和歌单浏览保持会话待补充；已确认播放或控制操作完成后结束。语音是同一输入框的另一种输入方式：开始录音保留已展示候选，新建/结束会话取消旧录音，迟到转写不进入新会话。处理结束不覆盖用户正在编辑的下一句话。
