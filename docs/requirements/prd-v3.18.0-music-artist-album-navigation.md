# PRD：音乐播放器 — 歌手/专辑交互导航增强 v3.18.0

**产品名称**: 中国风景时钟
**版本**: v3.18.0
**作者**: AI Agent
**日期**: 2026-08-05
**状态**: active
**依赖**: v3.17.0（一键清空队列、单曲移除、智能跳过、睡眠定时器）

## 一、产品概述

### 1.1 背景

v3.17.0 的音乐播放器已具备完整的播放能力：队列管理、搜索、发现、私人FM、歌词、歌手操作台（热门/专辑/相似）。但用户体验存在以下痛点：

1. **歌手名不可交互**：队列列表、推荐列表、播放条中的歌手名都是纯文本，无法点击跳转
2. **唯一入口受限**：歌手操作台（_openArtistActionSheet）仅在搜索歌手结果中可触达
3. **专辑信息缺失**：专辑封面、发行信息等在操作台中显示有限
4. **多歌手场景未处理**：合作歌曲显示为"歌手A/歌手B"，不可分别点击

### 1.2 目标

- **核心目标**：让所有歌曲列表中的歌手名成为可交互入口，点击即可查看歌手的热门 Top50、专辑列表、相似歌手
- **次要目标**：增强专辑详情展示，支持查看专辑封面和歌曲列表
- **体验目标**：从「线性播放」升级为「探索式发现」，用户可以通过歌手→专辑→新歌手的路径自然发现新音乐

### 1.3 成功指标

| 指标 | 目标 |
|------|------|
| 歌手可点击触点覆盖率 | 8/8 场景全部支持 |
| 歌手操作台打开成功率 | > 95%（含回退策略） |
| 专辑详情加载成功率 | > 90% |
| 导航返回操作成功率 | 100%（嵌套场景不丢失上下文） |

## 二、用户故事

### US-1：队列歌手跳转
> 作为用户，我在播放队列中看到一首喜欢的歌，想点击歌手名查看 TA 的其他歌曲。

### US-2：播放条歌手探索
> 作为用户，我正在听歌，想点击播放条上的歌手名快速查看 TA 的更多作品。

### US-3：推荐列表歌手发现
> 作为用户，我在每日推荐中发现一首好歌，想点击歌手名探索 TA 的全部音乐。

### US-4：搜索结果歌手跳转
> 作为用户，我搜索到一首歌，想通过歌手名查看 TA 的热门歌曲和专辑。

### US-5：合作歌曲多歌手
> 作为用户，我听一首合作歌曲（周杰伦/方文山），想分别点击查看每位歌手。

### US-6：歌手→专辑→歌手嵌套浏览
> 作为用户，我在歌手A的专辑中发现歌手B的合作曲，想继续查看歌手B，然后能返回歌手A。

### US-7：右键快速操作
> 作为用户，我右键点击一首歌，想快速跳转到歌手页或专辑页。

## 三、功能规格

### 3.1 Phase 1：歌手可点击 + 数据管线（核心）

#### 3.1.1 数据结构扩展

**当前数据结构**：
```js
playlist[] = { title, artist, songId, index, isActive }
```

**扩展后**：
```js
playlist[] = {
  title, artist, songId, index, isActive,
  artists: [{ id: number, name: string }],  // 新增：结构化歌手数组
  albumId: number,                           // 新增：专辑ID
  albumName: string,                         // 新增：专辑名
}
```

**数据来源**：网易云 API 返回的 `s.ar[]`（歌手数组）和 `s.al`（专辑信息）。

**影响范围**：
- `_playSongById()` 中 `/api/v3/song/detail` 响应解析
- `_renderRecommend()` 中推荐歌曲映射
- `_loadPlaylistSongsViaApi()` 中歌单歌曲映射
- `_savePlaylistCache()` 中缓存字段扩展
- `_restoreMusicState()` 中恢复逻辑

#### 3.1.2 歌手可点击触点（8 处）

| 优先级 | 位置 | 当前状态 | 改造目标 |
|--------|------|----------|----------|
| P0 | 队列列表 mc-row-artist | 纯文本 | 可点击链接 → _openArtistActionSheet() |
| P0 | 发现/推荐 mc-rec-row | 纯文本 | 可点击链接 |
| P0 | 搜索歌曲结果 | 纯文本 | 可点击链接 |
| P0 | 播放条 mc-sub | 纯文本 | 可点击链接 |
| P1 | 歌词面板顶部 | 无歌手信息 | 新增歌手可点击 |
| P1 | 歌手操作台内歌曲 | 纯文本 | 可点击链接（跳转其他歌手） |
| P1 | 专辑详情内歌曲 | 纯文本 | 可点击链接 |
| P1 | 右键菜单 | 无「查看歌手」 | 新增菜单项 |

#### 3.1.3 歌手名点击逻辑

```
点击歌手名
  ├─ 有 artistId → 直接调用 _openArtistActionSheet(artistId, name, img)
  └─ 无 artistId（缓存数据）
      ├─ 通过 /api/v3/song/detail 获取歌手ID → 成功 → 打开操作台
      └─ 失败 → 用歌手名搜索 /api/search/get/web type=100 → 匹配 → 打开操作台
```

#### 3.1.4 右键菜单增强

在现有右键菜单基础上增加：
- **查看歌手**：打开歌手操作台（多歌手时显示子菜单）
- **查看专辑**：打开专辑详情（需 albumId）

### 3.2 Phase 2：专辑详情增强

- 专辑详情页增加 header 区：大封面 + 专辑名 + 歌手（可点击）+ 发行年份 + 歌曲数
- 专辑歌曲列表中歌手名可点击（跳转其他歌手）

### 3.3 Phase 3：歌手主页增强

- 调用 `/api/artist/detail` 获取歌手大图和简介
- 操作台 header 升级为全宽头图
- 热门标签页 Top50 带序号色彩渐变
- 相似歌手行显示头像 + 歌曲数

### 3.4 Phase 4：体验打磨

- 导航返回栈（歌手A→专辑→歌手B→专辑… 可逐级返回）
- 多歌手拆分为独立可点击标签
- 歌手/专辑数据内存缓存（10 分钟 TTL）
- 加载态骨架屏替代 spinner

## 四、技术方案

### 4.1 API 接口

| 接口 | 方法 | 用途 | 状态 |
|------|------|------|------|
| /api/artist/top/song | GET | 歌手热门50首 | 已有 |
| /api/v1/artist | GET/POST | 歌手信息+热门 | 已有 |
| /api/artist/albums | GET/POST | 歌手专辑列表 | 已有 |
| /api/v1/album | GET | 专辑歌曲列表 | 已有 |
| /api/discovery/simiArtist | GET/POST | 相似歌手 | 已有 |
| /api/artist/detail | GET | 歌手详细资料 | Phase 3 新增 |
| /api/v3/song/detail | GET | 歌曲详情（ar[].id） | 已有 |

### 4.2 CSS 改造

- `.mc-row-artist` 从 `<span>` 改为可点击样式（cursor:pointer, hover 下划线, accent 色）
- `.mc-row-artist-tag` 新增：多歌手拆分标签样式
- `#mc-sub` 内歌手部分增加 `.mc-sub-artist` 可点击样式

### 4.3 缓存策略

- 内存缓存 `Map<artistId, { hotSongs, albums, similar, ts }>`
- TTL 10 分钟，会话级别，不写入 storage
- 缓存命中时跳过 API 请求直接渲染

## 六、风险与约束

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 缓存数据无 artistId | 点击歌手名无法直接打开 | 回退到 song/detail API 获取，再回退到搜索 |
| API 请求频率过高 | 触发网易云反爬 | 10 分钟内存缓存 + 防抖 |
| 深层嵌套导航丢失上下文 | 用户迷路 | 返回栈 + 深度限制 5 层 |
| 多歌手歌曲 ar[] 数据缺失 | 无法拆分显示 | 回退为整体可点击（按名搜索） |
