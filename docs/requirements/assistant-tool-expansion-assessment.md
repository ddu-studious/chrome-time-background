# 快捷助手工具补齐评估

日期：2026-09-16。状态：原始评估方案；P0、按需工具加载与P1已实现，实际合同和验证入口见 [P0实现说明](../design/assistant-adaptive-tools-v1.md) 与 [P1实现说明](../design/assistant-management-p1.md)。

## 目标与截图问题

截图中助手表示不能查看队列、不能执行“有队列随机播放，无队列添加歌单”的条件判断，并让用户选择两个分支。截图未展示完整原始输入，不能据此还原全部用户约束。

产品目标：对于能通过工具读取的事实，助手自行查询；按用户给定条件推进；只有对象歧义、能力不足或确需用户选择时暂停。

## 已核实的缺口

| 层级 | 当前代码证据 | 判断 |
|---|---|---|
| 工具目录 | `js/assistant-contract.js` 的 tools 仅含搜索、音乐意图、定时、提醒准备/列表、视频搜索/历史 | 缺少状态、队列、播放模式工具 |
| 队列界面 | `js/assistant-music.js` 的 choose 支持 music.queue，从 musicPlaylistCache 展示队列 | UI 已有能力，但模型无法直接调用；缓存也不能直接等同实时状态 |
| 随机播放 | `js/music-controller.js` 有 sequence/loop/single/shuffle 和随机队列 | 工作台有实现，但助手 controlMusic 未接入模式控制 |
| 后台续播 | `js/background.js` 的 advanceSilentMusicPlayback 按相邻索引推进；助手 next/previous 也按相邻索引选择 | 仅开放工作台随机按钮不足以保证关掉工作台后持续随机 |
| 计划执行 | `js/assistant-engine.js` 规划后线性执行最多三个步骤；工具结果主要变成界面和会话文字 | 缺少结构化观察结果驱动的后续决策 |
| 二级意图解析 | `local-ai/music-service.mjs` 每次一个动作，动作枚举不含读取队列/设置模式 | 复杂条件需求下发 music.intent 后仍可能再次被追问 |
| 路由 | `js/assistant-contract.js` 的 localPlan 会把许多音乐请求直接送入 music.intent | 必须同时修正规则路由，不能只改模型提示词 |
| 闹钟 | `js/background.js` 已有 user_alarm_save/rename/delete/toggle 消息入口 | 可评估复用已有业务；助手当前未暴露修改、删除、开关 |

## P0：完成截图中的闭环

以下为建议工具名，不代表已经实现。优先做六个工具入口，保留已有搜索、定时能力。

| 工具 | 输入概要 | 输出与职责 |
|---|---|---|
| music.state | 无 | 播放状态、当前歌曲引用、模式、队列数量、定时、状态来源、版本及读取时间；区分 empty/unavailable/stale |
| music.queue.list | cursor、limit | 真实队列条目引用、当前项、总数、版本；分页，避免把整队列塞进模型上下文 |
| music.playback.setMode | mode、expectedRevision | 顺序/列表循环/单曲循环/随机；统一工作台与后台续播语义，返回实际生效模式 |
| music.queue.play | 可选 trackRef、expectedRevision | 播放当前队列；按模式选择有效起点，验证真实播放回执 |
| music.collection.get | entityRef、cursor、limit | 从搜索结果引用读取歌手热门歌曲、专辑或歌单曲目，返回真实曲目引用及截断信息 |
| music.queue.apply | collectionRef 或 trackRefs、mode、startPlayback、expectedRevision | 显式 append/replace，是否立即播放；先准备资源，再提交队列，避免失败损坏旧队列 |

引用只能解析到真实工具结果，绑定任务/来源/版本；不接受模型编造歌曲 ID、URL。保留现有按钮的“单曲加入并播放、整组替换并播放”语义；新增工具中显式区分追加和替换。

截图场景目标流程：

1. 读取 music.state；需要了解内容时再读 music.queue.list。
2. 有有效队列：设置随机模式，播放当前队列，核对实际歌曲和模式。
3. 空队列：调用已有 music.search 搜索用户指定歌手的歌单，展示真实候选；用户若已明确授权自动选择，可按预先定义的匹配规则选择，否则沿用候选选择。
4. 读取已选歌单曲目，准备资源后应用到空队列；若原始需求要求随机播放，则继续设置随机并播放。只有“添加”时不得擅自推断需要播放。
5. 读取失败、缓存过期不是空队列；不得因此自动替换现有内容。提交前检查队列版本，用户中途操作优先。

## 执行流程必须同步升级

建议沿用现有统一 AI 控制面和 JSON 出口，先实现有上限的逐步决策，不把原生 tool_calls 迁移作为前置条件。

- 规划协议增加明确的下一步调用、完成、追问三类结果；每轮执行后把结构化观察交给规划器。旧版线性计划可保留兼容。
- 工具元数据增加完整输入/输出类型、枚举、必填字段、只读/写入标记、可重试性、用户选择要求；当前只有字段名的目录不足以表达执行合同。
- 统一观察格式：status、data、errorCode、retryable、revision、truncated、nextCursor。网络故障、无结果、未登录、空队列、不可播放必须可区分。
- 建议初始上限：每任务 6 次规划、12 次工具调用、每种可重试读取最多重试 1 次；写入不得盲目重试。保留现有执行超时及用户等待暂停语义。
- 结构化观察只保留必要摘要和真实引用；账号凭据、播放签名 URL 不进入模型输入。外部标题和简介作为资料处理。
- 执行日志关联 taskId、stepId、工具、耗时、回执；写入以步骤标识防重，恢复后台后先核对结果，不自动重放。
- localPlan 对条件词、多步骤意图不得降级成单动作 music.intent；避免两个解析层反复追问。
- 查询与已明确授权的播放控制直接执行；保留现有闹钟确认与候选选择约定，不额外增加查询许可弹窗。

## P1：补齐四个应用的日常操作

| 范围 | 建议新增/增强 | 可支持的需求与边界 |
|---|---|---|
| 音乐 | music.playback.control、music.playback.seek | 显式暂停/继续/上下首/音量，跳到指定秒数；控制能力部分已存在，需从自由文本意图中规范暴露 |
| 音乐 | music.queue.remove、music.queue.clear；分页搜索 | 去掉指定队列项、清空本地队列、继续找；目标引用与版本检查，明确不改云端歌单 |
| 闹钟 | alarm.get、alarm.update.prepare、alarm.toggle、alarm.delete.prepare | 找到目标、改到明天、关闭提醒、删除提醒；重名时先定位，修改/删除展示准确目标和变更 |
| 视频 | video.details、video.search 分页和过滤 | 搜索后取真实时长/作者/发布时间，再筛选；不能仅按标题猜内容；具体平台接口适配另行验证 |
| 视频 | video.open、video.progress.get | 将现有候选打开能力规范暴露；已打开与已播放分别回执，进度注明本地或平台来源 |
| 通用 | 按应用暴露连接状态/可用能力 | 未登录时给出准确连接入口，避免“无搜索结果”；能力也可随场景注入，不必每轮单独调用工具 |

## P2：后续独立评估

- 视频字幕读取与内容总结：先确认字幕真实获取通道、权限、覆盖范围，再纳入工具；摘要必须基于实际内容。
- 网易云云端收藏/歌单写入、B 站收藏等：需要独立核验账号权限、接口和写入语义，不与本地队列混用。
- 跨应用组合任务：在单应用状态、引用与写入回执可靠后，再开放作用域组合。
- 书签、任务、日程等已有模块：复用已登记 AI 场景和真实业务入口，单独定义工具合同；不在截图修复阶段扩大范围。

## 实施顺序和验收

第一阶段：统一音乐状态和模式控制，打通六个 P0 工具及规则路由；第二阶段：逐步决策与结果回传；第三阶段：P1 工具按使用频率逐项接入。第一、二阶段一起构成截图场景的可交付版本。

必要验收用例：

1. 有队列时执行随机播放，不重复搜索、不要求用户判断队列是否存在。
2. 空队列时搜索指定歌手歌单；选择后按原需求加载/播放；无结果不编造。
3. 工作台开着、关着、关闭后续播、后台重启恢复时，模式与当前曲目一致。
4. 切换播放模式后自动结束续播与手动下一首均遵循相同模式；FM 保持独立语义。
5. 状态读取失败、过期、版本冲突、未登录、部分曲目不可播放时给出准确结果，保留旧队列。
6. 用户中途手动操作、取消、重复确认、旧候选、重复请求不造成覆盖或重复提交。
7. 模型无法生成越权工具、额外参数、伪造引用或突破调用上限。
8. 队列准备完成不等于播放完成；最终文案由实际回执支撑。

证据边界：本评估是当前源码静态核对，未运行真实 Qwen、账号搜索、音频播放或扩展重载验收。实现时须分别报告自动测试、隔离页面验证和真实扩展结果。
